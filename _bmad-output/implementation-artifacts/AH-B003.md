## Reproduction

From the issue: run `bin/harness install --no-brew` on macOS, or any install on Linux, on a machine without `gh` or `npm`. The install ends in a Python traceback instead of a report. On Linux the `gh` install step is skipped but the closing `gh auth status` report is not.

## Root cause

The issue traces it to two calls in `bin/harness` at the time: `subprocess.run(["gh", "auth", "status"], capture_output=True)`, run unconditionally at the end of every install, and `_run(["npm", "install", "-g", "@openai/codex"], dry)`. `subprocess.run` raises `FileNotFoundError` when the executable is absent, and `_run`'s `check=False` suppresses a non-zero exit, not a missing binary. Separately, `BREW_PACKAGES` installs `node@22`, which is keg-only: Homebrew does not link it into its prefix, so `npm` is not on `PATH` after a fresh install.

## Acceptance criteria

1. **Given** an external tool that is missing, **when** install calls it, **then** the tool is named as missing in the report and the install carries on without raising, and the call never reaches `subprocess`.
2. **Given** `npm` only in the keg-only `node@22` bin directory, **when** it is looked up, **then** it is found; `PATH` wins when both exist, and a non-executable file does not count.
3. **Given** `gh` absent, **when** the logins block is printed, **then** it says "not installed" and `gh` is never invoked; present but logged out and logged in are each reported.
4. **Given** an absolute path, **when** it is run, **then** lookup is bypassed; given a dry run, **then** the tool is resolved but not executed.
5. **Given** a machine missing both tools, **when** install runs, **then** it completes without raising.

## Design

One helper resolves every external executable before it runs, searching `PATH` and then the keg-only `node@22` bin directory, and names the tool when it is missing. The `gh` line in the logins block checks for the binary first. This follows the issue's proposed fix (guard with `shutil.which`-style lookup, report missing tools, and find `npm` under the keg); the pull request records the lookup searching the keg directory rather than editing `PATH`.

The fix must not change behaviour when every tool is present.
