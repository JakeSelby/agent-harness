## Reproduction

1. Select the `auto` permission posture and run `harness sync` with Codex CLI 0.154.0-alpha.6.2
   installed.
2. Inspect `config.toml`, then run `codex exec --strict-config`, or read the effective configuration
   with the client's own `config/read`.

Observed: sync writes `approval_reviewer`. Under `--strict-config` Codex rejects it as an unknown field;
otherwise the key is dropped, so `permissions=auto` resolves in the client as review by the user and
nothing warns.
[Source: https://github.com/JakeSelby/agent-harness/issues/278]

## Root cause

The harness wrote a key name Codex does not read. The PR checked four clients from their own protocol
schema (0.154.0-alpha.6.2, 0.155.0-alpha.9, 0.155.1 and 0.156.0-alpha.9): every one defines
`approvals_reviewer` (`user`, `auto_review`, `guardian_subagent`) and none lists `approval_reviewer`.
The PR states the old spelling was never client-verified.

## Acceptance criteria

1. **Given** a supported Codex version, **when** sync runs, **then** it writes the key name the running
   client accepts, established from the client itself.
2. **Given** a client that accepts neither spelling, **when** sync runs, **then** it prints a notice and
   `doctor` reports a finding, never silence.
3. **Given** a stale harness-owned `approval_reviewer`, **when** sync runs, **then** it is removed, while
   a user's own same-named key is left alone; uninstall takes the key back out.
4. **Given** the `permission-controls` case, **when** it runs natively, **then** it can observe the
   automatic reviewer.

## Design

`lib/harness_core/codex_client.py` probes the installed client's schema; `lib/harness_core/reconcile.py`
writes the accepted key, defaulting to the newest supported spelling when no client is found. The
issue's alternative of writing both spellings was allowed only if every supported version tolerated the
unknown one; the record shows two of the four dropped it without a word and strict mode rejects it, so a
probe was used instead. The fix follows the project's rule that an unsupported connection setting fails
rather than being dropped.

## Regression test

`tests/test_codex_reviewer_key.py` (new). The PR also records a native check without a model turn: in a
disposable home carrying the old key, sync replaced it and the bundled client's own `config/read`
returned `approvals_reviewer auto_review`.
