## Story

As a maintainer who tells developers that prompt caching matters more than model tier or effort, I want
that claim measured by this repository, so that the cache-hygiene guidance rests on a replay result, a
measured dispatch overhead and a recorded TTL position rather than list-price arithmetic.

## Context and value

The headline "prompt caching beats both" in the cache-hygiene guidance rests on list-price arithmetic,
not a measurement. `harness usage --by prefix` measures a miss ratio and `docs/benchmarks.md` carries a
cache-normalised cost, but the replay has no cache axis, no per-event hook dispatch overhead figure
exists, and no TTL decision is recorded anywhere. The item came from the 2026-09-22 roadmap intake (B4
and B10), beside #431, and the re-derived epic map places it under this epic for the v0.15.0 "close the
loop" milestone, which lists cache-leverage measurement.
[Source: https://github.com/JakeSelby/agent-harness/issues/524]
[Source: _bmad-output/planning-artifacts/roadmap-intake-enterprise-review-2026-09-22.md#B4]

## Acceptance criteria

1. **Given** `scripts/cost_bench.py replay`, **when** it runs arms that differ by cache state (cold
   prefix versus warm, or a forced prefix change mid-run), **then** each results row carries cache read,
   cache write and normalised cost per arm.
2. **Given** `benchmarks/static.json`, **when** it is regenerated, **then** it carries a measured
   per-event coordinator dispatch time on the reference machine, with its method.
3. **Given** the `cache-hygiene` skill, **when** it is read, **then** it records the long-TTL and idle
   pre-warm findings as measured elsewhere, disputed at their source and to be reproduced before
   believed, and says the harness does not set the TTL.
4. **Given** a default flip in this area, **when** it is made, **then** it is recorded with the competing
   explanation it refuted ("off for cost, not for brokenness").

## Design

### Approach

Promote prefix stability to a replay axis so arms differ by cache state and not only by environment;
measure the single-coordinator hook dispatch once and publish it with its method; record the TTL
position in the skill.

### Decisions and alternatives

- **Method from the intake:** a default is flipped only after the competing explanation is refuted, and
  the record says which.
- **The harness does not set the TTL;** it records a position and says so.
- Other alternatives: not recorded in the issue or pull request.

### Do not implement

Not recorded in the issue or pull request.
