## Story

As the maintainer of this repository, I want every pull request to close exactly one dedicated issue,
checked in CI, so that no change merges without a tracking record and no issue is reused across
separately delivered pull requests.

## Context and value

The pull request template made issue linkage optional. Changes could merge without a tracking issue, and
one issue could be reused across several delivery pull requests. The issue asked for the rule to be
enforced by a required check rather than by the template alone.
[Source: https://github.com/JakeSelby/agent-harness/issues/153]

## Acceptance criteria

1. **Given** any repository change, documentation included, **when** it is prepared, **then** the
   instructions require a dedicated issue before it.
2. **Given** a pull request, **when** the check runs, **then** it requires exactly one closing issue, and
   separately delivered work uses child issues.
3. **Given** a pull request with a missing, multiple, foreign or reused closing issue, **when** the check
   runs, **then** it fails.
4. **Given** an earlier pull request for the same issue that closed unmerged, **when** a replacement is
   opened, **then** the check allows it.
5. **Given** an ordinary contextual issue reference, **when** the check runs, **then** it is permitted.
6. **Given** the check, **when** merging, **then** it is required, and its validation behaviour is
   covered by tests.

## Design

### Approach

A read-only CI job, `.github/workflows/issue-ownership.yml`, runs
`.github/scripts/check_issue_ownership.py`, which reads GitHub's closing-issue relationships through
read-only API calls and rejects missing, multiple, foreign or reused ownership. The repository
instructions, contribution guide and pull request template state the one-issue-per-PR rule.

### Decisions and alternatives

- **GitHub closing relationships as the source:** the check reads the platform's closing links rather
  than parsing free text, so contextual references stay allowed.
- **Replacement allowed:** reuse is permitted only when an earlier attempt closed without merging.
- **Known race documented:** two open pull requests can claim one issue at the same time, so the docs
  call for a recheck of ownership immediately before merging.
