## Story

As the release maintainer, I want scripted qualification cases executed on a cheaper capability class
while a strong class reads the observations, so that a round stops spending strong-tier output on
running scripts without the producer becoming the only reader of its evidence.

## Context and value

From the release-cost analysis tracked in #340. Once cases are scripted (#336), a per-target worker
runs a script, reads JSON and writes findings, which the issue says does not need the strong tier;
workers had run 0.7x–1.8x their output budget, mostly on authoring. The issue says the change is
worthless before the cases are scripted, and names the honesty risk: the published procedure requires
a reviewer, so a cheaper tier must not become the only reader of the evidence it produced.
[Source: https://github.com/JakeSelby/agent-harness/issues/338]

## Acceptance criteria

The issue has no acceptance section; these are taken from its mechanism and the PR:
1. **Given** a round, **when** it starts, **then** each target carries an execution class (default
   `standard`) and an assessment class (default `strong`, a floor), overridable per target with
   `--execution-class TARGET=CLASS`.
2. **Given** both classes, **when** they resolve through `adapters/<runtime>/bindings.json`, **then**
   they are recorded in the evidence record (`tier_routing`) and `round.json`.
3. **Given** an assessment class weaker than `strong`, **when** a round starts, **then** it is refused
   before any client launches.
4. **Given** a cheap execution class resolving to the assessor's own model, including by an alias,
   **when** a round starts, **then** it is refused.
5. **Given** an unmapped class, **when** resolved, **then** it is disclosed (the worker inherits the
   session model), never guessed; an unmapped assessor beside a mapped executor is refused.

## Design

### Approach

A new `lib/harness_core/qualification.py` resolves and validates the class pair; the runner and
`scripts/qualification_round.py` record it.
[Source: https://github.com/JakeSelby/agent-harness/pull/598]

### Decisions and alternatives

- Executing at or above the floor is allowed even when both classes resolve to one model, because
  that is the pre-existing arrangement the procedure accepts; the refusal is scoped to a cheap
  executor.
- Resolution ignores a personal `tiers.<runtime>` config override, since a round runs from a frozen
  clone; documented in the runbook.
- The saving figures are labelled as the issue's estimate in both docs.
- **After review:** model ids are normalised before the same-model check; the routing is the first
  durable-log line and `round.json` is written before the smoke tier, so a killed round records it;
  `--from-progress` refuses a log written under a different routing; the class-map parser names its
  flag in every error.

### Do not implement

A cheap class as the only reader of its own evidence.
