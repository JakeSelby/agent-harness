# AH-S101 — Bind judgment roles to capability classes instead of the session model

## Story

As a developer running judgment roles, I want each shared role to name a provider-neutral capability
class that each adapter maps to its own native model, so that a role's cost and capability no longer
follow whatever model the session happens to run.

## Context and value

`reviewer`, `spec-reviewer`, `planner` and `design-judge` inherited the session model. From a session on
the scarcest tier they spawned on the orchestrator's own rate-limited tier, which the delegation skill
forbids. Codex roles carried effort only, and `harness role run` failed for each without `--model`.
[Source: https://github.com/JakeSelby/agent-harness/issues/233]

## Acceptance criteria

1. **Given** a shared role contract, **when** it is read, **then** it names a capability class in
   `tier:`, and no role inherits the session model.
2. **Given** an adapter's `bindings.json`, **when** a class is resolved, **then** its `tiers` table maps
   it to a native model, and an unmapped class resolves upward or inherits, never downward.
3. **Given** a spawn request for the top class, including one from a planning framework's skill text,
   **when** the spawn hook sees it, **then** it refuses it, and it says so when the session model is not
   on its ladder.
4. **Given** the constrained-role refusal message and the BMad override templates, **when** they are
   read, **then** they no longer tell the caller to pass the parent session's model.
5. **Given** the Codex class table, **when** `harness tiers check` runs offline against the catalog
   Codex fetches from its provider, **then** it reports a model the runtime does not offer.
6. **Given** a `tiers.<runtime>.<class>` configuration key, **when** it is set, **then** it remaps that
   class without a release.
7. **Given** the change, **when** the gate runs, **then** lint is clean, the suite passes and
   `harness generate --check` reports no drift.

## Design

### Approach

Each role contract under `primitives/roles/` carries `tier:` (for example `tier: strong` on
`reviewer`). Each adapter's `bindings.json` gains a `tiers` table from class to native model;
`lib/harness_core/catalog.py` and `workers.py` resolve a role's class through it, applying any
`tiers` configuration override. `policy/hooks/tier-agent-spawns.py` tiers a planning-framework
repository like any other, refuses the top class by request, and reports an unknown session model.
`harness tiers check` compares the Codex table with Codex's own model catalog.

### Decisions and alternatives

- **Classes, not model names, in shared roles:** keeps roles provider-neutral; each adapter owns its
  mapping.
- **Resolve upward or inherit, never downward:** an unmapped class never silently lowers capability.
- **Codex ids are versioned and keep resolving after a successor ships,** so staleness is caught by
  `harness tiers check` rather than by failure.
- **Configuration remap:** `tiers.<runtime>.<class>` changes a class without waiting for a release.
