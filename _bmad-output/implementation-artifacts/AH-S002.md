## Story

As a developer using the tiered delegation stance, I want shipped `gatherer`, `reviewer` and `log-compressor` subagent definitions synced into `~/.claude/agents/`, so that the tier and the read-only restriction are enforced by agent frontmatter and tool lists instead of by prose in each brief.

## Context and value

The issue records that `claude/rules/delegation.md` and the tiered delegation stance said "enforce read-only with the tool list, not with the prompt", yet no `.claude/agents/` directory existed, so every spawn was a `general-purpose` agent with the full tool set and a hand-written brief. It notes the documented model precedence (per-invocation `model`, then agent frontmatter, then `CLAUDE_CODE_SUBAGENT_MODEL`, then the session model) and argues frontmatter is the right home because `OWNERSHIP.json` never touches `env`.

## Acceptance criteria

1. **Given** a sync, **when** it completes, **then** `gatherer`, `reviewer` and `log-compressor` from `claude/agents/` are linked into `~/.claude/agents/`, and uninstall removes them.
2. **Given** each shipped agent, **when** its frontmatter is read, **then** it declares name, description, model, tools and effort, and its tool list carries no write tool.
3. **Given** a hand-written agent file of the same name already in place, **when** sync runs, **then** it is not replaced without adopt.
4. **Given** a project that needs a different agent, **when** it places a same-named file in its own `.claude/agents/`, **then** that file overrides the shipped one.
5. **Given** the tiered delegation stance and the `delegation-tiering` skill, **when** they are read, **then** they name these agents rather than describing them.

## Design

### Approach

Three Markdown agent definitions with frontmatter: `gatherer` (one tier down, low effort, read-only tools), `reviewer` (fresh-context adversarial review, findings only) and `log-compressor` (two tiers down, failures and summary only). `bin/harness sync` gains `claude/agents/` as a link target, and `claude/OWNERSHIP.json` records it.

### Decisions and alternatives

- **Frontmatter over environment.** Per the issue, frontmatter `model` outranks `CLAUDE_CODE_SUBAGENT_MODEL`, and the harness does not own `env`.
- **The tool list is the enforcement.** The pull request states the tool lists are the read-only enforcement the delegation rule asks for.
- The agents' model names follow the `delegation` stance; the definitions themselves are universal (from the issue).

### Do not implement

Not recorded in the issue or pull request.

### Later change

At `origin/main` roles name capability classes rather than tiers relative to the session model, and constrained roles such as the gatherer and reviewer run as isolated role workers; the gatherer runs offline (AD-8). This story's "one tier down" wording and the gatherer's web tools describe the design as delivered in v0.2.0 only.
