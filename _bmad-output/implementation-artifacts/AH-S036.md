## Story

As a developer who has authorized a bounded class of outward actions, I want an external-actions stance that can honour that authority, so that the agent does not demand exact-text approval for every item I have already cleared, while nothing is published without authority.

## Context and value

A fixed draft-first rule requires exact-text approval even when the user has explicitly authorized a bounded class of outward actions ([#119](https://github.com/JakeSelby/agent-harness/issues/119)). The rule is still fixed on `main`: `primitives/rules/working-style.md` carries "Draft-first outward-facing: the exact text per item, nothing posted until the user approves it" [Source: primitives/rules/working-style.md].

The epic's 2026-09-21 assessment rated the story Not delivered, with no `external-actions` dimension ([#116 comment](https://github.com/JakeSelby/agent-harness/issues/116)). No such dimension exists under `primitives/stances/` today.

## Acceptance criteria

1. **Given** a one-shot user request, **when** the agent acts, **then** it is authorized only for the requested action and destination, and any wider scope asks for authorization.
2. **Given** a standing scope, **when** an action is matched against it, **then** the match is explicit and auditable, and an expired, missing or mismatched scope cannot authorize publication.
3. **Given** the supported shell and connector paths, **when** the variants are exercised, **then** enforcement is tested where it exists and labelled as guidance where it does not.

## Design

### Approach

The issue proposes `external-actions` with the variants `draft-first`, `explicit-request` and `scoped-standing-authority`, keeping `draft-first` as the default. Standing authority is scoped by action, destination and expiration or revocation. Native restrictions stay the ceiling, and the agent never grants itself authority ([#119](https://github.com/JakeSelby/agent-harness/issues/119)).

The plan adds that a prose stance is not proof of runtime enforcement and never bypasses a native denial [Source: docs/plans/stance-completeness.md#Step 3 — Existing opinions].

### Decisions and alternatives

- `draft-first` stays the default ([#119](https://github.com/JakeSelby/agent-harness/issues/119)).
- No other alternative is recorded in the issue or pull request.

### Do not implement

- No self-granted authority and no bypass of a native restriction ([#119](https://github.com/JakeSelby/agent-harness/issues/119)).
- Do not claim enforcement on a path that only carries guidance.
- Do not sync an unmerged candidate into the live installation.
