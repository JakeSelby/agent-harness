## Story

As an orchestrating session, I want each turn's spend and each finished subagent's actual spend against
its soft budget fed back to me, so that the budget stated in a brief closes into a loop and I can see
what work costs as it goes.

## Context and value

An agent cannot see its own token spend, and a finished subagent's cost was invisible to the session that
delegated it: a background spawn reports nothing useful on return, and the figure a synchronous return
carries describes only the subagent's last response. The issue calls a budget in the brief "only half a
loop" without the actual figure coming back; the budget itself came from #253.
[Source: https://github.com/JakeSelby/agent-harness/issues/255]

## Acceptance criteria

1. **Given** `turn_feed` on, **when** a turn ends, **then** the main thread gets a line with the last
   turn's and the session's output tokens and tool calls.
2. **Given** a subagent that finishes, **when** it is reported, **then** the line gives its actual spend,
   summed from its own transcript, against the soft budget of its cost row.
3. **Given** background and synchronous spawns, including several finishing at the same moment, **when**
   they finish, **then** each is reported exactly once.
4. **Given** more subagents running than the posture's width, **when** the feed runs, **then** it adds a
   line saying so.
5. **Given** `turn_feed` off, **when** the coordinator runs, **then** its output is byte-identical to
   before.
6. **Given** any path, **when** it runs, **then** it is bounded in time and bytes, and any failure emits
   nothing rather than blocking or denying.
7. **Given** feed state, **when** it is stored, **then** it holds counts and agent type names only, with
   owner-only permissions, and is pruned.

## Design

### Approach

`policy/hooks/usage-feed.py`, run through `lib/harness_core/lifecycle.py`, injects the feed on the main
thread only. `SubagentStart` and `SubagentStop` journal to an append-only file without taking a lock;
the reader state is mutated only under a bounded `flock`, and slow work never runs under it. A cold start
reads only the transcript's tail and marks totals partial; summing has a byte cap and a wall-clock
budget; a stop is always journalled; a start with no stop decays.

### Decisions and alternatives

- **Sum from the subagent's own transcript:** a synchronous return's figure describes only the last
  response, and a background spawn returns at launch.
- **Lock-free journal, locked reader:** writers never wait; exactly-once reporting is decided under the
  reader's lock.
- **Claude Code only:** the gap is declared for Codex in `adapters/codex/capabilities.json`.
- **Never deny or stop anything.**

### Do not implement

- Any denial or stop for cost.
