# AH-T029 — Record the token-only worker-login limitation in the 0.13.0 catalog

## Goal

State in the 0.13.0 catalog, before the tag, that a token-only login cannot run the isolated role
workers a Claude Code session launches. The optional BMad integration suite for 0.13.0 found it:
in a home logged in with `CLAUDE_CODE_OAUTH_TOKEN` alone, every reviewer worker the session launched
through `harness role run` failed "Not logged in", because the client strips the token from its tool
subprocesses, and the orchestrator then did the confined layers in its own context. Qualification
rounds launch workers from the runner, not from a client session, so they never met it. A user on a
token login, as in CI and containers, would otherwise meet it undocumented. The maintainer chose to
record it before tagging; #759 is the fix.

## Acceptance criteria

1. **Given** `compatibility/catalog.json`, **when** its limitations are read, **then** one states that
   a session with a token-only login cannot authenticate the isolated workers it launches, why, what a
   client may then do, that rounds do not exercise the path, and that #759 tracks it.
2. **Given** the release gates, **when** they run on the merged commit, **then** `bin/harness
   compatibility --release-check` and `scripts/release_preflight.py` still pass.

## Tasks

- [x] `bin/harness generate --check`, the lint and the unit suite; the release check and the preflight
