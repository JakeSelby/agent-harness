## Story

As a developer comparing spend across releases, I want each usage row to carry the harness version,
the session's effort and per-day slices, and a token view by stance value, so that a change in spend
can be tied to a release, separated from an effort change, and not dominated by where long sessions
happened to end.

## Context and value

- A session was attributed to the day it ended, so sessions running for days or weeks landed on one
  date; the issue records, from one machine, five sessions being 68% of all output tokens.
- A row did not say which harness version wrote it or the session's effort.
- `usage --by stance` reported rule hits only.
- `usage --by role` printed percentiles for roles with a handful of runs, with no small-sample mark.
[Source: https://github.com/JakeSelby/agent-harness/issues/331]

## Acceptance criteria

1. **Given** a new row, **when** written, **then** it carries `harness_version`; a rescanned row
   carries `null`, never a guess.
2. **Given** a session row on either runtime, **when** written, **then** it carries `effort` with its
   source, or `null` when it cannot be determined.
3. **Given** a session row, **when** written, **then** it carries per-day slices from message
   timestamps, and `usage --by day` uses them, falling back to the end date when absent.
4. **Given** `usage --by stance --stance <name>`, **when** run, **then** it groups tokens by that
   stance's value; `--rules --by stance` keeps the hit report.
5. **Given** `usage --by role`, **when** a role has fewer than 30 runs, **then** it is marked.
6. **Given** a fixture session spanning two dates, **when** reported by day, **then** it appears on
   both days.

## Design

### Approach

`policy/hooks/usage-log.py` stamps version, effort and slices on each row; `bin/harness` reads them;
`lib/harness_core/workers.py` stamps a worker run's version.

### Decisions and alternatives

- Slices must sum to the row's totals; a map that disagrees is dropped at write time.
- `--days` applies to the slice date.
- Both runtimes record effort per turn (Claude Code on each assistant record, Codex in
  `turn_context`), and it can change mid-session, so the row records the value covering the most
  output tokens, with `effort_source`.
- The stance view has an explicit `(unknown)` group; `--by stance` alone exits 2 with a usage line.
- The PR was stacked on #330.
[Source: https://github.com/JakeSelby/agent-harness/pull/343]
