## Story

As a new user of the harness, I want `harness init` and `harness config set` to write my configuration, and `sync` and `doctor` to tell me when my identity is still the example's placeholder, so that I never hand-edit JSON and never ship "Your Name" into always-loaded context by accident.

## Context and value

The issue records that `harness config` had only `get`, with no `set`, `init` or wizard, so configuring meant hand-editing JSON where a trailing comma breaks every later sync. It also records that `cmd_sync` copied `config.example.json` on first run and printed one line asking for an edit, nothing checked that the user made it, and `render_personal` wrote the example identity into `~/.claude/CLAUDE.personal.md`, which is always loaded. A zero-config `sync --dry-run` against a throwaway `$HOME` succeeded end to end.

## Acceptance criteria

1. **Given** `harness init`, **when** it runs, **then** it asks for identity one field at a time and offers each stance's variants with the default in brackets, writing JSON that resolves; a blank required answer or an unknown stance answer is asked again.
2. **Given** an existing configuration, **when** `harness init` runs without `--force`, **then** it refuses to replace it; with no terminal, it names `config set`.
3. **Given** `harness config set KEY VALUE`, **when** the stance, variant, identity field, posture or top-level key is unknown, **then** it is refused with the options named and nothing is written; boolean keys coerce.
4. **Given** a valid `config set`, **when** it writes, **then** it creates the file from the example if needed, keeps the rest of an existing file, and the result still resolves.
5. **Given** placeholder identity, including a missing field that `load_config` backfills, **when** `sync` or `doctor` runs, **then** it is reported and never fatal; `pronouns` and `timezone` are never flagged.

## Design

### Approach

`harness init` and `harness config set` in `bin/harness`, with a placeholder check shared by `sync` and `doctor`. `init` detects the timezone from `/etc/localtime` and the GitHub handle from `gh` when logged in.

### Decisions and alternatives

- **Validate before writing,** so a bad value fails at `set`, not at the next sync (from the pull request).
- **Report, never fail.** CI's dry-run sync against the example config still exits 0.
- **Exclude `pronouns` and `timezone`** from the placeholder check, since `they/them` and `UTC` are answers someone might mean.

### Do not implement

Not recorded in the issue or pull request.
