# AH-B042 — reserve allocates an ID without checking what the default branch already holds

## Reproduction

The issue records the incident on 2026-09-21: `AH-S143` was allocated to #401 on one branch and to
#386 on another, within minutes. Each branch's `audit` reported zero findings, because each map was
internally consistent. The duplicate surfaced only as an add/add conflict on
`_bmad-output/implementation-artifacts/AH-S143.md` at `git merge`. Resolving it meant rebuilding the map
from `main` and re-reserving six issues.

## Root cause

As filed, `reserve` allocated from `next_ids` in the local checkout's map and never consulted
`origin/main`.

**The issue is partly out of date.** At `origin/main`, PR #441 (merged 2026-09-23, closing #440) changed
`reserve`:

- `survey_ids_elsewhere` reads the working copy of every linked worktree's map, and the map on every
  local and remote-tracking branch;
- `unreadable_remote_heads` runs a best-effort `git fetch origin` first, so the remote-tracking refs are
  current, and reports heads it cannot scan;
- `collision_report` refuses when the counter is not past every ID of that kind already in use, naming
  each one and where it was found, and tells the caller to rebase onto the branch that took them;
- `--advance` skips the taken IDs and reports the ones it leaves unused.

## Acceptance criteria

From the issue's Acceptance section, with the state at `origin/main`:

1. **Given** the remote map already holds the ID `reserve` would allocate, **when** `reserve` runs,
   **then** it refuses and names the holder; after the default branch is merged in, it succeeds.
   Delivered by PR #441, which surveys remote-tracking branches after a fetch.
2. **Given** no network and an explicit skip, **when** `reserve` runs, **then** it succeeds and reports
   that the check did not run. Not delivered as specified: there is no skip flag. When `origin` cannot
   be reached, `reserve` prints a notice that it "could not be scanned" and continues.
3. Unit tests cover the collision, the clean case and the offline path. PR #441 added tests for the
   collision and the clean case in `tests/test_bmad_issue_sync.py`; none of its test names covers an
   unreachable `origin`.

## Design

The issue's scope asked for three things. PR #441 delivered a broader form of the first two:

- It compares against every reachable map, not only the remote default branch.
- Its refusal says to rebase onto the branch that took the ID, rather than "merge the default branch
  first".
- For the offline case, it degrades to a notice rather than requiring a skip flag.

What remains open is a decision rather than code: whether the notice-based offline path meets the
issue's third scope item, or whether an explicit skip flag is still wanted. This is recorded here as an
undelivered acceptance item; the issue is still open and does not reference #440 or #441.

Do not implement: a change to the immutability of IDs. `docs/bmad-governance.md` says reparenting never
changes an ID.

## Regression test

PR #441 added, in `tests/test_bmad_issue_sync.py`:
`test_a_reservation_committed_on_another_branch_is_seen`,
`test_a_counter_a_sibling_has_already_run_past_is_refused`, `test_advance_skips_the_taken_ids_and_says_which`,
`test_a_clear_counter_produces_no_report` and `test_a_remote_head_this_clone_cannot_read_is_reported`,
among others. The offline acceptance item has no test.
