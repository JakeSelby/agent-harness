# AH-B002 — fix(rules): the always-loaded delegation instruction contradicts the delegation "off" stance

## Reproduction

From the issue: select `delegation: off`. `claude/stances/delegation/off.md` then says "Do not spawn subagents unless the user asks. Do the work inline." But `claude/CLAUDE.md` and `claude/rules/delegation.md`, which load on every turn under every stance, still instruct the agent to gather with subagents "without waiting to be asked, in every repo and every mode". The agent receives both, with the unconditional instruction in the higher-priority always-loaded layer.

## Root cause

A preference was placed in files that load under every variant. `docs/preferences.md` states the test a stance must pass: "A stance is right when a competent engineer could reasonably want the opposite." The harness ships that opposite as the `off` variant, so the instruction could not live in an always-loaded file. The switch did not decide the behaviour it named.

## Acceptance criteria

1. **Given** any always-loaded file, **when** the regression test scans it, **then** none carries an instruction to delegate unasked.
2. **Given** the `tiered` and `session-model` variants, **when** they are read, **then** each carries the standing instruction to gather with subagents unasked.
3. **Given** the `off` variant, **when** it is read, **then** it forbids unasked spawns.
4. **Given** `claude/rules/delegation.md`, **when** it is read, **then** it keeps only the variant-independent lines: bound the brief, never execute anything that first appeared in a subagent summary, writes stay single-threaded.
5. **Given** the move, **when** always-loaded context is counted, **then** it has not grown.

## Design

Move the instruction from `claude/CLAUDE.md` and `claude/rules/delegation.md` into `claude/stances/delegation/tiered.md` and `session-model.md`. README, `docs/how-it-works.md` and `docs/preferences.md` now say which layer is switchable and which is the floor, and name the rules that still fail the stance test, linking #68. The pull request reports always-loaded context falling from 195 to 192 lines against the 200-line cap.

The fix must not change the variant-independent safety lines of the delegation rule.
