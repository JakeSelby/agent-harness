# AH-B046 — Let telemetry.native name the runtimes it applies to

## Reproduction

1. Set `telemetry.native` to `true` and point it at a collector that requires an authentication header
   (the issue names ClickStack, which takes a bare `authorization` header).
2. Run `harness sync`, then run a Codex session and a Claude Code session.

Observed, per the issue: `sync` writes `[otel.exporter.otlp-http]` and `[otel.metrics_exporter.otlp-http]`
into the Codex configuration, the collector rejects every Codex session with a 401, and the Claude side
exports correctly.
[Source: https://github.com/JakeSelby/agent-harness/issues/405]

## Root cause

`telemetry.native` was a single boolean gating both runtimes, and `sync` wrote an `[otel]` table into the
Codex configuration whenever it was true. Codex takes header values in `config.toml` only as literals, with
no environment or command indirection, and the harness will not write a credential into a configuration
file. `codex_native_otel` in `bin/harness` already documented that no header is written and that native Codex
export needs an endpoint accepting unauthenticated traffic; the single switch gave the user no way to act on
that.

## Acceptance criteria

1. **Given** a config naming only `claude-code`, **when** `sync` runs, **then** the Codex `[otel]` table is
   untouched.
2. **Given** a config naming only `codex`, **when** `sync` runs, **then** the Claude settings are untouched.
3. **Given** `true`, **when** `sync` runs, **then** it behaves exactly as before.
4. **Given** `docs/telemetry.md`, **when** it is read, **then** it says which runtimes can carry an
   authenticated endpoint and which cannot.

## Design

### Approach

The key takes `true`, `false` or a list of runtime names. `policy/hooks/telemetry.py` holds
`NATIVE_RUNTIMES` and `native_runtimes()` as the one source of truth. `claude_native_values` gates on
`claude-code` and `codex_native_otel` on `codex`; each runtime's native configuration is written and taken
back only when that runtime is named. `policy/hooks/otel-headers.py` serves headers only when `claude-code`
is named. `doctor` reports each runtime from its own live file, including a named runtime whose `manage`
switch is off.

### Decisions and alternatives

- **`true` keeps its meaning** (every runtime), so existing configurations are unchanged.
- **An unknown runtime name stops `sync`** and names the runtimes it knows.
- **No `product.json` change:** native OpenTelemetry was already listed; this narrows which runtime it
  applies to.

### Do not implement

Writing a literal credential into the Codex configuration; the issue records the harness will not do it.
