## Story

As someone using an agent for writing, research or organising files rather than shipping software, I want an expertise setting, a non-software preset and rules that say where they apply, so that the harness does not configure me as a professional engineer by default.

## Context and value

The issue records three problems. `claude/CLAUDE.personal.template.md` shipped a hardcoded "Communicate at expert level unless told otherwise; skip basics and fundamentals" to every user in always-loaded context, which for a beginner is exactly inverted. The shipped defaults are a professional SDLC, and the nearest non-software configuration was six separate opt-outs a newcomer could not discover. And `verification.md`, `secrets.md` and `conciseness.md` load wholesale (rules link as a directory) while reading as universal. The fix had to be length-neutral: always-loaded context stood at 193 of 200 lines.

## Acceptance criteria

1. **Given** `identity.expertise` set to `expert`, or absent, **when** the personal file renders, **then** it carries the expert line as before; set to `beginner`, **then** it carries the beginner guidance and never the expert line; an unrecognised value falls back rather than raising.
2. **Given** `config set identity.expertise`, **when** the value is unknown, **then** it is refused with the options named.
3. **Given** `harness init`, **when** it asks for a preset, **then** `software` supplies the shipped defaults and `general` turns off the commit, test, licensing and build-vs-buy ceremony and lightens plans, leaving `delegation`, `autonomy` and `cost` alone; every stance is still asked.
4. **Given** a `general` configuration, **when** it renders, **then** it carries the beginner guidance.
5. **Given** the three code-only rules and the always-loaded preamble, **when** they are read, **then** their headings say they are about code work, and one preamble line says a rule about repositories, tests or pull requests does not apply elsewhere.

## Design

### Approach

The field selects one paragraph of the personal file, which the context cap does not count. `init` gains the presets; `config.example.json` and `docs/preferences.md` document the field and the presets. The three rules change only their headings, and `claude/CLAUDE.md` gains one line. The pull request reports always-loaded context at 196, the full 196-line ratchet the budget tests hold (the cap in code is 200).

### Decisions and alternatives

- **`expert` stays the default**, so a configuration predating the field keeps its behaviour.
- **Presets supply defaults, not answers.** Every stance is still asked.
- **Delegation stays out of the preset.** The issue's six opt-outs included `delegation/off`; the pull request leaves `delegation`, `autonomy` and `cost` untouched, because "those questions are the same whatever the work is".
- **Scope rules by wording.** Rules link as a directory and cannot be deselected, so making them read as inapplicable is the length-neutral fix.

### Do not implement

- A new stance dimension, which would add its longest variant to the always-loaded total (from the issue's constraint).
