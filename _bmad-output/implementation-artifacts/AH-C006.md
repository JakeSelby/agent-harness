## Goal

Give every open and closed repository issue a stable typed BMad ID, a published linked artifact file, a
native GitHub type and hierarchy, and an idempotent validator and migration utility, while preserving the
original issue titles, prose, comments and state. Historical artifacts are marked reconstructed. Before
this, issues had no stable BMad identity or public artifact link, so planning and delivery could not be
followed in both directions.
[Source: https://github.com/JakeSelby/agent-harness/issues/192]
[Source: _bmad-output/implementation-artifacts/spec-gh-192-bmad-traceability.md#Intent]

## Acceptance criteria

1. **Given** the committed manifest and artifacts, **when** `audit` runs, **then** it reports zero
   duplicate, missing, broken-parent or reverse-link findings, and otherwise exits non-zero naming each.
2. **Given** live issues that differ from the manifest's projection, **when** the preview runs, **then** it
   lists only the required changes and reports a missing issue without mutating anything.
3. **Given** every artifact exists on `main`, **when** `apply` runs, **then** it preserves issue content
   and projects metadata idempotently; if any artifact is missing it refuses before any mutation.
4. **Given** a new triaged issue and a valid kind, **when** `reserve` runs, **then** it allocates the next
   typed ID and an authored artifact, and refuses a duplicate or missing issue.
5. **Given** a closed historical item, **when** its artifact is written, **then** it says `reconstructed`.

Taken from the spec's input and edge-case matrix and its boundaries.
[Source: _bmad-output/implementation-artifacts/spec-gh-192-bmad-traceability.md]

## Dev notes

- **Design:** GitHub stays authoritative for title, prose, comments, state and acceptance evidence. The
  tool writes only the Planning block, native type, exact type label and primary parent. Links must resolve
  on `main` before any remote mutation. New IDs use per-type monotonic counters and are never reused or
  changed by reparenting. Never install Beads, require GitHub Projects, rewrite issue prose, reopen issues,
  delete labels, or treat generated metadata as evidence that historical BMad files existed.
  [Source: _bmad-output/implementation-artifacts/spec-gh-192-bmad-traceability.md#Boundaries & Constraints]
