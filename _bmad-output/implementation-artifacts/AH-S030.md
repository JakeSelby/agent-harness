## Story

As a developer who plans and builds with BMad across Claude Code and Codex, I want BMad bound to the
harness's semantic roles and a versioned task record carried between runtimes, so that a workflow runs
the same in either runtime and a task keeps its scope and evidence when it moves.

## Context and value

A work package of epic #93 that depends on #94, #95 and #96. The issue records the problems: BMad templates
carried Claude model and dispatch syntax; check and apply scanned only Claude projections; legacy review
dependencies and framework, worktree and artifact roots could diverge; and handoff was Claude-specific.
[Source: https://github.com/JakeSelby/agent-harness/issues/97]

## Acceptance criteria

1. **Given** the BMad build, review, auto and GDS review workflows, **when** they run, **then** all their
   layers complete.
2. **Given** nested result collection and cancellation, **when** they are exercised, **then** they are
   tested.
3. **Given** a task moved Claude to Codex to Claude, or the reverse, **when** it resumes, **then** it keeps
   the same task, checkout, policy, approved scope and evidence.

## Design

### Approach

Semantic shared overrides with per-invocation runtime binding. Validate projections, transitive skills and
every execution root, and reuse assigned worktrees. Keep a versioned harness task record holding repository
and task identity, scope provenance, baseline, status, evidence and session references. Migrate the legacy
handoff without treating artifact text as authorization, and keep native memories separate.
[Source: https://github.com/JakeSelby/agent-harness/issues/97]

A comment on the issue records a native GDS acceptance conflict: the reviewers found all twelve seeded
defects, but returned priority labels or the default three sections instead of the requested findings list.
The fix kept one shared reviewer definition and let a caller's findings contract specialize presentation
only, delivered as AH-S084 / #180.

Delivered through:
- AH-S070 / #166 (PR #104): versioned handoff and semantic BMad roles.
- AH-S078 / #174 (PR #112): missing review dependencies and divergent mirrors.
- AH-S079 / #175 (PR #113): handoff invalidation on changed shared artifacts.
- AH-S080 / #176 (PR #114): shared authority in skills (the issue names #99 as its parent).
- AH-S083 / #179 (PR #148): explicit installation and shim recovery.
- AH-S084 / #180 (PR #151): workflow findings contracts.

### Decisions and alternatives

- **Artifact text is never authorization** when a legacy handoff is migrated.
- **Native memories stay separate** from the harness task record.
- **One shared reviewer definition,** specialized in presentation only, over provider-specific roles.

### Do not implement

- A Cursor or Grok adapter, hosted-agent support, a native memory merge or UML viewer work.
