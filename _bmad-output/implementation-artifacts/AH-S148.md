## Story

As a developer running the harness, I want each session's cache-prefix stability reported as a figure, so
that a mid-task change that turns cache reads into cache writes is visible instead of surfacing only as a
larger bill.

## Context and value

`primitives/rules/cache-hygiene.md` tells a session to keep its cached prefix stable mid-task, and
`scripts/cost_bench.py` already repriced each thread's first-turn cache reads as writes so run order could
not move the reported dollars. Nothing reported whether a session actually held its prefix. A mid-task change
to the tool set, the MCP server list, the model or the effort dial silently turns cache reads into cache
writes. Related: #123, #321, #369.
[Source: https://github.com/JakeSelby/agent-harness/issues/415]

## Acceptance criteria

1. **Given** existing ledger fields, **when** the ratio is computed, **then** it uses them only, with no new
   hook and no new event.
2. **Given** a session whose rows carry no cache fields, **when** it is reported, **then** it is `unknown`,
   never zero.
3. **Given** the unit tests, **when** they run, **then** they cover a clean session, a session with one
   mid-task step, mixed models in one session, and missing fields.
4. **Given** `docs/usage.md`, **when** it is read, **then** it documents the figure and says it measures
   rather than enforces.
5. **Given** a replay run, **when** it is recorded, **then** the same figure sits beside `normalised_cost` in
   `benchmarks/history.md` (delivered separately; see Completion notes).

## Design

### Approach

`lib/harness_core/cache_prefix.py` computes the per-session cache-miss ratio
`cache_write / (cache_read + cache_write)` from ledger rows, and names the slice at which the ratio rose most
sharply. `harness usage --by prefix` prints both per session.

### Decisions and alternatives

- **Subtract subagent rows from the parent:** the runtime folds subagent counts into the session row, and a
  fan-out would otherwise read as a re-bought prefix.
- **`unknown`, never zero:** for a session whose subagent rows are missing, a row with no cache fields, and a
  runtime that never reports cache writes.
- **`--by prefix` is refused with `--rules` or `--stance`.**
- **Codex gap recorded** in `adapters/codex/capabilities.json`: Codex exports no per-turn cache figures.

### Do not implement

- Enforcement: nothing denies or warns on a prefix change.
- The `context=preserve-cache` setting proposed in #123.
- Codex figures, beyond recording the gap.
