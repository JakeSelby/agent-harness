## Story

As a developer installing or removing the harness, I want link and adoption intent recorded before any
filesystem change, and my own redirected links and backups preserved, so that an interrupted install or
an uninstall can always be recovered and never silently drops something I own.

## Context and value

This is a delivery slice of #95 (installation, configuration ownership and reversible migration), under
epic #93. It records ownership of the already open PR #108 and adds no release scope. It hardens the
reconciliation delivered in #164 for the recovery cases. [ASSUMPTION: the issue does not name this sibling; the link is drawn from the issue map and epic.]
[Source: https://github.com/JakeSelby/agent-harness/issues/170]

## Design

### Approach

The reconciliation path in `bin/harness` writes intent before it mutates, validates native JSON before
installing links, and skips any path whose current state is not what the harness installed.
`docs/runtime-installation.md` documents recovery. [Source: https://github.com/JakeSelby/agent-harness/pull/108]

### Decisions and alternatives

- **Intent before mutation:** an interrupted run leaves a record to recover from.
- **Keep, don't drop, a recovery record that cannot apply.**
- Alternatives considered are not recorded in the issue or pull request.

### Do not implement

- Native qualification and publication (#98, #100).
