## Story

As a developer paying for agent sessions, I want a `cost` stance (`frugal`, `balanced`, `max`) and a short cache-hygiene rule, so that cost is managed structurally rather than left to prose in the delegation stance.

## Context and value

The issue records that nothing in the repository mentioned caching, compaction, effort or fast mode, and that the tiered delegation stance carried the only cost content, as prose. It splits the work by kind: the posture is a preference, so a stance; the cache facts are universal, so a rule. It also says `OWNERSHIP.json` rightly never touches `model`, `effortLevel` or `env`: the stance expresses the preference and the agent definitions from #3 carry the model.

## Acceptance criteria

1. **Given** the stance catalog, **when** it is listed, **then** a `cost` dimension offers `frugal`, `balanced` and `max`, and `balanced` is the default.
2. **Given** a `HARNESS_STANCE_*` environment override or a config-file selection, **when** the stance resolves, **then** the environment beats the config file, and an unknown variant fails loudly.
3. **Given** each variant, **when** it is read, **then** it governs effort, fan-out width, fast mode and compaction habits, and names no model id.
4. **Given** the new `cache-hygiene` rule, **when** it is read, **then** it carries only prefix-invalidation facts the prompt-caching documentation confirms.
5. **Given** the new files, **when** always-loaded context is counted, **then** it stays under the 200-line cap.

## Design

### Approach

Three stance variants under `claude/stances/cost/`, a five-line `claude/rules/cache-hygiene.md`, registration of `cost` in the CLI's stance list, `config.example.json` and `docs/preferences.md`, and budget notes in the `delegation-tiering` skill. Four duplicated lines came out of `claude/rules/delegation.md` to make room: the pull request reports always-loaded context at 195 of 200 lines.

### Decisions and alternatives

- **Tier stays with delegation.** The pull request records that the delegation stance keeps picking the tier and that neither stance names a model id.
- **Verify before building.** The issue asked that two research claims (settings keys for cache TTL, and `MAX_THINKING_TOKENS` being ignored by adaptive-reasoning models) be confirmed against the live docs first. Neither appears in the delivered rule; the record does not say whether they were checked.
