## Goal

Reconcile the provider-agnostic and client-qualification work into a defensible v1.0.0 epic and milestone,
with an approved stable support floor: Claude Code CLI and Codex CLI on macOS and Linux, while VS Code and
Codex desktop remain preview and do not block v1. The PR turned that boundary into a milestone, an epic,
five executable release-gate stories, immutable BMad mappings and a requirement map, and kept post-v1
adoption and editor and desktop graduation in separate epics so neither can silently expand the stable
contract.
[Source: https://github.com/JakeSelby/agent-harness/issues/193]
[Source: https://github.com/JakeSelby/agent-harness/pull/219]

## Acceptance criteria

1. **Given** the stable floor, **when** the program is planned, **then** a v1.0.0 milestone and epic
   (#206) exist with five release-gate stories: #207 freeze, #208 contract, #209 lifecycle, #210 audit,
   #211 publication.
2. **Given** each release-gate story, **when** it is read, **then** it has an exit test tied to one
   candidate commit and archive digest.
3. **Given** the requirements, **when** the plan is read, **then** a reverse coverage map names which
   implemented baseline and which v1 story covers each one.
4. **Given** adoption and editor and desktop graduation, **when** they are planned, **then** they sit in
   separate epics (#212, #216) that cannot expand the v1 support claim.
5. **Given** every new item, **when** it is mapped, **then** it has an immutable BMad ID and artifact.

The issue records no acceptance section; these criteria are taken from the PR's description and the plan
it added. [Source: _bmad-output/planning-artifacts/v1-release-plan.md]
