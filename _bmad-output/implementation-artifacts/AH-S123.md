## Story

As the release maintainer, I want qualification evidence invalidated per target rather than per
source tree, and a recorded decision on scoping it per case, so that a fix confined to one runtime
does not cost the other runtime's evidence.

## Context and value

From the release-cost analysis tracked in #340. Any change under the runtime source paths invalidated
all evidence. The issue records that two of 0.11.0's eight merged fixes were Codex-adapter-local and
either would have preserved both Claude targets whole. It splits the work: 1a, per-target path sets,
gated on a cross-read test; 1b, per-case path maps, which it says carries a real honesty risk (a
coupling the map does not model would pass unnoticed) and changes a v1 stable interface, so it
"needs an owner decision and a policy edit, not a quiet patch".
[Source: https://github.com/JakeSelby/agent-harness/issues/333]

## Acceptance criteria

1. **Given** a change confined to one runtime's per-runtime files, **when** evidence is validated,
   **then** the other runtime's targets stay valid.
2. **Given** a shared-source change, a shared file inside an adapter directory, or an adapter file no
   runtime owns, **when** evidence is validated, **then** every target is invalidated.
3. **Given** an unmapped runtime, a record with no `invalidation_scope`, or a record claiming a scope
   the catalog withholds, **when** validated, **then** the whole-source rule applies or the record is
   refused.
4. **Given** the loaders, **when** the isolation test runs, **then** it proves no runtime's loader
   reads a file under another runtime's directory, with positive controls.
5. **Given** per-case scoping (1b), **when** this issue closes, **then** it is filed as a decision,
   not built.

## Design

### Approach

The catalog declares a versioned `evidence_invalidation` block, and each evidence record states the
path set it was validated under. `lib/harness_core/compatibility.py` computes each target's set:
shared runtime source plus its own adapter directory, with the adapter files shared code reads carved
back into every target's set.
[Source: https://github.com/JakeSelby/agent-harness/pull/583]

### Decisions and alternatives

- Three call sites force the carve-back: the capability matrix reads every `capabilities.json`,
  `harness tiers` reads both `bindings.json`, and `harness role run --runtime` loads either
  `worker.py`. Only `hook.py` is per-runtime.
- The scope lives in the catalog, not in code, so a reviewer sees what was assumed.
- `harness freeze --merge-check` is not narrowed; whether it should go per-target is a possible
  follow-up.
- 1b is filed as decision #582, which is open.

### Do not implement

Per-case scoping (1b).
