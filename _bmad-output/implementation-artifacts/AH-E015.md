# AH-E015 — Guardrails and runtime parity: close the gaps between runtimes and between docs and code

This work item was authored as part of the repository's committed BMad planning system.

## Goal

Own the defects and parity gaps in the harness's guardrails and runtime handling: the places where a
documented behaviour differs between Claude Code and Codex, or between the docs and the code. Completion
is observable through the issue's two acceptance items:

- each capability behaves on each runtime as `adapters/<runtime>/capabilities.json` says;
- no guardrail can be bypassed through a spawn path that the architecture spine does not name.

## Architecture slice

- **AD-7 What a hook may and may not do:** it binds FR-30 to FR-32, FR-35 to FR-39 and FR-41. A gap is
  declared in `capabilities.json`, never papered over. This is acceptance item 1.
- **AD-8 Constrained roles run only as isolated role workers:** every spawn path is guarded or declared
  unguarded. The two named gaps are the Workflow tool's `agent()` (#576) and the plugin channel (#641).
  This is acceptance item 2.
- **AD-2 One resolver, fixed invariants:** the spine names #294 as the record of two precedence ladders
  disagreeing.
- **AD-18 Shared-machine concurrency and writes:** state that belongs to a session is keyed per session.
  The stop gate's release counter migrates to this (#611).
- **AD-19 Distribution channels carry no second authority:** the plugin carries no hooks. The spine marks
  the plugin manifest version as partial (#641).

## Exit criteria

- [ ] Each capability's behaviour on each runtime matches its `capabilities.json` entry: #292, #293 and
  #294 resolved, or declared as gaps.
- [ ] Every spawn path is guarded or named in the spine: the Workflow tool guard (#576) and plugin role
  confinement (#641).
- [ ] The stop gate's release counter is per session (#611).
- [ ] `task save`, `worktree remove` and `sync --dry-run` behave as documented (#406, #413, #650).
- [ ] Workflow rows are separated in `harness usage` (#577).
- [ ] The test flakes are closed (#531, and #538 once its fix is confirmed).
