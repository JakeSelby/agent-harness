## Reproduction

1. Let a GitHub issue close, or rename it, after it was mapped.
2. Run the local `audit`: it passes, because every artifact still matches the committed manifest.
3. Compare with GitHub: the manifest's title and lifecycle no longer match the live issue.

PR #379 records the scale when it was fixed: 94 issues had been filed without BMad IDs and 16 closed issues
were still `active` while CI reported zero findings.
[Source: https://github.com/JakeSelby/agent-harness/issues/218]
[Source: https://github.com/JakeSelby/agent-harness/pull/379]

## Root cause

The offline audit only proves that the map agrees with itself. The live planning path never compared the
GitHub title and state with the manifest's title and lifecycle, so the corpus could stay internally
consistent while drifting from GitHub, the declared delivery authority.
[Source: https://github.com/JakeSelby/agent-harness/issues/218]

## Acceptance criteria

1. **Given** a live repository, **when** the read-only verification runs, **then** it reports title and
   `OPEN`/`CLOSED` lifecycle drift without changing GitHub state.
2. **Given** a missing or renamed issue, **when** it is verified, **then** it produces a concise finding.
3. **Given** the unit suite, **when** it runs, **then** it covers open-to-completed, completed-to-active and
   title drift.
4. **Given** maintainer verification docs, **when** they are read, **then** they say when the live check is
   required.
5. **Given** `apply`, **when** it runs, **then** it never reopens, closes or renames an issue.

## Design

`scripts/bmad_issue_sync.py` gains a read-only `audit --live` that reports title and open/closed drift, a
missing Planning block and an accepted issue with no ID, and a `refresh` that repairs title and lifecycle
drift locally. `refresh` checks every drifted artifact before writing any, so a hand-amended artifact cannot
leave the map half-updated. A non-required `bmad traceability` workflow runs the live audit daily, on issue
events and when the map changes, with `--ignore-lifecycle --grace-days 2`: an issue closes before its map
entry can follow through a PR, and a new issue gets two days to receive its ID. The full audit is for
releases and triage passes. [Source: https://github.com/JakeSelby/agent-harness/pull/379]
[Source: .github/workflows/bmad-traceability.yml]
