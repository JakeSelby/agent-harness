## Story

As a developer whose sessions span days, I want a per-repository progress file read at session start and written by a `/handoff` command, with learnings captured to a durable place, so that a new session opens where the last one stopped and corrections become artifacts instead of repeated prompts.

## Context and value

The issue records that `harness workspace create` made an empty `memory/` directory that nothing read or wrote, and that there was no progress file, handoff command or learnings capture. It notes that every surveyed long-session harness (Anthropic's long-running harness post, compound-engineering, PAI, Ralph) reads a progress artifact first and writes one last.

## Acceptance criteria

1. **Given** a repository with `.claude/progress.md`, **when** a session starts, **then** its first 80 lines and the last five commits are injected as context.
2. **Given** no progress file, an empty one, or a working directory outside a repository, **when** a session starts, **then** nothing is printed and the hook exits zero.
3. **Given** `/handoff`, **when** it runs, **then** it overwrites the progress file in a fixed shape (done, open, next command, decisions needed, learnings) and appends generalizable learnings to a dated file under `docs/solutions/`.
4. **Given** a sync, **when** it writes the harness gitignore entries, **then** `.claude/progress.md` is among them.
5. **Given** the README, `docs/how-it-works.md` and `docs/settings-ownership.md`, **when** tests read them, **then** their counts of rules, commands and hooks match the tree.

## Design

### Approach

`claude/hooks/harness-session.py` gains the progress-file injection. A new `claude/commands/handoff.md` defines `/handoff`. The progress file is gitignored by the harness, so it stays local to the checkout.

### Decisions and alternatives

- **Explicit capture, not a Stop-hook append.** The issue proposed that the Stop hook (#1) append one line of learnings per completed task. The pull request records that this "is deliberately not built; the capture is explicit" through `/handoff`.
- The issue left the learnings location open as a possible repository setting; the delivered command writes under `docs/solutions/`.

### Do not implement

- The automatic Stop-hook learnings append (declined in the pull request).

### Undelivered item

The issue's third bullet, a Stop-hook append of learnings, was not delivered, by decision. The issue was closed as completed.
