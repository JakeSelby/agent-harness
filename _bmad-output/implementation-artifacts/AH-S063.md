## Story

As a developer reviewing a plan, I want a bounded check that each Review Card decision is answerable
and each step has an observable exit test, so that a card that passes the structural validator but is
semantically empty is caught. Closed as not planned on 2026-09-21; this file records the proposal as
history.

## Context and value

A structurally valid Review Card can still hold unanswerable decisions and unobservable exit tests. The
issue proposed a self-contained experiment over the short card and its rubric only, and called its
effectiveness unverified and not a first-release dependency. It was one of seven additional bounded
experiments (#156 to #162); the 2026-09-21 epic re-scope closed it with the other prose-level checks,
because nothing consumed those answers and nothing could score them.
[Source: https://github.com/JakeSelby/agent-harness/issues/158]
[Source: https://github.com/JakeSelby/agent-harness/issues/135]

## Acceptance criteria

As proposed, not delivered:
1. **Given** the shared provider and versioned pack contracts, **when** a card is judged, **then** each
   criterion returns a typed decision with explicit abstention and unavailable handling.
2. **Given** a pack's declared input limit, **when** an input is oversized or missing, **then** it stays
   unverified rather than being silently truncated, and no transcript or repository is uploaded.
3. **Given** formatting, counts and schema, **when** they are checked, **then** deterministic code
   checks them.
4. **Given** fixtures that pass structure but fail semantics, clear concise cards, and cards with no
   pending decisions, **when** they are judged, **then** each criterion is scored separately and
   compared with the structural validator.
5. **Given** labels fixed before evaluation and a held-out split, **when** the pack is evaluated,
   **then** misses, false alarms, abstentions, errors, latency and available cost are reported, and
   ordinary tests stay offline.
6. **Given** a provider failure, **when** it occurs, **then** current behaviour is preserved, and no
   enforcement is on by default before workload-specific validation.

## Design

### Approach

Input limited to the Review Card and its explicit rubric, excluding the plan addendum. Judge each
decision for answerability, each step for an observable exit test, and whether stated alternatives are
meaningfully distinct.

### Decisions and alternatives

- **Closed as not planned (2026-09-21)** in the epic re-scope.

### Do not implement

Technical feasibility, architectural correctness, completeness against unseen requirements, a generic
quality score, inferred permissions, model training or live configuration changes.
