## Reproduction

1. Install the harness hooks for codex-cli 0.154.0-alpha.6.2.
2. Make any PreToolUse call that no gate stops.

Observed: Codex reports `hook: PreToolUse Failed` and discards the hook output. Found by native
qualification of `codex-cli-macos` in the `hook-composition` case, and isolated with two stub hooks.
codex-cli 0.155.1 accepts the value.
[Source: https://github.com/JakeSelby/agent-harness/issues/285]

## Root cause

`_encode_pre()` in `lib/harness_core/lifecycle.py` emitted `permissionDecision: "allow"` for every
non-gated PreToolUse call, and that Codex version lists `allow` as an unsupported value. The hook fails
open, so nothing is blocked wrongly, but every allowed call shows a hook failure, real failures are
masked, and an `updatedInput` rewrite cannot take effect.

## Acceptance criteria

1. **Given** a non-gated PreToolUse call on Codex, **when** the coordinator encodes its output, **then**
   it sends no `permissionDecision`.
2. **Given** a deny on Codex, **when** it is encoded, **then** it is unchanged, including the Codex
   ask-to-deny narrowing.
3. **Given** an `updatedInput` rewrite on Codex, **when** it is encoded, **then** it carries `allow` with
   the `updatedInput`, where the value is required.
4. **Given** Claude Code, **when** any of these is encoded, **then** the output is unchanged.

## Design

On Codex, say nothing for a plain approval: absence of a decision is the client's default allow. Send
`allow` only alongside an `updatedInput` rewrite. Deny, the Codex narrowing and the Claude Code output
must not change. Out of scope per the issue: a `doctor` notice for a client that cannot apply rewrites
under any decision value.

## Regression test

`tests/test_codex_pre_allow.py` (new) pins each of the four cases.
