## Goal

Open the 0.13.0 release candidate on `main`: `VERSION`, the compatibility catalog in `candidate` state,
the 0.12.0 to 0.13.0 migration record, the changelog, the regenerated support summary, and a refreshed
static context figure. The issue says: "This opens a candidate. It releases nothing and creates no tag."

Delivered by PR #651, merged 2026-09-23, which closed the issue as completed. The PR body says it opens
the candidate "the way b076826 opened 0.12.0".

## Acceptance criteria

From the issue's Acceptance section, as delivered:

1. **Given** the candidate, **when** `VERSION` and `compatibility/catalog.json` are read, **then**
   `VERSION` reads `0.13.0` and the catalog is `candidate`, with its required CLI targets carrying no
   evidence. Delivered, with a deviation: the issue said four required CLI targets; the PR marks three
   `required_for_release` (`claude-code-cli-macos`, `claude-code-cli-linux`, `codex-cli-macos`).
   `codex-cli-linux` ships as a stated limitation "until #612 lets the acceptance runner drive it".
2. **Given** `compatibility/migration.json`, **when** it is read, **then** it states what to review in
   `harness sync --dry-run`, what is opt-in, and how to return to 0.12.0. Delivered: the record has
   `summary`, `actions` and `recovery` for 0.13.0.
3. **Given** `benchmarks/static.json`, **when** `cost_bench.py static --check` runs, **then** it passes
   for the new version. Delivered: the PR regenerated the file and records the check exiting 0.
4. **Given** the candidate, **when** the repository gate and `harness generate --check` run, **then**
   both are clean. Delivered: the PR records lint at 0 findings, the suite in three passes all `OK`, and
   `harness generate --check` exiting 0.

**Deviation recorded:** the Outcome asks for "the changelog under a 0.13.0 heading". The PR left
`CHANGELOG.md` unchanged. It says the dated 0.13.0 section belongs to the release pull request, which is
also the `changelog.d/` cut-over, and added `changelog.d/627.none.md` saying so.

The PR also records that `release_preflight.py` refuses on exactly the three required targets, "as a
candidate should".
