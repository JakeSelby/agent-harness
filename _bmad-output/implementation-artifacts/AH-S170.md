## Story

As a Claude Code user, I want to install agent-harness from the plugin marketplace with one command,
so that I can try it the way I install every other project in the field.

## Context and value

The field-parity epic (#442) found that the only path was a clone plus eight to twelve commands, while
every comparable project with an audience shipped a plugin manifest or a one-command install. The
plugin manifest itself (`.claude-plugin/plugin.json`) landed first in #465; this story added the
marketplace listing that makes it installable, the install doc and the catalog surface.
[Source: https://github.com/JakeSelby/agent-harness/issues/446]
[Source: https://github.com/JakeSelby/agent-harness/issues/442]
[Source: https://github.com/JakeSelby/agent-harness/pull/475]

## Acceptance criteria

1. **Given** the repository, **when** a user runs `/plugin marketplace add JakeSelby/agent-harness`,
   **then** `.claude-plugin/marketplace.json` resolves to the plugin that `plugin.json` describes, and
   both manifests pass `claude plugin validate . --strict`.
2. **Given** the plugin manifest, **when** it is read, **then** every path it names exists and it
   declares no hooks.
3. **Given** a home, **when** `harness doctor` runs, **then** it reports which install path is active:
   the marketplace plugin, the synced home, both, or neither.
4. **Given** the compatibility catalog, **when** it is read, **then** the marketplace install is a
   distinct client surface, `claude-code-plugin-marketplace`, with status `unqualified`.
5. **Given** `docs/runtime-installation.md`, **when** a user reads the marketplace section, **then** it
   lists what that path does not include compared with `bin/harness install`.

**Recorded divergence from the issue's acceptance.** The issue asked that the manifests describe rules
and hooks, that a marketplace session see the same primitives as a cloned install, and that
`harness uninstall` restore the home. The delivered design is a strict subset instead: no rules, no
stances, no hooks, no ownership journal and no restoring uninstall on that path, as the install doc
states. The issue was closed as completed on that basis; no comment records the change of scope.
[Source: docs/runtime-installation.md#Install from the plugin marketplace]

## Design

### Approach

`marketplace.json` lists one plugin whose source is the repository root, so an install reads
`plugin.json` and nothing is duplicated between the two manifests. The plugin carries the skills, the
eleven subagent roles, the slash commands and the output style; Claude Code namespaces a plugin skill
as `/agent-harness:<name>`. `bin/harness` gains `plugin_install_state()`, which reads Claude Code's
plugin registry and cache so that `doctor` can name the live path.
[Source: https://github.com/JakeSelby/agent-harness/pull/475]
[Source: bin/harness#plugin_install_state]

### Decisions and alternatives

- **No hooks in the plugin:** a synced home already registers them, and plugin hooks would merge with
  user hooks and fire twice, so the plugin never replaces `harness sync`. [Source:
  tests/test_plugin_manifests.py] [Source:
  _bmad-output/planning-artifacts/prds/prd-agent-harness-2026-09-23/prd.md#FR-18]
- **Unqualified surface:** no native evidence was recorded for the marketplace path, so the catalog
  marks it unqualified rather than inheriting the CLI's state.

### Do not implement

- Any change to the clone path; the epic is additive only. [Source:
  https://github.com/JakeSelby/agent-harness/issues/442]

## Dev notes

### Bound decisions and requirements

- FR-18, Plugin listing as a sampler. The PRD records it as partial: the plugin's constrained roles run
  as native agents with no hook to refuse their spawn, and the manifest's version lags `VERSION`. At
  `origin/main`, `plugin.json` says `0.11.1` and `VERSION` says `0.13.0`.
- AD-19, Distribution channels carry no second authority: the plugin carries no hooks, and enforcement
  needs `harness sync`.
- AD-8, Constrained roles run only as isolated role workers: names the plugin channel as an unguarded
  spawn path.
- AD-4, Evidence-backed compatibility: a surface without evidence is not claimed.
- [Source: _bmad-output/planning-artifacts/architecture-spines/architecture-agent-harness-2026-09-23/ARCHITECTURE-SPINE.md#AD-19]

### Files to touch

- `.claude-plugin/marketplace.json`: the listing.
- `bin/harness`: install-path detection for `doctor`.
- `compatibility/catalog.json`: the client surface.
- `docs/runtime-installation.md`, `docs/compatibility.md`, `README.md`: docs.

### Testing

no-hooks rule, the catalog entry, the install doc, and install-path detection (untouched home, synced
home, enabled, disabled, registered-only and another project's marketplace).
