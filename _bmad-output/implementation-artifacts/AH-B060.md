# AH-B060 — fix(remote-control): hosts never reuse their environment, so restarts archive sessions

## Reproduction

1. Install a Remote Control host with `harness remote-control install` on Claude Code 2.1.280.
2. Restart the host, or send it SIGTERM.
3. The relaunched host registers a fresh environment instead of reusing its prior one, and the SIGTERM
   archives the host's sessions.

[Source: https://github.com/JakeSelby/agent-harness/issues/603]

## Root cause

The CLI reads `bridge-pointer.json` only when `createSessionInDir` is on, and the harness launched every
host with `--no-create-session-in-dir`, so the pointer that `heal` keeps fresh was never read. The issue
records a probe host: with the flag, no `Found prior environment` line and a new environment; without it,
the host reuses the pointer's environment, writes its own pointer, and a SIGTERM logs
`Skipping archive+deregister to allow resume`.

## Acceptance criteria

1. **Given** a relaunched host, **when** it starts, **then** it logs `Found prior environment …
   requesting reuse` and keeps its environment id.
2. **Given** a live host whose plist changed, **when** it is reinstalled, **then** it keeps its
   environment id and its sessions stay `active`.
3. **Given** a disconnected session on a managed environment, **when** `heal` runs, **then** the session
   is reconnected within one interval.

## Design

**Approach.**
- Drop `--no-create-session-in-dir` from the host command.
- `install` on a changed plist first writes the pointer from the running host's environment, then
  SIGKILLs the host, so an unarmed shutdown cannot deregister the environment.
- `heal` re-queues active sessions that are disconnected on an environment this Mac owns through
  `POST /v1/environments/<env>/bridge/reconnect`, retrying each at most once per 10 minutes.
- A `remote_control.folders` entry can be an object with its own `spawn` and `env`, so one host serves
  each workspace root with that root's rules, skills and hooks.
- 2.1.280's pointer keys `parkedProjectThreadSessionIds` and its timestamp survive `heal`'s rewrite.

**Decisions and alternatives.** Sessions reaped by a shutdown stay reported with their manual command,
because unarchiving needs elevated auth.

**Not delivered from the issue's scope.** The issue lists "Docs, rule line, `product.json`". The PR
changed `docs/remote-control.md`, but its file list holds no rule file, and it states that no
`product.json` change was needed because this fixes documented behaviour and every `product.json` group
is full. Whether a rule line was later added is not recorded in the issue or pull request.
