## Story

As a developer running BMad workflows through the harness, I want BMad preflight to report a missing
review skill and a divergent Markdown or TOML mirror, so that a workflow does not start against an
incomplete or inconsistent installation just because the customization keys still match.

## Context and value

This slice of #97 and epic #93 records ownership of the already open PR #112, stacked after #111. The
earlier routing work (#166) rejected conflicting mirrors, but preflight could still pass when an explicitly
invoked review skill was missing or when mirrors had drifted apart with matching keys.
[Source: https://github.com/JakeSelby/agent-harness/issues/174]

## Acceptance criteria

1. **Given** a BMad workflow that explicitly invokes a review skill, **when** that skill is not installed,
   **then** preflight reports it.
2. **Given** Markdown and TOML mirrors whose customization keys match but whose content differs, **when**
   preflight runs, **then** it reports the divergence.
3. **Given** the build and code-review entry points, **when** preflight inspects them, **then**
   renderer-based build entry points are distinguished from resolver-based code review.

## Design

### Approach

The BMad preflight in `bin/harness` compares mirror content rather than only keys, checks for each
explicitly invoked review skill, and treats the build templates (rendered) and code review (resolved
through role layers) as different entry-point kinds. `docs/bmad.md` documents the distinction.
[Source: https://github.com/JakeSelby/agent-harness/pull/112]

### Decisions and alternatives

- **Compare content, not only keys:** matching keys had hidden divergent mirrors.
- **Framework-contract checks are not qualification:** the PR states its disposable-copy checks do not
  qualify native model or workflow behaviour.
- Alternatives considered are not recorded in the issue or pull request.

### Do not implement

- Native model or workflow qualification.
