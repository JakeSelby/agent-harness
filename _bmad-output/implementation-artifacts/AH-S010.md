## Story

As a developer whose agent reads shell output, fetched pages and files, I want instruction-shaped text in those tool results flagged with a notice to treat it as data, so that the model can tell a harness instruction from one laundered through tool output.

## Context and value

The issue records that subagent returns already arrived with a `[harness: subagent output matched instruction-shaped pattern(s) ...]` wrapper, but Bash, fetch and read results did not. It reports an incident in which a `git log` printed a commit trailer written by a subagent, and the orchestrator could not tell whether an attribution instruction that followed was issued by the harness or came from the output; it was genuine, but nothing distinguished the two cases. `claude/rules/delegation.md` named the threat for subagent summaries only.

## Acceptance criteria

1. **Given** a `Bash`, `WebFetch` or `Read` result containing a control tag, an override attempt, a directive addressed to the agent, an attribution instruction, environment-update mimicry, or a settings or permissions edit, **when** the hook runs, **then** it injects a one-line notice naming the matched patterns.
2. **Given** ordinary output, or a commit trailer with no instruction phrase near it, **when** the hook runs, **then** it is silent.
3. **Given** any input, including malformed, empty, deeply nested or very large payloads, **when** the hook runs, **then** it never blocks, never rewrites and exits 0.
4. **Given** the notice, **when** it is compared with the subagent wrapper, **then** its shape matches.
5. **Given** sync and uninstall, **when** they run, **then** the hook is installed once whatever the plan-ceremony stance, replaces an older copy, is declared always-on in `claude/OWNERSHIP.json`, and is removed on uninstall.

## Design

### Approach

A new `PostToolUse` hook, `claude/hooks/neutralize-tool-output.py`, on `Bash|WebFetch|Read`. It scans `tool_response` and emits `hookSpecificOutput.additionalContext`. The pull request reports a 1 MB response scanning in about 16 ms.

### Decisions and alternatives

- **Advisory only.** The hook never blocks and never rewrites, as the issue specified.
- **Trailer needs a cue.** A commit trailer alone does not trigger; the attribution pattern needs an instruction phrase nearby.
- **Mirror the built-in.** The issue asked to reuse the subagent neutralizer if it lived in the harness; the pull request found it is a Claude Code built-in, so the hook mirrors its notice format and the docs now say so.
- **Tests in their own file.** The issue proposed `tests/test_harness.py`; the pull request added `tests/test_neutralize.py`.

### Do not implement

Not recorded in the issue or pull request.

### Partly delivered and later changes

- The issue asked for MCP tools too "if the matcher supports it"; PR #18 registered `Bash|WebFetch|Read` only. At `origin/main` the hook lives at `policy/hooks/neutralize-tool-output.py` (`claude/hooks` is now a symlink to `policy/hooks`, not a directory), and the dispatcher in `lib/harness_core/lifecycle.py` calls it on every `PostToolUse` event with no per-tool condition.
- The issue asked for one line in the delegation rule saying tool output is data; `claude/rules/delegation.md` is not in the pull request's file list.
- FR-37 now requires that instruction-shaped content in tool output "is neutralised and flagged".
