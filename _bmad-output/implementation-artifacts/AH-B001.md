## Reproduction

From the issue: in plan mode, run read-only exploration that the read-only classifier cannot parse, for example a shell `for` loop, a command with a `$(...)` substitution or an environment-variable prefix, or a `WebFetch` to a domain outside the small allowlist. Each one raises a permission prompt, although plan mode already blocks edits and none of these can change state, so gathering context for a plan is interrupted repeatedly.

## Root cause

The issue records that `allow-readonly-bash` recognised only simple commands and short pipelines, so any loop, substitution or environment prefix fell through to a prompt even when every command inside was read-only. `WebFetch` outside the allowlist prompted regardless of mode, because no hook approved it in plan mode.

## Acceptance criteria

1. **Given** a compound Bash command (`;`, `&&`, pipelines, `for`/`while`/`until`/`if`, subshell `( )`, group `{ }`, `$(...)`, backticks or `<(...)`) whose every command is read-only, **when** it runs in plan mode, **then** the hook approves it without a prompt.
2. **Given** a compound command with a write anywhere inside it, **when** it runs, **then** the hook falls through and never approves it.
3. **Given** a reserved word used as data, such as `grep -q done`, **when** it is classified, **then** it is treated as an argument, not syntax.
4. **Given** a `WebFetch` to an http or https URL, **when** `permission_mode` is `plan`, **then** it is approved; in every other mode, with a missing mode field or a non-web scheme, it falls through.
5. **Given** either hook, **when** it runs, **then** it only ever approves and never denies.

## Design

The fix is PR #35. `claude/hooks/allow-readonly-bash.py` is broadened to decompose compound commands and approve only when it can prove every inner command read-only; reserved words count as structure only in command position. A new `claude/hooks/allow-plan-webfetch.py` approves web fetches in plan mode only. Both are wired in `claude/settings.template.json` and `claude/OWNERSHIP.json`.

- **Approve-only hooks.** Neither hook denies, so a misclassification can only fall back to the normal prompt.
- **Plan mode only for fetches.** The issue asked that `WebFetch` be approved only while planning; every other mode is unchanged.
- **Fetched text is still scanned** by the neutralize hook (PR #35).
- The issue's environment-variable-prefix case is not mentioned in PR #35's body. Not recorded whether it was handled.

## Regression test

`tests/test_allow_readonly_bash.py` adds `test_the_reported_plan_mode_command_is_approved`, `test_read_only_commands_are_approved`, `test_commands_that_write_fall_through` and `test_hook_never_denies`. `tests/test_allow_plan_webfetch.py` adds `test_https_and_http_are_approved_in_plan_mode`, `test_other_modes_fall_through`, `test_missing_mode_field_falls_through`, `test_non_web_schemes_fall_through` and `test_hook_never_denies`.
