## Story

As a list maintainer or plugin-catalog user looking for agent harnesses, I want the repository's About
panel, description and plugin manifest to carry the strings I search for, so that I can find and index
the project.

## Context and value

Phase 1 of the distribution work. The issue records why curated lists and the community plugin catalog
could not carry the project: the About panel used six topics, one of them (`personal-stances`) a topic of
a single repository; the description led with the tagline and buried the strings a list maintainer greps
for; and there was no `.claude-plugin/plugin.json`, so the plugin directory and marketplace scrapers had
nothing to index.
[Source: https://github.com/JakeSelby/agent-harness/issues/445]

## Acceptance criteria

1. **Given** the plugin manifest, **when** `claude plugin validate . --strict` runs, **then** it prints
   `Validation passed`.
2. **Given** `product.json` changed and GitHub not yet updated, **when** `sync_about.py --check` runs,
   **then** it names only description and topics as drift; **and** after `--apply` it exits 0.
3. **Given** the change, **when** the gate runs, **then** `bin/harness lint` and the unit suite are green.
4. **Given** any published string, **when** it is read, **then** it carries no em dash.

## Design

### Approach

- `product.json` `topics` gains twelve topics chosen by measured search volume on 2026-09-21, keeping
  `personal-stances`: eighteen of the twenty GitHub allows.
- `github_description` keeps the hero sentence in front, as `tests/test_release.py` requires, and follows
  it with the runtime and component names.
- `.claude-plugin/plugin.json` remaps `skills`, `agents`, `commands` and `outputStyles` to where they
  already live.
- `docs/assets/brand/mark.svg`, the dial-pointer mark, referenced once above the README's H1.
- `tests/fixtures/gh/repo-view.json` mirrors the new panel so the release-upkeep tests describe the state
  `sync_about.py --apply` will produce.

### Decisions and alternatives

- **No `hooks` key in the plugin manifest.** Plugin hooks merge with user hooks rather than replacing
  them, so a machine running both the plugin and `harness sync` would fire every hook twice.
- **Strict validation shaped the manifest.** `--strict` required `repository` as a plain URL and `agents`
  as an explicit list of the eleven role files.
