## Story

As a developer reviewing a change, I want a `spec-reviewer` agent that reports only scope deviations and runs before the quality reviewer in a separate context, so that scope creep is not rationalized by a reviewer that has just read the code for bugs.

## Context and value

The issue records that `/review` ran one `reviewer` pass hunting correctness, tests, secrets and scope together. It cites Superpowers, compound-engineering and Pocock's `/code-review` as splitting spec compliance from quality in separate contexts, "because a reviewer that has just read the code for bugs rationalizes scope creep".

## Acceptance criteria

1. **Given** an issue, plan or pull request plus the diff, **when** `spec-reviewer` runs, **then** it returns only scope deviations: done but not asked for, asked for but not done, and acceptance criteria the diff does not prove.
2. **Given** the agent definition, **when** it is read, **then** it is read-only, on the session model, at high effort, and makes no quality, style or fix findings.
3. **Given** `/review`, **when** it runs, **then** it runs the spec pass and then the quality pass in two fresh contexts, and reports them as **Scope** and **Quality**.
4. **Given** the agents directory, **when** agent files are added, **then** the existing agent tests still pass.

## Design

### Approach

A new `claude/agents/spec-reviewer.md` and a two-pass `claude/commands/review.md`.

### Decisions and alternatives

- **Separate contexts, spec first.** From the issue.
- **Relax the directory assertion.** `tests/test_agents.py` asserted the agents directory held exactly the original three files; the pull request changed it to assert those three are present, so agents can be added.

### Do not implement

- Quality, style or fix findings in the spec pass (from the issue).
