## Story

As a developer who has not opted in, I want the Jev provider off by default, with per-point modes, a
kill switch and an outbound-field allowlist, so that enabling external inference is an explicit choice
and I can see and bound exactly what leaves the machine.

## Context and value

Adding external inference changes what leaves the machine, and the existing local telemetry
preferences do not authorize sending transcripts or repository contents to a model service. The
2026-09-21 re-scope kept the purpose and made modes per decision point (`off`, `shadow`, `advise`,
`act`), added a sentinel that disables every call without touching configuration, fixed credentials to
the environment only, and excluded tool output and assistant prose from state for any point that
touches permissions. It sits on the critical path between #136 and #139.
[Source: https://github.com/JakeSelby/agent-harness/issues/137]

## Acceptance criteria

1. **Given** an existing configuration, **when** the harness runs, **then** every point is `off` and no
   provider request is made, from hooks, replay commands or background workers.
2. **Given** the kill-switch file exists, **when** any decision is taken, **then** no call is made; the
   file is read per decision.
3. **Given** a non-`off` mode, **when** no credential variable is set in the environment, **then** no
   call is made and no fallback is enabled.
4. **Given** `governance.jev.state_fields`, **when** a request is built, **then** only allowlisted
   fields among `command` and `summary` are sent, secret-shaped values are dropped whole, and no free
   text leaves when the pattern list will not load.
5. **Given** a request, **when** it is sent, **then** it has a 2 s timeout and request and token
   ceilings, and every failure falls back to the deterministic decision.
6. **Given** `harness doctor`, **when** it runs, **then** it prints the mode per point, the allowlist,
   the kill switch and which credential variable is set, never its value.
7. **Given** a `shadow` point, **when** it decides, **then** its row carries the judgment and severity
   labels plus the base and advised outcomes, so shadow is measurable.

## Design

### Approach

`lib/harness_core/decisions/controls.py` resolves the mode per point from a global default and
per-point overrides, checks the kill switch and the environment credential, filters the outbound state
through the allowlist and secret patterns, and keeps a per-session spend record in the state directory
under a lock. `harness config set governance.jev.*` coerces the dotted keys and never echoes a value.

### Decisions and alternatives

- **Presence disables:** the sentinel is a kill switch; the environment credential plus a non-`off`
  mode is what enables.
- **Credentials from the environment only;** the harness never reads a key file.
- **Budget shared across hook processes** through a locked per-session record; on lock contention the
  charge falls back to the in-process count rather than refusing, matching fail-open elsewhere.
- **A provider constructed by hand without config** keeps acting behaviour but can never be live, which
  keeps #136's tests honest.
- **An unknown point is `off`.**

### Do not implement

- Hook wiring: no hook consults a provider yet.
- Evaluation and ledger rows (#138, #139).
- Relaxing any decision; `act` may only tighten (#372).
