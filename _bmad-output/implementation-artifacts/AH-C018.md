## Goal

Let the suite pass on the first development branch after v0.11.0. The release-readiness test asserted no
release errors, and any runtime-source change after a release makes that false by design, because the
released catalog then reports source drift. The same edit was needed after v0.10.0 (#231). The issue
asked to make the assertion follow the catalog state once, so it would not need editing at every
release.
[Source: https://github.com/JakeSelby/agent-harness/issues/298]

## Acceptance criteria

1. **Given** a released catalog and changed runtime source, **when** the test runs, **then** it expects
   the drift error and no other.
2. **Given** a released catalog and unchanged source, **when** the test runs, **then** it expects no
   error.
3. **Given** a candidate catalog, **when** the test runs, **then** it expects exactly one `is unqualified`
   error per required client that lacks evidence.
4. **Given** a future release, **when** the catalog changes state, **then** the test needs no edit.

## Tasks

- [x] Released: drift-only when source changed, none otherwise (AC: 1, 2)
- [x] Candidate: one unqualified error per required, unqualified client (AC: 3)
