## Reproduction

1. Run the BMad traceability migration's `apply` against this repository, which a personal account owns.
2. Planning blocks, exact `type::*` labels and primary-parent relationships apply, but GitHub silently
   discards every native issue-type update.
3. Run `plan` again: it still reports 109 remaining actions, one per issue, although every supported
   projection succeeded.

Two issues created after the original snapshot were also unmapped.
[Source: https://github.com/JakeSelby/agent-harness/issues/203]

## Root cause

GitHub documents issue types as organization-managed metadata, so a personal-account repository accepts
but ignores native type writes. The sync tool assumed native types were always available and treated the
unavailable type as perpetual drift. [Source: https://github.com/JakeSelby/agent-harness/issues/203]

## Acceptance criteria

1. **Given** this repository after `apply`, **when** `plan` runs, **then** it reports no actions.
2. **Given** every mapped issue, **when** it is inspected, **then** it has exactly one owned type label and
   the intended primary parent.
3. **Given** the fix, **when** it runs live, **then** titles, states, comments and non-BMad issue prose are
   unchanged.
4. **Given** the committed map, **when** the fix is prepared, **then** it covers every issue that exists,
   without renumbering existing IDs.

## Design

Make exact `type::*` labels the authoritative type projection for a personal-account repository and keep
native sub-issue hierarchy. The manifest records the capability explicitly as `native_type_projection`,
either `labels-only` or `native-and-labels`, so unsupported metadata never appears as drift; a schema-1
manifest without the field keeps the original native projection. The tool refuses any other value before
planning or applying rather than silently accepting ignored writes. The public governance text and the
tool tests state the limitation. Issues #199, #200 and #203 are added to the map without renumbering.
[Source: https://github.com/JakeSelby/agent-harness/pull/205] [Source: scripts/bmad_issue_sync.py]

Current state: `_bmad-output/issue-map.json` is schema version 2 with `native_type_projection:
labels-only`. [Source: _bmad-output/issue-map.json]
