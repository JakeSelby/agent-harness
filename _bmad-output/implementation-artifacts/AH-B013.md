## Reproduction

1. With the usage feed on (#255), spawn a synchronous subagent in Claude Code.
2. Read the feed's line for the subagent's return, then compare it with the usage log's row for the same
   transcript after a later scan.

Observed in a live run: the feed said 143 output tokens where the usage log recorded 278. The gap is the
subagent's last response only, so it is small on real work, but the line reads as exact.
[Source: https://github.com/JakeSelby/agent-harness/issues/261]

## Root cause

The line is computed when `PostToolUse` fires on the `Agent` call, by summing the subagent's own
transcript. Claude Code writes one API response as several records, and the return fired between a
partial streaming count and the record that ends the response, so the final response had not been fully
written when the hook read the file.

## Acceptance criteria

1. **Given** a synchronous subagent return whose final record lands after the first read, **when** the
   feed computes its line, **then** it reports the settled figure.
2. **Given** a final record that never arrives within the hook's time budget, **when** the line is
   written, **then** the figure is marked provisional.
3. **Given** a figure that settles after its line, **when** the next turn line is written, **then** the
   session totals are raised from the settled figure without naming the agent twice.
4. **Given** the hook, **when** it waits, **then** it stays inside its time budget.

## Design

Of the three options the issue allowed (wait briefly, reconcile at the next turn line, or mark
provisional), the fix combines all three: `policy/hooks/usage-feed.py` waits at most a second, over the
transcript's tail, for the record carrying a `stop_reason`; says `(so far)` when it never arrives; and
raises the session totals from the settled figure afterwards. The PR records that in a sample of real
transcripts the record carrying a stop reason held the largest figure for its message id in 1,418 of
1,418 ids, which is why the stop-reason record is treated as final. The fix must not wait on a settled
or missing transcript.

## Regression test

`tests/test_usage_feed_settling.py` (new), as of #271, notably

`test_a_settled_transcript_is_not_waited_on_at_all`.
