## Reproduction

1. On macOS, create an empty directory and run `claude doctor` with `HOME` pointed at it.
2. Or run `python3 -m unittest discover -s tests` before the fix, or a native acceptance run.

Observed: a system dialog, "Keychain Not Found: a keychain cannot be found to store ...", with a
destructive **Reset To Defaults** button. `claude doctor` in an empty `HOME` starts `SecurityAgent`; in a
`HOME` carrying a keychain it does not. Two code paths raised it:
- `scripts/native_acceptance.py`, whose `Home.env()` points `HOME` at a disposable directory for every
  client turn;
- two tests in `tests/test_codex_reviewer_key.py` that called `cmd_doctor` inside `TempHome` without
  hiding the installed client, so the real `claude doctor` ran: two dialogs per suite run, and the
  stop-gate hook runs the suite on every turn with a changed tree.
[Source: https://github.com/JakeSelby/agent-harness/issues/282]

## Root cause

macOS resolves the default keychain from `$HOME/Library/Keychains/login.keychain-db`. A disposable home
has none (`security default-keychain` reports that no default keychain could be found), so the real
client prompts on every launch.

## Acceptance criteria

1. **Given** macOS, **when** a native acceptance run or a full test run executes, **then** no keychain
   dialog appears.
2. **Given** a run, **when** it finishes, **then** the operator's default keychain and search list are
   unchanged.
3. **Given** a disposable home whose keychain cannot be created, **when** its case would run, **then** it
   is reported `unverified` and no client is launched.
4. **Given** a non-macOS host, **when** the runner or suite runs, **then** nothing new runs.
5. **Given** a doctor call in a temporary home, **when** a test makes it, **then** it never launches the
   installed client.

## Design

Each disposable acceptance home gets its own throwaway keychain at the default path on macOS, so the
client's store succeeds silently and never touches the operator's login keychain. The two doctor tests
hide the installed client, and a tripwire test fails if a doctor call in a temporary home launches it
again. The fix must not change other hosts.

## Regression test

The tripwire in `tests/test_codex_reviewer_key.py`, and keychain tests in `tests/test_native_acceptance.py`.
The PR records a logging stand-in on `PATH` that saw no `claude` launch under a temporary `HOME`.
