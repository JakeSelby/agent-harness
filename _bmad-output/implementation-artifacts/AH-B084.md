# AH-B084 — spawn-confinement checks less than step 9 asks: the refusal's wording, the routed run, the false positives

- **Primary parent:** None
- **State:** active

The issue carries the summary, discussion and acceptance evidence; this file carries the design.

This work item was authored as part of the repository's committed BMad planning system.
<!-- bmad-sync:end -->

## Reproduction

Round 4 of the 0.13.0 native qualification ran `spawn-confinement` green on both Claude Code CLI
targets, and the strong-class assessor ruled it short of step 9 in `docs/compatibility.md`, read
against the round-4 records:

- the refusal was read for the framework it recognised and the input roots, never for the layer
  or `harness role run <role>`;
- the brief handed the descriptor's sentences over "copied exactly" instead of being "reworded as
  the client writes it";
- no routed run: nothing ran the same layer through `harness role run` or checked worker state;
- the ordinary spawn's brief was a bare reply request, so neither false positive (review words in
  passing, an edit under the framework's input roots) was exercised.

## Root cause

`case_spawn_confinement` in `scripts/native_acceptance.py` was written against the refusal's
framework and roots clauses only, and `framework_brief` supplied the classified text itself, so
the case tested the matcher on sentences it chose rather than on a brief the client wrote.

## Acceptance criteria

1. **Given** the first descriptor spawn with phrases, **when** its own declared sentences are handed
   to the client quoted whole, addressed to the subagent, with no `subagent_type`, **then** the
   spawn writes no subagent transcript, the decision log holds a `framework-spawn` deny whose
   logged input is that brief's fingerprint, and the Agent call's tool result names the framework,
   the layer, the constrained role, the input roots, `harness role run <role>` and `harness role
   run <role name>`.
2. **Given** a plain-words request for the same layer's work, **when** the model writes the brief
   itself with no role, **then** the observation records that brief, whether it was refused and
   what the classifier matched, stated as the claim's limit; neither outcome passes or fails.
3. **Given** the same layer, **when** it runs through `harness role run <role>` with each existing
   input root as `--read-dir`, **then** a completed isolated-cli worker writes `status.json` and
   `result.md` in its own directory under the state home's `workers/`, records those roots as read
   roots and returns findings naming the reviewed file; missing worker state fails the case.
4. **Given** an ordinary unnamed spawn whose brief mentions review, a diff and findings in passing,
   **when** it runs, **then** it writes a subagent transcript and no deny row.
5. **Given** an ordinary unnamed spawn told to edit a file under the second input root, **when** it
   runs, **then** it writes a subagent transcript, no deny row, and the file holds the edit.
6. **Given** a turn with no Agent call on the framework text, a named `subagent_type`, an ordinary
   brief that dropped its words, or an edit spawn that edited nothing, **then** the case is
   Unverified, never passed.

## Design

**Decision (maintainer, 2026-09-23): narrow the claim, not the product.** The first live run of a
brief the model wrote itself showed recognition is lexical: sonnet's brief kept
`_bmad/review-prompts/edge-case-hunter.md` and paraphrased every instruction, `classify` scored it
0 agents, 1 identifier, 0 phrases, below its identifier-plus-phrase threshold, and the spawn ran.
Step 9 in `docs/compatibility.md` now claims refusal for the framework's own spawn text as its
workflow hands it to the client, and asks for the rewording to be run and recorded as the claim's
observed limit. Recognising paraphrases is tracked in #739.

`framework_prompt` and `framework_brief` (from AH-B077) carry the descriptor's sentences quoted
whole and addressed to the subagent; `SPAWN_SUBJECT` now names the seeded `calc.py`.
`framework_refused` requires the refusal, and `refusal_gaps` names what a refusal omits;
`brief_rows` ties a log row to the brief by fingerprint. `reworded_probe` runs `layer_request`,
which points at the layer's instruction file (placed by `layer_instructions` at the layer's own
identifier under the first input root) and quotes no descriptor sentence, and records the brief,
whether it was refused and what the classifier matched; it never raises. `routed_layer` runs the
role worker and reads its state directory, and `ordinary_ran` drives both false positives.

Rejected: keeping the rewording as a pass criterion, which fails every round on known product
behaviour; loosening the phrase matcher or restating the phrases in the request so the model
echoes them, which would test the case's wording rather than the product; dropping the rewording
entirely, which would hide the claim's limit; reading refusal wording from the model's answer
first, since the tool result is what the hook returned. The descriptor, classifier and hook are
unchanged.

## Regression test

`tests/test_native_acceptance_spawn_confinement.py`, 20 tests, drives the whole case through a fake
client that passes each brief through the real `lifecycle.dispatch` hook path.
- **Before the fix:** the routed-run, false-positive, rewording and refusal-naming functions do not
  exist, and the old case passed with no routed run and a bare ordinary spawn.
- **After the fix:** all 20 pass, including a reworded brief recorded both refused and not refused
  while the case still passes. The superseded tests in
  `tests/test_native_acceptance_spawn_brief.py`, `tests/test_native_acceptance_spawn_refusal.py`,
  the `SpawnAttemptTests` class and two `SpawnConfinementTests` methods were moved here.
