# AH-B025 — A refused constrained-role spawn can be re-issued unnamed and run unconfined

## Reproduction

1. On Claude Code (Linux), run a BMad review whose layers are routed to the confined `reviewer` role.
2. Let the client spawn a native subagent naming `reviewer` or `spec-reviewer`; the spawn guard refuses
   it and points at `harness role run`.
3. Watch the client re-issue the same brief as an unnamed or generic native subagent.

Observed natively during 0.11.0 qualification: four spawns named `reviewer` or `spec-reviewer` were
refused, then four generic subagents carried the same briefs; four of five BMad review attempts ran
unconfined this way or by pasting the routed brief straight into an unnamed spawn.
[Source: https://github.com/JakeSelby/agent-harness/issues/300]

## Root cause

The spawn guard judged each spawn only by the role it named and kept no memory of a refusal, so dropping
the role name was enough to pass. The longer-term cause, confinement requested in a prompt rather than
enforced from a declared mapping, is #291.

## Acceptance criteria

1. **Given** a refused constrained-role spawn, **when** a later spawn in the same session carries the
   same or a near-identical brief, **then** it is refused whatever role it names or omits, and the reason
   says dropping the role name does not change the refusal.
2. **Given** unrelated spawns, other sessions, or no prior denial, **when** they arrive, **then** they
   are allowed.
3. **Given** a brief with a standalone `harness-role: <role>` line naming a constrained role, **when** it
   is spawned unnamed or generically, **then** it is refused, and `harness role run` accepts it.
4. **Given** a marker naming a non-constrained role, **when** it is spawned, **then** the marker is
   ignored.
5. **Given** unreadable session state or `delegation: off`, **when** a spawn arrives, **then** behaviour
   is as before.
6. **Given** this fix, **when** it lands, **then** #291 stays open.

## Design

Two small guards in `lib/harness_core/lifecycle.py`, generic to any constrained role: evade-after-deny,
which remembers a refused brief for the session, and the role marker, which the BMad review-layer
template `templates/bmad/custom/bmad-code-review.user.toml` carries. Both are best effort.

## Regression test

`tests/test_spawn_evasion_guard.py` (new) pins identical and near-identical re-spawns refused; unrelated,
other-session and no-prior-denial spawns allowed; the marker enforced for unnamed and generic spawns; a
non-constrained marker ignored; and `harness role run` accepting a marked brief.
`tests/test_bmad_templates.py` checks the templates carry the marker.
