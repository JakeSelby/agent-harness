# AH-B043 — issue-ownership does not say which issues it found, so a keyword in prose is invisible

## Reproduction

The issue records a pull request on 2026-09-21 whose body carried the sentence:

> #134 moved from the closed #98 to the v1 epic #206

GitHub read `closed #98` as a closing reference, so `closingIssuesReferences` was `[98, 391]`. The
`issue-ownership` check refused the pull request, correctly, for naming two delivery issues, and printed:

```
Issue ownership check failed: Link exactly one delivery issue using Closes #N.
```

Editing the body did not clear it, because the commit message carried the link too, and amending that
needs a force-push. The pull request was rebuilt on a new branch.

## Root cause

`validate` in `.github/scripts/check_issue_ownership.py` raises the same message whenever
`closingIssuesReferences.totalCount` is not 1, or the node count is not 1. It does not include the
numbers it found, so the zero case and the two-or-more case read the same. That is unchanged at
`origin/main`.

The cause of the double link is GitHub's rule, as the issue states it: a closing keyword immediately
before an issue reference is a link wherever it appears, and `closed`, `fixed` and `resolved` count as
well as `closes`.

## Acceptance criteria

From the issue's Acceptance section:

1. **Given** a pull request with two closing references, **when** the check runs, **then** it fails
   with a message naming both numbers.
2. **Given** a pull request with no closing reference, **when** the check runs, **then** it fails with
   a message saying none was found.
3. Unit tests cover both messages.

## Design

From the issue's Scope section:

- When the count is wrong, the failure names every issue GitHub is treating as a delivery issue.
- When there is more than one, the failure says that a closing keyword in prose also creates a link,
  and names the keywords.
- `AGENTS.md` warns against `closed`, `fixed` and `resolved` immediately before a number in prose, and
  gives the safe alternative.

`AGENTS.md` at `origin/main` says "Add `Closes #N` to the PR" and "contextual references do not
establish ownership", but carries no warning about keywords in prose.

Do not implement: the issue records no out-of-scope item. Parsing the body for keywords is not needed,
because GitHub already returns the references. [ASSUMPTION: the issue does not say this; it follows
from the check reading `closingIssuesReferences`.]

## Regression test

Not written. Tests in `tests/test_issue_ownership.py` would call `validate` with zero and with two
references, and assert the exact messages. The current `test_missing_multiple_and_foreign` covers the
refusal, but not the message.
