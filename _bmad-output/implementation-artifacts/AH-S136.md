## Story

As a harness maintainer, I want a zero-token count of what the harness adds to every Claude Code
session, committed per release and checked in CI, so that the harness's standing overhead against a
bare session is visible per version and cannot grow by accident.

## Context and value

A bare Claude Code session loads none of the harness's always-loaded layer, so that layer's whole size
is the harness's standing overhead against no harness. The issue records that a first spike showed this
overhead is most of the cost difference on a small task. The line cap in `harness lint` stays as it is;
this adds a per-version trend in tokens and dollars and does not replace the cap.
[Source: https://github.com/JakeSelby/agent-harness/issues/361]

## Acceptance criteria

1. **Given** a managed Claude Code profile, **when** `scripts/cost_bench.py static` runs, **then** it
   counts the always-loaded layer (global instructions, rules, the default and the longest stance
   variants, the output style) and the per-session listings (agent, skill and command descriptions),
   and reports files, lines, characters and an estimated token count.
2. **Given** that token estimate, **when** it is priced, **then** each model's cost comes from
   `policy/prices.json` as USD per session start (cache write) and USD per later turn (cache read).
3. **Given** the committed figure in `benchmarks/static.json`, **when** the estimate grows by more than
   the threshold (5% as built), **then** the check fails, unless `benchmarks/allow.json` names a reason.
4. **Given** a pull request, **when** CI runs, **then** it runs the static check.
5. **Given** the unit tests, **when** they run, **then** they cover the counter, the pricing and the gate,
   including a seeded growth that fails and an allow entry that passes it.

## Design

### Approach

A `static` subcommand in `scripts/cost_bench.py` counts the files a session loads before the first
prompt, estimates tokens, and prices the estimate per model from `policy/prices.json`. The figure for
0.11.1 is committed in `benchmarks/static.json`: as of #362, 53 files and 7,457 estimated tokens in total
(5,168 always loaded, 2,288 in listings), 7,516 worst case. CI runs `scripts/cost_bench.py static --check`,
which fails on growth past `GROWTH_LIMIT = 0.05` (as of #362) without a reasoned entry in
`benchmarks/allow.json`.

### Decisions and alternatives

- **Keep the lint line cap:** the static figure adds a trend in tokens and dollars beside the cap and
  does not replace it (issue text).
- **Growth threshold:** the issue left the threshold open; the PR set it at 5%.

### Do not implement

- The live replay benchmark (a separate issue, #367).
- Codex: its instructions are rendered at sync time and are not counted yet.
- Any change to `harness usage` or the ledger.
