## Story

As a developer who wants prose replies or my own house style, I want the output voice to be a stance I can switch, so that I do not have to edit a tracked file to change the harness's most visible opinion.

## Context and value

The issue records that `claude/rules/voice-and-format.md` loaded on every turn and opened by hard-wiring one style ("The Scannable style ... governs the main conversation"), with no config key to change or disable it. Against the harness's own test, "a stance is right when a competent engineer could reasonably want the opposite", output voice failed plainly. It was the last always-loaded rule that was a pure preference, so closing it made "every opinion is a switch" true rather than nearly true. The issue also notes the budget: always-loaded context sat at 192 of 200 after #67, and `tests/test_cost_stance.py` held a tighter 196.

## Acceptance criteria

1. **Given** the stance catalog, **when** it is listed, **then** a `voice` dimension offers `scannable` (the default, unchanged behaviour), `answer-card` and `off`.
2. **Given** an environment override or `config get`, **when** the dimension resolves, **then** it selects the variant, and an unknown variant fails loudly.
3. **Given** `voice-and-format.md`, **when** it is read, **then** it keeps only what no variant changes: a subagent inherits no voice, so its brief carries the output shape.
4. **Given** each variant, **when** it is read, **then** it names the shape it imposes and stays within the budget the tests assume.
5. **Given** the `voice/` detectors, **when** a voice was not selected, **then** they do not measure it as a violation.

## Design

### Approach

`claude/stances/voice/{scannable,answer-card,off}.md`, `voice` added to `STANCE_NAMES` in `bin/harness` and to `config.example.json`, a row in `docs/preferences.md`, and the two voice detectors in `claude/hooks/rule-detectors.py` gated on the dimension. The pull request reports always-loaded context moving from 193 to 195 of the 196-line budget: the rule gave up seven lines and the longest variant, `answer-card`, costs nine.

### Decisions and alternatives

- **Three variants, not two.** The issue asked for at least `scannable` and `off`; the pull request adds `answer-card` for reading on a phone.
- **The output style stays owned.** `answer-card` says it wins over the output style where they differ, because `outputStyle` stayed an owned settings key set to Scannable. Making the style selectable would touch `OWNERSHIP.json`, and the pull request calls that a separate change.

### Do not implement

- Making `outputStyle` stance-selectable (deferred by the pull request). FR-68 records voice-conditional output styles as delivered later, in 0.12 (#494).
- The issue also suggested auditing `conciseness.md` and `cache-hygiene.md` under the same test; the pull request does not change them.
