# AH-S218 — Pass CLAUDE_CODE_OAUTH_TOKEN into the disposable home so a subscription can run a Claude Code round

## Story

As the operator qualifying a release on a Claude subscription with no API key and no cloud
profile, I want the token `claude setup-token` mints to reach the runner's disposable home, so a
Claude Code round spends the subscription rather than on-demand credit.

## Acceptance criteria

1. **Given** `CLAUDE_CODE_OAUTH_TOKEN` is exported in the shell that invokes the runner, **when**
   a case launches its client under the disposable home, **then** the variable is present there
   and no other credential is copied.
2. **Given** only that variable is set, **when** the smoke tier's `credentials` check runs,
   **then** it reports the environment reachable and never prints the value.
3. **Given** the runbook's credentials section, **when** an operator reads it, **then** it names
   `claude setup-token` and the variable as the subscription route.

## Design

Add the name to `AUTH_PASSTHROUGH` in `scripts/native_acceptance.py` and to `API_KEY_VARS` in
`lib/harness_core/credentials.py`; both lists already treat presence as the whole test and never
read the value. Rejected: copying `.credentials.json` into the disposable home, which the probe
exists to refuse. The change must not alter what happens for `ANTHROPIC_API_KEY` or a cloud profile.
