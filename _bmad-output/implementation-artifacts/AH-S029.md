## Story

As a developer running either runtime under the harness, I want lifecycle policies, role confinement,
gates and telemetry to behave the same through each runtime's native hooks, so that a decision, a read-only
role or a green gate means the same thing whichever runtime I use.

## Context and value

A work package of epic #93 that depends on #94 and #95. The issue records the problems: native hooks
assumed Claude envelopes while Codex ask and rewrite semantics differ; gate identity omitted staged and
untracked content; role Bash access defeated read-only claims; and usage parsing was Claude-only.
[Source: https://github.com/JakeSelby/agent-harness/issues/96]

## Acceptance criteria

1. **Given** native allow, deny and rewrite results, patch paths, shell writes, role confinement and
   cancellation, **when** they are exercised, **then** the composed decision is correct in each runtime.
2. **Given** a green gate, **when** staged or untracked content changes, **then** the green evidence is
   invalidated.
3. **Given** a missing metric or a failed detector, **when** it is recorded, **then** it stays unknown rather
   than clean.
4. **Given** telemetry contention, **when** concurrent writers record events, **then** no event is lost.

## Design

### Approach

Normalize action and event inputs and compose shared decisions before emitting native results. Port every
lifecycle policy and helper with explicit coverage. Bind role authority, model, context and delegation
separately. Repair gate content identity and same-shell execution, and report timeout, cancel and error as
unverified. Normalize telemetry with provenance and reliable concurrent writes. Doctor distinguishes
installed, discovered, trusted, active and tested. [Source: https://github.com/JakeSelby/agent-harness/issues/96]

The issue's "Approved confinement design" section adds: shared roles whose authority is read-only or
artifact-write run as isolated CLI workers over the same role catalog; planner workers return content and
the harness alone validates it and creates a caller-selected plan under `.agent-harness/plans/`;
unsupported authority, missing inherited model identity, delegation-off, symlink or traversal paths,
existing artifacts and invalid worker output are rejected; and a sandbox that prevents every command from
starting counts as blocked, not passed.

Delivered through:
- AH-S069 / #165 (PR #103): shared lifecycle composition in both adapters.
- AH-S077 / #173 (PR #111): hook diagnostics for both runtimes.
- AH-S081 / #177 (PR #115): isolated role workers.
- AH-B006 / #181 (PR #182): normalized per-file plan feedback for Codex patch results.

### Decisions and alternatives

- **Isolated CLI workers rather than native subagent defaults** for constrained roles; native subagent
  launches of those roles are directed to the runner rather than claiming confinement from defaults.
- **Source tests are not native qualification:** worker lifecycle and native versions are recorded
  separately.

### Do not implement

- A Cursor or Grok adapter, hosted-agent support, a native memory merge or UML viewer work.
