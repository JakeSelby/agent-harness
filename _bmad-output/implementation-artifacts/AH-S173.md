## Story

As a developer reading the usage report, I want a model id the price table does not list to be
reported as unpriced, so that a premium variant is never billed at its family's lower rate and shown
as a known figure.

## Context and value

`policy/prices.json` let an unlisted variant of a listed family inherit the family's rate. That
under-billed a premium variant by a multiple (`gpt-5.5-pro` is $30/$180 per million tokens where
`gpt-5.5` is $5/$30) and presented a known-low figure as known: the one place the ledger broke its own
"unknown is never zero" discipline. Item B3 of the 2026-09-22 enterprise-review intake.
[Source: https://github.com/JakeSelby/agent-harness/issues/517]
[Source: https://github.com/JakeSelby/agent-harness/pull/549]

## Acceptance criteria

1. **Given** a model id with no exact entry in the price table after normalisation, **when** a row is
   priced, **then** `price_key()` returns no key, the row is unpriced, and the `harness usage` footer
   counts it as unpriced.
2. **Given** a dated or cloud-reseller spelling of a listed model (a date stamp, `-v1:0`, `@date`, a
   context-window suffix), **when** it is normalised, **then** it still reaches its family entry, while
   a word after the family name stays unpriced.
3. **Given** the twelve shipped ids, **when** they are priced, **then** each is priced as an exact key.
4. **Given** an unpriced row, **when** it is exported, **then** it carries neither `harness.usd` nor
   `harness.price_as_of`.
5. **Given** `policy/prices.json`'s `_limitations` and `docs/usage.md`, **when** a reader reads them,
   **then** they say inheritance is gone and how to add a variant.

**Recorded divergence from the issue's acceptance.** The issue asked that families which share a rate
declare an explicit prefix in `policy/prices.json`, with a test that a declared prefix still prices.
The delivered design has no prefix matching at all: exact keys after normalisation, and a variant is
added as its own entry or under `prices` in `config.json`.

## Design

### Approach

`price_key` in `policy/hooks/pricing.py` becomes a lookup rather than a longest-prefix scan, and
`normalise_model` drops a release suffix on the way to it.
[Source: policy/hooks/pricing.py#price_key]
[Source: https://github.com/JakeSelby/agent-harness/pull/549]

### Decisions and alternatives

- **Exact match, not declared prefixes:** "Nothing resolves by prefix. A variant of a listed family is
  a different model at a different price." [Source: policy/hooks/pricing.py#price_key]
- **Normalisation absorbs spelling differences,** so exact matching does not unprice dated or reseller
  ids.
- **Benchmark task spec corrected:** `benchmarks/tasks.json` stated the prefix rule as an acceptance
  criterion and is graded by the tests this changes.

### Do not implement

- Any `--json` surface for `harness usage`; the PR notes none exists, so nothing machine-readable
  changes shape.
