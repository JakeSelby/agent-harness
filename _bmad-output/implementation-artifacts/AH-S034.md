## Story

As a developer who selects stances, I want every selection to take effect across rules, skills, workflows, settings, hooks and detectors, so that no policy layer silently contradicts the variant I chose.

## Context and value

The issue was filed against the installed v0.8.0 sources, where `cost=max` permitted compaction while a core rule prohibited it, `voice=off` still installed the Scannable output style, and skills and commands could reintroduce a disabled policy ([#117](https://github.com/JakeSelby/agent-harness/issues/117)). It is the first step of the epic's plan, "Repair selection semantics" [Source: docs/plans/stance-completeness.md#Steps].

The epic's 2026-09-21 assessment rated this story Partial: the cost side worked through the `compaction` switch, and the voice side did not, because `merge_claude_settings` installed `"outputStyle": "Scannable"` whatever `voice` said ([#116 comment](https://github.com/JakeSelby/agent-harness/issues/116)). That defect was filed separately as #394 and fixed by PR #494 on 2026-09-22, so the issue's voice problem statement is now out of date. The story itself stays open.

## Acceptance criteria

1. **Given** `voice=off`, **when** `harness sync` runs, **then** no harness-owned Scannable preference is installed or retained, and a style the user set before installing survives variant transitions and uninstall.
2. **Given** `cost=max`, **when** its policy is projected, **then** compaction is permitted with no conflicting core instruction or violation detector, and an explicit context policy has documented precedence.
3. **Given** off/on/off transitions, config and session overrides, and both runtime projections, **when** sync runs repeatedly, **then** the result is idempotent and no session choice is persisted into the global configuration.

## Design

### Approach

The issue proposes an audit of rules, skills, workflows, settings, hooks and detectors against the resolved selection, a fix to voice ownership and restoration, a fix to cost-versus-context precedence, and a definition of `off` as removal of the harness preference only, never of native or repository constraints ([#117](https://github.com/JakeSelby/agent-harness/issues/117)).

The plan adds four policy classes (invariants, stances, settings, presets), keeps default, user, explicitly selected project, then session precedence, and records six surfaces per policy: rule text, skills, workflows, settings, hooks and detectors [Source: docs/plans/stance-completeness.md#Step 2 — Selection contract].

What exists on `main` today:
- Voice: `merge_claude_settings` takes `outputStyle` from the `voice` stance and removes only a style the reconciliation journal says the harness installed [Source: bin/harness#merge_claude_settings].
- Cost: `primitives/stances/cost/max.json` sets `compaction: compact-allowed`, one of the values in `SWITCH_VALUES` [Source: policy/hooks/posture.py#SWITCH_VALUES]. `max.md` says compaction is allowed and that the `cache-hygiene.md` costs apply, while the always-loaded `cache-hygiene.md` still says to use the native fresh-session control, "not compaction" [Source: primitives/rules/cache-hygiene.md].
- A generic `cache-hygiene/compact` detector ships in the vendored `ruleprobe` [Source: policy/hooks/rule-detectors.py]. Whether it is suppressed under `cost=max` was not verified for this record.
- Session overrides: `sync` strips `HARNESS_STANCE_*` variables before loading configuration, so a session selection is not written into persisted settings; #294 records that this also means sync ignores them while `harness stances` honours them [Source: bin/harness#_cmd_sync_unlocked].

### Decisions and alternatives

- The epic's plan recommended stacking on PR #115; the only implementation vehicle, PR #133, was closed unmerged against a `main` that had moved about 150 pull requests ([#116 comment](https://github.com/JakeSelby/agent-harness/issues/116)).
- The assessment recorded the voice defect as a shipped bug that deserved its own issue rather than part of this story; #394 and PR #494 carried it.

### Do not implement

- Do not weaken native restrictions, repository requirements, user-owned settings or explicit authorization; guidance is not enforcement ([#117](https://github.com/JakeSelby/agent-harness/issues/117) Boundaries).
- Do not sync an unmerged candidate into the live installation.
