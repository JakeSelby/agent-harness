## Story

As a developer running a planning framework in a repository, I want a bare subagent spawn there to keep the session model under the `tiered` stance, so that the framework's judgment spawns run at the capability its own contract requires.

## Context and value

The issue records the framework's rule that "all review subagents must run at the same model capability as the current session", and that most of its spawns are judgment work: the finalize reviewers of `bmad-prd`, `bmad-architecture` and `bmad-ux`, the GDS validators, the `bmad-review` lenses, and the inline reviewer roles of `gds-code-review` and `gds-quick-dev`. After #48, `tier-agent-spawns` moved every bare spawn one tier down. These skills launch from step logic or prompt-only lists (`finalize_reviewers`, `validation_checklist`, `lenses`) that BMad's customization contract cannot redirect to a named agent, so their judgment ran a tier down, against both the framework's rule and the stance's own "judgment on the session model".

## Acceptance criteria

1. **Given** a repository with a framework runtime (`_bmad/scripts/` or `_bmad/core/` at or above `cwd`) and the `tiered` stance, **when** a bare spawn runs, **then** it keeps the session model.
2. **Given** a worktree of such a repository, which carries only `_bmad/custom/`, **when** a bare spawn runs, **then** it is tiered down as before.
3. **Given** a named agent, an explicit model, `off` or `session-model`, **when** the hook runs in a framework repository, **then** behaviour is unchanged, and `off` still asks.
4. **Given** a missing or malformed `cwd`, **when** the hook runs, **then** the spawn is tiered as usual.

## Design

### Approach

`claude/hooks/tier-agent-spawns.py` looks for a framework runtime at or above `cwd` and, under `tiered`, skips the tier-down there. `docs/bmad.md`, `docs/how-it-works.md`, `docs/preferences.md` and the `tiered` stance line explain it.

### Decisions and alternatives

- **Detect the runtime, not the overrides.** A worktree holds only the committed `_bmad/custom/`, so it is still tiered (from the issue).
- **Accepted trade-off.** Gathering spawns in a framework repository, such as `bmad-deep-recon` researchers and `bmad-build` plan searches, also stay on the session model; `bmad-deep-recon` exposes `subagent_models` for anyone who wants them cheaper (from the issue).

Not recorded in the issue or pull request.
