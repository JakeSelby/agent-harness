## Reproduction

After v0.9.0 was released, make any later change to runtime, primitive, template or configuration source on
a development branch, then run `harness lint`, the projection checks or the unit suite. Each raises
`runtime source changed`, although the catalog is explicitly the released v0.9.0 record. Every post-release
pull request is blocked. [Source: https://github.com/JakeSelby/agent-harness/issues/200]

## Root cause

The v0.9.0 catalog validated every qualified evidence record against the current `HEAD`. That conflated
reading historical release support with qualifying a new source tree: a released catalog has no
current-source claim to make, yet was held to one.
[Source: https://github.com/JakeSelby/agent-harness/issues/200]

## Acceptance criteria

1. **Given** v0.9.0's released catalog, **when** it is validated from a descendant development commit,
   **then** it validates.
2. **Given** changed runtime source, **when** release publication is checked, **then** it is still blocked.
3. **Given** a released catalog whose qualification commit is missing, malformed or unavailable, **when** it
   is validated, **then** it fails closed.
4. **Given** a candidate catalog, **when** it is validated, **then** it stays bound to its current source.
5. **Given** the existing evidence-integrity regressions, **when** the suite runs, **then** they pass.
6. **Given** a post-release feature branch, **when** the gate runs, **then** lint and the full suite pass.

## Design

A released catalog records its immutable qualification source in `qualification_source_commit`.
`lib/harness_core/compatibility.py` validates released evidence against that commit, while candidate
catalogs still validate against the candidate source. It detects whether the checkout differs from the
released source across the runtime-source path set, keeps catalog display and generated release facts
readable when it does, and makes `compatibility --release-check` and release preflight fail until a new
candidate catalog and evidence qualify the changed source.

The fix must not weaken evidence hashes, version and client matching, required cases or native review
requirements, qualify a client, regenerate evidence or change a release version.
[Source: https://github.com/JakeSelby/agent-harness/pull/201]
[Source: lib/harness_core/compatibility.py]
