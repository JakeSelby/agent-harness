## Story

As a developer whose orchestrator spawns subagents without naming a role, I want those spawns routed to
band workers that carry my cost posture's class and effort, so that unnamed work stops inheriting the
session's effort whatever the work is.

## Context and value

The issue records that more than half of all spawns named no role. The spawn call has no effort input,
so such a subagent inherited the session's effort, and the issue calls effort a stronger cost lever
than model tier. An agent definition is the only place effort can be set for a native subagent, so
unnamed work needed definitions to land on.
[Source: https://github.com/JakeSelby/agent-harness/issues/251]

## Acceptance criteria

1. **Given** the three band workers `worker-a`, `worker-b` and `worker-c`, **when** sync runs, **then**
   they install like any other role and inherit every tool except the one that spawns subagents.
2. **Given** tiered delegation with a `default_band`, **when** a spawn names nothing, **then** it is
   routed to that band's worker with the band's model.
3. **Given** no `default_band`, no table, or a non-tiered delegation stance, **when** a spawn names
   nothing, **then** the hook's output is exactly what it was.
4. **Given** a worker definition shipped by a repository, **when** routing runs in that workspace,
   **then** it is never a routing target, and routing turns off there with a notice.
5. **Given** an unnamed spawn asking for the top class, **when** it is routed, **then** it gets the
   band's class.
6. **Given** a routed spawn, **when** usage is recorded, **then** the row records `rerouted` and
   `requested_type`.

## Design

### Approach

`primitives/roles/worker-{a,b,c}.md` and their `claude/agents/` projections define the bands; the cost
sidecar's rows give each its class and effort. `policy/hooks/tier-agent-spawns.py` rewrites an unnamed
spawn to the variant's `default_band` worker, reading the table through `policy/hooks/posture.py`, and
builds the table only for unnamed spawns. Bindings gain an optional `disallowed_tools`.
`policy/hooks/usage-log.py` joins `rerouted` and `requested_type` on the tool-use id.

### Decisions and alternatives

- **Inherit all tools but the spawn tool:** routed work keeps its MCP and other tools, and a worker
  cannot re-delegate.
- **User-level workers only:** a repository-shipped worker definition would outrank the user's, so its
  presence turns routing off for that workspace rather than routing to it.
- **Byte-identical otherwise:** every existing role renders unchanged with `disallowed_tools` absent,
  and the no-band output is held by fixtures.
