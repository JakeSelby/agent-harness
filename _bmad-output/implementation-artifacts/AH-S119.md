## Story

As an orchestrating session, I want to be told once when my context has grown past the posture's
fresh-session threshold, so that I finish the task, write the handoff and start fresh instead of
paying to re-read a large context every turn.

## Context and value

The cost stance already said a task ends with a fresh session rather than compaction, but nothing told
the orchestrator when its own session had become expensive to continue. The turn line reported output
tokens, while a long session's cost is mostly its context re-read every turn. Related: #306.
[Source: https://github.com/JakeSelby/agent-harness/issues/321]

## Acceptance criteria

1. **Given** a `session_nudge_at` list on the cost posture, resolved over `extends`, **when** the
   session's context crosses a threshold on `UserPromptSubmit`, **then** one line names the size, the
   threshold, and the advice to finish, hand off or start fresh.
2. **Given** a crossed threshold, **when** later turns stay above it, including after a resume,
   **then** it is not said again until the next threshold.
3. **Given** a context size that cannot be read, **when** the feed runs, **then** it prints no
   fabricated figure (the issue asked for `unknown`; see Completion notes).
4. **Given** `turn_feed: off`, **when** the feed runs, **then** it injects and writes nothing.
5. **Given** Codex, which raises no `UserPromptSubmit`, **when** its capabilities are read, **then**
   the nudge is declared uncovered.
6. **Given** `docs/usage.md` and lint, **when** read or run, **then** the switch is documented and
   validated against the sidecar schema.

## Design

### Approach

`session_nudge_at` on the cost posture lists context sizes in whole tokens. Context is input plus
cache-read plus cache-creation tokens of the latest turn, the three non-overlapping fields, so the turn
that first caches a large prefix reports its true size. Crossed thresholds are marked in the session
state file. The nudge is soft and never a decision.
[Source: https://github.com/JakeSelby/agent-harness/pull/580]

### Decisions and alternatives

- **Starting sizes:** `frugal` 80k and 120k, `balanced` 120k and 160k, `max` silent, "chosen against
  a 200k window rather than measured"; the doc says so, and the follow-up is to replace them from the
  ledger. This departs from the issue, which said thresholds ship from measured sessions and the
  switch stays empty in every shipped variant until then.
- **After review:** the mark survives a transcript reset and is re-armed when the context shrinks
  below it (an in-place compact); the line names the highest newly crossed threshold; validation
  rejects an unsorted or repeated list; oversized JSON numbers no longer wedge the feed.
- **Landing copy:** folded into the existing feed line, because the `spend-less` group is capped at
  six entries by the release test.

### Do not implement

Any block or deny; the nudge is information only.
