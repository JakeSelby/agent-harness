## Goal

For every acceptance item that a closed issue did not deliver, either track the work in an open issue
or record in the story file that it was waived and why
([#697](https://github.com/JakeSelby/agent-harness/issues/697)). The story enrichment wrote each gap into
its story file; none was filed or waived.

The items, as the issue lists them, with what each story file records:

1. **#137 (AH-S050): the payload preview.** The acceptance asked for "a local payload preview that
   explains exactly which fields would be sent". `harness doctor` shows the allowlist, but neither the
   pull request, `docs/runtime-controls.md` nor `bin/harness` names a preview. The epic keeps it as exit
   criterion 5 [Source: _bmad-output/implementation-artifacts/AH-S050.md#Tasks].
2. **#139 (AH-S052): the unchanged static benchmark.** The issue's re-scope asked to confirm that shadow
   mode leaves `scripts/cost_bench.py static` unchanged; the pull request did not address it
   [Source: _bmad-output/implementation-artifacts/AH-S052.md#Tasks].
3. **#453 (AH-S158): the sixty-second run on a user's own rules.** The issue comment records
   `uvx ruleprobe==0.1.0 report --since 7` printing the six-detector table on a machine with transcripts.
   The record shows no run printing hits for the user's own rules, and does not say the machine had never
   installed agent-harness [Source: _bmad-output/implementation-artifacts/AH-S158.md#Acceptance criteria].
4. **#455 (AH-S160): the lint flag.** "Below-floor flag in `harness lint`, as the issue asked; not
   delivered" [Source: _bmad-output/implementation-artifacts/AH-S160.md#Tasks].
5. **#483 (AH-B053): automatic reattach and the preserved permission mode.** The pull request delivered
   criterion 2, no worktree deleted by the give-up path. It did not automate reattachment (criterion 1),
   and criterion 3, keeping the permission mode and model, "is not addressed in the record". AH-B053 also
   records that "Environment reuse and automatic reconnect came later under #603 (PR #604)"
   [Source: _bmad-output/implementation-artifacts/AH-B053.md]. So criterion 1 may be partly met by later
   work; checking that is part of this item.
6. **#603 (AH-B060): the rule line and the `product.json` change.** The issue's scope listed "Docs, rule
   line, `product.json`". The pull request changed `docs/remote-control.md`, held no rule file, and said no
   `product.json` change was needed because the change fixes documented behaviour and every group is full
   [Source: _bmad-output/implementation-artifacts/AH-B060.md#Design].
7. **#230 and #300 (AH-S100, AH-B025): closed as completed.** #230's closing comment says "Closing as
   superseded" by #468 and #516, and that the primary-phrase acceptance line was not adopted
   [Source: _bmad-output/implementation-artifacts/AH-S100.md]. For #300, a comment on #291 reports that
   "#300 stays partially fixed: the guards are harmless and catch the verbatim case only"
   [Source: _bmad-output/implementation-artifacts/AH-B025.md].

## Acceptance criteria

From the issue's Acceptance section ([#697](https://github.com/JakeSelby/agent-harness/issues/697)):

1. **Given** each of the seven items above, **when** the triage is done, **then** it is either tracked by
   an open issue or recorded as waived, with the reason, in its story file.
2. **Given** an item reopened as a new issue, **when** it is filed, **then** it has a BMad ID and a story
   file, and the original story file points at it.

Criterion 2 follows from FR-9 and the repository's issue rules rather than the issue's text.
