## Story

As the release maintainer, I want a model-free smoke tier that runs before a paid qualification
round, so that deterministic plumbing faults are caught before any model turn is spent.

## Context and value

From the release-cost analysis tracked in #340. Of the defects 0.11.0's first round recorded, the
issue counts three as deterministic plumbing faults such a tier catches: a container holding only
session credentials failing as a 300-second hang, `Home.orchestrator_text()` returning an empty
string and letting `case_cost_posture` pass vacuously, and a pointer to a credential contract file
that did not exist. The fourth was genuine native behaviour. Honesty risk, per the issue: a green tier
must never be read as qualification, so it must never write into `compatibility/evidence/` or appear
in a catalog record.
[Source: https://github.com/JakeSelby/agent-harness/issues/334]
[Source: https://github.com/JakeSelby/agent-harness/issues/340]

## Acceptance criteria

The issue has no acceptance section; these are taken from its mechanism and the PR:
1. **Given** the tier, **when** it runs, **then** it spends no model turn and runs the runner
   self-tests against recorded transcripts, the documentation-link check, the credential-reachability
   probe, and the disposable-home sync, projection-drift and lifecycle checks.
2. **Given** an unauthenticatable environment, **when** a check runs, **then** a timeout makes it an
   error rather than a hang, and a check that could not run is `unverified`, never a pass.
3. **Given** failing output, **when** printed, **then** it is redacted of home paths and secrets.
4. **Given** anything the tier ran, **when** it wrote under `compatibility/evidence/` or into
   `compatibility/catalog.json`, **then** the run fails, checked by digest before and after.
5. **Given** a pull request, **when** CI runs, **then** a `smoke` job runs the tier outside the
   required checks, skipping the credential probe.

## Design

### Approach

`scripts/smoke_tier.py` runs the checks as one command; `lib/harness_core/credentials.py` hardens the
credential probe; hand-authored transcript fixtures with placeholder ids back the runner self-tests.
[Source: https://github.com/JakeSelby/agent-harness/pull/581]

### Decisions and alternatives

- **Advisory, not required:** the CI job is deliberately absent from the ruleset's required checks,
  and `docs/releasing.md` said it was advisory until the owner decided whether a red tier may block a
  freeze.
- **Amended 2026-09-26, decided by the owner under
  [#688](https://github.com/JakeSelby/agent-harness/issues/688) (AH-D011, option 3):** a red tier
  blocks the qualification round, in the round runner. `scripts/qualification_round.py` stops before
  any target runs when the tier fails or times out and records why in `round.json`; `--skip-smoke`
  keeps its meaning and is recorded as `skipped`. The CI job stays outside the required checks.
- `--skip` rather than an enumerated `--only` in CI; the lifecycle check reports `unverified` on a
  dirty tree rather than failing.
- The vacuous-pass defect was already fixed by #402.
- **After review:** output is redacted before it is cut; the credential probe never includes an
  environment value in a message; `git status` is bounded; process groups are killed on timeout; an
  empty selection exits non-zero; the digest guard is proven on a catalog write.

### Do not implement

Any write to evidence or the catalog; any claim of qualification.

- FR-52: One qualification round per release — a release passes a model-free smoke tier before any
  native case runs.
- AD-4: Evidence-backed compatibility — a model-free smoke tier runs before any native case.

PR ships the tier as advisory pending an owner decision. Recorded as a discrepancy between the PRD
and the delivered state; resolved by #688, which makes the round runner stop on a red tier, so the
