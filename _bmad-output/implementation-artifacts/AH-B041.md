## Reproduction

1. Select `voice=off` or `voice=answer-card`.
2. Run `harness sync`.

Observed, per the issue: Claude Code's settings receive `outputStyle: "Scannable"` whatever the `voice`
stance says, so a session running `voice=answer-card` has the Scannable output style active. The Codex
projection appends the scannable presentation only under `voice=scannable`, so the same configuration
produces different behaviour per runtime. Found while assessing #116; related to #117.
[Source: https://github.com/JakeSelby/agent-harness/issues/394]

## Root cause

`merge_claude_settings` in `bin/harness` copied every key listed in `claude/OWNERSHIP.json` from the
template unconditionally. `outputStyle` was one of those owned keys, and `claude/settings.template.json`
hard-coded `"outputStyle": "Scannable"`. The Codex projection was conditional on
`stances["voice"].stem == "scannable"`.

## Acceptance criteria

1. **Given** each `voice` variant, **when** `harness sync` runs, **then** it produces the matching
   `outputStyle`, and none under `off`.
2. **Given** a pre-existing user-chosen `outputStyle`, **when** sync runs at `voice=off`, **then** the
   user's style survives.
3. **Given** each variant, **when** the Claude and Codex projections are compared, **then** they agree on
   what the variant means.

## Design

### Approach

The style comes from the selected variant: `scannable` installs `Scannable`; `answer-card` and `off` install
none. `voice_output_style()` reads the style name from the style file, and `installed_output_style()` reads
the reconciliation journal. Ownership of `outputStyle` in `merge_claude_settings`, `strip_claude_settings`,
`claude_projection` and `cmd_sync` is conditional. The hard-coded style is removed from
`claude/settings.template.json`.

### Decisions and alternatives

- **Remove only what the journal says the harness installed:** a style the user chose, even one with the
  same name as the harness's, is never overwritten or stripped.
- **No `product.json` change:** the voice stance was already a listed capability; this makes the Claude
  side honour it as the Codex side already did.
