## Goal

Make a cost-replay regression diagnosable from the ledger alone. The issue records that diagnosing a
cost regression in the replay benchmark needed six facts the ledger did not carry; every one was already
in the raw CLI JSON the runner captures under `--raw`, so it was reverse-engineered from transcripts by
hand, twice, with two wrong calls along the way. Without the fields, the ledger records outcomes but not
mechanisms, and a one-change-at-a-time programme cannot say which change did what.
[Source: https://github.com/JakeSelby/agent-harness/issues/480]

## Acceptance criteria

1. **Given** recorded CLI output, **when** a row is derived, **then** each new field
   (`first_call_cache_write`, `tool_counts`, `spawns`, `arm_config_dir`, `arm_fingerprint`,
   `hook_blocks`, `change_note`) has a test, and `hook_blocks` is `None` on a stream with no hook
   decisions.
2. **Given** a history row, **when** `history.md` is rendered, **then** it includes per-task ratios with
   a max/min spread per cell and contains no em dash.
3. **Given** a results set on disk, **when** `backfill` runs, **then** it writes
   `results.enriched.jsonl` and leaves the original untouched unless `--in-place` is passed.
4. **Given** the change, **when** existing rows are read, **then** existing field meanings, the upsert
   key and the series hash are unchanged.
5. **Given** the change, **when** the gate runs, **then** lint is clean and the unit suite is green under
   both `python3` and `/usr/bin/python3`.

## Dev notes

- **Design, from the issue and PR.**
  - `first_call_cache_write` is the standing-prefix size, distinct from the existing total across
    calls; the issue calls it the only direct proof a context change landed.
  - `tool_counts` and `spawns` count every `tool_use` block by tool name.
  - `arm_config_dir` and `arm_fingerprint` record which profile the arm loaded and a size-only hash of its
    always-loaded surface. Sizes, never contents, so no path enters a row.
  - `hook_blocks` is never approximated from text.
  - Per-task spread was added because the set aggregate hid every real insight, and means without spread
    mislead at the within-cell variance observed.
  - Backfilled fingerprints carry `fingerprint_source: backfill`.
- **Bound requirements and decisions:** FR-56 (Live replay against a bare arm): every row reports its
  counter-figures beside the ratio, including turns and tool calls. AD-12 (Measurement invariants): every
  row records the provenance of its arm.
- **Files touched:** `scripts/cost_bench.py`, `tests/test_cost_bench.py`, the issue map and this story file.
- **Testing:** thirteen tests added to `tests/test_cost_bench.py`, among them
  `test_the_first_call_cache_write_is_the_standing_prefix_not_the_run_total`,
  `test_every_tool_use_block_is_counted_and_spawns_are_the_subagent_share`,
  `test_hook_blocks_is_none_because_this_output_format_carries_no_hook_decision`,
  `test_the_history_row_breaks_the_aggregate_down_by_task_with_each_cell_s_spread`,
  `test_backfill_enriches_a_copy_and_leaves_the_original_alone` and
  `test_a_missing_results_file_is_refused`.
