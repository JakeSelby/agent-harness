## Story

As a harness maintainer, I want each subagent return measured for whether it named a resolvable path and
stayed under its cap, so that the transcript-hygiene rule's cheapest property is checked deterministically
and produces labelled input for a later model judgment.

## Context and value

`primitives/rules/transcript-hygiene.md` requires a subagent's detail to go to a file and the verdict plus
the path to come back. `brief-guard` writes the return bound into the brief (#72), and #157 will judge
whether a return supplies the requested result type. Neither checked whether the return referenced a file
or stayed under its cap: the issue records that a return inlining a 3,000-word digest satisfied every check
the harness had. Related: #72, #157, #322, #370.
[Source: https://github.com/JakeSelby/agent-harness/issues/416]

## Acceptance criteria

1. **Given** a path in a fenced block, in inline backticks, or bare in prose, **when** the return is measured,
   **then** it counts; **given** a path that resolves outside the worktree and the scratchpad, **then** it
   does not.
2. **Given** a return with no path, **when** it is recorded, **then** it carries none and is not a failure.
3. **Given** `turn_feed: off`, **when** a subagent stops, **then** nothing is written. (Not applicable as
   built; see Decisions.)
4. **Given** the unit tests, **when** they run, **then** they cover each path form, an unresolvable path, an
   over-budget return, and a row whose runtime declares the field uncovered.
5. **Given** Codex, which raises no `SubagentStop`, **when** its capabilities file is read, **then** it names
   the gap.

## Design

### Approach

Subagent ledger rows carry `return_path` (`resolvable`, `unresolvable` or `none`) and `return_over_budget`,
joined to the parent `Agent` call on the `tool_use_id` the reroute marking already uses, over the
tool-result text the event list already keeps. There is no second read of the transcript and no brief or
return text in any row. `harness usage --by role` reports `path` (the share of returns that named a path
and resolved it) and `over` (the share over budget among measured runs, `-` when none).

### Decisions and alternatives

- **Measured in the SessionEnd usage scan, not on `SubagentStop`:** the issue asked for `SubagentStop`, but
  the row it names and the `--by role` acceptance belong to the SessionEnd scan, so the measurement lives
  there and is rescannable. The usage feed is untouched, so the PR records the `turn_feed: off` criterion as
  not applying.
- **Path shape:** a path in a fence or backticks is taken at its word; a bare token counts only with a
  path's shape (a root of `/`, `./`, `../` or `~/`, or a file extension on its last segment), so `pass/fail`,
  dates and URLs are prose. Resolution is taken when the row is written.
- **"The scratchpad" is the temp directory:** the PR records that the scratchpad has no definition in code.
- **The cap** is the one the rule detectors read from the brief, else the 400-word default `brief-guard`
  appends; an agent in the capped set with no stated cap is left `null`.
- **Truncated scans:** a tool result the scan truncated at 64 KB records `return_measured: "truncated"` with
  both fields null.
- **No `product.json` change:** measurement plumbing on an existing ledger and report.

### Do not implement

- Denying, truncating or rewriting a return.
- Model judgment of return quality (#157).
