## Story

As a visitor reading the README, the landing site or GitHub About, I want the landing copy to say what
the harness does for me, from one validated source, so that the three surfaces agree and sell the
harness rather than read as reference.

## Context and value

The issue records that the public overview read as reference rather than selling what the harness
does. The PR adds that the README's first screen led with which clients are unqualified. Holding the
copy as data lets the site, the README and GitHub About share one source.
[Source: https://github.com/JakeSelby/agent-harness/issues/318]
[Source: https://github.com/JakeSelby/agent-harness/pull/326]

## Acceptance criteria

1. **Given** `product.json`, **when** it is validated, **then** it carries `hero`, `capabilities` and
   `on_the_way`, and each capability group has a title, a one-sentence pitch and features of `name`,
   `line` and `doc`.
2. **Given** every feature, **when** it is tested, **then** its `doc` path exists in the repository.
3. **Given** the groups and features, **when** counted, **then** they stay in range.
4. **Given** every `on_the_way` entry, **when** tested, **then** it names an issue or a `planned`
   catalog client.
5. **Given** every string in `product.json`, **when** tested, **then** none carries an em dash.
6. **Given** the README feature section and `product.json`, **when** they disagree, **then** a test
   fails.

## Design

### Approach

Add `hero`, `capabilities` and `on_the_way` to `product.json`, and rebuild the README's first screen:
headline, a terminal capture, the description, then the six capability groups, one linked line per
feature. The release-status paragraph and the generated compatibility block move below the install
section under `## Release status`, markers untouched.

### Decisions and alternatives

- **Hero:** the existing headline, "Your way of working, across AI agents." A cost-led hero waits for
  a measured before-and-after figure. `headline` and `github_description` are unchanged, so GitHub
  About does not drift.
- **Visual:** real output of `bin/harness sync --dry-run` against a throwaway home, path shortened to
  `~`, as an SVG with no embedded font or third-party asset. The dry run was chosen over
  `harness stances`, which prints about a hundred lines of prose.
- **`description`:** one character changed (an em dash to a comma), because the new test forbids
  U+2014 in every string.
- **Schema:** one catalog id per entry, so "Grok and Cursor adapters" carries `catalog: "grok"` only.
- **Voice:** two pitch lines are first person on purpose, as product copy approved as written.

### Do not implement

Trimming the older README sections; `tests/test_docs.py` asserts them, and trimming is a separate
change.
