## Story

As a harness maintainer, I want the v1.0 release plan to carry the evaluation gate, so that 1.0 ships only when `harness evidence verify` re-derives the proof set and every selected module has a scorecard row.

## Context and value

PRD §9.1 now makes an evaluation gate part of the v1.0.0 contract: before 1.0 ships, `harness evidence verify` re-derives the proof set, and every selected module has a scorecard row, measured or marked unmeasured. `v1-release-plan.md` does not carry the gate yet.

Depends on #799 and #207. Traces to PRD §9.1.

## Acceptance criteria

1. Given `v1-release-plan.md`, then it states the gate and its two checks.
2. Given a 1.0 candidate, when release preflight runs, then it fails if the proof bundle does not verify, or if a module in the default selection has no scorecard row.
3. Given #207's frozen contract, then it includes the gate.
