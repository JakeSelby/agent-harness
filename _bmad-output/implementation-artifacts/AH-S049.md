## Story

As a harness developer, I want a Jev decision provider behind the shared `decide`, `record` and `learn`
contract, so that a remote semantic judgment can be consulted at a decision point without a
provider-specific hook in each runtime and without ever weakening the deterministic answer.

## Context and value

The harness had deterministic policies and no shared interface for optional semantic judgments; a
provider-specific hook per runtime would duplicate behaviour. The contract itself landed first in #486
(AH-S172, split out of this issue), so this story became the Jev client as a client of that contract.
The 2026-09-21 re-scope corrected the contract against the live API: there is no abstention outcome,
a yes/no answer carries a probability with no confidence field, a Score takes 2 to 10 ordered levels,
and answers are not deterministic across identical requests. This is the first link in the epic's
critical path.
[Source: https://github.com/JakeSelby/agent-harness/issues/136]

## Acceptance criteria

1. **Given** a response that is malformed, incomplete or carries an unrequested field, **when** the
   client parses it, **then** it is an error and never a judgment with the bad parts dropped.
2. **Given** a question pack, **when** it is validated before sending, **then** a `choice` question
   without an explicit `unknown` option is refused and a `score` takes an ordered array of 2 to 10
   levels.
3. **Given** a request, **when** it is built, **then** it is bounded at 64k tokens and its state plus
   the longest question at 32k, and a request and token budget is checked before the call and charged
   after it, whether or not a parsable response arrives.
4. **Given** any path with no usable answer (no key, timeout, exhausted budget, unparseable body,
   unexpected exception), **when** `decide` runs, **then** it returns the deterministic provider's
   decision unchanged with the reason in `rule_matches`.
5. **Given** a usable answer, **when** `JevProvider` applies it, **then** it may tighten an `allow`
   into an `ask`, capped at level 2, and never widens or denies.
6. **Given** a call, **when** it completes, **then** one ledger event records the status, requested and
   returned model ids, pack and request hashes, usage and latency, and never the state.
7. **Given** the repository's Python 3.9 floor, **when** the client is installed, **then** it uses the
   standard library only and adds no SDK.
8. **Given** the test suite, **when** it runs, **then** no path touches the network, and the client is
   inert unless constructed with `live=True`.

## Design

### Approach

`lib/harness_core/decisions/jev.py` implements the landed contract over `urllib`. Pack validation runs
before anything is sent. `decide` computes the base (`local`) decision first, then runs every later
step under one fail-open guard. The outbound state is a fixed two-field shape until #137 adds the
configurable allowlist. `lib/harness_core/decision.py` gains a lazy provider lookup keyed on
`governance.provider`; nothing consults the provider by default.

### Decisions and alternatives

- **Standard library over the vendor SDK:** the SDK needs Python 3.10 and five packages; the floor is
  3.9.
- **Explicit `unknown` required in every Choice pack:** the service has no abstention outcome, so a
  pack without one leaves the model no way to decline except by guessing. `unknown` and low confidence
  both mean "use the deterministic answer".
- **Tighten-only:** `confirm` turns `allow` into `ask`; the provider never widens and never denies.
- **No determinism promise:** only that the same request hashes the same.
- **After review:** a supplied pack must carry the `judgment` and `severity` questions `decide` reads;
  the client refuses a non-https endpoint and its opener handles `https` only; `harness decide`
  suppresses the ledger event so it still changes nothing.

### Do not implement

- Other live providers; the interface stays extensible without building them.
- Automatic paid-provider fallback or model upgrade.
- Opt-in configuration, per-point modes and the sentinel file (#137).
