# AH-D004 — Decide whether repeated agent pairs get an amortized return schema, and whether fan-outs get a shared workspace

## Context

Two inter-agent context-reduction patterns were absent from the harness, and the issue records the decision
and the condition that reopens it rather than leaving them unfiled. The harness already fixes a return shape
per role in its rendered agent definitions, and `worktree-per-agent` and the handoff file already cover
shared state for sequential work. The open gaps were a machine-checkable return schema per role, instead of
prose in a brief, and parallel fan-out, where each worker's return crosses the orchestrator's context whole.
[Source: https://github.com/JakeSelby/agent-harness/issues/417]

## Options

1. **Option A: an amortized return schema per repeated agent pair.** The issue describes a published pattern
   that negotiates a protocol document once, references it thereafter by content hash, and compiles it into
   a deterministic routine, and records that pattern's reported cut in communication cost. For: a
   machine-checkable schema per role. Against: the negotiation half is unnecessary here, because role
   definitions already fix a return shape; it costs a schema registry and a validation path.
2. **Option B: a shared workspace instead of broadcast.** A blackboard a fan-out reads from, rather than every
   message crossing every context. For: it addresses parallel fan-out. Against: a large change to delegation
   with no measured problem behind it.
3. **Decline both for this release** (the issue's recommendation).

## Decision

Recorded on the issue, 2026-09-22: "both options declined, as recommended." The issue was closed as not
planned.

The reopen condition, stated in numbers as the done-when required, from the same comment: in the first live
replay (harness 0.11.1 at `0fcfe25`, 16 runs) no run in either arm delegated to a subagent, so subagent
returns were 0% of orchestrator context and neither option had a problem to solve. Reopen Option A if the
second replay set, which #431 sizes to exercise delegation, shows subagent returns at 10% or more of the
harness arm's orchestrator input tokens. Option B stays declined unless fan-out returns alone exceed that
share.

## Consequences

- No schema registry, return validation path or shared fan-out workspace is built.
- Return shape stays fixed per role in the rendered agent definitions.
- The reopen decision depends on the second replay set (#431) measuring subagent returns as a share of the
  harness arm's orchestrator input tokens. Not recorded in the issue or pull request: whether that set has
  reported.
- Delivery: no pull request; the decision is the issue comment. Milestone v0.12.0.
- Bound requirements: none claimed. The issue predates the PRD and cites no FR or AD.
