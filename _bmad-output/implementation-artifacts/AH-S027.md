## Story

As a developer who uses both Claude Code and Codex, I want every primitive authored once in a neutral
source and rendered into each runtime's native form, with custom stances and overrides I can define and
switch, so that one edit changes both runtimes and my preferences are not tied to one vendor's syntax.

## Context and value

A work package of epic #93 and, per the issue, the first one, with no dependencies. The problem it records:
shared policy was authored under `claude/`, and roles and workflows mixed intent with Claude model IDs and
tool syntax, so a second runtime could only be served by a copy.
[Source: https://github.com/JakeSelby/agent-harness/issues/94]

## Acceptance criteria

1. **Given** a primitive, **when** it is edited once, **then** both the Claude Code and Codex projections
   update.
2. **Given** a custom stance, **when** it is authored, switched or overridden, **then** the behaviour is
   covered by tests, and an invalid selection is refused.
3. **Given** every existing primitive, **when** the migration completes, **then** each has an explicit
   disposition.
4. **Given** the catalog, **when** it is inspected, **then** it holds no duplicate vendor stance or skill
   catalog.

## Design

### Approach

Move authority to neutral primitive sources and define contracts for the resolved policy, roles,
workflows and capabilities; implement Claude Code and Codex renderers. Keep one procedure per skill.
Support custom stance dimensions and variants, central selections, project and session overrides,
precedence, conflict validation and effective-selection output. Model and provider IDs live in the
runtime bindings, and native restrictions remain the execution ceiling.
[Source: https://github.com/JakeSelby/agent-harness/issues/94]

Delivered through three slices:
- AH-S067 / #163 (PR #101): the shared primitive catalog, bindings and custom stances.
- AH-S072 / #168 (PR #106): session and project choices kept out of global projections.
- AH-S075 / #171 (PR #109): plan storage aligned and native guidance labelled.

### Decisions and alternatives

- **Model and provider IDs in runtime bindings, not in primitives.**
- **Native restrictions are the ceiling:** the harness does not claim to exceed what a runtime enforces.
- Alternatives considered are not recorded in the issue.

### Do not implement

- A Cursor or Grok adapter, hosted-agent support, a native memory merge or UML viewer work.
- Anything that splits the primitives, loses user configuration or overstates support.
