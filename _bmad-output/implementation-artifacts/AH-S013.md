## Story

As an orchestrator running `/plan`, I want a `planner` agent that carries the Review Card contract, so that plan writing moves to a fresh context while the orchestrator keeps its own context for the review conversation, and a malformed card is prevented rather than caught afterwards.

## Context and value

The issue records that `plan-authoring` warned that a subagent writing a plan never loads the user's rules, and told the orchestrator to paste the template into the prompt: a brief rebuilt every time. The validator hook caught a bad card after the fact; an agent body carrying the contract prevents it.

## Acceptance criteria

1. **Given** the `planner` agent, **when** its definition is read, **then** it runs on the session model at high effort and its body carries the Review Card contract: the section order and caps, the 70-line card, no tables, no Context section, the addendum anchors, and the self-check.
2. **Given** a plan request, **when** the planner finishes, **then** it returns the exact chat message the contract specifies, ending at the build gate.
3. **Given** `plan-authoring`'s Delegating section and `/plan`, **when** they are read, **then** they name `planner` instead of asking the orchestrator to paste the template.

## Design

### Approach

A new `claude/agents/planner.md`; `claude/commands/plan.md` and `claude/skills/plan-authoring/SKILL.md` point at it.

### Decisions and alternatives

- **Scoped write access.** The issue asked for read-only tools; the pull request gives the planner read-only tools plus `Write` scoped to `.claude/plans/`, so it can write the plan file. The record gives no further reason.

### Do not implement

Not recorded in the issue or pull request.

### Later change

At `origin/main` the planner is a constrained role run as an isolated worker: it returns content, and the harness validates it and publishes it to a new path (FR-40, AD-8). The scoped `Write` described here is the v0.2.0 design only.
