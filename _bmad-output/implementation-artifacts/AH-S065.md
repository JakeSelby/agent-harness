## Story

As a developer resuming from a handoff, I want a bounded check for direct contradictions between a
handoff's completion status, outstanding items, blockers and next step, so that a self-contradicting
handoff is flagged before someone acts on it. Closed as not planned on 2026-09-21; this file records the proposal as history.

## Context and value

A handoff can contradict itself about completed work, outstanding work, or the next action. The issue
proposed a self-contained experiment, called its effectiveness on this workload unverified, and said it
was neither a first-release dependency nor an implementation authorization. It was one of seven
additional bounded experiments (#156 to #162); the 2026-09-21 epic re-scope closed it with the other
prose-level checks, because nothing consumed those answers and nothing could score them.
[Source: https://github.com/JakeSelby/agent-harness/issues/161]
[Source: https://github.com/JakeSelby/agent-harness/issues/135]

## Acceptance criteria

As proposed, not delivered:
1. **Given** the shared provider and versioned pack contracts, **when** an input is judged, **then**
   each criterion returns a typed decision with explicit abstention and unavailable handling.
2. **Given** a pack's declared input limit, **when** an input is oversized or missing, **then** it stays
   unverified rather than being silently truncated, and no transcript or repository is uploaded.
3. **Given** formatting, counts and schema, **when** they are checked, **then** deterministic code
   checks them.
4. **Given** fixtures of superficially similar but compatible statements (implementation complete with
   tests pending, several distinct tasks, a next step that resolves a stated blocker), **when** they are
   judged, **then** they are not flagged as contradictions.
5. **Given** labels fixed before evaluation and a held-out split, **when** the pack is evaluated,
   **then** misses, false alarms, abstentions, errors, latency and available cost are reported, and
   ordinary tests stay offline with live tests opt-in and budgeted.
6. **Given** public or synthetic fixtures first and #137's outbound controls, **when** the provider
   fails, **then** current behaviour is preserved, and no enforcement is on by default before
   workload-specific validation.

## Design

### Approach

Input is one short handoff with named sections, without the originating session history. The pack checks
for direct internal contradictions and returns section IDs from a supplied set where useful.

### Decisions and alternatives

- **Closed as not planned (2026-09-21)** in the epic re-scope.
- Dependencies as proposed: #136, #137 and #138, with #140 only for later automatic runtime delivery.

### Do not implement

Certifying completeness, accuracy against the actual work, command safety, or readiness to resume. It
was to stay advisory and lower priority pending measured usefulness. No generic quality score, inferred
permissions, model training or live configuration changes; publishing the provider's performance results
stays subject to its terms.
