## Goal

Make agent-harness a general-purpose, model-provider-agnostic harness built around the user: rules,
skills, roles and workflows are authored once as shared primitives, personal stances are switchable, and
native adapters carry that meaning into Claude Code and Codex. Completion is observable as a published
release whose support claims rest on native evidence for each client and platform it names.

The closing comment on #93 (2026-09-19) records that v0.9.0 completed the epic's release scope, with all
seven required Claude Code and Codex client-platform combinations qualified.

## Scope and requirement coverage

**In scope**, from the issue's Outcome, Design and Release contract sections:

- A shared primitive authority and a resolved-policy contract, with thin runtime adapters.
- Safe configuration ownership, reversible migration and neutral task state.
- BMad bindings, and task continuation across Claude Code and Codex.
- Runtime policy enforcement, isolated role workers, gates and observability.
- A versioned compatibility catalog backed by native evidence, and repositioned product messaging.
- A coordinated release: the immutable tag, the reference site, the personal-site card and GitHub About.

**Out of scope**, as the issue deferred it: Cursor and Grok integrations, hosted agents, native memory
merging and the UML viewer. The release contract also forbids weakening a required guard to manufacture
parity.

**Requirement coverage.** `epics.md` lists this epic against FR-1, FR-3 to FR-8 and FR-10 to FR-12. Checked
against the 2026-09-23 PRD, each of these carries a status of implemented at 0.9 or earlier:

- FR-1 One provider-neutral catalog, FR-3 Native projections without claimed parity, FR-10 Extensible
  without a second authority: the shared primitive authority (#94).
- FR-4 Preview before apply, FR-5 Ownership journal: installation and reversible ownership (#95).
- FR-6 Diagnostics, FR-7 Evidence-backed compatibility, FR-12 Release integrity: native qualification and
  the catalog (#98), and coordinated publication (#100).
- FR-8 Task continuity: neutral task state and handoff invalidation (#97).
- FR-11 Local-first observability: the observability part of #96.

FR-12 remains partial in the PRD (the release floor and a waiver field are later work), and that remainder
belongs to AH-E005 and AH-E014, not to this epic.

The PRD's coverage table also places FR-40 to FR-44 and FR-68 (roles, role workers and the delivery loop)
under this epic, although the epic's own Covers line does not list them. The isolated role workers of
#177 fall under FR-40 Isolated role workers, which the PRD marks implemented at 0.9.

## Architecture slice

ADs of the 2026-09-23 spine whose text covers what this epic delivered:

- **AD-1 Shared primitive authority:** author shared meaning once; adapters translate but never redefine;
  a missing capability is declared in `capabilities.json`, never emulated.
- **AD-3 Reversible configuration ownership:** edit only declared fields, record prior and applied values,
  restore only while the current value still matches.
- **AD-4 Evidence-backed compatibility:** every supported target references passing native evidence for
  the exact source revision; a contradictory active failure blocks the claim (the #132 fix).
- **AD-8 Constrained roles run only as isolated role workers:** the isolated CLI worker design approved in
  the issue and delivered in PR #115, merged 2026-09-19.
- **AD-20 Continuity never moves authority:** task state is neutral and non-authoritative, and a changed
  shared plan invalidates prior verification (PR #113, merged 2026-09-19).

AD-2 One resolver and AD-11 Local ledgers describe later refinements of the resolver and the ledgers; this
epic's record does not describe their current rules, so they are not bound here.
