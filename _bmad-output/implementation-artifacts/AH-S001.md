## Story

As a developer running an agent in a repository with a quality gate, I want a `Stop` hook that runs that gate and refuses to let the agent finish while it is red, so that "run the gates before claiming done" is enforced by a machine check rather than by prose the model can skip.

## Context and value

The issue records that `claude/rules/verification.md` told the agent to run the gates locally before opening a pull request, but nothing enforced it, and `claude/settings.template.json` registered no `Stop`, `SubagentStop` or `UserPromptSubmit` hook. The issue cites Anthropic's best-practices page, Superpowers' `verification-before-completion`, compound-engineering and PAI as treating a machine-checked verification loop as the highest-leverage harness component. It asked for the block to be bounded (Anthropic's reference uses eight) so a broken gate cannot trap a session.

## Acceptance criteria

1. **Given** a repository whose `AGENTS.md` has no gate block, **when** the agent stops, **then** the hook does nothing.
2. **Given** a `## Gate` fenced block in `AGENTS.md`, or in `CLAUDE.md` when `AGENTS.md` is absent, **when** a gate command fails, **then** the turn is blocked and the reason names the failing command and its last 30 lines.
3. **Given** a green gate, **when** the tree has not changed since that run, **then** the commands are not run again.
4. **Given** eight consecutive blocks, **when** the agent stops again, **then** the turn is released with a note on stderr saying why.
5. **Given** a new session, **when** the hook runs, **then** the block count starts again.
6. **Given** a timeout, an error or malformed input, **when** the hook runs, **then** it releases the turn rather than trapping it.
7. **Given** the repository template and this repository's own `AGENTS.md`, **when** they are read, **then** each carries a `## Gate` section, and the hook is registered in `claude/OWNERSHIP.json`.

## Design

### Approach

A new `claude/hooks/stop-gate.py` reads the fenced block under a `## Gate` heading in the repository's `AGENTS.md` (falling back to `CLAUDE.md`). Repositories opt in by adding the section; the `## Commands` block is never run. The hook keys a green result to HEAD, status and a diff hash, and skips the commands when they match the last green run. It stores its state under the user's XDG state directory (`~/.local/state/agent-harness/stop-gate/`), resets the block count on a new session, and releases after eight consecutive blocks.

### Decisions and alternatives

- **Opt-in by heading.** The gate is a dedicated `## Gate` section, not the general `## Commands` block, so a repository chooses exactly what runs.
- **Bounded blocking.** `MAX_BLOCKS = 8`, following the reference the issue cites.
- **Fail open.** As delivered, a timeout or any error released the turn. The PRD's FR-36 now requires that "a timeout or an error never yields a clean result", and the hook at `origin/main` releases a timeout as unverified and blocks on an unexpected error; that change came from later work, not this story.

### Do not implement

Not recorded in the issue or pull request.
