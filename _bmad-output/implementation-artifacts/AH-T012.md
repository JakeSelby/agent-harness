## Goal

Re-derive the epic map from the re-baselined PRD, UX specification and spine, reconciled onto the existing
BMad IDs, so that every open issue belongs to an epic, has a BMad ID, and sits under a parent GitHub shows.
Also file the follow-ups that the PRD and spine reviews named, and the story-enrichment batches.

## Acceptance criteria

1. **Given** the open issues, **when** the map is regenerated, **then** every open issue has a BMad ID and
   a parent epic. The only exception is the backlog that the held reservation pull request (#529) owns,
   and the map lists it by number.
2. **Given** `audit`, **when** it runs on the branch, **then** it reports no findings.
3. **Given** the PRD, **when** a reader opens `epics.md`, **then** each requirement group names the epics
   that cover it.
4. **Given** the review findings the PRD and spine recorded as follow-ups, **when** the map is done,
   **then** each one is an issue under an epic.

- **Existing epics keep their IDs.** Closed work that has no epic is not given a parent retroactively.
  `epics.md` lists it by issue range, the same way the batches take it.
- **#529's backlog is left alone.** Reserving those issues here would collide with a held pull request, so
  they join the map when #529 merges.
- **After merge,** run `plan` and then `apply` from `main`, so that Planning blocks and parents reach the
  new issues on GitHub.
