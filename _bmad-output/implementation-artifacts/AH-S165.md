## Story

As a reader of the compatibility claims, I want the client-level and capability-level qualification
states to agree, so that the repository's honesty-based positioning does not ship over two
contradictory authorities.

## Context and value

`compatibility/catalog.json` marked four clients qualified while `adapters/*/capabilities.json` marked
every stance and `role_execution` unqualified, and both shipped as authorities. The positioning epic
(#444) required this contradiction reconciled before any repositioned copy shipped.
[Source: https://github.com/JakeSelby/agent-harness/issues/460]
[Source: https://github.com/JakeSelby/agent-harness/issues/444]

## Acceptance criteria

1. **Given** `docs/compatibility.md`, **when** a reader reads it, **then** it states what qualified
   means at the client level and at the capability level: a capability is qualified only when its
   client is qualified and a native acceptance case exercising it exists and passed.
2. **Given** `harness compatibility --json`, **when** it runs, **then** every client row carries
   per-capability states derived from the adapters' capability files.
3. **Given** the generated compatibility region in `docs/compatibility.md` and the README, **when** it
   renders, **then** it shows the per-capability states beside each client.
4. **Given** the two files disagreeing again, **when** the tests or release preflight run, **then**
   they fail.
5. **Given** the change, **when** it lands, **then** no qualification state changes.

## Design

### Approach

`lib/harness_core/compatibility.py` derives per-capability states from the adapters and attaches them
to each client row; `lib/harness_core/catalog.py` and `bin/harness` expose them through
`harness compatibility`. The generated region renders them, on the model of wshobson/agents'
generated capability matrix, which is credited.
[Source: https://github.com/JakeSelby/agent-harness/pull/472]

### Decisions and alternatives

- **The catalog is the single authority;** per-capability state is derived, never hand-edited twice.
- **A reconciliation error fails release preflight,** not only the unit tests.
[Source: https://github.com/JakeSelby/agent-harness/pull/472]

### Do not implement

- Changing any qualification state. [Source: https://github.com/JakeSelby/agent-harness/pull/472]
