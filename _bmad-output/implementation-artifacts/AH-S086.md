## Story

As a user choosing a client, I want Codex CLI on macOS and Linux qualified by native evidence against the
frozen 0.9.0 source, so that the compatibility catalog can claim Codex CLI support for 0.9.0 and back the
claim with records I can check.

## Context and value

A child of #98 under epic #93. The issue records the problem: the 0.9.0 catalog could not claim Codex CLI
support until the exact macOS and Linux clients passed every required native case against the frozen
release source, and generated projections and unit tests are not sufficient evidence.
[Source: https://github.com/JakeSelby/agent-harness/issues/185]

## Acceptance criteria

1. **Given** both Codex CLI tuples, **when** qualification completes, **then** every required case is
   `passed`.
2. **Given** a built-in stance switch, **when** it is applied, **then** projected instructions and observable
   worker behaviour change.
3. **Given** native role probes, **when** they run, **then** a read is allowed and out-of-scope writes are
   denied.
4. **Given** the evidence, **when** it is published, **then** it contains no credentials or private paths.
5. **Given** the catalog, **when** it is validated, **then** its hashes match the evidence bytes.
6. **Given** the change, **when** the gate runs, **then** lint, the full suite, generation checks and an
   independent evidence review pass.

## Design

### Approach

Record redacted native evidence for Codex CLI on macOS and Linux covering built-in and custom stance
behaviour, permission postures, hook composition, constrained roles, gate invalidation, BMad review, task
continuation and the installation lifecycle. Link each record by SHA-256 from the versioned catalog, then
regenerate the public support summaries. [Source: https://github.com/JakeSelby/agent-harness/issues/185]
The CI checkout was changed to fetch full history (`fetch-depth: 0`).
[Source: https://github.com/JakeSelby/agent-harness/commit/c9d9067]

### Decisions and alternatives

- **Exact client versions per tuple:** macOS `0.155.0-alpha.9` and Linux `0.155.1` were qualified, per the
  PR.
- Alternatives considered are not recorded in the issue or pull request.

### Do not implement

- Qualification of Claude Code or the Codex GUI clients (#187, #188). [ASSUMPTION: the issue does not name this sibling; the link is drawn from the issue map and epic.]
