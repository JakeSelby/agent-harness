## Story

As the maintainer running a qualification round, I want the acceptance runner's disposable
`CODEX_HOME` to use the Codex session login when I ask for it, so that a Codex target can be driven by
`scripts/native_acceptance.py` rather than by hand.

## Context and value

The issue says #408 records that every Codex round so far used the ChatGPT-session login that
`codex login` writes to `~/.codex/auth.json`. `docs/compatibility.md` and
`docs/qualification-runbook.md` ("Before a run", step 2) describe that login at `origin/main`.

The runner's disposable home never receives that file. So the credential probe can prove the login
exists, but the runner cannot use it, and the Codex targets stay hand-qualified. The issue says the next
verification round needs this to script the Codex cases #336 committed.

At `origin/main`:

- `adapters/codex/worker.py` `prepare` symlinks `auth.json` from the caller's `CODEX_HOME`, or
  `~/.codex`, into each role worker's disposable Codex home;
- `scripts/native_acceptance.py` sets `CODEX_HOME` to the run's own client directory and passes through
  only the variables in `AUTH_PASSTHROUGH`, which are Anthropic and cloud settings. Nothing gives that
  home a Codex login;
- its Codex surface says "no round has been run through it", and keeps every verdict `unverified`
  until `--home-confirmed` records that an operator compared one against a hand run.

PR #651, which opened the 0.13.0 candidate, says `codex-cli-linux` "ships as a stated limitation until
#612 lets the acceptance runner drive it". The issue's own scope names the owner's Mac. [ASSUMPTION: the
two are compatible, since a scripted login serves both hosts; neither record says so.]

## Acceptance criteria

From the issue's "Done when" section:

1. **Given** an explicit flag, **when** the runner prepares its disposable `CODEX_HOME`, **then** the
   home has the session login, copied or pointed to.
2. **Given** no flag, **when** the runner prepares the home, **then** it receives no login.
3. **Given** any run, **when** records and logs are written, **then** none contains the credential.
4. **Given** the owner's Mac, **when** one Codex case runs end to end through the runner, **then** its
   observation is compared against the hand run, per the runbook.

## Design

### Approach

From the issue: give the disposable home a working login "the way `adapters/codex/worker.py` already
does for role workers", behind an explicit flag that is never on by default.

### Decisions and alternatives

- Opt-in only: the issue requires "an explicit flag, never by default".
- Copy or point: the issue allows either. The worker adapter points, with a symlink. No choice is
  recorded for the runner.

### Do not implement

- Any default that exposes the login without the flag (AC 2).
- Writing the credential into a record or log (AC 3).

## Tasks

- [ ] Add the opt-in flag to `scripts/native_acceptance.py` (AC 1, 2).
- [ ] Place or link `auth.json` into the disposable `CODEX_HOME` when it is set (AC 1).
- [ ] Prove the redaction keeps the credential out of every record and log (AC 3).
- [ ] Run one Codex case end to end and compare it against the hand run (AC 4).
