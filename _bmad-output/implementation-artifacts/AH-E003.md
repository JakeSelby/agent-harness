## Goal

An optional decision provider answers typed questions about judgments the harness hooks already make,
runs beside the deterministic check that makes each one today, and is promoted per decision point only
on labels the harness itself observes. Deterministic checks stay authoritative and every provider path
fails open to them. The epic is complete when each candidate decision point has a measured held-out
result from the decision log and sits at the stage its written criterion allows, with the release
saying which points stayed in `shadow`.

The issue was re-scoped on 2026-09-21. The first plan checked the manner of the agent's prose; nothing
consumed those answers and nothing could score them. The re-scope moved the provider onto decisions
that have a consumer and an observable outcome: is a completion claim supported, should a command
prompt, which band gets a spawn, which skill fits a request.
[Source: https://github.com/JakeSelby/agent-harness/issues/135]

## Scope and requirement coverage

In scope:
- The provider foundation: the contract with `none`, `local` and `jev` providers, opt-in configuration,
  outbound-data controls, question packs, the evaluation runner, ledger rows and diagnostics (FR-47,
  FR-49).
- Per-point stages `off`, `shadow`, `advise` and `act`, where `act` may only tighten (FR-48).
- The first consumers: stop-claim verification and the ask-band gate, both aiming for `advise`, plus
  band recommendation and skill shortlists measured in `shadow` only (FR-48, FR-49).
- Hand-labelled seed fixtures for the first two consumers, since the label-yield count came back far
  below the bar (FR-49).
- Evidence-driven stance proposals (FR-50) and the per-rule measurement view (FR-20, FR-67, #647), which
  the re-derived epic map places here. No child issue covers FR-50 yet.
- Measurement and delegation work attached to the epic after its re-scope, none of it listed in the
  epic's issue body:
  - #523 (tier-0 capability class) and #524 (cache-leverage measurement), added by the 2026-09-22
    intake comment on #135 "in v0.14.0"; both issues now carry the v0.15.0 milestone.
  - #540 (Workflow-tool spike, milestone v0.13.0) and #545 (scripted `/review` and `/research`,
    milestone v0.16.0), parented to #135 as filed and reserved in #548.
  - #647 (`harness usage --rules`, no milestone), filed as a PRD and spine review follow-up and mapped
    to AH-E003 in #664.

Out of scope:
- Any relaxation: the provider never relaxes a deny, never sees a grade 2 or higher command, and never
  overrides a named role's bindings.
- Semantic auto-authorization, which the PRD lists as a non-goal.
- Response-manner and prose-quality checks, closed as not planned: #142, #144, #146, #158, #159, #160,
  #161, #162. #372 supersedes #146 and carries the bounded on-task comparison #142 held.
- Publishing accuracy, latency or cost figures that measure the third-party provider's model, unless
  its terms permit publication.

## Architecture slice

From the 2026-09-23 spine [Source: _bmad-output/planning-artifacts/architecture-spines/architecture-agent-harness-2026-09-23/ARCHITECTURE-SPINE.md#AD-15]:
- **AD-15, Decision providers are subordinate** (binds FR-47 to FR-50): the deterministic answer is
  authoritative; a stage advances only by its written criterion; at `act` a provider may only tighten
  and never denies; errors fail open; thresholds key to the pinned model id and pack version; the
  egress allowlist is empty by default; evidence changes a stance only as a proposal.
- **AD-7, What a hook may and may not do** (binds FR-48): the enforcement powers the consumers may use,
  and gaps declared in `capabilities.json`.
- **AD-11, Local ledgers are the system of record** (binds FR-23 to FR-27): decision rows append under
  the ledger lock, and the decision log is never exported.
- **AD-13, Detector logic lives in `ruleprobe`** (binds FR-20, FR-67): #647's declarative loading.
- **AD-14, For cost, hooks only route and refuse frontier** (binds FR-28 to FR-34): #523 and #145.
- **AD-12, Measurement invariants** (binds FR-55 to FR-58): #524 and #545's replay arms.
- **AD-8, Constrained roles run only as isolated role workers:** names the Workflow tool's `agent()`
  as an unguarded path (#576), which #540 measured.
- **AD-21, Dependencies:** the Jev client is standard-library only on the Python 3.9 floor.
- Components: `lib/harness_core/decision.py` (the contract) and `lib/harness_core/decisions/` (the Jev client, controls, packs, evaluation and ledger), the decision log and usage ledger,
  `harness decide`, `harness decisions eval`, `harness doctor`, and the hook decision points (stop
  gate, command grading, band routing, skill shortlists).

AD-15 is the decision this epic implements; its status in the spine is "ADOPTED for the contract; act
consumers planned".

## Exit criteria

1. Each candidate decision point has a measured agreement, calibration, cost and latency figure from
   the decision log, on a held-out split.
2. A point reaches `advise` only by meeting its written criterion; one that misses ships in `shadow` and
   the release says so.
3. Disabled integration makes no external requests. Failures are recorded as unknown and preserve
   existing behaviour.
4. Shadow mode adds no context tokens: the static benchmark is unchanged.
5. Exactly which fields leave the machine is documented per point, with a local payload preview.
6. Original adapter code and permitted fixtures ship under MIT; the external service is not included in
   that licence.

Figures under criterion 1 that measure the third-party provider's model stay local unless its terms
permit publication (FR-49).
