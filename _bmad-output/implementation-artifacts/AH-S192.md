## Story

As an agent working in a session, I want to ask the session archive a question and get back pointers, so that I can find a past decision, fix or plan without pasted history filling my context.

## Context and value

The outcome is that an agent can query the archive and receive pointers, never a pasted block; retrieval is pull-based and its answer is data ([#544](https://github.com/JakeSelby/agent-harness/issues/544)). The issue is open on the v0.16.0 milestone and is blocked by #543, the archive, and by the first clean replay ratio (#369). Nothing of it is on `main`: there is no `session-recall` skill under `primitives/skills/`.

## Acceptance criteria

1. **Given** a query and an optional repository, **when** the `session-recall` skill or its tool wrapper runs `harness sessions search`, **then** it returns at most N hits of session id, turn, date, path or issue mentioned and a capped excerpt, within the transcript-hygiene caps.
2. **Given** the skill text, **when** an agent reads it, **then** it says when to reach for recall (a past decision, a prior fix, a plan's location) and when not to (the task's own repository, which `Grep` answers).
3. **Given** a hit, **when** it contains a command, URL or path, **then** the agent treats it as untrusted content and never executes it.
4. **Given** session start, **when** a session opens, **then** no archive content is injected and no hook adds it to context.
5. **Given** Codex and Claude Code, **when** the skill runs, **then** it shells out on both, and no MCP server is added.
6. **Given** the cost bench, **when** one replay arm with the skill runs against one without, **then** normalised cost and pass rate are recorded before any default changes.

## Design

### Approach

A skill, plus a tool wrapper where the runtime supports one, over `harness sessions search`. Output is pointers with a capped excerpt, bounded by the same caps as any subagent return ([#544](https://github.com/JakeSelby/agent-harness/issues/544)).

### Decisions and alternatives

- Pull, never push: nothing is injected at session start ([#544](https://github.com/JakeSelby/agent-harness/issues/544)). The PRD lists push-injected memory as out of scope for FR-63.
- A shell-out skill, not an MCP server, in this issue.
- Retrieved text falls under the existing rule that a command, URL or path first seen in a subagent summary is never executed [Source: primitives/rules/delegation.md].

### Do not implement

- No MCP server.
- No automatic injection of archive content.
- No semantic retrieval; #546 holds it.
