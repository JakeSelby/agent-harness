## Context

PR #583 (merged 2026-09-23, closing #333) scoped qualification-evidence invalidation per target. From
its body:

- evidence is invalidated by the shared runtime source plus that runtime's own adapter directory, with
  the adapter files shared code reads carved back into every target's set;
- only `hook.py` is per-runtime, so a fix confined to one runtime's hook no longer costs the other
  runtime's targets;
- it fails closed, and the catalog declares the scope in a versioned `evidence_invalidation` block.

The PR body ends: "Part 1b, per-case scoping, is a policy edit and is filed as decision #582 rather than
built here."

The issue gives the reason it is a decision rather than engineering: the catalog's evidence
requirements are a v1 stable interface, and a published sentence in `docs/compatibility.md` defined
when qualification holds. Replacing it with a path-scoped rule is a policy edit, so it needs an explicit
yes.

**The issue's quotation is out of date.** It quotes the sentence as "no subsequent runtime-source
changes". At `origin/main`, after PR #583, `docs/compatibility.md` reads "subsequent change under the
paths that invalidate this target", and its section "Which source change invalidates which evidence"
describes the per-target rule. The decision is unchanged: per-case scoping would amend that text again.

The 2026-09-23 PRD lists this as open question 1, "Should qualification evidence be invalidated per
case, or only per target (#582)?", blocking FR-51 and needed by v0.14.0. The spine lists it under
Deferred: "Per-case evidence invalidation (#582). Per-runtime scoping (AD-4) holds until then."

## Options

From the issue:

1. **Accept per-case, path-scoped invalidation, and amend the published sentence.** Each required case
   declares the source paths it depends on. A change under an unmapped path invalidates everything,
   failing closed. The map version is recorded in the catalog and on each evidence record, so a reviewer
   can see what was assumed. The issue estimates about 200 lines plus tests, and a saving of about 45
   percent of a qualification round. The issue says the #340 analysis recommends this option.
2. **Keep whole-source invalidation per target, as #333 landed it**, and revisit after one round
   measures the per-target saving. For: no policy edit before there is a measurement. Against: every
   source change still costs the target's whole round.

The 45 percent figure is the issue's estimate, not a measured result.

## Decision

Open: the maintainer answers by number on the issue. The issue says option 1 is recommended by the #340
analysis; no answer is recorded.

## Consequences

From the issue's "Done when" section:

- if option 1 is chosen, it becomes a story that defines the map format;
- if option 2 is chosen, this issue closes.

Option 1 amends `docs/compatibility.md` and adds a versioned case-to-path map to the catalog and to each
evidence record. Option 2 leaves AD-4's per-runtime rule as the standing policy.

Bound requirement: FR-51: Scoped evidence invalidation, whose status line says "Per-case scoping is a
pending decision". Bound decision: AD-4: Evidence-backed compatibility.
