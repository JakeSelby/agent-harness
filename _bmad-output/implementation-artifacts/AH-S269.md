## Story

As a reader of the README, the docs or the landing copy, I want the product called Model Citizen and its
examples to use `citizen`, so that what I read matches what I install and run, and a search for the old name
still lands.

## Context and value

The rename (AD-24) changes the brand in living copy. Dated records keep the old name. The lower-case
category noun "agent harness" still describes the product and stays. This is PR C of the plan, merged after
AH-S267 so every `citizen` example runs.

## Acceptance criteria

1. **Given** README.md, CONTRIBUTING.md, the AGENTS.md title, living `docs/` pages (not `docs/plans/`),
   `product.json`'s `hero.subtitle`, `primitives/instructions.md`, `codex/config.toml.example`, the brand
   mark's `aria-label` and the release workflow's release title, **then** the brand reads Model Citizen.
2. **Given** command examples in README, `docs/`, `product.json`, `primitives/` and `templates/`, **then**
   they read `citizen <subcommand>`; the AGENTS.md Gate block and CI keep `bin/harness`, so the two stay
   identical.
3. **Given** the lower-case category noun, **then** it stays.
4. **Given** README and the docs index, **then** each carries one "Formerly Agent Harness" line.
5. **Given** the harness-authoring skill's repository examples, **then** they write `<owner>/model-citizen`.
6. **Given** `docs/assets/sync-dry-run.svg`, **then** it is re-captured from `bin/citizen sync --dry-run`.
7. **Given** the PRD and the product brief, **then** their product name reads Model Citizen, PRD FR text
   that names the command reads `citizen`, each amended through its skill's update intent with a memlog
   entry. The brief's positioning line changes only once the maintainer picks one. The UX specification's
   brand lines (two in `DESIGN.md`, one in `EXPERIENCE.md`) and the architecture spine's title and `name`
   read Model Citizen, amended the same way.
8. **Given** the change, **then** `bin/harness generate --check` passes and the gate is green.

## Design

### Approach

- Edit the brand in the files in AC 1, then run `bin/harness generate` so `claude/CLAUDE.md` follows
  `primitives/instructions.md`.
- Move command examples to `citizen` across the living files; the plan's inventory counts about 156.
- Add the two "Formerly Agent Harness" lines.
- Re-capture the dry-run image with the method AH-S116 used.
- Amend the PRD and the brief through `bmad-prd` and `bmad-product-brief`. Their directory names stay.
- Add a changelog fragment `changelog.d/879.changed.md`: "Renamed the product to Model Citizen."

### Decisions and alternatives

- **Keep the category noun.** It names what the product is, not the product.
- **Keep `bin/harness` in the Gate block and CI,** so the documented gate and the checks stay identical and
  a checkout without the new link still runs them.
- **One "Formerly Agent Harness" line in the README and one in the docs index,** so searches for the old
  name land; the `retired-name` lint rule (AH-C079) allowlists exactly those lines.

### Do not implement

- No edits to dated records: `_bmad-output/` dated artifacts, `docs/plans/`, changelog entries, or the
  sha256-pinned compatibility evidence.
- No slug or site URL change (AH-C079).
- No positioning line the maintainer has not chosen.
- Test invocations of `bin/harness` stay.
