## Story

As a developer, I want to select whether a fix stays minimal, cleans up nearby code or addresses the underlying pattern, so that the build and review workflows size a change the way I intend without ever authorizing unrelated work.

## Context and value

Users cannot select whether fixes stay minimal, clean up nearby code or address an underlying pattern ([#126](https://github.com/JakeSelby/agent-harness/issues/126)). The epic's 2026-09-21 assessment rated the story Not delivered, with no `change-scope/` dimension ([#116 comment](https://github.com/JakeSelby/agent-harness/issues/116)); none exists under `primitives/stances/` today.

## Acceptance criteria

1. **Given** a selected change scope, **when** the build and review workflows run, **then** they use it, and no variant authorizes unrelated work or destructive changes.
2. **Given** the variant documentation, **when** a reader compares the examples, **then** they distinguish a necessary root-cause fix from opportunistic cleanup and from cross-module redesign.
3. **Given** every variant, **when** projections and workflow routing are tested, **then** an explicit user scope overrides the default.

## Design

### Approach

The issue proposes `change-scope` with `minimal-diff`, `local-cleanup` and `systemic-fix`, default `minimal-diff`. Every variant stays bounded by the user's request. `systemic-fix` must surface new architecture or product decisions and the external blast radius before it expands scope ([#126](https://github.com/JakeSelby/agent-harness/issues/126)). The plan repeats that none of the variants permits unrelated work [Source: docs/plans/stance-completeness.md#Step 4 — New choices].

### Decisions and alternatives

- `minimal-diff` is the default ([#126](https://github.com/JakeSelby/agent-harness/issues/126)).
- No other alternative is recorded in the issue or pull request.

### Do not implement

- Do not let any variant authorize unrelated or destructive work.
- Do not let `systemic-fix` expand scope before surfacing the decision and its blast radius.
- Do not sync an unmerged candidate into the live installation.
