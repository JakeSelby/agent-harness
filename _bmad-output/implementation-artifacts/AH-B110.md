# AH-B110 — Policy-file guard gates commands that only mention a policy path

## Reproduction

With a decision provider configured (`governance.provider: local`), run any graded command whose
text names a policy path only as data, for example `gh issue create --body-file - <<'EOF'` with a
body naming `.agent-harness/governance.json`. The hook answers `ask` with "Governance: this
changes the governance policy file agent-harness/governance.json, which is level 1", though
nothing writes the file. Observed on `main` before this fix; the regression test reproduces it.

## Root cause

`_policy_hits` in `policy/hooks/grade-bash.py` first judged the paths the segment walk found
written, and when none was a policy file it fell back to searching the whole command text with
`POLICY_RE` and `CONFIG_RE`. That text includes quoted arguments and here-document bodies, so any
mention matched. The fallback existed to catch writes the walk cannot see: inline interpreter
code (`python3 -c 'open(...)'`) and lines that do not decompose.

## Acceptance criteria

1. **Given** a configured provider, **when** a command names a policy path only inside a quoted
   argument or a here-document body that no shell runs, **then** the policy-file guard does not
   gate it and the command is put to the provider as usual.
2. **Given** a configured provider, **when** a command writes a policy file through a redirect,
   `tee`, `sed -i`, `perl -i`, a `cp` or `mv` operand, or an unresolved operand ending in
   `governance.json` or `config.json`, **then** it is asked about as a level-1 action.
3. **Given** a configured provider, **when** inline interpreter code (`python -c`, `node -e`,
   `perl -e`, `ruby -e`, `php -r`) names a policy path, a shell runs a here-document that writes
   one, or a line that does not decompose names one, **then** it is still level 1.

## Design

- The text-wide search now runs only when the walk could not decompose the line (`walked` false
  in `govern`), which keeps the fail-closed behaviour for opaque text.
- `_written` adds policy paths named in inline interpreter code (`_inline_code`, `MENTION_RE`),
  left unresolved so `_policy_hits` judges them by name. This replaces the old fallback for
  `python3 -c` writes.
- `_stdin_scripts` walks here-document bodies when a segment is a shell reading its script from
  stdin (`bash <<'EOF'`), with the directory unknown, so a write in that script stays gated.
- Rejected: stripping quoted strings from the text before the search. It would miss inline code
  writes and still gate mentions in unquoted here-document bodies.
- Not changed: `grade_tokens`, redirect-only segment grading (#899), the provider decision loop,
  the `harness config set governance` text check and `govern_file`.
- Default taken: a here-document fed to an interpreter (`python3 - <<'EOF'`) is data for this
  guard, because the issue names it as a false positive; a policy write from such a script is not
  gated by name, as a write from a script file never was.

## Regression test

`tests/test_policy_mentions.py`, `PolicyMentions.test_regression_a_mention_in_data_is_not_gated`,
fails on the unfixed code (the `gh issue create` here-document is gated at level 1) and passes
after it. `test_a_real_write_is_still_gated` and the `InlineCode` cases pin criteria 2 and 3.
