# AH-B054 — Id-less assistant usage records are never deduplicated

## Reproduction

A Claude Code transcript in which the runtime writes the same assistant response several times
without a message id. `claude/hooks/usage-log.py` keyed each such line as its own slot, so every
repeat added its usage again and the session total grew with no bound. Reported as finding B2 of the
2026-09-22 enterprise-review intake; the issue records no specific runtime version that emits such
records.
[Source: https://github.com/JakeSelby/agent-harness/issues/519]
[Source: https://github.com/JakeSelby/agent-harness/pull/565]

## Root cause

Deduplication keyed assistant records on the message id. A record without one opened a new slot per
line, so it could never collide with a repeat of itself.
[Source: https://github.com/JakeSelby/agent-harness/pull/565]

## Acceptance criteria

1. **Given** a record with a message id, **when** it is read, **then** it keys on the id exactly as
   before, and rows for id-bearing transcripts are unchanged.
2. **Given** an id-less record with a `requestId`, **when** it is read, **then** it keys on the request
   id, unscoped by file, so the same API call in a session file and a subagent file is one response.
3. **Given** an id-less record whose request id also appears on an id-bearing record, **when** both are
   read in either order, **then** the id-less record joins that id-bearing slot.
4. **Given** two message ids sharing one request id, **when** they are read, **then** they stay two
   messages.
5. **Given** a record with neither a message id nor a request id, **when** it is read, **then** it is
   summed as written and counted in `idless_records`, which on a session row includes the subagent
   files folded into its totals.

**Recorded divergence from the issue's acceptance.** The issue asked that a fixture of repeated
id-less records produce one count. As delivered, repeats that share a `requestId` collapse to one,
but two identical records carrying neither identifier are counted as two and flagged in
`idless_records`: the PR treats them as unknown, not duplicates. The issue's "Expected" section allowed
"counted once and flagged" or a stable surrogate.

## Design

A surrogate key on `requestId`, with a link map recording which slot each request id resolved to, so
an id-less record can join its call's id-bearing slot in either read order. Only a slot the surrogate
itself opened is ever folded away.

- **Rejected after review:** the first commit keyed id-less records on a timestamp, model and usage
  fingerprint. Review showed that collapses distinct responses and never merges the streaming partials
  it was meant to, so the second commit replaced it.
- **Must not change:** rows for transcripts that carry message ids; a row without the new field was
  deduplicated whole.
- **Out of scope:** the raw-to-deduplicated ratio, which is #518.
[Source: https://github.com/JakeSelby/agent-harness/pull/565]
