## Goal

State in one place, per client, whether the delegation stance's model-tier restriction actually binds.
The compatibility matrix stated qualification only; the facts (the spawn hook rewrites a top-class
request on Claude Code, the session's own `--model` is never touched, Codex differs) were scattered.
Item B1 of the 2026-09-22 enterprise-review intake.
[Source: https://github.com/JakeSelby/agent-harness/issues/520]
[Source: https://github.com/JakeSelby/agent-harness/pull/566]

**Issue text out of date.** The issue says Codex "has no spawn hook". The PR records the actual reason
Codex reads `advisory`: the tier rewrite alone is gated to Claude Code in
`lib/harness_core/lifecycle.py`, not because Codex raises no hooks.

## Acceptance criteria

1. **Given** the capability matrix, **when** it renders, **then** it has a `tier restriction` row reading
   `enforced`, `advisory` or `none` per client, generated from each adapter's `tier_restriction`
   declaration and never hand-edited.
2. **Given** the clients at the PR's merge, **when** the row renders, **then** Claude Code CLI and VS
   Code read `enforced`, Codex reads `advisory`, and the plugin-marketplace install reads `advisory`
   because it installs no hooks.
3. **Given** the row's note, **when** a reader reads it, **then** it states when `enforced` still
   rewrites nothing: the session's own model, a surface with no spawn hook, a `delegation` variant other
   than `tiered`, and a class table mapping fewer than two models.
4. **Given** a top-class `Agent` spawn under `tiered`, **when** `lifecycle.dispatch` runs per runtime,
   **then** the model is rewritten exactly where the row reads `enforced` and untouched where it reads
   `advisory`.
5. **Given** the `delegation-tiering` skill, **when** a reader reaches the restriction, **then** it links
   to the row instead of restating it.
