## Story

As a developer working across Claude Code and Codex, I want a durable, searchable archive of every session the ledger knows about, so that a past decision or fix stays findable after the runtime's own transcript has expired.

## Context and value

The issue asks for `harness sessions`: one SQLite file under the state directory, populated by the pass the usage log already makes ([#543](https://github.com/JakeSelby/agent-harness/issues/543)). The motivation is recorded in its blocking spike: Claude Code transcripts expire at 30 days and Codex rollouts are zstd-compressed after 7 days, so the native record is lost or unreadable under the 3.9 floor ([#541](https://github.com/JakeSelby/agent-harness/issues/541)).

The issue is open on the v0.15.0 milestone. Nothing of it is on `main`: `bin/harness` has no `sessions` command. It is blocked by #541, and wants #128 in the same milestone for the retention switch.

## Acceptance criteria

1. **Given** the archive, **when** it is created, **then** it holds tables for sessions, turns, tool calls and subagent links in the row #541 chose, full-text search over turn text and tool results, and foreign keys to the usage ledger keys, decision-log ids, worker run ids and the native Claude and Codex ids.
2. **Given** new sessions, **when** the usage log's byte-offset pass runs, **then** the archive is populated incrementally; a full rescan exists and is idempotent; Codex zstd is handled by an optional dependency that `harness doctor` reports when missing.
3. **Given** a query, **when** `harness sessions search "<query>" [--repo] [--since] [--runtime]` runs, **then** it returns session, turn, timestamp and a capped excerpt, and `harness sessions show <id>` prints one session as neutral rows.
4. **Given** the settings `telemetry.sessions` (default on) and `telemetry.sessions_bodies` (default off), **when** they are set, **then** they control collection and whether message and tool-result text is stored or only metadata, and:
   - with `sessions_bodies` unset, the archive stores no message or tool-result text;
   - only the developer's explicit `telemetry.sessions_bodies: true` turns bodies on; no stance, posture, sync default or migration sets it;
   - #128's `retention_days` applies to stored bodies;
   - every body is redacted for secret patterns before it is written, so the archive file never holds an unredacted body.
5. **Given** a session deleted from the archive, **when** the deletion completes, **then** its rows and full-text entries are gone and its ledger row survives.
6. **Given** any archive command, **when** it runs, **then** it reads nothing from the network and exports nothing.
7. **Given** the reference machine, **when** the archive is measured, **then** full-rescan time, database size and search latency are recorded in `benchmarks/static.json`.

## Design

### Approach

From the issue: SQLite with FTS5, keyed to the existing ledgers, filled by the incremental pass `usage-log.py` already runs, with a full-rescan command for recovery ([#543](https://github.com/JakeSelby/agent-harness/issues/543)). The row format is left to #541, and the spine defers it the same way [Source: _bmad-output/planning-artifacts/architecture-spines/architecture-agent-harness-2026-09-23/ARCHITECTURE-SPINE.md#Deferred].

### Decisions and alternatives

- Full-text search, not embeddings: semantic retrieval is held by #546 until its reopen criteria are met.
- Export stays the OTLP ledger copy; the archive never exports ([#543](https://github.com/JakeSelby/agent-harness/issues/543)).
- `sessions_bodies` exists so a shared machine can keep metadata only ([#543](https://github.com/JakeSelby/agent-harness/issues/543)).
- Decided by the owner on 2026-09-26, AH-D009 option 2, opt-in only ([#685](https://github.com/JakeSelby/agent-harness/issues/685)): the archive may store message and tool-result bodies, off by default and on only through `telemetry.sessions_bodies`; #128's `retention_days` applies to them; secret patterns are redacted when a body is written. Two defaults taken in AH-D009 bind this build: redaction uses the decision log's `redact` and its `SECRET_PATTERNS` list [Source: policy/hooks/decisions.py#redact], and turning bodies off stops new bodies without deleting stored ones, purging being a separate explicit operation.

### Recorded contradictions and gaps

- Resolved by AH-D009 (#685): #128 said "Do not collect commands or message bodies", while criterion 4 lets `telemetry.sessions_bodies` store message and tool-result text. #128's rule is narrowed to the usage ledger's collectors, and criterion 4 carries the default, consent, retention and redaction the decision sets.
- FR-63 requires that "Every archive search is logged with a usefulness signal, so the #546 reopen criteria can be evaluated." Neither this issue nor #544 carries that logging in its acceptance criteria, so no story in this batch covers it.

### Do not implement

- No network reads or export from the archive.
- No embeddings or semantic retrieval (#546).
- No agent-facing recall tool; that is #544.
