## Story

As a developer with more than one primitive root, I want sync to refuse a skill, agent or command name
that two roots both define, so that the runtime never resolves the clash silently on a first-wins
basis.

## Context and value

Claude Code resolves a name clash silently, first-wins. This repository had hit such a clash and had no
check for it. wshobson/agents ships an equivalent check and is credited. The importer (#448) and
external-root projection (#477) both depend on this refusal.
[Source: https://github.com/JakeSelby/agent-harness/issues/449]
[Source: https://github.com/JakeSelby/agent-harness/pull/471]

## Acceptance criteria

1. **Given** two primitive roots that define the same skill, agent or command name, **when**
   `harness lint` runs, **then** it fails and names both sources.
2. **Given** the same collision, **when** `harness sync` runs, **then** it exits 2 before any write and
   names both sources.
3. **Given** a project-level `.claude/agents/` or `.claude/skills/` definition that shadows a
   user-level name, **when** sync runs, **then** it reports a notice and still succeeds.
4. **Given** the roots this repository ships, **when** they are checked alone, **then** they carry no
   collision.
5. **Given** the clash that `docs/bmad.md` records (two installs projecting one skill name), **when**
   the tests run, **then** a regression test refuses it with both paths.

## Design

### Approach

A new module, `lib/harness_core/collisions.py`, collects skill, agent and command names across the
shipped and custom primitive roots and the project level. `bin/harness` calls it from `lint` and from
`sync` before any write. A relative primitive root is ignored rather than read.
[Source: https://github.com/JakeSelby/agent-harness/pull/471]
[Source: tests/test_name_collisions.py]

### Decisions and alternatives

- **Collision refuses, shadow informs:** a clash between roots is an error; a project definition
  shadowing a user-level one is a notice, never a collision. [Source: tests/test_name_collisions.py]
- The issue text says the regression test covers the clash "this repository's own CLAUDE.md records";
  the test's comment names `docs/bmad.md` as where that clash is recorded.
