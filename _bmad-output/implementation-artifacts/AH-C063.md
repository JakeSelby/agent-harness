## Goal

Give the story template for every kind a closing `## Change log` section, so that enrichment builders
stop putting change-log lines under References or Dev notes
([#699](https://github.com/JakeSelby/agent-harness/issues/699)). AH-D002 is the recorded example: its
References end "Change log (the decision template has no change-log heading, so it is kept here)"
[Source: _bmad-output/implementation-artifacts/AH-D002.md#References]. AH-D007 does the same. Six other
decision files, AH-D001, AH-D003, AH-D004, AH-D005, AH-D006 and AH-D008, added their own `## Change log`
heading instead, so the batch is inconsistent.

**Correction to the issue text, from the templates at HEAD.** The issue says the story, bug, epic and
task templates end with `## Change log`, and the decision and spike templates do not. At HEAD
[Source: scripts/bmad_story_templates/]:
- `spike.md` already ends with `## Change log`, after Question, Experiment, Exit criterion, Result,
  Decision and Dev notes. It has since `1d4ed82` (#629), the only commit to the file.
- `decision.md` ends with `## References`, with no change log, as the issue says.
- `epic.md` ends with `## Exit criteria`, with no change log, contrary to the issue.
- `story.md`, `bug.md` and `task.md` end with `## Change log`.

`tests/test_bmad_story_files.py` pins each template's headings in order, in
`test_kind_specific_sections`, and pins the same shape for decision and epic without a change log
[Source: tests/test_bmad_story_files.py].

## Acceptance criteria

From the issue's Acceptance section ([#699](https://github.com/JakeSelby/agent-harness/issues/699)):

1. **Given** every template in `scripts/bmad_story_templates/`, **when** it is read, **then** it ends with
   a `## Change log` section.
2. **Given** the existing decision and spike story files, **when** `python3 scripts/bmad_issue_sync.py audit`
   runs, **then** they still pass.
3. **Given** the question of whether the section is required, **when** it is settled, **then** `upgrade`
   and the depth check behave as decided.

Criterion 3 is from the issue's Scope, not its Acceptance section.

## Dev notes

- **Bound:** FR-64: Story files as design records, which says each story file "must carry the design for
  its kind" and that the sync tool preserves that content
  [Source: _bmad-output/planning-artifacts/prds/prd-agent-harness-2026-09-23/prd.md#FR-64: Story files as design records].
- **Existing files are not rewritten.** `upgrade` converts only legacy stubs and reports a typed file as
  "already in the typed format", so adding a heading to a template does not add it to existing files
  [Source: scripts/bmad_issue_sync.py#upgrade_text]. The depth check requires only the `REQUIRED`
  sections for each kind, which today are Context, Options, Decision and Consequences for a decision and
  Question, Experiment, Exit criterion and Result for a spike, so existing files keep passing unless
  `Change log` is added to `REQUIRED` [Source: scripts/bmad_issue_sync.py#REQUIRED].
- **Files to touch:** `scripts/bmad_story_templates/decision.md`, possibly `epic.md`,
  `tests/test_bmad_story_files.py`, and `scripts/bmad_issue_sync.py` if the section becomes required.
  `docs/bmad.md` if it lists template sections.
- **Testing:** `python3 -m unittest discover -s tests` and `python3 scripts/bmad_issue_sync.py audit`.
