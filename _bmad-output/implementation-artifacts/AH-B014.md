## Reproduction

1. Spawn one subagent that the spawn hook routes to a band worker, and one directly by name, on the same
   model.
2. Run `harness usage --by model`.

Observed: the routed spawn's row carries the alias the spawn hook wrote (`opus`), while the directly
spawned agent's row carries the full model id its transcript records, so the same model appears under
two names.
[Source: https://github.com/JakeSelby/agent-harness/issues/262]

## Root cause

A subagent row took its model from the request, which for a routed spawn is the alias the spawn hook
wrote, rather than from the model the subagent's own transcript reports.

## Acceptance criteria

1. **Given** a subagent or worker that recorded a response, **when** its row is written, **then** it
   records the model id its transcript reports.
2. **Given** one that recorded no response, **when** its row is written, **then** it falls back to the
   requested alias.
3. **Given** rows already on file, **when** `harness usage --rescan` runs, **then** it normalises them.
4. **Given** routed and directly spawned agents on the same model, **when** `--by model` runs, **then**
   they group together.

## Design

`policy/hooks/usage-log.py` names a subagent's model from its own transcript, with the requested alias
only as a fallback. As of #271, the tests also pin how a turn's model is chosen: the most frequent
model wins and a tie goes to the last, and a streamed response does not make its model win a turn it did
not. A rescan replaces a legacy alias row rather than adding one.

## Regression test

`tests/test_usage_model_name.py`, as of #271 (names confirmed in that PR's diff), including `test_a_direct_spawn_and_a_routed_one_land_under_the_same_name`
and `test_a_rescan_replaces_a_legacy_alias_row_rather_than_adding_one`.
