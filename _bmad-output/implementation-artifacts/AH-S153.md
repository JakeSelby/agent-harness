## Story

As a developer with an existing CLAUDE.md, AGENTS.md or `.cursorrules`, I want `harness import` to
turn it into primitives under an external root, so that adopting the harness does not mean discarding
the configuration I already have.

## Context and value

The field-parity epic (#442) observed that the strongest projects in the field import a user's
existing rules rather than asking them to start over, and the field scan names the missing importer as
an honest gap. rulesync's `import` is the reference and is credited in the issue and the PR.
[Source: https://github.com/JakeSelby/agent-harness/issues/448]
[Source: https://github.com/JakeSelby/agent-harness/pull/478]

## Acceptance criteria

1. **Given** a CLAUDE.md, AGENTS.md, `.cursorrules` or `.cursor/rules/*.mdc`, **when** the user runs
   `harness import <path>`, **then** the first run is a dry run that prints the plan and the projected
   sync, and writes nothing.
2. **Given** a confirmed second run, **when** it completes, **then** one rule per top-level section is
   written under an external primitive root, and the root is registered.
3. **Given** `@`-imports and `.mdc` front matter, **when** they are imported, **then** imports are
   followed one level and front matter is preserved.
4. **Given** content that cannot be classified, **when** it is imported, **then** it lands in an
   `-unsorted` rule, and a byte-count check proves nothing was lost.
5. **Given** a file the ownership journal already owns, **when** it is imported, **then** the import is
   refused with the ownership record shown.
6. **Given** a rule name another root already uses, **when** it is imported, **then** the import is
   refused (#449).
7. **Given** the source file, **when** any import runs, **then** it is never edited.

## Design

### Approach

`lib/harness_core/importer.py` splits the source file into rule files; `bin/harness import` takes
`[--root] [--name] [--dry-run]`. `lib/harness_core/catalog.py` skips a root that has no `stances/`
folder, so a rules-only external root no longer breaks sync.
[Source: https://github.com/JakeSelby/agent-harness/pull/478]
[Source: docs/primitive-authoring.md]

### Decisions and alternatives

- **Dry run first:** the first run only prints; a second run writes and registers the root. The issue
  asked for the sync diff before anything is adopted.
- **One rule per top-level section**, with unclassified content kept rather than dropped.
- **Known gap accepted:** sync did not yet project rules from external roots, so an imported file was
  registered but not linked into the runtime until #477. The PR filed #477 and carried its reservation.

### Do not implement

- Projecting external-root rules at sync; that was #477. [Source:
  https://github.com/JakeSelby/agent-harness/pull/478]
