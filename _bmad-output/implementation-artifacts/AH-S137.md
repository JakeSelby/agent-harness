## Story

As a harness maintainer, I want a runner that replays pinned tasks headlessly against bare Claude Code
and against the harness, scoring each run with a held-back check, so that a cost claim can be measured
as a same-day ratio before it is published.

## Context and value

The static figure (#361) counts only what the harness loads; it says nothing about what a task costs end
to end. The runner stores the harness as a same-day ratio to bare, so a cost claim can be measured before
it is published. The PR records that no live run had happened at merge and that nothing in it claims a
saving.
[Source: https://github.com/JakeSelby/agent-harness/pull/368]

## Acceptance criteria

1. **Given** each task in `benchmarks/tasks.json`, **when** its check runs, **then** it fails at the
   task's parent sha and passes at its good sha.
2. **Given** a run that would exceed the cap, **when** it is seeded, **then** it stops before launching.
3. **Given** a run that errors, **when** it is recorded, **then** it is an error and never a failure.
4. **Given** the suite, **when** it runs on Python 3.9 and on a current Python, **then** it is green.

## Design

### Approach

`scripts/cost_bench.py replay` runs pinned tasks against bare Claude Code and against the installed
harness, reads cost from the CLI's JSON result, scores each run with a held-back check, and appends one
row per harness version to `benchmarks/history.jsonl`. As of #368 the manifest held four tasks; their
oracle checks live in `benchmarks/oracles/`.

### Decisions and alternatives

- **Same-day ratio to bare, not dollars:** the harness figure is stored relative to a bare run on the same
  day.
- **Held-back check:** the agent under test never sees the oracle that scores it.

### Do not implement

Live results, ledger changes, published copy.
