## Story

As a release qualifier, I want a driver for the `permission-controls` case that classifies each posture's
result through the bypass classification, so that the case stops being qualified by hand and a model's own
decline is never read as a policy block.

## Context and value

#309 recorded a defect in the `permission-controls` driver: it asserted on the bypass sentinel file's
existence alone, so a model declining the acknowledged-bypass turn on its own judgement read as a policy
block. Fixing it revealed there was no such driver: the case is required in `compatibility/catalog.json` but
resolved to `NOT_AUTOMATED`, so it was qualified by hand every round. #309 had landed `bypass_verdict()`,
`permission_denials()` and `Home.permission_mode()` in `scripts/native_acceptance.py` uncalled on purpose,
because a live driver would flip a required case from hand-verified to automated with no real run behind it.
[Source: https://github.com/JakeSelby/agent-harness/issues/404]

## Acceptance criteria

1. **Given** `scripts/native_acceptance.py`, **when** the plan is printed, **then** the driver runs there
   and the case no longer resolves to `NOT_AUTOMATED`.
2. **Given** a recorded model-declined turn, **when** it is classified, **then** it is a refusal, not a
   block; **given** a recorded policy denial, **then** it is a block. Both as fixtures, not live runs.
3. **Given** a completed bypass turn, **when** it is classified, **then** it is reported as neither.
4. **Given** the first live round after this lands, **when** its verdict is read, **then** it is compared
   against the hand-run result for the same target before the automated verdict is trusted.

## Design

### Approach

The driver walks manual, unacknowledged bypass, acknowledged bypass and auto postures. For each it reads
twice: the permission mode `harness sync` wrote into the client's settings, and what a one-command file
write then did. The acknowledged bypass is judged through `bypass_verdict`, so a decline is `unverified`
rather than a block. `turn_outcome` tells blocked, declined and completed apart for every posture.
`--dry-plan` no longer prints `not automated yet` for the case.

### Decisions and alternatives

- **Seed `autonomy=execute`:** under `ask`, a grade-bash deny blocks the probe write regardless of posture,
  which is the `hook-composition` case's control, not this one.
- **Auto is reported, not asserted:** its outcome differed between macOS and Linux across the 0.11.x
  records.
- **Recorded fixtures:** three headless turns recorded on 2026-09-22 under `default` and
  `bypassPermissions`, each with the turn's own transcript record carrying the client's reported
  `permissionMode` and the sentinel state it left; outcomes are read from those files, never hand-set.
- **The declined fixture is synthetic:** no probe run declined, so it is a real bypass turn whose decline
  was induced by a substitute prompt, and the fixture README and test docstring label it so. The PR body
  gives two counts for the probe runs that all completed, "six" in one bullet and "all four" in its notes.
- **Additive `CASES` entry** above `cost-posture`, so it merges cleanly with the smoke tier in #581.
