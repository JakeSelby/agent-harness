## Goal

Remove three user-facing rough edges that native qualification of the Codex CLI recorded in disposable
homes during the 0.11.0 run: uninstall left the empty `harness-*` skill directories it created; a
stale-writer `harness task save` exited through a Python traceback that leaked paths; and `harness
doctor` said Codex was not installed and that Codex credentials were present in the same report,
without explaining that the binary was simply not on `PATH`. None affected correctness, but each read as
a defect. A fourth observation was recorded as documentation, not a fix: syncing a home back to an older
release leaves role files the older release does not ship, and the older release's `diff` reports no
drift because it cannot know about them.
[Source: https://github.com/JakeSelby/agent-harness/issues/279]

## Acceptance criteria

1. **Given** a sync followed by uninstall, **when** uninstall runs, **then** it leaves no empty directory
   it created, and keeps a directory holding a file the harness does not own.
2. **Given** a stale-writer `harness task save`, **when** it is refused, **then** it prints one line and
   exits 1, and the concurrency guard is exactly as strict as before.
3. **Given** a Codex client that is not on `PATH`, **when** `doctor` runs, **then** it says "not on
   PATH" rather than "not installed", and explains credentials present with no client on `PATH`.
4. **Given** `docs/runtime-controls.md`, **when** the downgrade note is read, **then** it names leftover
   role files explicitly, with `harness uninstall` before a downgrade as the remedy.

## Tasks

- [x] Uninstall removes the empty directories sync created (AC: 1)

- [x] `doctor` distinguishes "not on PATH" from "not installed" (AC: 3)
