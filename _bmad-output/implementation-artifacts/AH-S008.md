## Story

As a developer adopting the repository template, I want `templates/repo/settings.json` to carry `permissions.deny` read rules for secrets and generated directories, so that a new repository keeps the agent away from credentials and bulky generated output from day one.

## Context and value

The issue records that Claude Code had no working `.claudeignore`, so deny rules were the mechanism, and that the template carried only narrow allow rules. It argues the repository template is the right home rather than the user-level settings: `OWNERSHIP.json` correctly never touches the user's `permissions.deny`, and a repository knows its own generated directories.

## Acceptance criteria

1. **Given** the repository template, **when** its `settings.json` is read, **then** it is a settings object with `permissions.deny` rules, each a relative read rule.
2. **Given** the deny list, **when** it is read, **then** it covers secret files (`.env*`, keys, certificates, `.netrc`) and generated directories.
3. **Given** the template's allow rules, **when** the change lands, **then** they are unchanged.
4. **Given** the template README, **when** an adopter reads it, **then** it says to keep the secrets entries and prune the generated-directory list to what the repository produces.

## Design

### Approach

Add read-deny entries to `templates/repo/settings.json`, explain them in `templates/repo/README.md`, and note the mechanism in `docs/how-it-works.md`.

### Decisions and alternatives

- **Repository template, not user settings.** From the issue: the harness never owns the user-level `permissions.deny`.
- **Deny rules, not an ignore file.** From the issue and the pull request: Claude Code has no ignore file, and deny rules are the documented mechanism.
- **Secrets universal, generated directories per repository.** The issue classes the secrets patterns as universal and the directory list as a starting point.

### Do not implement

- Writing `permissions.deny` at user level (the issue records the harness correctly never touches it).
