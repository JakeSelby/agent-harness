## Story

As a harness maintainer, I want observing the bare arm to change no model request, so that the bare arm stays a fair baseline for every comparison with the harness.

## Context and value

The harness is judged against bare Claude Code, so observing the bare arm must not change what its model sees. AD-23 gives observation its own entry point: observation only, failing open and silent, and the only harness component installed in the bare arm. The spine requires a test that compares every model request in each arm with observation on and off, not only the first.

Depends on #789. Traces to AD-23 and PRD §9 (v0.14.0).

## Acceptance criteria

1. Given a stub model endpoint that returns fixed responses, when a bare-arm task runs with observation on and then off, then every model request is byte-identical between the two runs.
2. Given the same comparison in the harness arm, then observation adds nothing to any request beyond what the harness profile itself adds.
3. Given an observation failure, such as an unwritable ledger or a crashed recorder, when a session runs, then the session proceeds unchanged and nothing reaches the model or the user.
4. Given a bare-arm install, when its files are listed, then the observation entry point is the only harness component present.
