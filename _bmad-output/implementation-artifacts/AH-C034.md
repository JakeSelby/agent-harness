# AH-C034 — Ignore .agent-harness/evidence/ repository-wide so captured transcripts cannot redden another session's gate

## Goal

Ignore `.agent-harness/evidence/` repository-wide, so captured cost-replay transcripts cannot turn
another session's stop gate red. The transcripts are untracked but were not ignored, and they carry
home-directory paths by construction, so `bin/harness lint` flagged them and the gate went red for
whichever session ended its turn next, in a checkout whose own change was clean. The issue records that
the evidence is never meant to be committed (only redacted figures move into git at publish time), and
that this was the third local ignore worked around through `.git/info/exclude`, which does not travel,
so every worktree rediscovered the problem.
[Source: https://github.com/JakeSelby/agent-harness/issues/432]

## Acceptance criteria

1. **Given** captured transcripts under `.agent-harness/evidence/`, **when** git lists files, **then**
   they are ignored repository-wide, can never be staged, and never reach `lint_tree`, which walks
   `git ls-files --cached --others --exclude-standard`.
2. **Given** the three locally excluded paths (`evidence/`, `task.json`, `sync.lock`), **when** the
   repository's ignore rules are read, **then** those that belong there have moved from the local
   exclude into `.gitignore`.
3. **Given** a later edit to the ignore file, **when** the tests run, **then** a test catches a removed
   rule.

**Not addressed.** The issue's separate note that the lint's `email address` findings were false
positives on Python traceback fragments (`contextlib.contextmanager` read as a domain) was left out of
this change, as the PR states. The issue said it was worth tightening separately; a follow-up is not
recorded in the issue or pull request.
