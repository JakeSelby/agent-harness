## Story

As a developer who tunes delegation tiers, I want a hook that records each session's token usage to a local file and a `harness usage` report over it, so that per-agent cost can be checked when the model lineup changes, without any network telemetry.

## Context and value

The issue records that the harness owned no usage data at all, and that the `delegation-tiering` skill described an eval for the tiering bands that had never been implemented: without cost attribution the bands could not be checked. It notes Claude Code's `/usage` and `ccusage` as partial alternatives, and asked that the hook payload be confirmed before the record was designed.

## Acceptance criteria

1. **Given** a session ends, **when** the hook fires, **then** a detached worker writes one record for the session to `~/.local/state/agent-harness/usage.jsonl`, with input, output, cache-read and cache-write tokens, subagent spawns and turns.
2. **Given** a transcript that repeats one response's usage across several entries, **when** the worker sums it, **then** each message id is counted once.
3. **Given** a session already recorded, **when** it is recorded again, **then** the record is replaced, not appended.
4. **Given** `harness usage [--days N] [--by day|repo|model]`, **when** it runs, **then** it prints sessions, tokens and cache hit rate with a totals row, and an empty state is not an error.
5. **Given** `--rescan`, **when** it runs, **then** it picks up recent transcripts the hook never saw, within the window.
6. **Given** malformed input, **when** the hook runs, **then** it exits zero quickly.

## Design

### Approach

`claude/hooks/usage-log.py` runs on `SessionEnd` and forks a detached worker, so the session is not held while the transcript is read. The worker streams the transcript, deduplicates by message id and upserts one row per session. `bin/harness usage` reads the file and groups it. Everything stays in a local file.

### Decisions and alternatives

- **Deduplicate by message id.** The pull request records that the transcript repeats a response's usage across entries, so naive sums over-count by about 2.5 times.
- **`SessionEnd` over `Stop`.** The issue offered either; the pull request uses `SessionEnd`. The record gives no reason.
- **Local only.** The issue requires no network; the pull request confirms it.

### Do not implement

- Network export (the issue: "Local file only; no network").

### Undelivered item

The issue asked for a summary "by day, repo and agent". The delivered `--by` accepts `day`, `repo` and `model`; a per-agent grouping is not in PR #21. FR-23 now lists `--by role` among the groupings.
