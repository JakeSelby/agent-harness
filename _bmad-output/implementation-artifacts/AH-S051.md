## Story

As a harness maintainer deciding whether a decision point may leave `shadow`, I want versioned question
packs and a reproducible evaluation runner over the decision log, so that a promotion rests on a
held-out result keyed to the exact words asked rather than on a typed answer taken as evidence.

## Context and value

A typed answer is not evidence of correctness; semantic checks need reproducible labels, explicit
uncertainty handling and versioned inputs. The 2026-09-21 re-scope moved the evaluation source from
synthetic fixtures to the decision log (#370): real inputs, the deterministic answer, and the outcome
the harness observed. Thresholds are fitted per point, because published routing work shows an optimal
threshold does not transfer between workloads. This runner is the instrument FR-49's evidence gates
read.
[Source: https://github.com/JakeSelby/agent-harness/issues/138]

## Acceptance criteria

1. **Given** a question pack, **when** it is constructed, **then** it carries an id, a
   major.minor.patch version and a content hash, and is frozen so nothing holding it can rewrite a
   criterion after hashing.
2. **Given** a provider call, **when** its ledger row is written, **then** the row carries the pack id
   and version beside the request hash, so a row resolves to the words asked.
3. **Given** `harness decisions eval` with `--replay`, **when** it runs, **then** it opens no socket,
   needs no credential, writes no ledger row and ignores the kill switch.
4. **Given** labelled rows, **when** they are split, **then** the dev and held-out split is seeded by the
   hash of the judged text, so a re-run reproduces it, new rows do not reshuffle old ones, and a hash
   on both sides is refused.
5. **Given** a decision point, **when** its threshold is fitted, **then** it is fitted on dev and
   reported on held-out only, and a point with no labelled dev case is reported unfitted rather than
   given the shipped 0.8 default.
6. **Given** a run, **when** the report is written, **then** it carries accuracy, confusion by label,
   agreement with the deterministic answer as a baseline column, a calibration table with expected
   calibration error and a deterministic bootstrap interval, flip rate, tokens, cost where a price was
   given, and an `unusable` block in which an error is never a pass.
7. **Given** two runs over one log, **when** their reports are compared, **then** they are identical:
   no clock, basenames only, no input text.
8. **Given** `--budget-usd` without `--usd-per-mtok`, **when** the command runs, **then** it refuses,
   since no price is published in the repository.

## Design

### Approach

`lib/harness_core/decisions/packs.py` defines immutable, hashed packs.
`lib/harness_core/decisions/evaluation.py` replays the labelled rows of the decision log through a pack
in shadow mode against a recorded fixture, fits a threshold per point on dev, and writes a JSON report.
`bin/harness` gains `decisions eval --point P --split dev|heldout --replay FILE | --live
--max-requests N --budget-usd X`.

### Decisions and alternatives

- **No global threshold:** a cutoff does not transfer between workloads.
- **Hash-seeded split, not `random`,** for reproducibility and stability as rows are added.
- **Threshold fit under provider semantics:** below the threshold the deterministic answer is what is
  compared (after review).
- **Bootstrap from a SHA-256 stream,** not a power-of-two LCG (after review).
- **Pack separator `:` rather than `@`,** because `id@version` trips the repository's own email lint.
- **Label mapping:** a `ran` outcome maps to proceed and `not_run` to confirm; for the stop gate,
  `failed` is confirm and `passed` is proceed. The PR flags this mapping as the judgement most worth an
  owner's review.
- **Under `--replay`,** latency and flip rate are reported as unmeasured and zero by construction.

### Do not implement

- Recurring CI, cloud provisioning or a new native release prerequisite (#134 owns provider-backed
  recurring tests).
- Publication of the third-party provider's benchmark or performance figures without its permission.
- An action class or grade on the decision-log row; the runner derives one per point, and whether #370's
  row should carry them is a follow-up.
