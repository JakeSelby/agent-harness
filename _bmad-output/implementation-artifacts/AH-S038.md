## Story

As a developer who prefers structured choices where my client offers them, I want a selectable decision interface, so that the way a decision is presented can change without changing what counts as approval.

## Context and value

Core rules ban chooser widgets for substantive questions and require the decision block as a standalone final message, whatever the user prefers or the UI offers ([#121](https://github.com/JakeSelby/agent-harness/issues/121)). That rule is unchanged on `main`: `primitives/rules/decisions-and-plans.md` opens with "No chooser widget for substantive decisions" [Source: primitives/rules/decisions-and-plans.md].

The epic's 2026-09-21 assessment rated the story Not delivered, with no dimension ([#116 comment](https://github.com/JakeSelby/agent-harness/issues/116)). No decision-interface dimension exists under `primitives/stances/` today.

## Acceptance criteria

1. **Given** the `structured` or `adaptive` variant, **when** a choice is presented, **then** it keeps the recommendation, the alternatives and the consequences, and the `prose` variant contains no mandatory chooser.
2. **Given** any interface variant, **when** a plan awaits approval, **then** explicit approval is still required and silence is never read as approval.
3. **Given** the plan and decision skills and their projections, **when** a variant is selected or the requested interface is unavailable, **then** the selection and the prose fallback are tested.

## Design

### Approach

The issue proposes `decision-interface` with `prose`, `structured` and `adaptive`, default `prose`. When the requested UI is unavailable the agent falls back to plain prose. Presentation never changes the meaning or scope of authorization ([#121](https://github.com/JakeSelby/agent-harness/issues/121)).

### Decisions and alternatives

- `prose` is the default [Source: docs/plans/stance-completeness.md#Step 3 — Existing opinions].
- The plan states that explicit approval is preserved regardless of UI [Source: docs/plans/stance-completeness.md#Step 3 — Existing opinions].
- No other alternative is recorded in the issue or pull request.

### Do not implement

- Do not let a UI choice stand in for approval.
- Do not sync an unmerged candidate into the live installation.
