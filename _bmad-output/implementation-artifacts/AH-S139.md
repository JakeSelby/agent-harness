## Story

As a harness maintainer, I want every hook judgment logged locally with the outcome that later settles
it, so that any attempt to replace or supplement a heuristic has labelled data to be measured against.

## Context and value

0.12.0 priced sessions, subagents, roles, stances and days, but no record said whether a given hook
decision turned out right. The harness already produced those labels and discarded them; each week
without the log was a week of labels lost. The issue names this log as the benchmark the 0.13.0 decision
layer (#135) is measured against. Spike #371 found 3,001 subagent rows in the usage ledger with no budget
on any of them, which is why subagent rows gain their soft budget here.
[Source: https://github.com/JakeSelby/agent-harness/issues/370]

## Acceptance criteria

1. **Given** a graded Bash command answered `ask`, **when** the user approves or denies it, **then** one
   decision row is written and the later outcome is joined to it.
2. **Given** a Stop event, **when** the gate runs, **then** a row records the gate result. (The issue asked
   for the completion claim as well; see Completion notes.)
3. **Given** `telemetry.decisions` set to `false`, **when** a hook decides, **then** nothing is written.
4. **Given** the change, **when** `scripts/cost_bench.py static` runs, **then** its figure is unchanged.
5. **Given** both adapters, **when** they share an event, **then** both write rows; Claude-only events are
   named as a Codex gap.
6. **Given** the log, **when** `harness usage --by decision` runs, **then** it reports counts, outcome
   rates and the unlabelled share per point.

## Design

### Approach

`policy/hooks/decisions.py` appends to a local `decisions.jsonl` beside the usage ledger: one record when
a hook judges, and a second when the outcome is observed, joined by `decision_id` at read time. Five
writers: the Bash ask or deny answer (`ran` at PostToolUse, `not_run` at SessionEnd, since a refusal and
an interrupt look the same), the stop gate with its own result, band routing, `brief-guard`, and
`evasion_deny` in `lib/harness_core/lifecycle.py`. Subagent rows in the usage ledger gain
`budget_output_tokens` and `budget_tool_calls`, so an overrun is a subtraction on one row.

### Decisions and alternatives

- **Two records joined at read time** rather than rewriting a row when its outcome arrives.
- **`input` capped at 2 KiB, hash over the uncapped text;** no tool output and no assistant prose.
- **Every write failure is counted and swallowed:** the log cannot change a decision or an exit status.
- **New `telemetry.decisions` switch, on by default:** the PR records that there was no existing local
  telemetry switch to follow, because #128 is open.

### Do not implement

- Any network call, classifier or model-visible output; the log adds zero context tokens.
- OTLP export of decision rows.
- Tool output or assistant prose in `input`.
