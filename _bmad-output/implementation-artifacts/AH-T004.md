## Goal

Make the replay tasks' success bar independent of the arm's profile, and pre-flight that bar. The issue
records that task prompts told the agent the full gate must pass, but the suite was red on any bench
profile at every snapshot commit because of the `claude_dir()` defect (#498), and the sandbox refused its
writes. Told the suite must pass, the agent ran it repeatedly and worked around failures that were not its
to fix, so the benchmark had been measuring the fence and the profile rather than the harness. Fixing
`main` does not reach the old trees the tasks run in.
[Source: https://github.com/JakeSelby/agent-harness/issues/499]

## Acceptance criteria

1. **Given** the issue task prompts, **when** they are read, **then** none contains "the suite passes" or
   an equivalent full-gate demand, and `--verify-tasks` still proves each held-back test fails at the
   parent and passes at the known-good commit.
2. **Given** a bench profile whose full suite is red but whose lint is clean, **when** the pre-flight
   runs, **then** it passes; **and** it refuses when lint is red or a read is refused.
3. **Given** the manifest change, **when** the series hash is computed, **then** it rotates and a new
   series starts.
4. **Given** the change, **when** the gate runs, **then** lint is clean and the suite is green under both
   `python3` and `/usr/bin/python3`.

## Tasks

- [x] Pre-flight runs `bin/harness lint` under each arm's fence and judges the tool output (AC: 2)
- [x] Tests (AC: 2, 4)

## Dev notes

- **Design, from the PR.** Both the prompts and the pre-flight now ask for what the scorer checks: lint
  clean and the tests the agent adds or changes. `link-alias` was the only prompt with the demand; the
  synthetic oracle tasks never had one. A suite verdict in the pre-flight's output is ignored either way.
  The issue notes this changes what the agent is told, not what it is measured on, since scoring already
  used only the held-back test.
- **Bound requirements and decisions:** FR-56 (Live replay against a bare arm). AD-12 (Measurement
  invariants): arms differ only by environment, and each fence is proved before scoring.
- **Files touched:** `benchmarks/tasks.json`, `scripts/cost_bench.py`, `tests/test_cost_bench.py`, the
  issue map and this story file.
- **Testing:** the merge commit adds `test_the_bar_is_lint_and_a_red_suite_does_not_refuse` and
  `test_a_refused_read_is_red_even_when_lint_is_clean` to `tests/test_cost_bench.py`.
- **Stacking.** The PR was stacked on #489. A PR comment records that `issue-ownership` failed while it
  targeted a non-default base, because GitHub populates closing references only for pull requests that
  target the default branch.
