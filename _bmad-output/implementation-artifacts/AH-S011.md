## Story

As an orchestrator delegating implementation, I want a `builder` agent that carries the standing implementation brief, so that `/build` and any orchestrator can spawn it without rewriting the same instructions each time.

## Context and value

The issue records that eleven pull requests had been built that week by `general-purpose` agents reading a brief kept outside the repository, and that every gate was green on the first local run: the brief worked but had no home. `/build` described the same steps in prose and relied on the orchestrator to do them itself.

## Acceptance criteria

1. **Given** the `builder` agent, **when** its definition is read, **then** it runs on Opus at medium effort with full edit tools and no `Agent` tool, and it is the only agent holding `Edit` and `Write`.
2. **Given** its body, **when** it is read, **then** it carries the brief: a worktree off `origin/main`, the repository's instructions read first, tests with every change, the repository gate, one local Conventional Commit with `Closes #N`, never push, and a fixed return shape.
3. **Given** `/build`, **when** it runs, **then** it spawns `builder` and then runs the gate itself before pushing and opening the pull request.
4. **Given** the docs and README, **when** they are read, **then** they list all seven agents, with counts computed from the tree in tests.

## Design

### Approach

A new `claude/agents/builder.md` holding the brief in its body; `claude/commands/build.md` rewritten to spawn it.

### Decisions and alternatives

- **The orchestrator re-runs the gate.** The pull request records that `/build` runs the gate itself after the builder returns, "so a verifier's result is never taken from a subagent's report".
- **No `Agent` tool.** The builder cannot re-delegate.
- **Model.** The issue asked for Opus and said the alias follows the delegation stance's "one tier below" for implementation; the pull request records Opus and medium effort.

### Do not implement

- Pushing, and editing `CHANGELOG.md`, are prohibited to the builder (from the issue's brief).
