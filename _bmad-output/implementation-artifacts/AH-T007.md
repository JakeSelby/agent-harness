# AH-T007 — Replay a pinned older tag into a temporary config directory, not only the installed candidate

## Goal

Make `scripts/cost_bench.py replay --tag` real and repeatable, so two harness versions can be compared
against bare in one invocation. The issue records that `replay` refused any tag other than `candidate`,
that the harness arm always inherited whichever harness was live at the default config directory, and
that comparing, for example, `v0.12.0` with `v0.13.0` needed two manual install cycles between runs.
`candidate` was to keep its existing behaviour exactly.
[Source: https://github.com/JakeSelby/agent-harness/issues/599]

## Acceptance criteria

1. **Given** `--tag v0.12.0 --tag v0.13.0 --model <model>`, **when** `replay` runs, **then** the full
   task set runs against both tags in one invocation and writes two history rows labelled by each tag's
   own version and sha.
2. **Given** a tagged run, **when** it syncs and runs, **then** it never reads or writes the developer's
   real profile, and a unit test proves this against a sentinel the test controls.
3. **Given** a ref that does not resolve, **when** `replay` starts, **then** it stops with a named error
   before any tag launches, never a silent skip.
4. **Given** a run that raises or is interrupted mid-schedule, **when** it ends, **then** every temporary
   directory is removed.
5. **Given** `--dry-run`, **when** it runs, **then** it prints the schedule per tag and syncs nothing.
6. **Given** the change, **when** the gate runs, **then** lint and the suite are clean.

**Divergence recorded.** The issue asked for each tag to be synced into a fresh temporary config
directory. The PR found that a fresh temporary profile cannot be signed in, because credentials are keyed
on the config directory. Instead `--harness-config <dir>` names a signed-in profile; each tag is synced
into it, and the sync is then taken back out using the sync's own manifest and ownership records.
**Unverified:** the PR's evidence for criterion 1 is a real sync of `v0.12.0` then `HEAD` into a
signed-in-shaped profile, not a full two-tag replay against a model. A full run is not recorded in the
issue or pull request.

## Dev notes

- **Design, from the PR.** The harness arm's fence admits the tag's checkout read-only; the bare arm is
  unchanged. The undo removes only what the sync wrote, restores `settings.json` atomically, never copies,
  writes or deletes credentials or the CLI's own files, and a leftover after the undo stops the run
  before the next tag spends. Every target and ref refusal happens before the first launch.
- **Bound requirements and decisions:** FR-57 (Per-release tag replay): replay an older tag through a
  signed-in profile, then undo exactly what that sync recorded; the undo never touches credential-named
  files; a residue check runs before the next tag spends. The PRD names #609 as its delivery. AD-12
  (Measurement invariants): no tagged sync touches a live profile.
- **Files touched:** `scripts/cost_bench.py`, `tests/test_cost_bench_tags.py` (new), `docs/benchmarks.md`,
  `CHANGELOG.md`, the issue map and this story file.
- **Testing:** `tests/test_cost_bench_tags.py`, new; as of #609 it holds 30 test methods, including
  `test_syncing_a_tag_neither_reads_nor_writes_the_profile_the_owner_runs`,
  `test_a_ref_that_does_not_resolve_stops_the_run_before_any_tag_launches`,
  `test_every_temporary_directory_goes_even_when_the_tag_raises`,
  `test_a_dry_run_prints_the_schedule_for_every_tag_and_syncs_nothing`,
  `test_only_what_the_sync_recorded_is_removed_and_a_new_credential_survives` and
  `test_the_real_sync_at_head_is_taken_back_out_of_a_seeded_profile`. The PR reports one local suite
  failure, `test_codex_reviewer_key`, attributed to #538.
