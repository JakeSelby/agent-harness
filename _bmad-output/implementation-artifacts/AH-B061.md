## Reproduction

1. In a checkout, write a local, never-committed planning note under `.agent-harness/` that names a
   project outside `docs/`.
2. Run `harness lint`.
3. The lint reports a finding, and the stop-hook gate stays red in the live checkout for every session.

[Source: https://github.com/JakeSelby/agent-harness/issues/605]

## Root cause

`harness lint` walks every file git would commit: tracked files plus untracked files that are not
ignored. `.agent-harness/` is deliberately not ignored, because plans and progress there are task inputs
a handoff reads, and `tests/test_ignore_rules.py` pins that. So any local note there is linted as if it
were about to be committed.

## Acceptance criteria

1. **Given** an untracked `.agent-harness/` file carrying a docs-only project name, **when** the lint
   runs, **then** it produces no finding.
2. **Given** the same file once staged or committed, **when** the lint runs, **then** it produces the
   finding.
3. **Given** untracked files elsewhere, **when** the lint runs, **then** they are still linted.

## Design

**Approach.** Lint every tracked file under `.agent-harness/`, and skip the untracked ones. Staging a
file there brings it back into the lint before it can be committed.

**Decisions and alternatives.** Both recorded in the issue and repeated in the PR:
- Ignoring `.agent-harness/` was ruled out: it hides plans and progress from handoffs, and some plans are
  committed.
- Adding it to `LINT_SKIP_DIRS` was ruled out: it would stop linting plans that are committed.

**Do not implement.** Either rejected alternative.

## Regression test

`tests/test_harness.py`, `LintTests.test_untracked_local_work_is_skipped_until_it_is_staged`. The PR says
it fails on the old code and passes on the new.
