## Story

As the harness maintainer, I want the harness to consume the published measurement engine as a
vendored wheel, so that the harness and the standalone tool never disagree about whether a rule fired,
and no installed home has to change.

## Context and value

Step 6 of the 0.13 release plan: once the engine was carved out (#451), the harness imports it back.
The plan found that both detector loaders and the lint gate load `rule-detectors.py` by file path and
read only `DETECTORS` and `OPT_OUT`, and that hooks run from the checkout by absolute path, so a wheel
in `lib/vendor` is always reachable without a re-install.
[Source: https://github.com/JakeSelby/agent-harness/issues/454]
[Source: _bmad-output/planning-artifacts/v0.13-adoption-release-plan.md#Step 6 — Import it back]

## Acceptance criteria

1. **Given** `bin/harness`'s `load_detectors`, `usage-log.py`'s loader and `check_detectors`, **when**
   the change lands, **then** they are untouched and still load the rule pack by file path.
2. **Given** the repository, **when** `python3 -m unittest discover -s tests` and `harness lint` run,
   **then** both are green.
3. **Given** the rule pack before and after, **when** `harness usage --rules` runs, **then** its output
   is byte-identical, and a golden test pins the seventeen report rows and one fixture session's
   counts.
4. **Given** an existing installed home, **when** a session ends through the installed hook, **then**
   it runs with no re-install.

## Design

### Approach

`lib/vendor/ruleprobe-0.1.0-py3-none-any.whl`, beside `tomlkit`, carries the transcript readers, shell
tokenizer, registry and report engine. `rule-detectors.py` (under `policy/hooks/`, which `claude/hooks`
links to) shrinks from 955 to 428 lines and becomes the repository's rule pack: eleven
repository-specific detectors, `OPT_OUT`, `RENAMED` and `DETECTORS`, with the six generic detectors
delegating to the wheel. The wheel's sha256 is recorded in `third-party.json` and both notices files.
[Source: https://github.com/JakeSelby/agent-harness/pull/488]

### Decisions and alternatives

- **Vendored wheel, not a PyPI dependency:** the plan chose a wheel beside `tomlkit`, loaded by path,
  so there is no package-manager dependency at runtime.
- **`usage-log.py` keeps its own single-pass reader,** because it also builds token sums and budgets.
[Source: https://github.com/JakeSelby/agent-harness/pull/488]

### Do not implement

- Any change to the detector loaders or the lint gate. [Source:
  https://github.com/JakeSelby/agent-harness/issues/454]
