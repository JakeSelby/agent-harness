# AH-B067 — stop-gate: interleaved sessions in one checkout reset each other's block count, so the gate never releases

## Reproduction

In one trusted checkout with a red gate, stop two sessions alternately, for example a Remote Control
host session and an interactive one. Each stop records its own `session_id` and a block count of 1, so
neither session's count reaches `MAX_BLOCKS` (8). A gate that cannot pass never releases either
session.

## Root cause

Traced in `policy/hooks/stop-gate.py` at `origin/main`. The issue names `claude/hooks/stop-gate.py`,
which is the same file: `claude/hooks` is a symlink to `policy/hooks`.

- The hook keeps one state record per checkout, with `green_hash`, `status`, `blocks` and `session_id`.
- On a red run it reads `blocks` only when the stored `session_id` equals the stopping session's, and
  otherwise starts from 0. It then writes the new count with its own `session_id`.
- So two interleaved sessions each overwrite the other's `session_id`, and each count restarts.

`test_a_new_session_restarts_the_count` in `tests/test_stop_gate.py` pins that restart for a new
session, which is the behaviour the fix has to keep for a single session change while fixing the
interleaved case. [ASSUMPTION: the test's intent is read from its name.]

## Acceptance criteria

From the issue's Acceptance section:

1. **Given** two sessions stopping alternately in one checkout with a red gate, **when** each reaches
   its own eighth consecutive block, **then** that session is released.
2. **Given** per-session counts, **when** a green run completes, **then** every session's count is
   cleared.
3. A regression test in `tests/test_stop_gate.py` covers the interleaved case.

## Design

From the issue's Fix section: key the counter by session. Store `blocks` as a map from session id to
consecutive blocks, prune entries that have gone stale, and leave the per-checkout `green_hash` and
`status` as they are.

The pruning rule is not specified. [ASSUMPTION: "stale" is undefined in the issue; an age or a count
limit are both open.]

Do not implement: a change to `green_hash` or `status`, which stay per checkout.

## Regression test

Not written. A test in `tests/test_stop_gate.py` would alternate two session ids against a red gate and
assert that each is released on its own eighth block, then run green and assert every count clears.
