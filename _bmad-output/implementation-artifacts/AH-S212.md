## Story

As a developer running Remote Control hosts through the harness, I want the client versions its
recovery was verified on pinned in one place and `harness doctor` to warn when I run outside them, so
that a Claude Code update that changes the internals it relies on is noticed rather than silently
breaking recovery.

## Context and value

Remote Control recovery relies on client behaviour read from Claude Code's internals. The issue records
that this behaviour changed between 2.1.278 and 2.1.280 and that the verified versions appear only in
code comments. On `main`, `lib/harness_core/remote_control.py` names both versions in comments only:
2.1.278 for the bridge pointer's TTL behaviour, and 2.1.280 for reading the pointer while
`createSessionInDir` is on and for two added pointer keys. AD-17 in the 2026-09-23 spine requires the
pin and the doctor check, and marks itself partial until they land.
[Source: https://github.com/JakeSelby/agent-harness/issues/646]

## Acceptance criteria

1. **Given** a running client whose version is outside the pinned range, **when** `harness doctor`
   runs, **then** it prints a warning that includes the pinned range.

## Design

### Approach

Pin the verified client versions in one place in the Remote Control module, and have `harness doctor`
compare the running client's version with that pin.

### Decisions and alternatives

- **Warn, do not refuse:** the acceptance asks for a doctor warning only.
- **Such features stay outside the v1 stable surface** (AD-17).

### Do not implement

Not recorded in the issue or pull request.
