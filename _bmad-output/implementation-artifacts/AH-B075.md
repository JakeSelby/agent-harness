# AH-B075 — cost-posture and framework-spawn-routing cannot tell a headless resume from a restart

## Reproduction

Native qualification round 1 for 0.13.0, targets `claude-code-cli-macos` and `claude-code-cli-linux`, runner at `d426d6d`, Claude Code 2.1.280. `case_cost_posture` stashes the synced `worker-*.md` definitions, runs one headless turn (`claude -p ... --output-format json`), restores the definitions, then runs `claude -p <spawn prompt> --resume <id>` and expects the unnamed spawn not to be rerouted to a `worker-*`. Both targets failed after three sessions with "a session whose record predates the workers was rerouted to worker-a". `framework-spawn-routing` calls `case_cost_posture` as its last step, so it fails on the same assertion.

A local probe with a logging `SessionStart` hook reproduced the client behaviour: the resumed turn returned the same `session_id`, `SessionStart` fired twice (`source: startup`, then `source: resume`, same id), and the transcript gained a second `agent_listing_delta` with `isInitial: false` and `addedTypes` naming the definition added between the two turns.

## Root cause

The case, not the product. A headless `--resume` is a new process with the same session id. `policy/hooks/harness-session.py` `record_session` sees `source: resume`, so it narrows the record and leaves the restored workers out, as its contract requires. The new process then loads its registry from disk and announces the workers through a non-initial `agent_listing_delta`. `tier-agent-spawns.py` `announced()` reads that through `posture.transcript_agents` and routes on it by design (#584). The reroute was correct: the subagent ran as `worker-a`, so the session did resolve it. The case assumed that a resumed session still runs on its old registry, which a headless client cannot produce. So it could not tell a resume that widened routing wrongly from one the runtime sanctioned.

## Acceptance criteria

1. **Given** a session record with no workers and a `resume` event with the workers back on disk, **when** the session hook runs, **then** the record still names no worker.
2. **Given** that record and a transcript with only the initial listing, **when** an unnamed spawn reaches the spawn hook, **then** it is not rerouted.
3. **Given** the non-initial listing a headless resume writes, **when** the same spawn arrives, **then** it is rerouted to the band worker and the record is still unwidened.
4. **Given** the resumed turn's record, announcement and subagent, **when** the case judges it, **then** a reroute passes only when the runtime announced that worker, while a widened record, a reroute nothing named, or a spawn that did not run fails, and a missing record is `unverified`.

## Design

`scripts/native_acceptance.py` gains `resume_verdict(record, announced, agent_type, ran)`, `hook_posture()` (it loads the hooks' own `policy/hooks/posture.py`) and `Home.transcript_path`. The resumed turn is judged by the session record the hook wrote and by `posture.transcript_agents` on its transcript, not by the fact of the resume. The summary clause says which of the two outcomes was observed. Rejected: removing the resume step, which would drop the live check that a resume never widens the record. Also rejected: changing the hooks, since their contract held. No hook, posture or routing code changes.

## Regression test

`tests/test_resume_reroute.py`: `HookSequenceTests` drives the session and spawn hooks through the case's own sequence (criteria 1 to 3), and `ResumeVerdictTests` pins the case's judgement (criterion 4). The old case logic failed on exactly the announced-reroute input that `test_a_reroute_the_runtime_announced_passes_and_says_so` now accepts.
