## Story

As a developer deciding whether the harness supports my client, I want one versioned compatibility
catalog backed by per-client native evidence, so that a support claim is never made for a client, version
or platform that was not actually qualified.

## Context and value

This is a delivery slice of #98 (native client qualification and a versioned compatibility catalog),
under epic #93. It records ownership of the already open PR #105 and adds no release scope. At the time
every target remained unqualified, and the PR kept them honestly so.
[Source: https://github.com/JakeSelby/agent-harness/issues/167]

## Acceptance criteria

1. **Given** the compatibility catalog, **when** it is read, **then** providers, runtimes, clients,
   platforms and native evidence are separate entries in one versioned document.
2. **Given** a built-in or custom stance, **when** its coverage is shown, **then** its instruction, hook and
   setting coverage is exposed per runtime.
3. **Given** a target without per-client, version-matched native acceptance evidence, **when** release
   qualification is attempted, **then** it is refused.
4. **Given** the targets at merge time, **when** the catalog is published, **then** they remain unqualified.

## Design

### Approach

`compatibility/catalog.json` is the one versioned catalog; `lib/harness_core/compatibility.py` validates
it and refuses qualification without matching evidence. Each adapter publishes
`adapters/<runtime>/capabilities.json`, which the CLI reads to report instruction, hook and setting
coverage. `docs/compatibility.md` documents the qualification rules.
[Source: https://github.com/JakeSelby/agent-harness/pull/105]

### Decisions and alternatives

- **Evidence per client and version, not per runtime:** a claim needs version-matched native acceptance
  evidence for each client.
- **No qualification at merge:** the PR left current targets unqualified rather than claim support.
- Alternatives considered are not recorded in the issue or pull request.

### Do not implement

- The native qualification rounds themselves (#185, #187, #188).
- Publication (#100).
