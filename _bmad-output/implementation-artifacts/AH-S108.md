## Story

As a developer who selects a `cost` variant, I want `harness sync` to render the native agent
definitions from that variant wherever it differs from the defaults, so that the variant actually
changes each subagent's model class and effort.

## Context and value

The issue calls reasoning effort the second-strongest cost lever after prompt caching. For a native
subagent it exists only in the agent definition's frontmatter; the spawn call has no effort input.
Those definitions were committed projections that sync symlinked, so no selection could change them.
Codex definitions were already rendered at sync with `role_bindings`; Claude definitions needed the same
path. The table being consumed came from #248, under #247.
[Source: https://github.com/JakeSelby/agent-harness/issues/249]

## Acceptance criteria

1. **Given** a role whose rendering under the selected variant and `role_bindings` differs from the
   committed projection, **when** sync runs, **then** it is written as a generated file.
2. **Given** a role that renders identically, **when** sync runs, **then** it keeps its managed link, so
   a default install is unchanged and can downgrade cleanly.
3. **Given** a role, **when** it is rendered, **then** precedence is role defaults, then the cost row,
   then `role_bindings`, and fixed roles never move.
4. **Given** migration, re-runs, variant changes in both directions, role removal, `--adopt`, dry runs
   and uninstall, **when** they run, **then** none removes or overwrites a file or link the user owns,
   and none leaves a role without a definition.

## Design

### Approach

`harness sync` renders a Claude role from the resolved cost variant only when the result differs from
the committed projection; an identical role keeps its managed link. Codex takes the same rows. Every
read and render happens before the first unlink or write. Logic lives in `bin/harness`,
`lib/harness_core/catalog.py` and `lib/harness_core/reconcile.py`.

### Decisions and alternatives

- **Render only on difference:** a default install stays byte-for-byte what it was.
- **Class from the cost row only under tiered delegation;** fixed roles never move.
- **Ownership first:** a dangling or alias-spelled managed link retires and renders; a link or file the
  user owns is preserved and reported, and `--adopt` moves it aside first. Roles that no longer exist
  retire; a hand-edited generated file is reported, never removed.
- **Warnings never fail a sync:** sidecar warnings print as notices.
- **Sync-scoped effort:** a session-level cost override does not change a native agent's effort until
  the next sync.
