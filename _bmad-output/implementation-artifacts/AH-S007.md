## Story

As a developer following the research, plan, build and review sequence, I want `/research`, `/plan`, `/build` and `/review` slash commands that reuse the existing skills and agents, so that each step is one keystroke instead of a sequence assembled by hand.

## Context and value

The issue records that the skills existed but the sequence was assembled by hand every time, and there was no `.claude/commands/` directory. It cites Horthy's research, plan, implement split and the command sets of Pocock and Osmani, and names the important detail: the worktree is created only at build, not at research.

## Acceptance criteria

1. **Given** a sync, **when** it completes, **then** the four commands in `claude/commands/` are linked into `~/.claude/commands/`, and uninstall removes them.
2. **Given** `/research`, **when** it runs, **then** it fans out read-only `gatherer` agents and returns a synthesis.
3. **Given** `/plan`, **when** it runs, **then** it runs `plan-authoring` and stops at the build gate.
4. **Given** `/build`, **when** it runs, **then** it isolates in a worktree, implements with tests, runs the repository gate and opens the pull request.
5. **Given** `/review`, **when** it runs, **then** it runs the fresh-context `reviewer` on the diff and returns findings only.
6. **Given** a command file the user wrote, **when** sync runs, **then** it is not replaced without adopt; and a file dropped from the source is unlinked on the next sync.

## Design

### Approach

Four short command files, each naming the skill it runs or the agent it spawns. Sync gains a generic per-file directory linker: adopt-safe, recorded in the manifest, and pruning links whose source is gone. The commands use it; uninstall already removed manifest links.

### Decisions and alternatives

- **Worktree at build only.** From the issue: research and planning do not create a worktree.
- **A generic linker.** The pull request adds a reusable per-file linker rather than a commands-specific path. The record gives no alternative.

### Do not implement

Not recorded in the issue or pull request.
