# AH-S155 — Source the always-loaded cap or replace it with the measured figure

## Story

As a maintainer, I want the always-loaded context cap to rest on a source or a measurement, so that
the lint gate enforces a number that can be defended rather than an arbitrary line count.

## Context and value

Six projects in the field enforce an always-loaded cap and no two agree; only agents-md-cookbook cites
a mechanism (Codex truncates AGENTS.md at 32 KiB). This repository had a 200-line cap with no runtime
behaviour behind it, while it already had a measured standing-context figure from #430. The field scan
lists the unsourced cap as an honest gap.
[Source: https://github.com/JakeSelby/agent-harness/issues/450]
[Source: https://github.com/JakeSelby/agent-harness/pull/474]

## Acceptance criteria

1. **Given** the always-loaded layer, **when** `harness lint` runs, **then** it measures the layer in
   tokens against `ALWAYS_LOADED_TOKEN_CAP`, derived from the 12,607-token standing context measured in
   #430, and prints both the token and the line measure against their caps.
2. **Given** a layer over either cap, **when** lint runs, **then** it fails.
3. **Given** `docs/how-it-works.md`, **when** a reader reaches Context discipline, **then** it says the
   binding cap is tokens and why the 200-line figure is not a runtime limit.
4. **Given** the three test files that hard-coded `BUDGET = 196`, **when** they run, **then** their
   budget derives from one helper.

## Design

### Approach

`bin/harness` defines `ALWAYS_LOADED_TOKEN_CAP = MEASURED_STANDING_CONTEXT_TOKENS // 3`, a third of
the measured prefix, and keeps `ALWAYS_LOADED_CAP = 200` lines as a secondary guard. Tokens are
characters over four, the approximation `scripts/cost_bench.py` uses. `tests/context_budget.py` is the
one helper the stance tests now read.
[Source: bin/harness]
[Source: docs/how-it-works.md#Context discipline]

### Decisions and alternatives

- **Restate in tokens rather than cite a mechanism:** Claude Code loads a CLAUDE.md of up to 4 MiB in
  full, and its "under 200 lines" guidance is per-file authoring advice for auto-memory, not a sum over
  rules and stances. No runtime behaviour backed the line cap, so the issue's first option was not
  available.
- **Keep the line cap as secondary:** a layer that is cheap in tokens but sprawls over hundreds of short
  lines is still hard to read and to obey.

### Do not implement

Not recorded in the issue or pull request.
