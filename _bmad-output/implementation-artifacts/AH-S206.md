## Story

As a contributor or agent picking up a work item, I want its story file to hold the design, with the
GitHub issue linked and summarised, so that I can build from the repository without a private
conversation and the sync tool never destroys what I wrote.

## Context and value

Every story file was a 26-line stub that said the issue owned the design. `refresh` refused any file that
was not a byte-exact stub, so a story could not carry design without breaking the tool. Design depth ended
up in issue bodies and in uncommitted plan files. This story changes the tool so that the story file can
be the design record. The planning corpus re-baseline (AH-E012) and the story-enrichment batches that
follow depend on it.

## Acceptance criteria

1. **Given** an enriched typed story, **when** `refresh` updates its title or lifecycle, **then** the
   frontmatter and managed block change and every body byte is preserved, including CRLF endings, a BOM
   and lines above the H1.
2. **Given** the 340 legacy stubs on `main`, **when** `upgrade --check` runs, **then** every stub reports
   as convertible without loss. A carried `## Amendment` section keeps its exact bytes.
3. **Given** a pull request whose delivery story is typed and has an unfilled required section, **when**
   `issue-ownership` runs, **then** it fails and names the section. A filled story passes.
4. **Given** a legacy stub, **when** `audit --delivery` runs, **then** it passes with a notice until the
   story is upgraded.
5. **Given** a typed story whose begin or end marker was removed, or a body with no markers, **when**
   `refresh`, `audit`, `upgrade` or `audit --delivery` runs, **then** the file is refused as malformed.
   It is never treated as legacy.
6. **Given** a marker string quoted in prose or inside a fenced block, **when** any command parses the
   file, **then** the quote is ordinary body text.

## Design

### Approach

- **Typed templates.** One Markdown template per kind lives under `scripts/bmad_story_templates/`: story,
  bug, spike, decision, epic, and task (chore uses task). Placeholders are HTML comments.
- **Tool-owned head.** The tool owns the frontmatter (the nine audited fields plus `updated`), the H1, and
  a managed block directly after the H1, bounded by `<!-- bmad-sync:begin -->` and
  `<!-- bmad-sync:end -->`. Everything after the block is human-owned.
- **Positive legacy test.** A file is a legacy stub only when its LF-normalised text starts with the
  legacy render for its item. Any other file without a well-formed block is malformed.
- **Depth check.** `audit --delivery N` checks only the delivery story. A section counts as filled when
  text remains after stripping comments (including unclosed ones) and H3 to H6 sub-headings. Setext and
  ATX H1 and H2 headings end sections, and a duplicated required heading is a finding.
- **Safe writes.** Every write goes through a temporary file, an fsync and an atomic replace, and keeps
  the file's mode. `upgrade` converts everything in memory first and restores already-written files if a
  later write fails.

### Decisions and alternatives

- **CI check, not a runtime hook.** A hook on issue creation was rejected as brittle: it breaks on quoting
  and misses issues filed in the web UI.
- **Only the delivery story is checked.** Checking every story would block unrelated pull requests until
  the enrichment batches land.
- **Legacy stubs pass with a notice.** `upgrade` is not bulk-applied here. The enrichment batches convert
  and fill each story together, so no skeleton full of placeholders sits on `main`.
- **The provenance sentence stays inside the managed block,** so reconstructed items keep their
  disclaimer.
- **Sub-headings do not count as content.** Without that rule, the template's own H3s would pass as a
  filled Design section.
- **Legacy recognition is positive.** The first fix treated any markerless file as legacy. Review showed
  that deleting the begin marker then skipped the depth gate, so a legacy stub must match its render.

### Do not implement

- No bulk `upgrade` of the corpus, which belongs to the enrichment batches.
- No change to `docs/bmad-governance.md` or `AGENTS.md`, which belong to AH-S207 (#621).
- No enforcement on stories other than the delivery story.

## Review findings

- **Scope review (fresh context):**
  - Minor deviations: the provenance line in the managed block, and sub-heading stripping. Both were kept
    deliberately, and are recorded under Decisions.
  - The remaining defects from the tool's earlier blind review were reported rather than fixed, and are
    tracked for a follow-up.
- **Adversarial review, round 1:** one blocking finding (markers matched anywhere, so an amendment that
  quoted them could be overwritten) and ten further findings. All were fixed: positional markers, CRLF
  handling, all-or-none `upgrade`, unclosed comments, file mode and fsync, heading rules, CommonMark
  fences, a verbatim carry, a narrower exception catch and a subprocess timeout.
- **Adversarial review, round 2:** one blocking regression (deleting the begin marker skipped the depth
  gate) plus fence, BOM, pre-H1 and rollback findings. All were fixed with positive legacy recognition and
  the remaining hardening.
