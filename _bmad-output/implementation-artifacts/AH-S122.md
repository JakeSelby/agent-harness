## Story

As the release maintainer, I want qualification frozen on a release branch, with no defect fixed
mid-round, so that other sessions keep merging to `main` without invalidating a round's evidence, and
a round is not wasted on a mid-round fix.

## Context and value

From an analysis of why the 0.11.0 and 0.11.1 releases took about twenty hours, tracked in the
umbrella issue #340. The issue records that three of 0.11.0's four qualification rounds bought no new
observation, because any change under the runtime source paths invalidates all evidence. It estimates
a saving of about 60 minutes and about 1M orchestrator tokens per avoided round, and names no honesty
risk provided the evidence commit stays an ancestor of the tagged release, which `evidence_errors`
already enforces with `merge-base --is-ancestor`.
[Source: https://github.com/JakeSelby/agent-harness/issues/332]

## Acceptance criteria

The issue has no acceptance section; these are taken from its mechanism and the PR:
1. **Given** a release under qualification, **when** it is frozen, **then** `compatibility/freeze.json`
   names the frozen commit and the `release/vX.Y.Z` branch.
2. **Given** the frozen record, **when** `harness freeze` runs and the tip has changed under the
   runtime source paths, **then** it reports the drift path by path and exits non-zero.
3. **Given** `harness freeze --merge-check REF`, **when** a merge would change those paths on the
   frozen branch, **then** it is refused.
4. **Given** an unknown revision or an unreadable record, **when** checked, **then** it fails closed.
5. **Given** `docs/releasing.md`, **when** read, **then** it carries the freeze procedure and the rule
   that a round runs to completion and collects defects, with fixes landing afterwards.

## Design

### Approach

A freeze record, a `harness freeze` subcommand backed by `lib/harness_core/compatibility.py`, and a
release-doc procedure. The branch part is process, not code.

### Decisions and alternatives

- Qualify on a release branch rather than `main`, so merges to `main` do not touch the evidence
  source.
- Triage rule: collect defects during a round and fix them together, then re-qualify once, because
  any source-path change invalidates every record for that round.
[Source: https://github.com/JakeSelby/agent-harness/pull/396]

Not recorded in the issue or pull request.
