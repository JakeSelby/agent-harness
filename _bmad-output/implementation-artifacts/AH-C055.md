# AH-C055 — Align product.json on-the-way entries with the PRD and drop em dashes from README copy

## Goal

Make the published "on the way" list claim only what the PRD backs, and make the README copy follow the
no-em-dash rule. `product.json` is the one source for the landing page, the README and GitHub About.
When the issue was filed its "on the way" list advertised two things the PRD does not back: "Budget
nudges mid-run", which the spike rejected, and "Six runtimes at equal depth", where the PRD commits
only to equal depth with no count. The issue is open.
[Source: https://github.com/JakeSelby/agent-harness/issues/648]
[Source: _bmad-output/planning-artifacts/prds/prd-agent-harness-2026-09-23/prd.md#FR-54]

The issue has no milestone.

## Acceptance criteria

1. **Given** `product.json`'s `on_the_way`, **when** it is read, **then** every entry names an open issue
   on a milestone.
2. **Given** every entry, **when** it is compared with the PRD's roadmap, **then** the PRD backs it; no
   entry names a runtime count.
3. **Given** the README and other published copy, **when** it is checked, **then** it holds no em dash.

## Tasks

- [ ] Every `on_the_way` entry names an open issue on a milestone (AC: 1)
- [x] Remove "Budget nudges mid-run": already gone at `origin/main`. #651, merged after this issue was
      filed, removed the entries for closed issues #321 and #322, and this was one of them (AC: 2)
- [ ] Drop the runtime count from "Grok and Cursor adapters" (AC: 2)
- [ ] Remove the README's em dashes (AC: 3)

## Dev notes

### State at `origin/main`

- `on_the_way` holds two entries. "Grok and Cursor adapters" still reads "Six runtimes at equal depth
  is the target" and names a catalog entry (`grok`) rather than an issue. "Close the loop" names #135,
  which is open on v0.15.0.
- `README.md` holds five em dashes, on four lines. `product.json` holds none.
- The PRD's roadmap puts "additional runtimes, each at equal depth" under v0.16.0, with no count.

### Bound decisions and requirements

- FR-54, Landing copy as data: all landing, README and About copy comes from `product.json`, and
  published copy uses no em dashes. The PRD records the latter as partial because the README still has
  some and no test checks copy for them.
- AD-19, Distribution channels carry no second authority: landing, README and About copy come from
  `product.json` only.
- NFR-13, Claims discipline: every public claim is labelled implemented, validated, proposed,
  historical or unknown.
- [Source: _bmad-output/planning-artifacts/architecture-spines/architecture-agent-harness-2026-09-23/ARCHITECTURE-SPINE.md#AD-19]

### Files to touch

`product.json`, `README.md`, and any README lines rendered from `on_the_way`. The repository rule that
`on_the_way` is capped at five entries, each naming the issue, planned client or document it stands
for, is in `AGENTS.md`; this issue's criterion 1 is stricter, requiring an open issue on a milestone.

### Testing

Not recorded in the issue. `ProductCopyTests` in `tests/test_release.py` and
`scripts/sync_about.py --check` are the existing copy checks. An em-dash assertion does not exist yet,
per the PRD.
