## Goal

Give the two macOS CLI targets native acceptance evidence, so a release again ships with a qualified
floor:

- `claude-code-cli-macos`, through `scripts/native_acceptance.py`;
- `codex-cli-macos`, through the hand-driven procedure in `docs/compatibility.md`.

The issue was filed on 2026-09-22 for the 0.12.0 source. Its one comment, the same day, records that it
was not done for 0.12.0. That release shipped with a deliberately narrower support contract: no client
was required for release and none carried evidence. The comment gives the reason it was deferred rather
than run:

- `scripts/native_acceptance.py` automated one of the eleven required cases, so every target was a
  mostly hand-driven round;
- `evidence_errors` rejects a record that does not cover every required case, so a partial record
  cannot make a client qualified.

The comment moved the issue to v0.12.1, and set the order as #336 first, so the remaining ten cases are
in the runner before the next round is spent.

**The issue is out of date at `origin/main`, recorded here as a contradiction.**

- The issue's milestone is still v0.12.1, and the PRD's roadmap says "v0.12.1: restore the qualified
  release floor (#533)". No v0.12.1 tag exists.
- `main` is at the 0.13.0 candidate (PR #651, closing #627). Its catalog marks three targets
  `required_for_release`: `claude-code-cli-macos`, `claude-code-cli-linux` and `codex-cli-macos`.
- The issue puts the Linux targets out of scope ("no Linux host is available for this release (#408)").
  The 0.13.0 candidate requires `claude-code-cli-linux`.
- #336, the prerequisite the comment names, closed as completed on 2026-09-23. #408, on provisioning,
  closed as completed the same day.
- The catalog now lists 12 `required_cases`; the comment counted eleven.

Whether this issue carries the 0.13.0 round, or is superseded by it, is not recorded.

## Acceptance criteria

From the issue's Acceptance section:

1. **Given** each of the two macOS CLI targets, **when** the round completes, **then** a redacted
   `kind: native` evidence record exists for it, with exact runtime and client versions, the frozen
   source commit, observations, and a `cases` object covering every entry in `required_cases`.
2. **Given** each record, **when** the catalog is read, **then** its entry links the record's path and
   SHA256, and reads `qualified`.
3. **Given** the round, **when** it runs, **then** it runs on the frozen release branch recorded in
   `compatibility/freeze.json`, and no runtime source path changes between the freeze commit and the end
   of the round.

## Tasks

- [ ] Freeze a release branch in `compatibility/freeze.json` (AC 3). At `origin/main` its `state` is
  `open`, with no branch or commit.
- [ ] Run the `claude-code-cli-macos` round through `scripts/native_acceptance.py` (AC 1).
- [ ] Run the `codex-cli-macos` round (AC 1).
- [ ] Link each record's path and SHA256 from the catalog, and mark it `qualified` (AC 2).
- [ ] Settle whether this issue carries the 0.13.0 round, including the Linux target, or closes.
