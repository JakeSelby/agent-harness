## Goal

Name every release surface in the repository instructions, so a release is not reported done at the
tag while another surface is stale. A release touches several surfaces that go stale independently:
the tag and GitHub release, the reference site (a separate repository that vendors this one by tag),
the personal-site card, the GitHub About fields, and the catalog state that lets development resume.
The procedure was in `docs/releasing.md`, but nothing in the repository instructions named the
surfaces, and v0.11.0 was reported done at the tag while the reference site still showed the previous
version.
[Source: https://github.com/JakeSelby/agent-harness/issues/302]

## Acceptance criteria

1. **Given** `AGENTS.md`, **when** it is read, **then** a short section lists every release surface
   in order.
2. **Given** that section, **when** a release is reported, **then** each surface is reported as done,
   skipped or unverified, and never inferred from another.
3. **Given** that section, **when** a step deploys to production, **then** the section notes that the
   step needs its own approval.
4. **Given** that section, **when** it needs the procedure, **then** it points at `docs/releasing.md`
   rather than restating it.

## Tasks

- [x] State the done, skipped or unverified reporting rule (AC: 2)
- [x] Mark the steps that need their own approval (AC: 3)
- [x] Point at `docs/releasing.md` for the procedure (AC: 4)
