## Goal

Publish 0.12.0 with a deliberately narrower support contract.
[Source: https://github.com/JakeSelby/agent-harness/issues/534]

## Acceptance criteria

As written in the issue:
1. **Given** the release, **when** `compatibility/catalog.json` is read, **then** it is `released`, pins
   the qualification source commit, marks `claude-code-cli-linux` and `codex-cli-linux` as
   `required_for_release: false`, and leaves their status `unqualified` with no evidence.
2. **Given** `README.md`, `docs/compatibility.md` and `docs/releasing.md`, **when** they are read,
   **then** they state plainly which targets 0.12.0 qualifies and which it does not.
3. **Given** the test that pins the required-client list, **when** it is read, **then** it records the
   narrowed contract and the reason for it.
4. **Given** a clean checkout, **when** `scripts/release_preflight.py` runs, **then** it reports no
   blockers.

**Contradiction recorded.** The issue's outcome says the two macOS CLI targets are qualified and only the
two Linux targets ship unqualified. The PR published 0.12.0 without native qualification: all four CLI
targets that carried the previous floor were made non-required and kept `unqualified` with no evidence,
and the docs and release notes state that no client holds evidence for this source and that 0.11.1
remains the last qualified release. The PRD's FR-12 agrees with the PR: "0.12.0 shipped with no qualified
target". The issue's premise that the macOS targets would be qualified was therefore not delivered, and
the issue was closed as completed.

## Dev notes

- **Why the narrower contract, from the PR.** It was taken for a pre-1.0 release rather than spending a
  qualification round. `scripts/native_acceptance.py` automated one of the eleven required cases, so
  qualifying even one target was a mostly hand-driven round, and a partial evidence record cannot make a
  client qualified, since `evidence_errors` rejects a record that does not cover every required case.
  The PR says the required flags return with the next round.
- **Bound requirements and decisions:** FR-12 (Release integrity): before 1.0 a release may ship without a
  qualified target only when its compatibility status says so. AD-4 (Evidence-backed compatibility).
- **Files touched:** `README.md`, `compatibility/catalog.json`, `compatibility/migration.json`,
  `docs/compatibility.md`, `docs/releasing.md`, `tests/test_compatibility.py`, `tests/test_docs.py`.
- **Testing:** the required-client test in `tests/test_compatibility.py` was changed to record the
  narrowed contract; `tests/test_docs.py` was also changed.
- **Follow-up:** FR-12 records the minimum required target as planned for v0.12.1 under #533.
