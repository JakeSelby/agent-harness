# AH-B083 — stance-switch and custom-stance switch only delegation and never try a project override

## Reproduction

Round 4 of the 0.13.0 native qualification ran `stance-switch` and `custom-stance` on
`claude-code-cli-macos` and `claude-code-cli-linux`, and the assessor found: "Only delegation was
switched, and no project override was tried in any case." Step 2 of the procedure in
`docs/compatibility.md` asks for a representative communication and delegation stance switched,
with instruction text and behaviour observed, repeated with a custom dimension, a project override
and an invalid choice.

## Root cause

`case_stance_switch` in `scripts/native_acceptance.py` cycled `delegation` only, and neither it nor
`case_custom_stance` selected a stance for one project, so no record could show either behaviour.

## Acceptance criteria

1. **Given** a synced home with `voice=scannable`, **when** the case selects `answer-card`, **then**
   it reads the resolved voice link and its text about tables move, and the settings `outputStyle`.
2. **Given** the same comparison prompt asked under each voice variant, **when** the replies are
   read, **then** the case passes only if the `scannable` reply carries a markdown table and the
   `answer-card` reply does not; replies that agree are `unverified`, and an inverted pair fails.
3. **Given** `proof=tagged` selected globally and a disposable repository whose project file selects
   `proof=plain`, **when** a turn starts inside it with `HARNESS_PROJECT_CONFIG` naming that file
   and another starts outside without it, **then** the inside turn closes `PLAIN`, the outside turn
   closes `TAGGED`, and the global proof link is the same before and after.
4. **Given** the delegation cycle, the custom dimension and the invalid choice, **when** the cases
   run, **then** each is still checked as before, except that an `off` turn whose transcript holds
   no Agent call attempted nothing and is `unverified` rather than failed.

## Design

`delegation_cycle` runs first, under `voice=scannable` as in round 4, then `voice_cycle`, which is
runtime-neutral. The first live run failed the `off` turn: no refusal was reported because the
model attempted no spawn, which the binding verdict rule makes `unverified`, so the driver now
reads the turn's Agent calls before calling a missing refusal a failure. The pair is
`scannable` (one table allowed for three or more items across the same fields) and `answer-card`
(no tables), and a three-type, four-field comparison prompt, because a table is a single-turn,
mechanically detectable difference that both texts state. Either half unobserved does not hide the
other: the case raises `unverified` with both observations. The project override
uses the harness's own mechanism, `HARNESS_PROJECT_CONFIG` naming a file that may select stances
only [Source: bin/harness#load_config], resolved into the turn by the session hook
[Source: policy/hooks/harness-session.py#resolved_overrides]; the observation says the override is
carried by that variable, not discovered from the working directory. It lives in `custom-stance`
because a single closing word observes it without ambiguity. Rejected: `answer-card` against
`off`, since `off` says nothing a reply must do differently; status vocabulary, which both
`scannable` and `answer-card` prescribe; applying the override with `voice`, whose table
difference is less reliable than a one-word proof stance.

## Regression test

`tests/test_native_acceptance_stance_switch.py`.
- **Before the fix:** the voice, table, closing-word and project-override tests fail, since the
  readers and the cycle do not exist and the cases start no turn in another repository.
- **After the fix:** all 10 pass.
