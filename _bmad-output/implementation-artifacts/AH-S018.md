## Story

As a maintainer of the always-loaded rules, I want a registry of deterministic detectors over session transcripts, with a lint check that every rule has a detector or a stated reason for having none, so that every rule is measurable and an unmeasured rule is a visible choice.

## Context and value

The issue sets the goal that "every always-loaded rule should be measurable", and scopes this pull request to the registry, its corpus and the lint check; the session-end run and the report follow in #59. It also moves `SECRET_PATTERNS` into the registry so the lint and the secrets detector share one source.

## Acceptance criteria

1. **Given** the registry, **when** it is read, **then** every entry carries an id, a rule and a kind, and every opt-out carries a reason.
2. **Given** `run(events)`, **when** detectors hit, **then** each hit is a detector id, a turn index and a tool-use id, never a snippet, and detectors with no hits are omitted.
3. **Given** the corpus, **when** tests run, **then** every detector has at least one hitting case and one clean case, each case yields its expected hit count, and the corpus names no detector the registry lacks.
4. **Given** a `claude/rules/*.md` file with neither a detector nor an opt-out, **when** `harness lint` runs, **then** it fails and names the rule; a missing registry is itself a finding.
5. **Given** the lint's secret check, **when** it runs, **then** it reads its patterns from the registry, and an empty pattern list is a finding, not a pass.
6. **Given** a detector that raises, **when** it runs normally, **then** the error is swallowed; under strict mode it is raised.

## Design

### Approach

A library module, `claude/hooks/rule-detectors.py`, with no lifecycle event of its own: a `Detector(id, rule, kind, fn)` registry and a `run(events)` entry point. The pull request ships fourteen detectors (for example whole-file `cat`, unfiltered `find`, a subagent brief with no word cap, `--no-verify`, a secret in a write, a non-conventional commit subject, a missing trailer) and an opt-out for the three rules nothing in a transcript can decide. `bin/harness lint` gains `check_detectors`.

### Decisions and alternatives

- **Hits carry no text.** A hit records where, never what, so the registry never copies transcript content (from the issue).
- **One source for secret patterns.** The lint imports them from the registry so the two cannot drift.
- **No session behaviour change here.** The worker wiring is #59.

### Do not implement

- Running the registry at session end, or reporting it (deferred to #59 by the issue).

### Later change

At `origin/main` the detector engine is vendored from `ruleprobe` and `rule-detectors.py` is the harness's rule pack (PR #488); FR-19 records seventeen detectors, six generic and eleven specific to this repository.
