## Story

As a developer who does not use the harness, I want the rule-measurement engine as a standalone
package, so that I can measure my own agent's rules against my own transcripts without installing the
harness's way of working.

## Context and value

The instrument epic (#443) sets the sixty-second test as the design bar: a stranger with a CLAUDE.md
and existing transcripts learns which of their rules fired. The rule-agnostic half of
`claude/hooks/rule-detectors.py` (`analyse()`, the shell tokenizer, event construction) and the Claude
Code and Codex transcript readers in `usage-log.py` were the library; the repository's own detector
entries were not. This story is the carve-out, the first story the epic lists.
[Source: https://github.com/JakeSelby/agent-harness/issues/443]
[Source: https://github.com/JakeSelby/agent-harness/issues/451]
[Source: _bmad-output/planning-artifacts/v0.13-adoption-release-plan.md#Step 5 — Carve out the measurement engine]

## Acceptance criteria

1. **Given** the new package, **when** it is built and tested on Python 3.9, **then** it passes with no
   dependency on this repository.
2. **Given** its public API, **when** it is imported, **then** `iter_sessions`, `run`, `Registry` and
   `report` exist with the signatures in the 0.13 release plan.
3. **Given** the detectors, **when** the package ships, **then** it carries the six generic detectors
   and none of this repository's other detectors.

## Design

### Approach

The release plan names the package layout (`events.py`, `shell.py`, `registry.py`, `report.py`,
`cli.py`, `readers/claude_code.py`, `readers/codex.py`, `detectors/common.py`) and the six generic
detectors: whole-file-cat, unfiltered-find, no-verify, secret-in-write, compact and model-switch. Both
transcript readers already emitted the same event schema, so they moved without reshaping. The work
landed as commit 9bce55a in the `ruleprobe` repository, an MIT repository kept private until
publication (#453).
[Source: _bmad-output/planning-artifacts/v0.13-adoption-release-plan.md#Step 5 — Carve out the measurement engine]
[Source: https://github.com/JakeSelby/agent-harness/issues/451]

### Decisions and alternatives

- **Split, not a wholesale move:** the generic engine and six detectors leave; the repository's own
  detector entries stay as its rule pack (#454).
- **Name provisional:** the plan required a PyPI and GitHub availability check before filing.
[Source: _bmad-output/planning-artifacts/v0.13-adoption-release-plan.md#Step 5 — Carve out the measurement engine]

### Do not implement

- This repository's own detectors in the package. [Source:
  https://github.com/JakeSelby/agent-harness/issues/451]
- Detector generation from rule prose: the plan puts it in a later `ruleprobe` version. [Source:
  _bmad-output/planning-artifacts/v0.13-adoption-release-plan.md#Step 5 — Carve out the measurement engine]
