## Story

As a developer whose session was already running when `harness sync` installed the band workers, I want
that session to start routing unnamed spawns once its runtime can resolve the workers, so that routing
is not lost until I restart.

## Context and value

Since #258 (under #257), routing is decided from a record of the agent definitions present when the session started,
because a reroute to a type the running session cannot resolve fails the spawn. The issue calls that
gate deliberately conservative. Claude Code was observed announcing newly installed agent types to a
long-running session some time after a sync, so such a session could route safely from that point, but
nothing told the hook that the registry had reloaded.
[Source: https://github.com/JakeSelby/agent-harness/issues/263]

## Acceptance criteria

1. **Given** a reliable signal that the registry reloaded, **when** it appears, **then** the session's
   routing record is refreshed from it; or, if none exists, the investigation records that with the
   evidence and the conservative gate stays. (Delivered: a signal was found.)
2. **Given** a Claude Code transcript's `agent_listing_delta` attachments after the initial one, **when**
   an unnamed spawn arrives, **then** routing applies their `addedTypes` and `removedTypes` in order.
3. **Given** an `isInitial` listing, **when** it is read, **then** it replaces everything before it, so
   a resume narrows and never widens.
4. **Given** an absent or unreadable transcript, a listing that fell out of the read tail, a worker
   removed again, or a session that reloaded nothing, **when** an unnamed spawn arrives, **then** it
   routes exactly as before.
5. **Given** any case, **when** routing and pricing decide, **then** a reroute never turns a working
   spawn into a failing one, and no spawn is priced by one band and routed to another.

## Design

### Approach

`policy/hooks/posture.py` reads the later `agent_listing_delta` attachments from a bounded 256 KiB tail
of the transcript. What the tail found is kept in the session record under `announced`, so routing
survives the delta scrolling out of the tail. The start-time record stays the floor.
`policy/hooks/tier-agent-spawns.py` and `policy/hooks/brief-guard.py` call the same function with the
same transcript.

### Decisions and alternatives

- **Replace, not merge, the `announced` memory:** a removal is never undone, and a `resume` narrows it
  to what is still on disk.
- **Strict record matching:** the tail splits on newlines alone, and a record counts only when it is
  this session's own `attachment` and not a sidechain.
- **Evidence first:** the spike note `docs/spikes/2026-09-22-registry-reload.md` measured eight
  sessions: interactive sessions reload within seconds, including for a user-scope symlink, the shape
  sync writes; headless sessions never do.

### Do not implement

Not recorded in the issue or pull request. The PR notes one limit nothing in the harness can shorten: a
reload mid-turn is only attached at the next user turn, so routing resumes one turn later than it could.
