## Story

As a user reading the compatibility catalog, I want a qualification claim rejected whenever any linked
evidence record for a case failed or is unverified, so that a passing record can never hide a failure or a
mismatched client version.

## Context and value

This is a delivery slice of #98, under epic #93, recording ownership of the already open PR #132. The PR
records the defect: passing results were unioned, so a passing record could hide a failed one for the same
case. The contradictory pass/fail and concurrent-replacement fixtures reproduced their defects before the
fixes.
[Source: https://github.com/JakeSelby/agent-harness/issues/178]

Taken from the issue's own acceptance section. The outcomes listed under AC 1 restate the

1. **Given** PR #132, **when** it is reviewed, **then** its implementation and documentation satisfy the

   1. **Given** a case with one passing and one failed or unverified record, **when** qualification is

   2. **Given** evidence, **when** it is matched, **then** it must match the exact runtime and client versions

4. **Given** native evidence, **when** it is reported, **then** it names its exact tested source and

## Design

### Approach

`lib/harness_core/compatibility.py` reads each evidence file once, hashes and parses the same bytes, and
evaluates every linked record per case, failing the case on any failed or unverified result.
`docs/compatibility.md` documents the rules. [Source: https://github.com/JakeSelby/agent-harness/pull/132]

### Decisions and alternatives

- **Any failure wins over any pass for the same case:** replaces the union of passing results.
- **One snapshot for hash and parse:** closes the concurrent-replacement window.
- Alternatives considered are not recorded in the issue or pull request.

### Do not implement

- New client qualification; the PR qualifies no client.
