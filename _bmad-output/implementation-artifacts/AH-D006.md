# AH-D006 — grade-bash refuses a sub-issue delete that bmad_issue_sync apply performs unattended

## Context

`grade-bash` refuses a direct `gh api --method DELETE .../issues/98/sub_issue` as grade 3,
irreversible. At `origin/main`, `policy/hooks/grade-bash.py` grades any `gh api` call with method
`DELETE` as grade 3 (`remote-delete`).

The same call runs unattended inside `apply_manifest` in `scripts/bmad_issue_sync.py`. To reparent an
issue, `apply` detaches the sub-issue from its current parent with a `DELETE`, then attaches it to the
new parent with a `POST`. If the attach fails, it tries to re-attach the sub-issue to the old parent.

The issue records the effect on 2026-09-21: a one-line reparent of #134 had to be handed to the user,
while `apply` reparented other issues in the same session without a prompt.

The issue's own analysis: the asymmetry is inherent to grading shell commands rather than effects, and
"not obviously wrong", because a script the repository owns and tests is a different risk from an
ad-hoc command. But it is undocumented, and an agent that hits the refusal has an obvious, silent way
around it: record the change in the map and run `apply`. Nothing stops that, and nothing notices.

The 2026-09-23 PRD lists this as open question 3: "Command grading refuses a sub-issue delete that the
sync tool's `apply` performs unattended (#421). Which side changes?" It blocks FR-9 and FR-35, and is
needed by v0.14.0.

## Options

From the issue, which gives no case for or against options 1 and 2, and for option 3 only that a
sub-issue link is trivially restorable:

1. **Accept and document it.** The grade applies to ad-hoc commands; repository-owned scripts carry
   their own review. Say so in the `sandbox` skill or `docs/how-it-works.md`, and state plainly that
   rerouting a refused action through a script is not permitted.
2. **Grade the effect.** Have the script call the same check before a destructive API call, so both
   paths prompt.
3. **Lower the grade for this specific call**, since a sub-issue link is trivially restorable by
   re-adding it.

## Decision

Open: the maintainer decides which side changes. The PRD records it as open question 3, owned by the
maintainer and needed by v0.14.0.

A nearby rule already exists: `primitives/rules/working-style.md` says "Never script around a refused
provisioning gate". [ASSUMPTION: whether that rule already covers a refused `gh api DELETE` is not
recorded; it names provisioning gates only.]

## Consequences

From the issue's Acceptance section:

- a decision is recorded with its reasoning;
- if the asymmetry stands, the rule against rerouting a refused action through a script is written
  where an agent will read it.

Option 3 changes the grade `policy/hooks/grade-bash.py` assigns to this call, which FR-35's 0-to-3
scale governs. Option 2 adds a check to
`apply_manifest`.

Bound requirements: FR-35: Graded shell commands, and FR-9: Traceable work items, both named by the PRD
question. Bound decision: AD-7: What a hook may and may not do. [ASSUMPTION: AD-7 binds FR-35 and says
enforcement may rely on pre-tool deny or ask; it does not address scripts.]
