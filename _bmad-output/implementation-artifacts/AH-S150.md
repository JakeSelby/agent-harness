## Story

As a developer ending a finished agent session, I want one `/close-out` workflow that sweeps for open
work, lands and hands off through the existing workflows, and archives only when asked, so that the
end-of-session sequence stops being re-derived by hand and stops leaking.

## Context and value

Sessions ended with the same ask in different words, and each one re-derived the same sequence by hand.
The issue names the leaks of the ad-hoc version: a refused worktree cleanup reported as "already gone",
another session's untracked scratch files turning the stop gate red, and stale worktrees and follow-up
work left unrecorded. `/land` already owned the merge, the worktree and the release check, and `/handoff`
owned the progress file and durable learnings; the gap was the session-level wrapper around them.
[Source: https://github.com/JakeSelby/agent-harness/issues/426]

## Acceptance criteria

1. **Given** `primitives/workflows/close-out.md`, **when** `harness generate` runs, **then** it is
   projected to `claude/commands/` and to the Codex skill view.
2. **Given** an invocation, **when** the workflow starts, **then** it sweeps for open work (dirty
   checkouts, `harness worktree audit`, the session's pull requests and their checks, running background
   work, parked decisions) before changing anything, and an empty sweep is a stated result.
3. **Given** a merge or a progress file is needed, **when** the workflow reaches it, **then** it
   delegates to `land` and `handoff` and never inlines their steps.
4. **Given** follow-up work, **when** it is found, **then** it is batched as proposed issues and filed
   only on an explicit go-ahead, never fixed in place instead.
5. **Given** sibling sessions to reach, **when** the workflow reaches them, **then** it names no
   client-specific tool.
6. **Given** any close-out, **when** it ends, **then** it never clears or compacts before archiving, and
   archives only when the invocation asked it to.
7. **Given** the command tests, **when** they run, **then** each criterion above is covered and the body
   stays inside the existing 35-line cap.

## Design

### Approach

A thin workflow that wraps the ones that already exist rather than restating them: sweep first, then
delegate the merge to `land` and the progress file to `handoff`, batch follow-ups for a gated filing
step, and archive last and only on request. It is authored once under `primitives/workflows/` and
projected to every runtime.

### Decisions and alternatives

- **Delegate rather than inline.** A test asserts the body never inlines `gh pr merge`.
- **Runtime-neutral sibling contact.** Workflows project to Codex too, where client-specific session
  tools do not exist, so the body names none.
- **Landing copy.** The ritual line in `product.json` and the README had omitted `/land`; both were
  updated to name the full set, and the pitch count was made to match.

### Do not implement

Not recorded in the issue or pull request.
