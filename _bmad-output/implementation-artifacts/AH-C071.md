## Goal

Publish 0.13.1, the patch that ships the control-plane landing copy (#764) with the #743 timing-test
fix. The reference site renders `product.json` from the harness release it pins, so the new copy
reaches it only in a release. The candidate opened in #766; what remains is the dated changelog
section, released status prose, and the round-6 native evidence that lets
`scripts/release_preflight.py` publish.

## Acceptance criteria

1. **Given** `CHANGELOG.md`, **when** the release is read, **then** `## [Unreleased]` is empty and
   `## [0.13.1] — 2026-09-24` holds a Changed block with #764 and a Fixed block with #743,
   assembled from the fragments, and the #765 waiver is not rendered.
2. **Given** `changelog.d/`, **when** the release lands, **then** it holds only its README and this release's own waiver, which is never rendered.
3. **Given** `README.md`, `docs/compatibility.md` and `docs/releasing.md`, **when** they are read,
   **then** each states 0.13.1 as released on the two Claude Code CLI targets, changing the landing
   copy only against 0.13.0, and 0.11.1 as the last release qualifying the Codex CLI, and
   `tests/test_docs.py` pins the README wording, `**Qualified:**` included.
4. **Given** round 6 of the native qualification at the candidate commit, **when** a strong-class
   assessment reads its records, **then** `claude-code-cli-macos` and `claude-code-cli-linux` are
   qualified, the evidence is committed, and the catalog is `released`, pinned to the round's
   source commit, with its limitations current.
5. **Given** a fresh clone of the merged commit, **when** `release_preflight.py` runs, **then** it
   is clean.
