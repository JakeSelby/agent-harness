## Goal

Name the decision log in `product.json`, the one source of the landing copy, the README grid and the GitHub
About description, and say plainly what it records and where it stays. #385 shipped `harness usage --by
decision` and a local `decisions.jsonl`, a user-visible capability, without touching `product.json`, although
`AGENTS.md` requires that update in the same pull request; nothing enforced the rule, and #385 passed every
check. The issue asked for a narrow line: the log records what a hook decided and what settled it, on this
machine, and nothing reads it yet but `harness usage`. It also asked whether the rule deserves a check.
[Source: https://github.com/JakeSelby/agent-harness/issues/390]

## Acceptance criteria

1. **Given** `product.json`, **when** the change lands, **then** the cost group names the decision log in a
   line under the 170-character cap and free of em dashes.
2. **Given** the release tests, **when** `python3 -m unittest tests.test_release` runs, **then** it passes
   and the README grid matches.
3. **Given** the rule in `AGENTS.md`, **when** it is considered for a check, **then** either a check exists
   or a separate issue is filed. (The PR built the check: `landing-copy`.)
4. **Given** a pull request that changes `bin/`, `lib/`, `adapters/`, `primitives/` or `policy/` without
   `product.json`, **when** `landing-copy` runs, **then** it fails unless the body carries a `Landing copy:`
   line saying why no update is needed; a docs-only, tests-only or CI-only pull request never fires it.

Out of scope, per the issue: promoting the Jev `on_the_way` entry, and any change to the log or the command.

### Design as built

- **Extend, not add:** the `spend-less` group is already at the six-feature cap `tests/test_release.py`
  enforces, so the existing `Live usage feed` line is extended rather than a seventh feature added. The issue
  asked for "one feature line"; this is the recorded reason it is an extended line.
- **A new workflow, not a step in `issue-ownership`:** branch protection references that check's name.
- **Retro-run in the PR:** the check fails #385 and #384, which each changed a user-visible CLI capability
  without touching `product.json`, and does not apply to #383, #382 or #326.
