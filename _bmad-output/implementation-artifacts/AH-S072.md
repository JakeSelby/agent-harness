## Story

As a developer running several sessions at once, I want a project or session stance choice resolved at
session start instead of written into the global projections, so that one session's choice never changes
the policy another session is running under.

## Context and value

This delivery slice of #94, under epic #93, records ownership of the already open PR #106, which also references #95. The global
projections in the user's configuration home are shared by every session. A stance choice made for one
project or session had been mutating them, which changed the policy of every other session too.
[Source: https://github.com/JakeSelby/agent-harness/issues/168]

## Design

### Approach

`bin/harness` stops rendering project and session selections into the global projection, and
`policy/hooks/harness-session.py` resolves them into policy text at session start. The Claude renderer
computes the personal-file import from the configured home, and the Codex projection points at the
shared instructions rather than a rendered copy. `docs/runtime-installation.md` records the behaviour.
[Source: https://github.com/JakeSelby/agent-harness/pull/106]

### Decisions and alternatives

- **Resolve at session start rather than at sync:** the only place a per-session choice can apply
  without touching shared files.
- Alternatives considered are not recorded in the issue or pull request.

### Do not implement

- Native qualification and publication (#98, #100).
