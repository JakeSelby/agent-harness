## Goal

One kernel helper performs every whole-file rewrite: write a temporary file, fsync it, replace the
target atomically, and keep the target's mode. AD-18 in the 2026-09-23 spine requires it, so that
concurrent sessions on one machine never leave a half-written file or a changed mode. Append-only
ledgers stay as they are.
[Source: https://github.com/JakeSelby/agent-harness/issues/645]

## Acceptance criteria

1. **Given** any whole-file rewrite in scope, **when** it writes, **then** it goes through the helper.
2. **Given** a file with a non-default mode, **when** the helper rewrites it, **then** a test proves the
   mode is kept.
3. **Given** an interrupted write, **when** the helper is stopped part-way, **then** a test proves no
   partial file survives.

## Dev notes

- **Bound decisions:** AD-18, Shared-machine concurrency and writes: one shared helper that writes a
  temporary file, fsyncs, replaces atomically and keeps the mode; it lives in the kernel. AD-11 keeps
  ledgers append-only apart from the usage worker's `upsert`.
- **Bound requirements:** NFR-10, Concurrency safety.
- **Current state on `main`, checked against the issue:**
  - `bin/harness` `write_json_atomic` builds its temporary name as `path.name + ".harness-tmp"`, a fixed
    suffix rather than a fixed name, so two writers of the same file share one temporary path; it does
    not fsync and does not keep the mode. The issue calls this a "fixed temporary name without fsync".
  - `lib/harness_core/reconcile.py` `atomic_text` uses a unique temporary file and fsyncs, but does not
    keep the mode.
  - `scripts/cost_bench.py` `atomic_write` already fsyncs and keeps the mode (`os.chmod` from the
    target's `st_mode`), as of commit a36b4fe (#609). The issue's "None of them keeps the file's mode"
    is out of date for this writer.
  - `scripts/bmad_issue_sync.py` also fsyncs and keeps the mode; the spine records that the sync tool
    already writes this way (#629).
- **Recorded scope gap:** the issue names three writers. AD-18 names seven that converge on the helper
  under #636: `bin/harness`, `reconcile.py`, `cost_bench.py`, `posture.py`, `stop-gate.py`,
  `usage-feed.py` and `usage-log.py`. Each of the last four has its own temporary-file-and-replace code
  on `main`. Moving only three leaves AD-18's migration note standing, while epic #636's acceptance is
  that the spine's migration notes are removed [Source: https://github.com/JakeSelby/agent-harness/issues/636]. The issue was not changed.
- **Files to touch:** a new kernel helper module, the three writers the issue names, and tests.
