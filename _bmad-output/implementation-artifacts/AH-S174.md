## Story

As a developer reading the usage report, I want to see how much the deduplication removed, so that two
sessions with the same corrected total but very different duplication are not indistinguishable.

## Context and value

`usage-log` kept the largest figure each message id reported per field and discarded the raw sum, so
the size of the correction was invisible: a transcript that repeated every response and one that
repeated none reported the same figure. `docs/usage.md` already said per-line counting inflates every
total. Item B2 of the 2026-09-22 enterprise-review intake.
[Source: https://github.com/JakeSelby/agent-harness/issues/518]
[Source: https://github.com/JakeSelby/agent-harness/pull/587]

## Acceptance criteria

1. **Given** a session row, **when** it is written, **then** it carries `raw_vs_deduped`: the per-line
   sum of the four token fields over the deduplicated total, over the session's records and the
   subagent files folded into them.
2. **Given** `harness usage`, **when** it prints, **then** the token-weighted ratio for the window
   appears beside `unpriced`, weighted where the columns count, so under `--days N` a long session is
   weighted by its in-window slices.
3. **Given** an export, **when** a session row is sent, **then** the OTLP record carries the row's own
   ratio as a `raw_vs_deduped` attribute.
4. **Given** a Codex session row, a subagent, worker or pre-release row, **when** the ratio is read,
   **then** it is `unknown` or absent and read as unknown, never defaulted to `1.0`.
5. **Given** `docs/usage.md`, **when** a reader reads it, **then** it states that the ratio is the
   measured inflation and that cache reads dominate it.
6. **Given** a fixture transcript with a known duplication pattern, **when** the tests run, **then** the
   ratio matches.

## Design

### Approach

`policy/hooks/usage-log.py` accumulates the raw per-line sum alongside the deduplicated slots and
writes the ratio on the session row; `bin/harness` prints the window figure in the footer. Built on
#519's slot rules (#565), so the ratio covers exactly the slots the totals cover.
[Source: https://github.com/JakeSelby/agent-harness/pull/587]

### Decisions and alternatives

- **One ratio, not one per field:** the fields are deduplicated by the same slots, and the row already
  carries each field apart. The issue left this choice to the story.
- **Subagent rows carry no ratio:** their records are in the session's figure.
- **Codex reads `unknown`:** its snapshots are cumulative.
[Source: https://github.com/JakeSelby/agent-harness/pull/587]

### Do not implement

- A new command or flag; the figure sits in the footer. [Source:
  https://github.com/JakeSelby/agent-harness/pull/587]
