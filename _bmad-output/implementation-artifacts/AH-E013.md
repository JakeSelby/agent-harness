## Goal

Own the evidence that the harness is worth its cost. That covers three things:

- the live benchmark against a bare arm;
- the instrument's own correctness;
- the cheap evaluation tiers that let a rule change be tested without a full live run.

Completion is observable as the issue's two acceptance items. First, a live result on the release task set
is published, pass or fail, at the minimum power the PRD states. Second, every mechanism a saving is
credited to shows in the ledger rows that it fired.

The PRD makes the cost claim conditional on this evidence (SM-2 Measured cost claim), and decides a stop
condition. If the release task set on clean snapshots shows no harness win on long tasks, the instrument
findings are published and the saving claim is retired. §4.6 then stands on routing control and
legibility, not on savings.

## Architecture slice

- **AD-12 Measurement invariants:**
  - Compare ratios across days, never dollars.
  - Arms differ only by environment, and each fence is proved before scoring.
  - Unknown values are never zero, and an errored run is never a failure.
  - Micro-tier rows never enter the production series. This governs #512's tier.
  - Every row records its arm's provenance.
- **AD-13 Detector logic lives in `ruleprobe`:** the harness binds rules to detectors, and vendors the
  engine without forking it. The two detectors under the floor, `secrets/git-add-secret-file` and
  `autonomy/denied-by-grade`, are repository-specific (#602). So they are tightened in the harness rule
  pack, not in the vendored engine.
- **AD-14 For cost, hooks only route and refuse frontier:** budgets, feeds and nudges are information, and
  no hook denies for cost. The delegation nudge (#513) is a nudge under this rule.

- The confounds (#428, #482) come out before a live result on the release task set counts as

## Exit criteria

From the issue's Acceptance section and the PRD:

- [ ] A live result on the release task set is published, pass or fail, from three or more reps, with the
  per-task figures beside the headline (SM-2).
- [ ] Every mechanism a saving is credited to shows it fired in ledger rows. Under `cost=balanced`, the
  harness arm spawns at least once on a task above the break-even (FR-34).
- [ ] Every detector scores at or above the 0.9 precision floor, and none is recorded as known below it
  (FR-22, #602).
- [ ] If the result shows no harness win on long tasks, the instrument findings are published and the
  saving claim is retired (SM-2's stop condition).
- [ ] The scoped issues held by #529 receive BMad IDs and join this epic.
