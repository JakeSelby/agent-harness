# AH-C038 — Document the single-coordinator dispatch model and drop the dead hook entries from the template

## Goal

Document the single-coordinator dispatch model as a property, and stop committing hook entries nothing
reads. `runtime_template()` replaced `claude/settings.template.json`'s hooks block wholesale with
`lifecycle.registration()` at sync, so the per-policy entries in the template were dead, and an entry
added there by hand would have been discarded silently. Item B10 of the 2026-09-22 enterprise-review
intake.
[Source: https://github.com/JakeSelby/agent-harness/issues/521]
[Source: https://github.com/JakeSelby/agent-harness/pull/567]

## Acceptance criteria

1. **Given** `docs/how-it-works.md`, **when** a reader reaches the authority section, **then** it states
   that a sync registers one coordinator command per lifecycle event, that precedence is decided in
   `lifecycle.py` rather than by registration order, and that the coordinator fails closed.
2. **Given** `claude/settings.template.json`, **when** it is read, **then** it carries no hooks block.
3. **Given** the runtime template, **when** `tests/test_dispatch_model.py` runs, **then** its hooks equal
   the coordinator's registration, every registered command names a script on disk, and hook health
   finds them all.
4. **Given** a live Claude Code settings file, **when** it is merged before and after the change,
   **then** the result is identical.
5. **Given** the behaviours the retired per-hook registration tests carried (per-event timeouts: Stop
   300 s, SessionEnd 2 s, otherwise 10 s; tool routing for plan-mode WebFetch, tier-agent-spawns and
   brief-guard), **when** the tests run, **then** they are asserted through `lifecycle`.
