## Reproduction

As filed on 2026-09-22: run `tests/test_codex_reviewer_key.py` on a machine with a `codex` binary on
`PATH`. `DetectionTests.test_no_client_on_path_writes_the_newest_supported_spelling` asserts a status of
`absent`, gets `detected`, and fails:

```
AssertionError: Tuples differ: ('detected', 'approvals_reviewer') != ('absent', 'approvals_reviewer')
```

The issue records the proof: two runs on an unchanged tree, 18 of 18 passing with no `codex` on `PATH`,
one failing with it. CI has no Codex client, so CI never sees it.

**This no longer reproduces at `origin/main`.** PR #615 (merged 2026-09-23) fixed the test under a
separate issue, #606, which it closes.

## Root cause

From PR #615's body: the test "prepended an empty directory to `PATH` and kept the rest, so on a
machine with Codex installed it found the real client and got `detected` instead of `absent`."

## Acceptance criteria

From the issue's Acceptance section, with the state at `origin/main`:

1. **Given** the module, **when** it runs with and without a `codex` binary on `PATH`, **then** it
   passes both ways. Delivered by PR #615, whose checklist records "2626 tests OK on a Mac with Codex
   installed, where this test failed before".
2. **Given** any other test that reads a real client from `PATH`, **when** the audit this item asks for
   is done, **then** each one is given the same treatment. Not delivered: PR #615 changed only
   `tests/test_codex_reviewer_key.py`, and no audit of other tests is recorded.

## Design

As built in PR #615: with no client, the fake sets `PATH` to the empty directory alone, so the test is
hermetic whatever the machine has installed. The code comment at `origin/main` reads: "No client means
none at all: keeping the rest of PATH would find one the machine has."

The issue asked to point detection at a controlled `PATH` "the way `SyncTests.doctor` does". The same
module has a `doctor` helper, and so do `tests/test_keychain.py` and `tests/test_native_telemetry.py`.
The issue also says the pattern is "already documented in `AGENTS.md`"; `AGENTS.md` at `origin/main`
does not mention it.

**Duplicate recorded.** #606 and this issue describe the same failing test. #606 closed as completed
through PR #615; this issue is still open, with AC 2 outstanding.

Do not implement: the issue records no out-of-scope item.

## Regression test

The existing `test_no_client_on_path_writes_the_newest_supported_spelling` is the regression test,
made hermetic by PR #615. It fails on a machine with Codex installed before the fix, and passes after.
