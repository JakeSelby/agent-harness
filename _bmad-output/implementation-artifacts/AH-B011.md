# AH-B011 — Stop reporting a managed link as redirected when it reaches its file through an alias

## Reproduction

1. Sync with stances selected. `claude/stances` is a link to `primitives/stances`, so each stance file
   is reachable under two spellings of the checkout.
2. Let `ensure_link` accept an existing link that reaches the wanted file through the other spelling.
3. Run `harness diff` or `harness doctor`, then `harness uninstall`.

Observed: every selected stance is reported as a "redirected link" on every run, and uninstall leaves
those links behind as if the user had changed them.
[Source: https://github.com/JakeSelby/agent-harness/issues/237]

## Root cause

`ensure_link` recorded the new spelling in the manifest while the old one stayed on disk. The drift
report, uninstall and both link-retirement paths then compared the recorded target and the link on disk
as text, so two spellings of the same file looked like a user redirect.

## Acceptance criteria

1. **Given** a managed link that leads to its recorded target through an alias of the checkout, **when**
   `harness diff` or `harness doctor` runs, **then** it reports no drift.
2. **Given** the same link, **when** `harness uninstall` runs, **then** it removes the link.
3. **Given** a link pointed at a different file, **when** any of the four judgments runs, **then** it is
   still reported as a redirect and still preserved.
4. **Given** the change, **when** the gate runs, **then** lint is clean and the suite passes.

## Design

One helper, `_leads_to` in `bin/harness`, decides whether a symlink leads to a target: by that spelling,
or by resolving to the same file. The drift report, uninstall and both link-retirement paths use it.
A link pointed at a different file is unchanged in treatment: reported and preserved.

## Regression test

`tests/test_harness.py`, class `LinkAliasTests`, as of #238:
- `test_an_alias_of_the_recorded_target_is_not_drift_and_a_real_redirect_still_is`;
- `test_uninstall_removes_an_aliased_link_and_preserves_a_real_redirect`.
