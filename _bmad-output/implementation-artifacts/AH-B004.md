## Reproduction

From the issue: run `/build`, `/review`, `/handoff` or `/plan` outside a git repository, or `/build` without a GitHub account. `/build` creates a worktree, runs the gate and only fails at `gh pr create`, after the work has started. `/review` stops at `git diff --stat <base>...HEAD` when the base does not resolve. `/handoff` overwrites `.claude/progress.md` "at the repository root", and `/plan` writes into `.claude/plans/`. Only `/research` works anywhere.

## Root cause

Each command assumed a git repository and discovered otherwise partway through its steps, because none stated or checked a precondition before starting, and none named a fallback (from the issue).

## Acceptance criteria

1. **Given** a command that needs a repository, **when** it starts, **then** its first step states and checks that precondition before any work begins.
2. **Given** `/build` with no repository, **when** it runs, **then** it offers to make the change in place; with a repository but no remote or no `gh`, **then** it stops at the local commit.
3. **Given** `/review` outside a repository, **when** it runs, **then** it says there is no diff before either pass spawns, and offers named files or a pasted patch.
4. **Given** `/plan` or `/handoff` with no repository root, **when** they run, **then** they write beside the work in the current directory, and `/plan` says it needs neither a repository nor code.
5. **Given** every command, **when** its body is measured, **then** it stays under the 35-line cap.

## Design

Each command gains an explicit precondition line as its first step and a named fallback, not a bare stop, as the issue proposed. `/plan` and `/handoff` degrade to writing beside the work. The fix must not break the 35-line body cap.

## Regression test

`tests/test_commands.py`: `test_every_command_that_needs_a_repository_says_so_before_it_starts`, `test_the_repository_bound_commands_name_a_fallback_rather_than_only_stopping`, `test_the_writing_commands_have_a_path_outside_a_repository` and `test_plan_states_that_it_needs_no_repository`.
