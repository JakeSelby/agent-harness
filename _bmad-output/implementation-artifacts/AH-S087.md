## Story

As a user choosing a Claude Code client, I want the macOS CLI, Linux CLI and macOS VS Code extension
qualified by native evidence against the frozen 0.9.0 source, so that the catalog can claim Claude Code
support for 0.9.0 and state any limitation explicitly.

## Context and value

A child of #98 under epic #93. The catalog could not claim Claude Code support until the three tuples
passed every required native case. Most cases were covered, but the `auto` permission posture needs a
model Claude Code accepts for Auto Mode, and the model it required was not callable on the tested provider
account. The issue comments record the diagnosis and conclude that the result is an account capability
boundary, not a harness or permissions defect.
[Source: https://github.com/JakeSelby/agent-harness/issues/187]

## Acceptance criteria

1. **Given** all three Claude Code tuples, **when** qualification completes, **then** every required case is
   `passed`.
2. **Given** each requested permission posture, **when** the client starts natively, **then** the posture is
   observed and has the expected write consequence.
3. **Given** CLI and editor hook trust, BMad, role boundaries and handoff, **when** they are exercised,
   **then** they pass without weakening native restrictions.
4. **Given** the evidence, **when** it is published, **then** it contains no credentials or private paths
   and matches its catalog hash.
5. **Given** the change, **when** the gate runs, **then** lint, the full suite, generation checks and an
   independent evidence review pass.

## Design

### Approach

Complete redacted native evidence for the three tuples, exercising manual, Auto Mode and acknowledged
bypass with a model that retains each requested posture, and finish the editor-specific BMad and hook cases
in an unlocked VS Code client. Link evidence by SHA-256 and regenerate the support surfaces.
[Source: https://github.com/JakeSelby/agent-harness/issues/187]

### Decisions and alternatives

- **Use a callable model for non-Auto work:** an issue comment directs non-Auto qualification work to a
  model that was callable but did not support Auto Mode, and keeps the Auto posture unverified.
- **Qualify with the limitation stated rather than wait:** the final comment decides that the record will
  qualify the tested behaviour, "manual/deny and acknowledged bypass are validated, while native Auto
  execution is unavailable on this account."

### Do not implement

- Codex qualification (#185, #188).
