## Context

The PRD and the release catalog disagree on when Codex CLI becomes a release requirement
([#686](https://github.com/JakeSelby/agent-harness/issues/686)):

- **FR-12, Release integrity:** "Codex targets stay non-required until one scripted round passes with
  `--home-confirmed` and agrees with a hand-driven round on every case outcome."
  [Source: _bmad-output/planning-artifacts/prds/prd-agent-harness-2026-09-23/prd.md#FR-12: Release integrity]
- **PRD §9.1, the v1.0.0 stable contract:** Codex CLI's place in the 1.0 contract "is conditional. Its
  native cases now have drivers (#336), but one scripted round must still agree with a hand-driven round
  (FR-12)." [Source: _bmad-output/planning-artifacts/prds/prd-agent-harness-2026-09-23/prd.md#9.1 The v1.0.0 stable contract]
- **#206, the v1 release epic (AH-E005):** its stable floor promises Codex CLI on macOS and Linux with no
  such condition, and the issue has not been amended
  [Source: _bmad-output/implementation-artifacts/AH-E005.md].
- **PR #651** (merged 2026-09-23, closing #627) opened the 0.13.0 candidate and set
  `required_for_release: true` for `codex-cli-macos`, beside the two Claude Code CLI targets. AH-E014
  records that the agreement round is not on record
  [Source: _bmad-output/implementation-artifacts/AH-E014.md].

**Current state at HEAD.** `compatibility/catalog.json` is at `harness_version` 0.13.0,
`release_state` candidate. Three targets are `required_for_release: true`: `claude-code-cli-macos`,
`claude-code-cli-linux` and `codex-cli-macos`. `codex-cli-linux` is not required, and #612 gates it.
Every target is `unqualified` [Source: compatibility/catalog.json]. `docs/releasing.md` says a Codex
target reports `unverified` "whatever it observed until `--home-confirmed` says its configuration home
was compared against a hand run" [Source: docs/releasing.md#Source and qualification].
Its Release status section also says the 0.13.0 candidate requires fresh native qualification for "Claude
Code CLI and Codex CLI on macOS and Linux", which is one more target than the catalog requires
[Source: docs/releasing.md#Release status].

## Options

Recorded in the issue ([#686](https://github.com/JakeSelby/agent-harness/issues/686)):

1. **A release may require a Codex CLI target before the agreement round.** FR-12's consequence and
   PRD §9.1 are amended to match the catalog and #206.
2. **It may not, and `codex-cli-macos` returns to optional for 0.13.0.** The catalog changes to match
   FR-12, and #206's floor is amended to state the condition.
3. **It may not in general, but `codex-cli-macos` stays required for 0.13.0 as a stated exception.** The
   exception is written into the release notes, and FR-12 stays as the rule.

The issue records no case for or against any option. [ASSUMPTION: option 3 keeps the 0.13.0 round's
target list as PR #651 opened it; option 2 changes a catalog field in an open candidate.]

## Decision

Decided for 0.13.0 on 2026-09-23, by the owner's call recorded in PR #701 (closes #700).
- **The rule:** a release does not require a Codex CLI target before FR-12's agreement round.
- **For 0.13.0:** `codex-cli-macos` returned to `required_for_release: false`, and Codex CLI is deferred to
  0.14.0. #612 is what lets the acceptance runner drive Codex.
- **Still open:** #206's v1 text, which promises Codex CLI without FR-12's condition. This issue stays open
  until #206 carries that condition.

## Consequences

- The acceptance for this item: the decision is recorded here and in AH-E014, and the catalog, FR-12
  and #206 agree, or the exception is written into the release notes
  ([#686](https://github.com/JakeSelby/agent-harness/issues/686)).
- AD-4 binds FR-12, and its rule that every supported target references passing evidence for the exact
  source revision holds under every option; the choice changes which targets must carry that evidence
  before a release [Source: _bmad-output/planning-artifacts/architecture-spines/architecture-agent-harness-2026-09-23/ARCHITECTURE-SPINE.md#AD-4: Evidence-backed compatibility [ADOPTED]].
- A change to `compatibility/catalog.json` is outside the evidence source paths, so it does not
  invalidate recorded evidence [Source: lib/harness_core/compatibility.py].
- Under option 1, FR-12 and PRD §9.1 change in the same pull request, under FR-65's currency rule.
- The Release status line in `docs/releasing.md` should be brought into line with whichever target list
  results. [ASSUMPTION: the issue does not name this doc drift.]
