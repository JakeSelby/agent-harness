## Story

As a developer running an agent under a chosen autonomy stance, I want every Bash command graded from read-only to irreversible and the grades my stance forbids gated before they run, so that the autonomy stance has a mechanism behind it rather than only a permission mode.

## Context and value

The pull request records that "the autonomy stance finally has a mechanism behind it". The issue specifies a second `PreToolUse` hook on Bash that reuses the read-only decomposition from `allow-readonly-bash.py` and gates by stance, with a confirm path that works in the permission modes where the runtime ignores `ask`.

## Acceptance criteria

1. **Given** a Bash command, **when** the hook grades it, **then** read-only is 0, a local write 1, a remote mutation 2 and an irreversible act 3 (force-push, `reset --hard`, `rm -rf` outside the tree, `DROP`, migrations, deploys, cloud deletes, `sudo`); an unknown command is 1, never 3.
2. **Given** a compound command, **when** it is graded, **then** its highest segment sets the grade; every ALLOW and APPROVED case of the read-only corpus grades 0.
3. **Given** the stance `execute`, `confirm-writes` or `ask`, **when** a command reaches grade 3, 2 or 1 respectively, **then** it is gated; `HARNESS_STANCE_AUTONOMY` overrides config.
4. **Given** a prompting permission mode (`default`, `plan`, `acceptEdits`, `dontAsk`), **when** a command is gated, **then** the hook answers `ask` with a reason naming the grade, verb, target, consequence and stance.
5. **Given** `auto` or `bypassPermissions`, **when** a command is gated, **then** the hook answers `deny` with the same reason and the confirm path.
6. **Given** a command prefixed `HARNESS_CONFIRMED=1`, **when** it is graded, **then** the marker is stripped and it passes at any grade.
7. **Given** any error, **when** the hook runs, **then** it exits silently.

## Design

### Approach

`claude/hooks/grade-bash.py`, registered in `claude/settings.template.json` and `claude/OWNERSHIP.json`, imports the read-only grammar and adds a grading table. `SECURITY.md` gains a line in the threat model.

### Decisions and alternatives

- **Deny where ask is ignored.** The pull request records that the hooks reference says `ask` is ignored in `auto` and `bypassPermissions` while `deny` holds, so those modes get `deny`; the confirm path is a chat "yes" and a re-run with `HARNESS_CONFIRMED=1`.
- **Unknown is local, not irreversible,** so an unrecognised command does not prompt at every stance (from the issue).
- **Fail open.** Any error is a silent exit (from the pull request).

Not recorded in the issue or pull request.
