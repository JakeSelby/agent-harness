## Story

As an orchestrator spawning subagents, I want a hook that appends a return bound to any brief that omits one, so that every subagent's return is bounded without relying on the orchestrator to remember.

## Context and value

The issue cites the detector `transcript-hygiene/brief-without-cap` firing 536 times across 29 of 97 sessions, a 30 percent session share, the second loudest in the registry, although `claude/rules/delegation.md` said "Bound the brief: file list, return schema, word cap". It adapts a principle from `unclebob/swarm-forge`, whose handoff helper fills fields from the worktree so the agent never types them: a field the agent never writes is a field it cannot get wrong.

## Acceptance criteria

1. **Given** an `Agent` spawn whose brief states no word cap and no return schema, **when** the hook runs, **then** it appends a 400-word return bound through `updatedInput` and preserves the other fields.
2. **Given** a brief that already states a cap, or an agent whose definition carries one, **when** the hook runs, **then** the brief is untouched.
3. **Given** `delegation: off`, including through the environment override, **when** the hook runs, **then** it does nothing.
4. **Given** a non-`Agent` tool, an empty prompt, garbage input, a missing config or a failed detector import, **when** the hook runs, **then** it does not raise.
5. **Given** the appended text, **when** the detector searches it, **then** it counts as a bound.
6. **Given** the settings template and `claude/OWNERSHIP.json`, **when** they are read, **then** the hook is registered on the `Agent` event and owned.

## Design

### Approach

`claude/hooks/brief-guard.py`, `PreToolUse` on `Agent` beside `tier-agent-spawns.py`. It imports `WORD_CAP_RE` and `CAPPED_AGENTS` from `rule-detectors.py` rather than copying them.

### Decisions and alternatives

- **Fix, don't deny.** The pull request records that a denied spawn costs the orchestrator a turn and teaches nothing, while a rewritten one proceeds and the system message says what changed.
- **The parity test is load-bearing.** Without it the hook could append text the detector still counts as missing, and the metric would never move.
- **Share the detector's pattern** rather than copy it.

### Do not implement

Not recorded in the issue or pull request.

### Later change

FR-31 now describes the brief guard adding a soft budget (expected output tokens and tool calls) to a brief that lacks one; this story's 400-word return bound is the v0.7.0 behaviour.
