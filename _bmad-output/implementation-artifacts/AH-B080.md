# AH-B080 — A native evidence record pairs its observations with the wrong cases

## Reproduction

Round 4 of the 0.13.0 native qualification (source commit `ebf2674`, both Claude Code CLI targets)
ran all 12 cases, and the strong-class assessor found: "`cases` is sorted alphabetically, but
`observations` follow the catalog's `required_cases` order. Pairing them by the position of the
keys in `cases` puts 10 of the 12 observations against the wrong case." Reproduced by running
`scripts/native_acceptance.py --client claude-code-cli-macos --out <path>` and reading the record:
`cases` comes out alphabetical, `observations` in run order, and a case finishing without an
observation drops out of the list and shifts every later position.

## Root cause

`build_record` in `scripts/native_acceptance.py` kept `observations` as a bare list aligned with
`cases` by insertion order, skipped a case without one, and nothing in an observation named its
case. `main` then writes the record with `json.dumps(..., sort_keys=True)`, which reorders the
`cases` object and leaves the list alone.

## Acceptance criteria

1. **Given** cases finished in the catalog's run order, **when** the record is written, **then**
   every case observation opens with `<case>: ` and the list follows the written `cases` order.
2. **Given** a case that finished without an observation, **when** the record is built, **then** it
   still has an entry saying no observation was recorded, so no other entry shifts.
3. **Given** an old durable log whose lines hold bare observations, **when** it is rebuilt with
   `--from-progress`, **then** the rebuilt record pairs by case the same way.
4. **Given** a note the round runner appends, **when** the record is read, **then** it carries no
   case prefix and so stays distinguishable from a case observation.
5. **Given** the evidence records committed under `compatibility/evidence/`, **when** the validator
   runs, **then** they still validate.

## Design

`build_record` now sorts `cases` itself and emits one observation per case through `named`, which
prefixes `<case>: ` unless the text already carries it, and substitutes `NO_OBSERVATION` for a
case with none. The pairing is applied when the record is built, so a rebuild of an old log gains
it. Round-level notes stay unprefixed, which leaves `scripts/qualification_round.py` and its string
de-duplication unchanged. `observations` stays a list of strings, so the validator's accepted
shape and the committed records are untouched. Rejected: turning `observations` into an object
keyed by case, which the validator, the committed records and the round runner's appends would
all have to change for; a `round: ` prefix on round notes, which would edit the round runner for
no gain once every case observation is named.

## Regression test

`tests/test_native_acceptance_record_pairing.py`.
- **Before the fix:** 4 of its 7 tests fail against the old `build_record`.
- **After the fix:** all 7 pass. Three assertions in `tests/test_native_acceptance.py` and
  `tests/test_native_acceptance_progress.py` that compared bare strings now expect the prefix.
