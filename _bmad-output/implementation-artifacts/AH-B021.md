# AH-B021 — BMad review confinement is requested in a prompt, not enforced at the spawn hook

The issue carries the summary, discussion and acceptance evidence; this file carries the design.

This work item was authored as part of the repository's committed BMad planning system.
<!-- bmad-sync:end -->

## Reproduction

1. Run `harness bmad apply`, which routes the BMad code-review layers to the confined `reviewer` role by
   replacing each layer's instruction text with "launch `harness role run reviewer` ...".
2. Run a BMad code review on a client that spawns an unnamed native subagent carrying the reviewer
   brief.

Observed by native qualification on `claude-code-cli-linux` in two rounds: from the assigned worktree as
project root the resolver returned the upstream, unrouted layers; with the framework checkout as both
project root and cwd, 1 of 3 otherwise identical runs still completed a full review with no worker state
written. The four layers ran unconfined, the review reported a result, and nothing signalled the skipped
boundary.
[Source: https://github.com/JakeSelby/agent-harness/issues/291]

## Root cause

Confinement was a request inside a prompt, not enforcement. The spawn guard in
`lib/harness_core/lifecycle.py` denied a native spawn only when it *named* a constrained role
(`subagent_type`), so an unnamed spawn carrying the same work passed straight through. The routing text
predates 0.11.0.

## Acceptance criteria

1. **Given** a declared framework descriptor, **when** an `Agent` call carries a constrained role's work,
   **then** the spawn hook denies it whatever name the spawn carries, as it denies a named one.
2. **Given** a brief that merely mentions a review, a diff or findings, or edits the framework's
   templates, **when** it is classified, **then** it still runs (false-positive check).
3. **Given** a refused layer, **when** it comes back reworded in the same session, **then** the refusal
   is remembered for a marked or layer-named refusal.
4. **Given** the qualification catalog, **when** it is read, **then** it requires a `spawn-confinement`
   case with its procedure and false-positive check, and records what a descriptor still cannot
   recognise.
5. **Given** 0.11.0, **when** it shipped, **then** this was a known issue and the `bmad-workflow` case
   passed only on a run where worker state was written, recording how many attempts were unconfined.

## Design

`policy/integrations/bmad.json` declares a framework, its version pin (BMad Method 6.12.0), how its
spawns are recognised, the spawn-to-role mapping and the input roots a confined worker needs.
`lib/harness_core/frameworks.py` loads descriptors, and `lifecycle.dispatch` classifies an `Agent` call
against them after the `harness-role:` marker check, so the marker line is only an optimisation. The
corroboration rule, as revised after review: a layer name in `subagent_type` denies on its own; an
`identifiers` path denies only with one phrase beside it; phrases alone need two, and they are whole
sentences of each layer's prompt text. Descriptor-classified refusals do not enter the evasion memory,
so one false classification cannot lock a session out of its corrected brief. An unusable descriptor is
announced once per session. Input roots are declaration only, never a signal. `harness-role:` lines are
not descriptor identifiers, because a loose substring would refuse prose quoting them. `bin/harness
bmad` is untouched; #349 owns the decoupling.

**Recorded tension:** the issue comment of 2026-09-21, after the guards from #301 (under #300), concluded that
"matching on prompt text is the wrong layer" and that confinement needs a signal independent of what the
model writes, such as session state saying a routed review is in flight. The delivered classifier still
recognises work from identifiers and prompt phrases, and the PR records the limit: a full rewrite with no
identifier and fewer than two phrases still runs. FR-41's consequence ("While a routed review is in
flight, an unnamed spawn carrying review work is refused") names #585 as its source, but neither #585's
body nor `lib/harness_core/lifecycle.py` or `frameworks.py` at `origin/main` contains an in-flight review
signal.

## Regression test

`tests/test_framework_spawn_confinement.py` (new): an unnamed spawn carrying a layer's work is denied,
and briefs that only mention reviews or edit templates run. A test asserts the descriptor and the
templates agree on layers, roles and pin.

## Review findings

Recorded in the PR's notes for review: after review, the corroboration rule was tightened (a layer name in
`subagent_type` denies alone; an identifiers path needs one phrase; phrases alone need two, as whole
sentences), descriptor refusals were kept out of the evasion memory, and an unusable descriptor is
announced once per session.
