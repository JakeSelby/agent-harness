## Story

As a developer finishing a pull request, I want one `/land` workflow that merges, cleans up and checks
whether a release is due, so that I do not have to instruct each of those steps every time.

## Context and value

`/build` ends at the pull request. Nothing removed the worktree, deleted the merged branch, or asked
whether a release was due, so each needed an instruction every time.
[Source: https://github.com/JakeSelby/agent-harness/issues/319]

## Acceptance criteria

1. **Given** a pull request ready to land, **when** `/land` runs, **then** it confirms CI and the
   ownership check on the current head before it merges.
2. **Given** the merge, **when** it completes, **then** the workflow deletes the remote branch,
   fast-forwards the shared checkout, runs `harness worktree remove`, `git branch -d` and
   `harness worktree audit`.
3. **Given** unmerged or dirty state, **when** the workflow meets it, **then** it stops with the
   reason, and it never uses `-D` or a forced removal.
4. **Given** a completed land, **when** it ends, **then** it reads the repository's release rule and
   either says no release is due or posts the release card.
5. **Given** the new workflow, **when** projections are regenerated, **then** `harness generate
   --check` is clean and tests cover it alongside the existing workflows.

## Design

### Approach

A shared workflow, `primitives/workflows/land.md`, with its generated projection
`claude/commands/land.md`. Registration is glob-driven, so no list needed editing.

### Decisions and alternatives

- `-D` stays out of compound commands too, because the shell-grading hook denies a whole compound
  command when one segment is irreversible.
- Merging stays approval-gated; the workflow never tags or deploys.
- `tests/test_reconciliation.py` pinned the Codex skill count at `20`; it now derives the count from
  `primitives/skills` plus `primitives/workflows` rather than being re-pinned.
[Source: https://github.com/JakeSelby/agent-harness/pull/327]

### Do not implement

Tagging or deploying; changes to `primitives/rules` or the stances (the PR records none).
