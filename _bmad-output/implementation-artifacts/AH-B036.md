# AH-B036 — /land cannot finish its cleanup after a squash merge: dirty worktree, blocked cache delete, refused branch delete

## Reproduction

1. Merge a pull request through `/land` (added in #327) in this repository, whose ruleset requires a
   squash merge and deletes the remote branch on merge.
2. Run the cleanup: `harness worktree remove` on the task worktree, then delete the local branch.

Observed, per the issue: both merged worktrees had zero tracked or untracked changes and eight ignored
`__pycache__` entries. `harness worktree remove` refused them and `harness worktree audit` listed them
as `dirty`; clearing the caches by hand needs a recursive delete that the shell-grading hook grades 3 and
denies under the `execute` autonomy stance; and `git branch -d` reported the branch as not fully merged.
Every run left a worktree and a branch behind. Found right after #326 and #327 landed.

## Root cause

Three independent causes, as the issue traces them:

1. Running the gate before every push writes `__pycache__` directories, and removal treated any ignored
   file as uncommitted work.
2. The shell-grading hook cannot know the directories are regenerable, so it correctly denies the
   recursive delete.
3. After a squash merge the branch's commits are not ancestors of `main`, and with the upstream ref gone
   `git branch -d` refuses. Ancestry is the wrong test after a squash; the workflow correctly forbids
   `-D`.

## Acceptance criteria

1. **Given** a squash-merged pull request, **when** it is landed, **then** `harness worktree audit` is
   clean and no local branch remains, with no forced flag and no command the shell-grading hook denies.
2. **Given** a branch whose tip is not the merged pull request's head, **when** removal with branch
   deletion runs, **then** it is refused with the reason and nothing is deleted.
3. **Given** a worktree with only known cache directories, **when** it is removed, **then** removal
   proceeds; **given** a real untracked file, **then** removal is refused.

## Design

### Approach

Removal stops counting known regenerable caches as work: `__pycache__`, `.pytest_cache`, `.mypy_cache`,
`.ruff_cache`, `node_modules` and `.astro`, only when git reports the entry ignored; git deletes ignored
files with the checkout. `--also-clear NAME` names one more top-level directory and is validated. A new
`--merged` flag deletes the local branch once a merged pull request from this repository has the branch
tip as its head commit. The proof runs before the removal. `harness worktree audit` reports a cache-only
checkout as clean. `primitives/workflows/land.md` hands both cleanup steps to the one command and keeps
the rule against `git branch -D` in the agent's own shell.

### Decisions and alternatives

- **Proof of merge by pull-request head, not ancestry:** the pull request for the branch is merged and
  its head equals the local tip.
- **Refusals delete nothing:** missing or failing `gh`, no matching pull request, a pull request from a
  fork, a tip that is not the merged head, a detached checkout, or the default branch.
- **Without `--merged` the branch is kept.**
- The issue also proposed running the gate with `PYTHONDONTWRITEBYTECODE=1`. The PR body does not
  record adopting it.

### Do not implement

Not recorded in the issue or pull request. The PR names one known limit it leaves alone: git refuses to
remove a worktree holding an initialised submodule (FR-44 tracks this as #413).
