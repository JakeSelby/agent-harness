## Story

As a developer whose session is governed by a check hosted outside the model, I want that check to bind
every subagent the session spawns, so that a guarded action such as a commit or a push is never
silently taken best-effort because it moved into a subagent without the tool.

## Context and value

A check that lives outside the model (a governance or trust call hosted by an MCP server, an approval
gate, a scan) bound the session the user talks to, but not the subagents it spawned. A subagent's tool
list is usually narrower than its spawner's, so the check was skipped the moment the guarded action
moved into a subagent. The issue records a downstream soak in which every builder that mentioned the
check had no access to it and committed best-effort, while the coordinator's own commits were held by
the same check. The issue asks for a generic rule, not one tied to any single check.
[Source: https://github.com/JakeSelby/agent-harness/issues/284]

## Acceptance criteria

1. **Given** a spawner bound by a check, **when** it writes a brief, **then** it names each required
   check with the action it guards.
2. **Given** a subagent that holds the check's tool, **when** it reaches the guarded action, **then** it
   makes the call itself and obeys the answer.
3. **Given** a subagent that cannot make the call, or gets an answer that is not a clear go, **when** it
   reaches the guarded action, **then** it does not act and returns the action as pending to its
   spawner; each level repeats this, and only the top session prompts the user.
4. **Given** a spawner that pre-clears a named action before dispatch, **when** it says so in the brief,
   **then** the subagent may proceed.
5. **Given** `primitives/rules/delegation.md`, **when** it is loaded, **then** it carries the operative
   line inside the always-loaded budget, and `delegation-tiering` carries the full chain.
6. **Given** the `builder` role with a named check neither runnable nor pre-cleared, **when** it
   finishes, **then** it leaves the work staged, returns the commit as a pending action, and its report
   has a checks line.

## Design

### Approach

One resident line in `primitives/rules/delegation.md`: "A check that binds you binds your subagents:
name it in the brief. Each level makes the call if it can, else hands the pending action up; only the
top session asks the user. Never skip it best-effort." The chain and pre-clearing live in
`primitives/skills/delegation-tiering/SKILL.md`. The `builder` role contract and its projection gain the
pending-action return and the checks line.

### Decisions and alternatives

- **Generic, not per-check:** the rule names no specific governance tool.
- **Resident line plus skill:** the always-loaded rule carries only the operative line; the reasoning
  lives in the skill, keeping the always-loaded budget.

### Do not implement

- A rule tied to any one check.
