## Story

As a developer whose agent runs test and build commands, I want a `PreToolUse` hook that pipes their output through a filter, so that only failures, the summary and the tail enter the transcript and later turns do not pay for a full run's output.

## Context and value

The issue records that `claude/rules/transcript-hygiene.md` asked the model to read narrowly and keep output short, but that this was advice: a full `cargo test` or `pytest -v` run landed in context whole and every later turn paid for it. It calls this a computational job, not an inferential one, and cites the Claude Code costs page, which recommends pre-filtering verbose output, and the hooks reference, which ships a reference script using `updatedInput`.

## Acceptance criteria

1. **Given** a `Bash` call running a matched test or build command, **when** the hook runs, **then** it rewrites the command to pipe through the filter, and emits `updatedInput` only, with no permission decision.
2. **Given** filtered output, **when** it reaches the transcript, **then** failures, tracebacks, the summary line and the last 20 lines remain, and passing lines do not.
3. **Given** a command that already pages or filters, uses `--watch` or redirects to a file, or any command outside the table, **when** the hook runs, **then** the command is left alone.
4. **Given** a failing or passing wrapped command, **when** it exits, **then** `pipefail` preserves its real exit status.
5. **Given** another tool or malformed input, **when** the hook runs, **then** it does nothing.
6. **Given** the settings template and `claude/OWNERSHIP.json`, **when** they are read, **then** the hook is registered under `PreToolUse` and its id is owned.

## Design

### Approach

Two scripts: `claude/hooks/filter-output.py` matches the command against a rewrite table and returns an `updatedInput` that pipes it through `claude/hooks/filter-lines.py`, which keeps failures, tracebacks, the summary and the last 20 lines. The delivered table is wider than the issue's proposal: `pytest`, `unittest`, `cargo test|check|clippy|build`, `npm|pnpm|yarn test`, `go test`, `tsc`, `vitest` and `jest`.

### Decisions and alternatives

- **Rewrite, not deny.** The hook emits `updatedInput` and no permission decision, so it never gates a command.
- **Preserve the exit status** with `pipefail`, so a filtered failure still fails.
- **Tests in their own file.** The issue proposed `tests/test_harness.py`; the pull request added `tests/test_filter_output.py`. The record gives no reason.

### Do not implement

Not recorded in the issue or pull request.
