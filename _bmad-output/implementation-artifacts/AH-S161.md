## Story

As a developer using the harness, I want `harness --help` to list `usage --rules` and the docs to
explain the standalone path, so that the per-rule report is discoverable from the tool itself.

## Context and value

The field scan found per-rule hit rates nowhere else in the field, yet the capability was
undiscoverable from the tool. This is the last story of the instrument epic (#443): it surfaces the
report in the CLI and explains when the report alone is the answer.
[Source: https://github.com/JakeSelby/agent-harness/issues/456]
[Source: https://github.com/JakeSelby/agent-harness/pull/469]

## Acceptance criteria

1. **Given** `harness --help`, **when** it prints, **then** the banner lists `usage --rules` and its
   `--by rule|repo|stance` groupings, beside the token groupings.
2. **Given** `docs/usage.md`, **when** a reader opens it, **then** "Which rules fired" is a top-level
   section ahead of the record format, and documents both promotion thresholds.
3. **Given** the documented thresholds, **when** the tests run, **then** they equal the constants the
   report uses, `RULE_PROMOTE_SHARE = 0.30` and `RULE_MIN_SESSIONS = 20`.
4. **Given** `docs/standalone-measurement.md`, **when** a reader opens it, **then** it explains when to
   use the report alone versus the whole harness, and links #453.

## Design

### Approach

One line in the `bin/harness` help banner, a promoted section in `docs/usage.md`, and a new
`docs/standalone-measurement.md` with "When the whole harness is the answer", "When the report alone is
the answer" and "The packaged path".
[Source: https://github.com/JakeSelby/agent-harness/pull/469]
[Source: docs/usage.md#Which rules fired]

### Decisions and alternatives

- **Thresholds pinned to source:** a test asserts that the documented thresholds match the constants,
  so the doc cannot drift from the report.

### Do not implement

Not recorded in the issue or pull request.
