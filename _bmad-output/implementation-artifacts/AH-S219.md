## Story

As a developer using the architecture-viewer integration, I want the mailbox adapter available behind
the existing viewer selector, so that FR-46's external-adapter path is complete rather than a preview
with its adapter gated.

## Context and value

FR-46 requires "an architecture-viewer capability with a builtin or custom selector and an external
adapter". Its status is "partial: implemented (0.10) as a preview. The mailbox adapter is gated on an
upstream seam (unscheduled)"
[Source: _bmad-output/planning-artifacts/prds/prd-agent-harness-2026-09-23/prd.md#FR-46: Architecture-viewer integration].
No open issue carried the remaining work, so the readiness report recorded FR-46 as a requirement with
no open story
([#691](https://github.com/JakeSelby/agent-harness/issues/691);
[Source: _bmad-output/planning-artifacts/implementation-readiness-2026-09-23.md#Traceability]).

**What exists at HEAD.** #199 (AH-S089) delivered the generic boundary: the selector, adapter contract
1, the architecture-diagram profile, and one custom adapter, `upstream-uml-viewer`, which calls the
standalone viewer's installed public CLI and imports no viewer code
[Source: _bmad-output/implementation-artifacts/AH-S089.md]
[Source: docs/viewer-integrations.md#Adapter contract 1]. The code is `lib/harness_core/upstream_viewer.py`,
reached through `integrations/architecture-viewer/upstream.py`, and the command is `harness viewer`
[Source: lib/harness_core/upstream_viewer.py]. The docs say this distribution "currently has no builtin
viewer adapter", and the selector does not substitute a custom viewer
[Source: docs/viewer-integrations.md].

Nothing named a mailbox adapter exists in the tree. Neither the issue, the PRD nor AH-S089 names the
upstream seam, its owner, or the condition that unblocks it.

## Acceptance criteria

From the issue's Acceptance section and FR-46's testable consequences
([#691](https://github.com/JakeSelby/agent-harness/issues/691)):

1. **Given** the upstream seam does not yet exist, **when** this story is read, **then** it records the
   seam as its blocker, with the condition that unblocks it.
2. **Given** the seam exists, **when** the developer selects the mailbox adapter, **then** it is selected
   and renders through the existing viewer seam, with no second selector.
3. **Given** a viewer path outside the project root, **when** the mailbox adapter resolves it, **then**
   it is refused unless the developer pre-authorized that root.
4. **Given** the mailbox adapter's renderer, **when** its licence falls outside the permissive-only
   policy, **then** no viewer is bundled.

## Design

### Approach

Two phases, as the issue's scope orders them:
1. Record the upstream seam the mailbox adapter needs, and the condition that unblocks it. Until then
   this story stays blocked.
2. Once the seam exists, add the adapter behind the existing selector, under adapter contract 1, keeping
   FR-46's path and licence rules.

The spine says the viewer predates the integration-descriptor contract and "moves to a descriptor when
its mailbox adapter lands"
[Source: _bmad-output/planning-artifacts/architecture-spines/architecture-agent-harness-2026-09-23/ARCHITECTURE-SPINE.md#AD-10: Integrations are descriptors bound at the hook port [ADOPTED for BMad; the viewer migrates]].
[ASSUMPTION: that migration to a descriptor in `policy/integrations/` is part of this story's phase 2;
the issue does not mention it.]

### Decisions and alternatives

None recorded in the issue. The path rule is already enforced by the existing resolution, which rejects
`..`, missing paths and symlinks that escape the project root or a pre-authorized `allowed_roots` entry
[Source: docs/viewer-integrations.md#Invoke and continue]. The new adapter reuses it.

### Do not implement

- Any bundled renderer outside the permissive licence policy
  ([#691](https://github.com/JakeSelby/agent-harness/issues/691)).
- Any vendored upstream code, or a claim that upstream is distributable before its licence and release
  work is complete; these are #199's own boundaries [Source: _bmad-output/implementation-artifacts/AH-S089.md].
- Phase 2 before the seam exists.

## Tasks
