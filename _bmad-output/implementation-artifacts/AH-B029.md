## Reproduction

The issue records five defects in `scripts/native_acceptance.py` from 0.11.0 qualification, none in
the harness runtime:
1. **A refusal looks like a block.** The issue says the `permission-controls` driver asserts on the
   bypass sentinel file's existence alone, so a model declining the acknowledged-bypass turn on its
   own judgement (seen 1 in 5, with `defaultMode: bypassPermissions` and an empty
   `permission_denials`) reads as `failed`.
2. **`orchestrator_text()` returns empty** for a session that spawned no subagent.
3. **The runner links to a runbook that does not exist.**
4. **AWS session variables are not passed through**, so a container holding only
   the three AWS session variables (access key id, secret key and session token) cannot
   authenticate. The variable names are in the issue.
5. **The runner does not drive Codex targets**, so those are qualified with hand-written scripts.
A comment from the release-cost analysis (#340) records that the credential gap, which presented as a
300-second hang, and the missing runbook cost 0.11.0 its first qualification round.
[Source: https://github.com/JakeSelby/agent-harness/issues/309]

## Root cause

- `orchestrator_text()` read the transcript only when a subagent directory had been written, so a
  session with none returned an empty string and let a `cost-posture` assertion pass vacuously.
- The runbook the runner cited had never been written.
- The three AWS session variables were not on the pass-through list.
- For defect 1, the PR records that the issue's premise does not hold: no `permission-controls`
  driver existed on `main` or any branch; the case was registered as required but resolved to
  `NOT_AUTOMATED`.
[Source: https://github.com/JakeSelby/agent-harness/pull/402]

## Acceptance criteria

1. **Given** a session that spawned no subagent, **when** `orchestrator_text()` reads it, **then** it
   returns the session's transcript text.
2. **Given** the runner, **when** it points at a document, **then** the document exists, and the
   runbook names the session variables the runner passes through.
3. **Given** AWS session variables in the environment, **when** the client launches, **then** they
   reach it, and nothing outside the pass-through list travels.
4. **Given** a declined bypass turn with no recorded denial and the bypass mode, **when** it is
   classified, **then** it is unverified, never failed; a recorded denial or another permission mode
   is the block.

## Design

- **Approach:** read the transcript whether or not a subagent directory exists; write
  `docs/qualification-runbook.md`; add the three AWS variables by name.
- **Decision:** for defect 1 the PR lands and tests only the classification a driver would need,
  reading recorded denials and the permission mode, and calls it from nothing. Writing the driver is
  new work for its own issue, "because a live driver would flip a required case from unverified to
  automated with no real run behind it". PR #586 (closing #404) later drove `permission-controls`
  through that classification, `bypass_verdict`, so it is no longer uncalled at `origin/main`.
  [Source: https://github.com/JakeSelby/agent-harness/pull/586]
- **Not addressed here:** defect 5 (the runner driving Codex). Not recorded in the pull request;
  PR #595 (closing #336) later added a Codex configuration home to the runner.
  [Source: https://github.com/JakeSelby/agent-harness/pull/595]
[Source: https://github.com/JakeSelby/agent-harness/pull/402]
[Source: https://github.com/JakeSelby/agent-harness/issues/336]
