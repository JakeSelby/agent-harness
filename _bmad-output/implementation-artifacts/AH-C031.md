## Goal

Make the `landing-copy` check a required status check on the `main` ruleset, beside `lint`, `test` and
`issue-ownership`. #390 (delivered in #395) added the check; it ran on every pull request and reported, but
it was not in the ruleset, so it could not block a merge, and the rule it enforces stayed on the honour
system, which is how #385 shipped a user-visible capability without touching `product.json`. The issue
records that adding a required status check is a repository settings change for the owner to make, and that
an agent should not edit branch protection. It also records what the check refuses: run against merged pull
requests it fails #385 and #384 and does not apply to #383, #382 or #326.
[Source: https://github.com/JakeSelby/agent-harness/issues/414]

## Acceptance criteria

1. **Given** a pull request that changes a capability path without `product.json` and without the
   `Landing copy:` escape, **when** it is merged, **then** the merge is blocked.
2. **Given** the ruleset after the change, **when** it is read, **then** the other three required checks are
   unchanged and the `issue-ownership` check name is untouched.

## Tasks

- [x] Add `landing-copy` to the required status checks on the `main` ruleset (AC: 1)
- [x] Keep `lint`, `test` and `issue-ownership` unchanged, with the strict up-to-date policy (AC: 2)
