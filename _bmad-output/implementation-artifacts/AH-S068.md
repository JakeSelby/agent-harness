## Story

As a developer installing the harness, I want either runtime bootstrapped on its own and every managed
setting owned reversibly, so that installing or removing the harness never corrupts or silently loses my
own Claude Code or Codex configuration.

## Context and value

This is a delivery slice of #95 (installation, configuration ownership and reversible migration), under
epic #93. It records ownership of the already open PR #102, which followed #101, and adds no release
scope. The problem it removes is named in the PR: line-based TOML updates to the Codex configuration were
unsafe.
[Source: https://github.com/JakeSelby/agent-harness/issues/164]

## Acceptance criteria

1. **Given** a machine with only one supported runtime, **when** the harness is installed, **then** that
   runtime is bootstrapped without the other.
2. **Given** Codex, **when** the harness installs, **then** the shared skills, roles and workflows are
   installed for it.
3. **Given** a TOML or JSON settings file, **when** sync writes a managed value, **then** the edit is
   structural and recorded in an ownership ledger that preserves a conflicting user value.
4. **Given** the final integrated commit, **when** CI runs, **then** regression tests, lint and the
   generated-projection check pass.
5. **Given** the pull request, **when** it is reviewed, **then** it owns only this delivery issue and makes
   no client-support claim.

## Design

### Approach

A reconciliation library, `lib/harness_core/reconcile.py`, edits JSON and TOML structurally and records
what it owns in a conflict-preserving ledger, covering generated files as well as settings. TOML editing
uses a bundled TOMLKit 0.15.1 wheel under `lib/vendor/`, with its MIT notice and checksum recorded in
`THIRD_PARTY_NOTICES` and `third-party.json`. `docs/runtime-installation.md` documents the per-runtime
install. [Source: https://github.com/JakeSelby/agent-harness/pull/102]

### Decisions and alternatives

- **Structural editing over line-based TOML updates:** the PR replaces the line-based approach because it
  was unsafe.
- **Vendor TOMLKit rather than depend on it at install time:** the wheel is bundled with exact-package
  notices and a checksum. Why vendoring was preferred is not recorded in the issue or pull request.

### Do not implement

- Native qualification and publication (#98, #100).
- A claim of native role execution or hook enforcement on Codex; the PR says its probe does not establish
  either.
