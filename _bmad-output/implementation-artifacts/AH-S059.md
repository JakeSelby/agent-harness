## Story

As a developer who drafts messages and documents in my own name through an agent, I want the agent to
follow a private personal writing profile when I keep one, so that drafts sound like me without the
profile or its source material ever entering the public harness repository.

## Context and value

The reply-layout `voice` stance governs how answers are laid out, not how a draft written in the user's
name should sound. The issue asked for personal writing profiles to be supported for drafting in the
user's name, and for their private placement to be documented separately from the reply-layout stance.
The issue was created retrospectively, after PR #150 merged, to repair its missing tracking record.
[Source: https://github.com/JakeSelby/agent-harness/issues/152]

## Acceptance criteria

1. **Given** a user who keeps a personal writing profile, **when** the agent drafts in that user's name,
   **then** it defers to the profile before the selected reply-layout stance.
2. **Given** a personal writing profile, **when** the agent drafts from it, **then** it does not imitate
   accidental typos.
3. **Given** the public repository, **when** the change lands, **then** personal profiles and source
   conversations stay outside it, and the docs say the profile belongs in the preserved personal file.
4. **Given** the change, **when** the gate runs, **then** lint and the repository tests pass.

## Design

### Approach

A rule line in `voice-and-format.md` makes user-authored drafts honor an untracked personal voice
profile first and then the `voice` stance for layout, and excludes incidental typos from imitation. The
docs place the profile in the user's preserved personal instructions file, separate from the public
reply-layout stance. At `origin/main` the line reads "Deliverables and posts in the user's name honor
any personal voice profile first, then use the `voice` stance for layout; never imitate incidental
typos", in `primitives/rules/voice-and-format.md` with its projection in `claude/rules/`.

### Decisions and alternatives

- **Profile outside the repository:** the public rule only points at the profile; the profile itself
  lives in the preserved personal file. No alternative is recorded.

Not recorded in the issue or pull request.
