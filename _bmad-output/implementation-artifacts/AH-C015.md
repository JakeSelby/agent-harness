## Goal

Publish 0.11.0 only after every required surface has native evidence for one frozen source: the four CLI
targets pass every catalog case, including a new case that exercises the cost posture layer itself, and
lifecycle acceptance passes on both reference operating systems under the oldest and newest supported
Python. The ten earlier required cases predated the cost posture layer, so a client could pass all of
them without the release's main change ever running natively. The issue cites a defect of exactly that
kind, a reroute that failed spawns in already-running sessions (#257), which passed every test and
review and was caught only by a live run. Qualification also had no runbook.
[Source: https://github.com/JakeSelby/agent-harness/issues/268]

## Acceptance criteria

1. **Given** the frozen source, **when** `harness compatibility --release-check` and
   `scripts/release_preflight.py` run, **then** both pass with no refusal, on evidence whose source
   commit is the release's.
2. **Given** every evidence file, **when** it is read, **then** it contains no credential, private
   transcript or personal setting.
3. **Given** the matrix (Claude Code CLI and Codex CLI on current stable macOS on Apple silicon and on
   Ubuntu 24.04; lifecycle on both under Python 3.9 and the newest stable Python), **when** it runs,
   **then** every required case passes, including `cost-posture`.
4. **Given** GUI clients, **when** the release is qualified, **then** they stay previews outside the
   gate.
