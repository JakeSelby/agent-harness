## Story

As a visitor to the repository, I want the front door to lead with the capability the field does not
have, so that I see first what I can check in my own transcripts rather than a contestable claim.

## Context and value

The field scan (#467) found that stances have prior art in three projects and that breadth is two
runtimes against fifty-two; the uncontested capability is the measurement loop. #230's appended
amendment (#457) recorded the revision, and this story is the literal copy. `product.json` is the one
source of the landing copy, the README grid and the GitHub About description.
[Source: https://github.com/JakeSelby/agent-harness/issues/458]
[Source: https://github.com/JakeSelby/agent-harness/pull/468]

## Acceptance criteria

1. **Given** `product.json`, **when** it is read, **then** the headline is "Find out which of your agent
   rules actually fire.", and new `description`, `stances`, `github_description`, `hero.*` and `topics`
   land, with `model-provider-agnostic` out of the headline.
2. **Given** `product.json`, **when** `ProductCopyTests` run, **then** no string holds an em dash, every
   feature line is under 170 characters, and every `doc` path exists.
3. **Given** the capability groups, **when** they render, **then** the order is measured rules,
   guardrails, owned settings, spend less, readable output, preferences as switches.
4. **Given** the stances copy, **when** a reader reads it, **then** it states that three of nine stance
   axes bind to enforcement.
5. **Given** the README, **when** a reader opens it, **then** the delivery loop is a section rather than
   a capability group.
6. **Given** the change, **when** `tests/test_release.py`, `.github/scripts/check_landing_copy.py` and
   `scripts/sync_about.py --check` run, **then** they pass.

## Design

### Approach

Rewrite `product.json` and the README front door in one PR, and update the `gh` repository-view
fixture the About check reads. The PR was stacked on the field-scan branch because a new feature line
points at `docs/field-scan.md`, and retargeted to `main` when #467 merged. `sync_about.py --apply` was
to run after merge; the epic's closing comment says GitHub About was re-applied from `main`.
[Source: https://github.com/JakeSelby/agent-harness/pull/468]
[Source: https://github.com/JakeSelby/agent-harness/issues/444]

### Decisions and alternatives

- **Measured rules lead; stances support:** per the amended #230.
- **Name the runtimes rather than claim provider-agnosticism.**
[Source: https://github.com/JakeSelby/agent-harness/issues/230]

### Do not implement

- The follow-on docs; that is #462. [Source: https://github.com/JakeSelby/agent-harness/issues/444]
