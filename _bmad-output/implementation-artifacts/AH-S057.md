## Story

As a harness maintainer, I want a decision provider to recommend a band for an unnamed spawn from its
bounded brief, measured in `shadow` beside the current routing rule, so that there is evidence on
whether band routing could do better than the posture's default band before anything changes.

## Context and value

Choosing a worker for extraction, implementation or judgment relies on the orchestrator interpreting a
brief and the resolved delegation policy. The 2026-09-21 re-scope re-aimed this story at the decision the
harness makes: which band an unnamed spawn is routed to in `policy/hooks/tier-agent-spawns.py`. The issue
describes that rule as "one rung below the session model", which is out of date. On `main`, under the
`tiered` delegation stance, the hook routes an unnamed spawn to the cost variant's default band worker,
and only with no default band rewrites `model` to one tier below the session model (the hook's
docstring, and FR-30). The label, a budget overrun or a re-spawn of the same work at
a higher band, is weak, which is why the point is measured and not promoted in this release.
[Source: https://github.com/JakeSelby/agent-harness/issues/145]

## Acceptance criteria

1. **Given** a bounded brief for an unnamed spawn, **when** the point runs, **then** it returns only an
   allowed band or role ID from the supplied set, or no recommendation; missing context and low
   confidence leave selection to the existing routing.
2. **Given** a named role, **when** a recommendation exists, **then** it never overrides the role's
   resolved bindings, and model and effort still come from those bindings.
3. **Given** explicit user model selections, delegation-off, depth limits and review independence,
   **when** the point runs, **then** they stay authoritative.
4. **Given** role tool restrictions, the sandbox and the no-redelegation rule, **when** a recommendation
   is recorded, **then** they stay intact.
5. **Given** the point, **when** it is measured, **then** it reports agreement with the current heuristic,
   the overrun rate per band, and cost per passed task from a replayed pair, default routing against
   the recommendation (#754). It stays in `shadow`. Agreement alone can only show imitation, so any
   future promotion criterion is set on the pair's cost per passed task.
6. **Given** any recommendation, **when** it is applied, **then** there is no parent-model switch and no
   silent premium upgrade.

## Design

### Approach

Classify a short, self-contained brief at the point `tier-agent-spawns.py` routes an unnamed spawn, and
record the recommended band beside the band the routing rule chose. The recommendation is kept separate
from authority and execution.

### Decisions and alternatives

- **Re-aimed from role recommendation to band routing** (re-scope), because band routing is the decision
  the harness makes today.
- **Model and effort prediction removed:** resolved role bindings set them; the provider does not predict
  the cheapest capable model.
- **Measured, not promoted,** because the label is weak.
- **Publication:** the issue says to publish agreement with the heuristic and the overrun rate per band.
  [ASSUMPTION: FR-49, written after this issue, keeps figures that measure a third-party provider's
  model local unless its terms permit publication, so a published report would cover harness-owned
  figures only; the issue itself does not say so.]

### Do not implement

- A promotion criterion or `advise` mode in this release.
- Overriding a named role or its bindings.
