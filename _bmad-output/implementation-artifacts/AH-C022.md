## Goal

Open the 0.11.1 candidate so the patch can be qualified. Runtime source had changed since v0.11.0 (the
spawn guards in #301, the `delegation: off` wording in PR #311 and the builder report in PR #312),
which invalidates the 0.11.0 evidence by design. This releases nothing and creates no tag.
[Source: https://github.com/JakeSelby/agent-harness/issues/313]

## Acceptance criteria

1. **Given** `VERSION`, **when** the candidate opens, **then** it reads 0.11.1.
2. **Given** the compatibility catalog, **when** the candidate opens, **then** it is back in
   `candidate` state, with the four required CLI targets `unqualified` and no evidence carried over.
3. **Given** `compatibility/migration.json`, **when** read, **then** it carries the 0.11.0 → 0.11.1
   migration entry.
4. **Given** the changelog and release-status prose, **when** read, **then** the changelog has the
   0.11.1 section with a fresh `Unreleased`, and the status prose describes the open candidate.
5. **Given** the open candidate, **when** `release_preflight.py` runs, **then** it refuses on exactly
   the four unqualified targets.
