# AH-D009 — Decide whether the session archive may store the message bodies #128 forbids collecting

<!-- bmad-sync:begin -->

- **Primary parent:** [AH-E002](https://github.com/JakeSelby/agent-harness/issues/116)
- **State:** active

The issue carries the summary, discussion and acceptance evidence; this file carries the design.

This work item was authored as part of the repository's committed BMad planning system.
<!-- bmad-sync:end -->

## Context

Two open issues on the v0.15.0 milestone disagree about whether message bodies may be stored
([#685](https://github.com/JakeSelby/agent-harness/issues/685)):

- **#128, local telemetry controls and retention (AH-S045):** "Do not collect commands or message
  bodies." It proposes `observability.enabled`, `retention_days`, `include_repo` and `include_branch`,
  with `retention_days=0` meaning no automatic expiry
  ([#128](https://github.com/JakeSelby/agent-harness/issues/128)).
- **#543, the session archive (AH-S191):** adds `telemetry.sessions` (default on) and
  `telemetry.sessions_bodies`, which controls whether message and tool-result text is stored or only
  metadata, and applies #128's `retention_days` to the archive. The issue says `sessions_bodies` exists
  so that a shared machine can keep metadata only
  ([#543](https://github.com/JakeSelby/agent-harness/issues/543)).

Both story files record the disagreement and say neither issue has been changed
[Source: _bmad-output/implementation-artifacts/AH-S045.md#Design]
[Source: _bmad-output/implementation-artifacts/AH-S191.md#Design]. A builder of either issue would have
to pick a side.

FR-63 requires the archive to be "local and not authoritative" and to store "neutral turn rows keyed to
the harness session, searchable by full text". It does not say whether a turn row carries the message
text [Source: _bmad-output/planning-artifacts/prds/prd-agent-harness-2026-09-23/prd.md#FR-63: Coordination for parallel agents].
The spine defers the row format to the #541 spike, bound by AD-11 and AD-16
[Source: _bmad-output/planning-artifacts/architecture-spines/architecture-agent-harness-2026-09-23/ARCHITECTURE-SPINE.md#Deferred].

**Current behaviour at HEAD.** Neither #128's controls nor `harness sessions` exists yet
(AH-S045, AH-S191). The decision log, `policy/hooks/decisions.py`, already stores the text a hook judged
("a command or a brief, never tool output and never assistant prose"), capped at 2 KiB. Its
`telemetry.completion_claim` switch, off by default, is "the only assistant prose this file ever holds,
which is why it is a switch of its own and why it is off" [Source: policy/hooks/decisions.py].
So #128's "do not collect commands" is already not the rule for the decision log. Whether #128 meant
that log is not recorded in the issue.

## Options

The issue records two directions, one per issue that could change
([#685](https://github.com/JakeSelby/agent-harness/issues/685)):

1. **#128's rule holds; the archive stores metadata only.** `telemetry.sessions_bodies` is dropped from
   #543, and FR-63's archive text says the turn rows carry no message or tool-result text.
   - For: keeps the one privacy rule the telemetry epic states, and a shared machine needs no switch.
   - Against: full-text search over metadata alone finds identifiers only where they sit outside the
     message text. [ASSUMPTION: the issues do not record how much of the archive's search value depends
     on bodies.]
2. **The archive may store bodies under a stated default, consent and retention.** #128's rule is
   narrowed to the collectors it names, and #543's `sessions_bodies` stays with its default, consent and
   retention written down.
   - For: this is #543's design as filed, and #546's recall criteria assume queries that match text in
     past sessions ([#546](https://github.com/JakeSelby/agent-harness/issues/546)).
   - Against: it is the first store of tool-result text, which can include web content and secrets a
     tool printed. [ASSUMPTION: the issues do not weigh this risk; the decision log's own docstring is
     the nearest record of why assistant prose is kept behind an off-by-default switch.]

The issue asks, for option 2, "under which default, which consent, and which retention". Neither issue
records candidate values beyond #543's own: `sessions` on by default, and #128's `retention_days`
applied.

## Decision

Open: decided by the owner on this issue. The answer must say whether the archive may store message
and tool-result text at all, and, if it may, its default, consent and retention. It must also name which
record changes to match: #128's rule, or #543's setting together with FR-63's archive text
([#685](https://github.com/JakeSelby/agent-harness/issues/685)).

## Consequences

- Until this is decided, AH-S045's "do not collect command text or message bodies" and AH-S191's
  criterion 4 cannot both be built as written.
- The row format that the #541 spike chooses depends on the answer: whether a neutral turn row has a
  text field at all. [ASSUMPTION: the spike's issue does not name this decision as an input.]
- Whichever side changes, the acceptance for this item requires the decision in this file, in AH-S045
  and in AH-S191, and #128 and #543 no longer contradicting each other.
- If option 2 is chosen, FR-63's archive consequence gains the stated default and consent, and the
  PRD amendment lands in the same pull request as the decision, under FR-65's currency rule.
