## Story

As a developer who manages only Codex, or both runtimes, I want the diagnostics to inspect hook
registrations for every runtime the harness manages, so that a Codex-only installation gets useful hook
health output and one runtime's broken file never hides the other's results.

## Context and value

This slice of #96 and epic #93 records ownership of the already open PR #111, stacked after #110. Before
it, the hook diagnostics did not serve a Codex-only installation usefully.
[Source: https://github.com/JakeSelby/agent-harness/issues/173]

## Acceptance criteria

1. **Given** Claude Code and Codex both managed, **when** diagnostics run, **then** hook registrations are
   inspected for both.
2. **Given** a runtime the harness does not manage, **when** diagnostics run, **then** it is not reported as
   a failure.
3. **Given** one runtime's settings JSON is malformed, **when** diagnostics run, **then** the malformed file
   is reported and the other runtime's results are still shown.
4. **Given** a registered hook whose script path exists, **when** diagnostics report it, **then** the report
   does not claim native activation.

## Design

### Approach

The hook-health check in `bin/harness` iterates over each managed runtime, parses its native hook
registration, and reports per runtime, isolating a parse error to the runtime that caused it.
[Source: https://github.com/JakeSelby/agent-harness/pull/111]

### Decisions and alternatives

- **An existing script path does not certify activation:** diagnostics stay distinct from native
  qualification.
- Alternatives considered are not recorded in the issue or pull request.

### Do not implement

- Native activation proof, which belongs to qualification (#98).
