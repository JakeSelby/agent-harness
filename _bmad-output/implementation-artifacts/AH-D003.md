# AH-D003 — Decide whether the credential probe names the variable it found

## Context

The credential probe added for #401 (delivered in #398) does not name which variable it found. It prints
`credentials: reachable` and nothing more, because CodeQL reads any output revealing which environment
variable answered as `py/clear-text-logging-sensitive-data` at high severity. The issue records three shapes
that were flagged before a fixed string cleared the alert: printing the name returned by `reachable`,
printing the matched member of a constant tuple behind an equality guard, and printing a constant at an
integer index. `reachable` returns only a member of a module-level constant tuple and never a value read
from the environment, so the issue calls the alert a false positive in all three.

The question: restore the variable name and dismiss the alert as a false positive, or keep the fixed string.
[Source: https://github.com/JakeSelby/agent-harness/issues/409]

## Options

1. **Restore the variable name and dismiss the alert.** For: whoever debugs a failing qualification round
   learns whether the probe answered on a cloud profile or an API key, which the issue calls the useful half
   of a green result. Against: it costs a dismissal on a high-severity alert, a deliberate act that would
   need a recorded reason.
2. **Keep the fixed string.** For: the scan stays clean with no exceptions; a caller that needs the name
   calls `reachable` directly, and only the command-line output is reduced. Against: the green line carries
   less for a debugger. In both options the stderr failure path is unaffected and still carries the full
   reason.

## Decision

Recorded on the issue, 2026-09-22: "keep the fixed string. The scan stays clean with no dismissals, and a
caller that needs the name calls `reachable` directly; the stderr failure path already carries the full
reason." The PR (#504) states the reasoning as a clean scan with no dismissals being judged worth more than
the name on stdout.

## Consequences

- The issue's done-when required the docstring to say why. #504 added that to the `main()` docstring in
  `lib/harness_core/credentials.py`, with a changelog line and no behaviour change; it merged 2026-09-22.
- The issue comment records the item was moved off the v0.12.0 milestone to the backlog until that line
  landed, because it did not gate the release. The issue's `milestone` field is empty.
- The test `test_the_output_never_names_which_variable_was_found`, added to `tests/test_credential_probe.py`
  by #398, pins the fixed-string behaviour; #504 added no test.
- Bound requirements: none claimed. The issue and PR cite no FR or AD.
