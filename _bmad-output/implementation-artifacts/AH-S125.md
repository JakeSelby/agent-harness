## Story

As the release maintainer, I want the `bmad-workflow` qualification case to cost less without losing
the observation it exists for, so that a release does not spend most of a round on one case.

## Context and value

From the release-cost analysis tracked in #340. The case was expensive because four isolated review
workers each loaded the full harness context. The issue weighed four options:
- **4a, lighter isolated workers:** cut each worker's load to roughly 30K tokens.
- **4b, sequential layers under the cap:** required for correctness, because a running role worker
  publishes no token figure, so concurrency is how a 450K cap became 985K.
- **4c, one layer native and three resolved dry:** "Not recommended", because it hides the
  confinement defect the case observes.
- **4d, remove the case from `required_cases`:** honest only if the limitation is published; an
  owner decision.
[Source: https://github.com/JakeSelby/agent-harness/issues/335]

## Acceptance criteria

The issue has no acceptance section; these are taken from the options it weighed and the PR:
1. **Given** an isolated worker, **when** it launches, **then** it is mounted the shared policy, the
   resolved stances, its role body, the skills and documents the policy text cites, and the skills its
   contract's `skills:` line names, not the repository root.
2. **Given** a `skills:` name that resolves to no shipped skill, **when** a run starts, **then** it
   fails, and the native spawn is refused.
3. **Given** a run, **when** it records `status.json`, **then** it records `context` (policy, skill and
   total tokens against a budget), recorded and not enforced.
4. **Given** the BMad review layers, **when** they run, **then** they are asked to run one at a time.

## Design

### Approach

`lib/harness_core/workers.py` derives what to mount by scanning the resolved policy text, with nothing
hand-maintained; role contracts for `planner`, `design-judge` and `designer` gain a `skills:` line; the
three `templates/bmad/custom/*.user.toml` ask for sequential layers.
[Source: https://github.com/JakeSelby/agent-harness/pull/594]

### Decisions and alternatives

- **4a and 4b taken.** A review layer mounts about 30,800 tokens, from about 1,074,000 for the whole
  root; skill authority offered drops from about 31,600 to about 26,600. The PR says the corpus a
  layer might read "shrinks less than the issue hoped".
- **4c rejected** in the issue. **4d** already landed in #349 (PR #591), which moved the BMad run to
  an optional suite, and is not redone here.
- Sequencing is instruction text only, because a new customize key would be reported as drift by
  `harness integration check`.
- **After review:** the spawn guard fails closed when a contract will not load; the narrowing is
  enforced on Claude Code and advisory on Codex, stated per runtime in `docs/role-workers.md`.
- Whether the budget becomes an enforced ceiling is an owner call.

### Do not implement

4c; enforcing the context budget.
