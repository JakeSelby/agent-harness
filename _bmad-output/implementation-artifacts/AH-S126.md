## Story

As the release maintainer, I want the qualification case scripts committed, Codex driven by the
runner, and every required case automated, so that a round executes committed code instead of a
worker re-authoring prose each time.

## Context and value

From the release-cost analysis tracked in #340. `CASES` in the acceptance runner held one entry and
`CLIENTS` only the two Claude CLI rows; every other case returned `"not automated yet"`, and the
provisioning and driver scripts lived only in per-round scratch copies. The issue attributes the
orchestrator cost to authoring (224 and 239 tool calls on Codex targets against 86–112 on Claude
ones), and names one honesty risk: a scripted case can pass on a weaker assertion than a human
applied, so each scripted case must still emit an observation string a reviewer reads.
[Source: https://github.com/JakeSelby/agent-harness/issues/336]

## Acceptance criteria

The issue has no acceptance section; these are taken from its mechanism and the PR:
1. **Given** the provisioning and driver scripts, **when** the change lands, **then** they are
   committed under `scripts/`.
2. **Given** a Codex target, **when** the runner drives it, **then** it uses a Codex configuration
   home (`CODEX_HOME`, `codex exec --json`, rollout layout).
3. **Given** every required case, **when** `--dry-plan` runs, **then** none is reported as not
   automated.
4. **Given** a scripted case, **when** its evidence was not observed, **then** it returns
   `unverified`, never a pass, and it emits an observation string for the reviewer.
5. **Given** an unconfirmed Codex surface, **when** an assertion fails, **then** it maps to
   `unverified` until `--home-confirmed` records the hand comparison for that target.

## Design

### Approach

Nine prose cases become drivers in `scripts/native_acceptance.py`; the `permission-controls` driver
came from PR #586 (closing #404), and `cost-posture` was already automated; `scripts/qualification_provision.py`
and `scripts/qualification_round.py` hold the provisioning and round scripts. The clone comes from
the local object store; the pinned BMad installer is the only network step, and it is opt-in.
[Source: https://github.com/JakeSelby/agent-harness/pull/595]

### Decisions and alternatives

- After #349, `bmad-workflow` is no longer a required case; the PR says its driver is removed, and
  the `spawn-confinement` case from #291 is driven instead.
- `gate-invalidation` delivers Stop events to the runtime's own coordinator rather than paying for
  eleven client turns, and says so in its observation.
- Partial by design: `hook-composition` asserts the merged table and the deny-beats-bypass reading but
  runs no Write turn.
- **After review:** the clone uses `--no-shared`; a latent contract-field bug in the task store is
  fixed; a previous record is moved aside so a silent runner yields `unverified`; timeouts are
  recorded; `--out` inside any checkout of this repository is refused and only a marked clone
  directory is deleted; `--home-confirmed` is per target.
