## Story

As a developer deciding whether to trust the harness on my client, I want every support claim backed by
versioned native evidence for the exact runtime, client, operating system and source, so that "supported"
means a real client passed real cases, not that unit tests and generated files looked right.

## Context and value

A work package of epic #93 that depends on #95, #96 and #97. The problem it records: passing unit tests and
generated instructions do not prove native end-to-end support, and clients can run different binaries with
different capabilities. [Source: https://github.com/JakeSelby/agent-harness/issues/98]

## Acceptance criteria

1. **Given** each supported tuple, **when** the release is published, **then** it has passing evidence for
   the released source.
2. **Given** the required native tests, **when** a tuple is qualified, **then** none is skipped.
3. **Given** `harness doctor`, **when** it runs, **then** it separates published qualification from local
   activation.
4. **Given** Cursor and Grok, **when** the catalog lists them, **then** they are planned only.

## Design

### Approach

Records for runtime, client, operating system, version, capability and evidence, with supported,
experimental, planned and unsupported states. Minimum-Python and macOS and Linux CI, focused regressions,
and separate authenticated native release cases. Verify the actual client executables, the distributable
install, migration and uninstall, and dependency notices. A missing required capability blocks its support
claim. [Source: https://github.com/JakeSelby/agent-harness/issues/98]

The issue's "Evidence validation correction" section adds that linked passing and failing results for the
same case produced no validation error, and that evidence did not match versions and platform; the
validator must reject both, and a superseded artifact must leave the active claim.

Delivered through:
- AH-S071 / #167 (PR #105): the versioned catalog and the evidence requirement.
- AH-S082 / #178 (PR #132): contradictory evidence rejected, one snapshot hashed and parsed.
- AH-S086 / #185 (PR #186): Codex CLI on macOS and Linux.
- AH-S087 / #187 (PR #195): Claude Code CLI on macOS and Linux and the VS Code extension on macOS.
- AH-S088 / #188 (PR #197): Codex VS Code and desktop on macOS.
- AH-B007 / #200 (PR #201): released qualification preserved after development resumes.

### Decisions and alternatives

- **Focused observations are not qualification:** the issue's updates repeatedly record native probes as
  observations short of client qualification.
- **Limitations are recorded, not papered over:** where a native posture behaved differently, it was
  recorded as a limitation rather than claimed as equivalent.
- **Recurring inexpensive provider tests deferred to #134** (AH-S048), with no CI expansion scheduled.

### Do not implement

- A Cursor or Grok adapter, hosted-agent support, a native memory merge or UML viewer work.
