# AH-B070 — sync --dry-run words its summary lines as if it had applied the changes

## Reproduction

Run `harness sync --dry-run`. It changes nothing, but several summary lines read as if it had. At
`origin/main`, `bin/harness` prints, with no check of the dry-run flag first:

- `  path    ~/.local/bin added to PATH in <file>`: printed before `if not dry:`, so a dry run
  prints it too;
- `  codex   hooks registered; native hook trust must be accepted in the client`;
- `sync complete`, the last line of a run with nothing needing attention.

The output is also a flat list keyed by action kind.

## Root cause

The summary lines in `bin/harness` are written in the past tense and printed on both the applying and
the dry-run paths. `ensure_local_bin_on_path` prints its line before it checks `dry`. The `hooks
registered` line sits in the Codex block of the sync flow, which has no dry-run branch of its own; the
writes there go through the ownership store. [ASSUMPTION: read from the code; no dry-run capture was
taken.]

## Acceptance criteria

From the issue:

1. **Given** `harness sync --dry-run`, **when** it prints its summary, **then** no line is in the past
   tense.
2. **Given** the documented preview format, **when** a dry run prints, **then** its output matches it,
   and a test pins it.

## Design

From the issue's scope:

- word every dry-run line as a proposal;
- group the preview by runtime and owner, or change the UX specification to match the flat list.

**Contradiction recorded between the planning documents.** The issue says the PRD and the UX
specification both describe changes grouped by runtime and owner.

- The PRD's FR-4 does: "`harness sync --dry-run` lists every link, rendered file, setting and conflict,
  grouped by runtime and owner, and changes nothing."
- The 2026-09-19 UX `EXPERIENCE.md` does: "Preview output groups proposed actions by runtime and
  ownership target."
- The 2026-09-23 UX `EXPERIENCE.md` does not. UJ-1 says the dry run "lists each proposed action by kind
  (link, render, path, native setting)", and its component list says the preview "lists each proposed
  action by kind, and names conflicts with their owner".

So the current UX specification already matches the flat list, and the PRD does not. Which document
wins is not recorded.

Do not implement: any change that makes `--dry-run` write. FR-4 requires that it "changes nothing".
