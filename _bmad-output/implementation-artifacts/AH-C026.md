## Goal

Add one worked, tested backend example to the telemetry docs, and put the measurement beside the
fan-out claim in the usage docs.
- `docs/telemetry.md` said "any OTLP/HTTP endpoint" and stopped, so the first person to point the
  exporter at a real backend would meet setup steps nobody wrote down.
- `docs/usage.md` said a repository whose cache hit rate falls as its subagent count rises is paying
  for fan-out. The issue records, from one machine across 137 sessions, hit rates of 97.0%, 97.2%,
  97.3% and 97.1% at 0, 1–6, 7–50 and 51+ subagents, so the sentence needed the measurement beside it.
[Source: https://github.com/JakeSelby/agent-harness/issues/359]

## Acceptance criteria

1. **Given** `docs/telemetry.md`, **when** read, **then** it carries a ClickStack (HyperDX all-in-one)
   reference recipe as one example backend, not a requirement: the run command with persistent volumes;
   the two manual steps before data is accepted; the default 30-day expiry and the statement that
   raises it; the HTTP API path under `/api/api/v2/` on the UI port; and header values kept in a
   mode-600 file outside any repository.
2. **Given** the recipe, **when** read, **then** it contains no step that creates an account, stores a
   password or deletes a container or volume.
3. **Given** the docs, **when** read, **then** a dashboard definition ships beside them as JSON, with
   the repository's own SQL over the standard OpenTelemetry tables and a placeholder connection id.
4. **Given** the recipe, **when** read, **then** it carries a licence note for each component and
   says the repository distributes none of it.
5. **Given** the fan-out sentence, **when** amended, **then** the measurement is appended, not
   rewritten.
6. **Given** `harness lint`, **when** run, **then** it is clean: no personal strings, home paths or
   instance-specific ids.

## Dev notes

### Bound decisions and requirements

- FR-25: OTLP export with replay — a backend needs only the documented de-duplication query, not a
  harness-specific adapter. [ASSUMPTION: the recipe serves FR-25's backend-neutral claim; it is an
  example, not a requirement.]
- FR-26: Native telemetry pass-through — the dashboard reads the runtime's native cost metrics.

### Files to touch

`docs/telemetry.md`, `docs/telemetry/clickstack-dashboard-native-cost.json`, `docs/usage.md`,
`CHANGELOG.md`.

### Testing

Docs only; the PR records lint `0 finding(s)` and unittest `OK`. Every command and response in the
recipe was exercised against a running instance, and the dashboard JSON passed the instance's own
`/validate` endpoint before the connection id was replaced with a placeholder.

### Licensing

Nothing third-party is incorporated, so there is no manifest entry or notice. The recipe states each
component's licence as read from its LICENSE file: HyperDX MIT; ClickHouse and the OpenTelemetry
Collector Apache-2.0; MongoDB, inside the all-in-one image, SSPL v1. The user downloads the image from
its publisher; the repository distributes none of it and copies none of its dashboards or
documentation.
