## Story

As a developer running unattended loops under the `execute` autonomy stance, I want a documented isolation posture, the built-in sandbox or a container, so that an autonomous agent cannot reach outside the repository or read secrets.

## Context and value

The issue records that `worktree-per-agent` isolated branches, not the process, that the autonomy stances changed only the permission mode, and that nothing in the repository described sandboxing. It cites Ronacher's isolated "yolo" mode and OpenClaw's CI-parity sandbox as reference shapes, and marks the work lowest priority of its set, to land after #1 to #4.

## Acceptance criteria

1. **Given** the new `sandbox` skill, **when** it is read, **then** it describes the built-in sandbox with network off and secrets paths denied, a container recipe with the worktree mounted and the network cut, and when to use which.
2. **Given** the skill's frontmatter, **when** it is read, **then** it carries a name and a description that says when to use the skill.
3. **Given** `docs/sandboxing.md`, **when** it is read, **then** it links the skill, and the README lists it.
4. **Given** the `execute` autonomy stance, **when** it is read, **then** it points unattended loops at the skill without growing.

## Design

### Approach

A skill plus a docs page, as the issue anticipated. The skill quotes the sandboxing documentation for the settings keys and gives a container recipe.

### Decisions and alternatives

- **Settings keys as documented, not as guessed.** The pull request records that the keys differ from the issue's guess: network-off is an empty `allowedDomains` with `strictAllowlist`, honoured only at user or managed scope, and secrets blocking is `sandbox.filesystem.denyRead`.
- **No `sandbox.*` key written by sync.** The issue floated a `sandbox` posture key in `OWNERSHIP.json` "if the settings support it"; the pull request declines, because those are user-level settings.
- **A container still needs the model API.** A fully offline container also cuts the model API, so the recipe names the host to allow.

### Do not implement

- A synced `sandbox.*` setting (declined in the pull request).
