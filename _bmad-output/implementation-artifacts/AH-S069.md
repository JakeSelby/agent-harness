## Story

As a developer running Claude Code or Codex, I want one set of shared lifecycle policies composed
through each runtime's native hooks, so that both runtimes enforce the same gates and the stronger
decision wins wherever two policies overlap.

## Context and value

This is a delivery slice of #96 (runtime policy enforcement, roles, gates and observability), under epic
#93. It records ownership of the already open PR #103, stacked on the runtime-installation branch, and
adds no release scope. Native client qualification stayed pending under #98.
[Source: https://github.com/JakeSelby/agent-harness/issues/165]

## Acceptance criteria

1. **Given** shared hook policies, **when** a Claude Code or Codex event fires, **then** the native adapter
   runs the same composed policies for that runtime.
2. **Given** two policies that decide the same event differently, **when** their results are combined,
   **then** the stronger decision is kept.
3. **Given** a gate result, **when** staged or untracked content changes, **then** the result is
   invalidated.
4. **Given** telemetry or a detector that cannot report, **when** it is recorded, **then** unknown
   telemetry and a failed detector are distinguishable from a clean result.
5. **Given** a Claude read-only role, **when** it runs, **then** it has no shell access.
6. **Given** the final integrated commit, **when** CI runs, **then** tests, lint and generated projections
   pass, and the PR makes no client-support claim.

## Design

### Approach

Shared policy scripts live in `policy/hooks/`. `lib/harness_core/lifecycle.py` loads and invokes them,
and each runtime's `adapters/<runtime>/hook.py` translates native events in and decisions out. When
several policies answer a pre-tool event, the encoder takes the strongest of `deny`, `ask` and `allow`.
Gate results are keyed on staged and untracked content, and shell context is preserved across the
composition. [Source: https://github.com/JakeSelby/agent-harness/pull/103]
[Source: lib/harness_core/lifecycle.py]

### Decisions and alternatives

- **Stronger decision wins on overlap:** stated in the issue's design.
- **Read-only roles lose shell access on Claude:** the Claude bindings for the gatherer, reviewer and
  spec-reviewer roles were narrowed.
- **Codex parent permission overrides stay a named limitation:** the PR records that a Codex parent can
  still override a role's permissions, rather than claiming confinement there.

### Do not implement

- Native client qualification and publication (#98, #100).
