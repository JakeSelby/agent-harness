## Story

As a developer who starts Claude Code sessions from the mobile app, I want an always-on Remote Control
server for each folder I configure, so that I can start a new session in that folder from my phone
without keeping a terminal open.

## Context and value

Claude Code's `/remote-control` shares one running session with the mobile app. Starting a *new*
session from the phone needs `claude remote-control` running as a server in the folder, one server per
folder, and that server dies with its terminal. The issue asked for a macOS command that keeps the
servers running under launchd. The issue carries no milestone.
[Source: https://github.com/JakeSelby/agent-harness/issues/239]

## Acceptance criteria

The issue has no separate acceptance section; these are its requested behaviours.

1. **Given** a `remote_control.folders` list in the configuration, **when** `harness remote-control
   install` runs on macOS, **then** it installs one launchd agent per entry, honouring the `spawn`,
   `permission_mode` and `keep_awake` options.
2. **Given** a folder whose workspace trust was never accepted, **when** `install` runs, **then** the
   folder is reported and skipped, and never trusted on the user's behalf.
3. **Given** an unchanged, loaded agent, **when** `install` runs again, **then** it is left alone.
4. **Given** a folder dropped from the list, **when** `install` runs again, **then** its agent is
   removed.
5. **Given** installed agents, **when** `status` or `uninstall` runs, **then** it reports or removes
   them.

## Design

### Approach

`harness remote-control install|status|uninstall` in `bin/harness`, backed by
`lib/harness_core/remote_control.py`, writes one launchd agent per configured folder. A folder entry is
a path, or an object with a `path` and its own `spawn` and `env`; `spawn`, `permission_mode` and
`keep_awake` apply to every server unless a folder overrides them. `keep_awake` wraps the server in
`caffeinate -is`. Trust is read from the exact folder, so a trusted parent does not trust a child.
[Source: docs/remote-control.md]

### Decisions and alternatives

- **Never trust on the user's behalf:** an untrusted folder is skipped with instructions, not trusted
  by the harness.
- **Idempotent install:** an unchanged, loaded agent is left alone, so re-running is safe.

### Do not implement

Not recorded in the issue or pull request. Outage survival (the `heal` agent, the live bridge pointer and
the graceful stop) was delivered on the same branch under #483, not under this issue.
