## Goal

Re-baseline the UX specification and the architecture spine against the shipped code and the 2026-09-23 PRD,
so that builders of the v0.14 to v0.16 stories converge on the same invariants and the same user-facing
behaviour. The 2026-09-19 versions described only the 0.9 core. They had no decision covering any of these:
- the policy kernel, dispatcher or integration contract;
- ledgers, cost posture or decision providers;
- releases or shared-machine concurrency.

## Acceptance criteria

1. **Given** the 2026-09-19 spine, **when** the new spine is written, **then** AD-1 to AD-5 keep their ids
   (amended in place), and each new decision gets the next id with Binds, Prevents and Rule.
2. **Given** the codebase, **when** a reviewer checks the spine, **then** no AD contradicts the code
   without a status tag and a migration note naming its issue.
3. **Given** `lint_spine.py`, **when** it runs, **then** it reports no findings.
4. **Given** the UX documents, **when** a reviewer checks them against the CLI, **then** every behaviour
   the CLI does not have today is marked planned, with its milestone.
5. **Given** the superseded 2026-09-19 documents, **when** they are opened, **then** each points to its
   successor and has not been rewritten.
