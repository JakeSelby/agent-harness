## Reproduction

Export ledger rows over OTLP (#353) and inspect them in a backend:
- A row carries tokens but no dollars, because `harness usage` prices rows at report time; a backend
  dashboard has to re-implement the price table in its own query language and keep it in step by hand.
- Each stance arrives twice, once as `stances.<name>` and once as `harness.<name>`.
[Source: https://github.com/JakeSelby/agent-harness/issues/358]

## Root cause

- Pricing lived only in `bin/harness`, which the standalone hook cannot import, so the export path had
  no way to price a row.
- The record body carried the row's `stances` map while attributes carried one `harness.<name>` per
  stance, so a backend that flattens the JSON body saw each stance twice.
[Source: https://github.com/JakeSelby/agent-harness/pull/364]

## Acceptance criteria

1. **Given** a priced row, **when** exported live or by `usage export` replay, **then** it carries a
   list-price USD figure and the `as_of` date of the prices used, computed by the same code path
   `harness usage` uses.
2. **Given** an unpriced row, **when** exported, **then** it carries neither attribute, never a zero.
3. **Given** the pricing code, **when** called from the CLI or the hook, **then** it is one
   implementation.
4. **Given** a row with stances, **when** exported, **then** each stance appears once, as
   `harness.<name>`.
5. **Given** `docs/telemetry.md`, **when** read, **then** it says the figure is a list-price
   equivalent fixed at export time and that a replay after a price change re-stamps it.

## Design

- **Approach:** move the pricing functions from `bin/harness` into `policy/hooks/pricing.py`, beside
  the hook, because the standalone hook cannot import `lib/`; the CLI loads the same file. A priced row
  carries `harness.usd` and `harness.price_as_of`. The body drops its `stances` map.
- **Decisions:** a Claude Code session row's figure includes its subagents, as `usage` reports it, and
  the docs say so, so nobody sums session and subagent rows. A pricing failure on the live hook path
  never raises or changes the hook's exit status; the row goes out unpriced and the failure is recorded.
  The de-duplication example takes the latest record per `harness.row_key`.
- **Must not change:** `harness usage` output; the recorded-session oracle still prices exactly.
[Source: https://github.com/JakeSelby/agent-harness/pull/364]
