# AH-B076 — The runner stamps a Linux record from the target spec without checking the host, so a round on the Mac produces a fake Linux record

The issue carries the summary, discussion and acceptance evidence; this file carries the design.

This work item was authored as part of the repository's committed BMad planning system.
<!-- bmad-sync:end -->

## Reproduction

1. On a macOS host, provision a round and run
   `python3 scripts/qualification_round.py --round <dir> --targets claude-code-cli-linux`.
2. The round launches `scripts/native_acceptance.py --client claude-code-cli-linux` on the Mac.

Observed on 2026-09-23 in the first 0.13.0 round: the runner drove every case with the host's
`claude` (2.1.280, where the Linux image pins 2.1.278) and wrote `claude-code-cli-linux.json` with
`platform: linux`. The record was byte-for-byte the macOS outcome, including a case that fails in the
image for a different reason (`/tmp` there is not a symlink).

## Root cause

`record()` writes the header's `platform` from the `CLIENTS` spec and never compares it with
the host, and nothing before it does either. The round driver launches every named target on the
host it runs on, so the only guard was the runbook's instruction to run a Linux target inside the
container. [Source: scripts/native_acceptance.py#record] [Source: docs/qualification-runbook.md#target-hosts]

## Acceptance criteria

1. **Given** a Darwin host, **when** `native_acceptance.py --client claude-code-cli-linux` runs a
   case, **then** it exits through `SystemExit` before any case, client or `git` process runs, naming
   the target, its platform, the host, and where to run it instead.
2. **Given** a Linux host, **when** a macOS target is named, **then** it is refused the same way; an
   unknown host runs no target.
3. **Given** a target on its own platform, or `--dry-plan`, **when** the runner is called, **then**
   nothing is refused.
4. **Given** `qualification_round.py --plan`, **then** each target prints `runs on this host`,
   `runs inside the Linux image`, or `runs on a macOS host, not this one`.
5. **Given** a mixed `--targets` list on a Mac, **when** the round runs, **then** the macOS target runs,
   the Linux target is printed as `not run here` with the refusal and recorded under `not_run_here` in
   `round.json`, and the exit status is decided by the targets that ran.
6. **Given** no named target runs on this host, **then** the round launches nothing, writes no
   `round.json`, and exits 1.

## Design

- `native_acceptance.host_mismatch(client, host=None)` maps `platform.system()` (`Darwin` to
  `macos`, `Linux` to `linux`) and returns the refusal text, or `""` when the host matches. `main()`
  raises it as `SystemExit`, the runner's existing precondition shape, before `record()`.
- The round driver imports the same function: `where()` words the plan, and `main()` splits the
  targets before `run_round`, so the smoke tier and runner see only the targets that run here.
- `--dry-plan` and `--from-progress` are not refused: neither runs a client, and a log written inside
  the image may be rebuilt on the Mac.
- **Rejected:** stamping `platform` from the host instead of the spec, which would let a Linux target
  run on a Mac and silently write a macOS record under the Linux name. **Rejected:** checking inside
  `record()` or `run_round()`, which every existing runner test calls with a macOS target and would
  break on the Linux CI runner.
- The Linux check is platform only. It does not prove the process is inside the target image.
- **Must not change:** the record schema, the case drivers, or `run_round`.

## Regression test

`tests/test_native_acceptance_host.py`, with `platform.system()` patched in every test.
- **Before the fix:** four tests fail: the refusal, the mixed round, the round that passes beside a
  skipped target, and the round with nothing to run.
- **After the fix:** all 11 pass, under Python 3.9 and a current Python.
