# AH-B081 — role-confinement never has a read-only role attempt a write

## Reproduction

Round 4 of the 0.13.0 native qualification (`claude-code-cli-macos` and `claude-code-cli-linux`,
client 2.1.280) ran `role-confinement` passed on both targets, and the assessor ruled it short of
step 4 of the procedure in `docs/compatibility.md`, "attempt writes from read-only roles and
outside the planner artifact scope": "No read-only role tried a write: the reviewer spawn was
refused before it ran. The planner refusal, '--artifact must be a Markdown filename, not a path',
is a command-line argument check, not a write the role attempted."

## Root cause

`case_role_confinement` in `scripts/native_acceptance.py` checked the native reviewer-spawn
refusal, one isolated `gatherer` read, and `harness role run planner --artifact ../escape.md`,
which `artifact_slot` in `lib/harness_core/workers.py` rejects by regular expression before any
worker starts. No step gave a read-only role, or the planner, a write to attempt. Reading one
would also have needed the run itself: `adapters/claude-code/worker.py` runs the client with
`--output-format json` and `--no-session-persistence`, so a worker leaves no init event and no
transcript, only the result envelope.

## Acceptance criteria

1. **Given** a disposable home, **when** the read-only `gatherer` is run by `harness role run` and
   told to create a named file in its workspace, **then** the case reads from that run's own event
   stream whether it attempted the write and what stopped it, and that no file landed in the
   workspace or anywhere under the disposable home.
2. **Given** the same home, **when** the planner is run by `harness role run` with a valid
   `--artifact` and told to write a file inside the workspace and one above it, **then** the case
   reads that no file landed outside `.agent-harness/plans/<artifact>` and where the artifact did
   land.
3. **Given** either probe, **when** the file lands or a write call comes back successful, **then**
   the case fails; **when** the role held a write tool and never called it, or its stream carried
   no tool set, **then** the case is unverified.
4. **Given** a role whose run's init event lists only read tools, **when** it makes no write call,
   **then** the case records that as the observed confinement, naming the tools and the source.
5. **Given** the change, **when** the case runs, **then** the native spawn refusal, the isolated
   read and the `--artifact` argument check are still read.

## Design

`role_write_attempts` runs both probes through `role_run`, the routed path, with `PATH` led by a
per-run wrapper from `stream_shim`. The wrapper passes the worker's argv to the real client
unchanged except `--output-format json`, which becomes `stream-json --verbose`; it saves the
stream and prints only the final result event, the envelope the worker parses. `write_reading`
reads the init event's tool set, every non-read tool call with its result, and the result's
`permission_denials`; `judge_write` turns that and the files found into a sentence or a verdict.
A Codex worker already logs its `--json` stream, so it is read from the worker's `stdout.log`
with no wrapper. Rejected: reading the tool set from the role definition or the adapter's argv,
which is configuration, not the run; asking the model to list its tools, which is testimony;
changing the adapter to keep its stream, which is product code outside this fix. The existing
checks are unchanged; the argument check's sentence now calls it that.

## Regression test

`tests/test_native_acceptance_role_writes.py`.
- **Before the fix:** `role_write_attempts`, `write_reading`, `judge_write` and `stream_shim` do not
  exist, so every test errors.
- **After the fix:** all 19 pass. `tests/test_native_acceptance_observation.py`'s pass-path test
  patches the new probes, since it fakes a single gatherer record for every run.
