## Story

As a developer who has imported an existing instruction file, I want `harness sync` to project rules
and skills from my external primitive root the way it projects the repository's own, so that the
imported rules actually reach Claude Code and Codex.

## Context and value

`harness import` (#478, for #448) wrote primitives into an external root that nothing projected, so an
imported CLAUDE.md never reached either runtime. #478 recorded the gap and filed this issue, carrying
its BMad reservation.
[Source: https://github.com/JakeSelby/agent-harness/issues/477]
[Source: https://github.com/JakeSelby/agent-harness/pull/478]
[Source: https://github.com/JakeSelby/agent-harness/pull/484]

## Acceptance criteria

1. **Given** roots in `primitive_roots`, **when** `harness sync` runs, **then** it projects their rules
   and skills after the repository's own, deterministically, and only after the name-collision check
   (#449) passes.
2. **Given** Claude Code, **when** sync projects an external root, **then** its rules are linked under
   `~/.claude/rules/harness-roots/<slug>/` and its skills beside the repository's.
3. **Given** Codex, **when** sync renders `AGENTS.md`, **then** external rules follow the repository's,
   with a source comment per root.
4. **Given** the link manifest, **when** it is written, **then** it records the root for each file, so
   `harness diff` reports drift and `harness uninstall` removes exactly what was adopted.
5. **Given** `harness sync --dry-run`, **when** it prints, **then** projected files are grouped by root.
6. **Given** a configured root that is missing, **when** sync runs, **then** it prints a notice and does
   not crash.
7. **Given** a CLAUDE.md imported into a temporary root, **when** it is synced and then uninstalled in
   a disposable home, **then** its rules appear and then disappear.

## Design

### Approach

`bin/harness` extends sync to iterate the registered roots after `primitives/`, with a per-root slug
for the Claude link directory and a per-root source comment in the Codex render. The ownership record
carries the root, which gives diff and uninstall their scope.
[Source: https://github.com/JakeSelby/agent-harness/pull/484]
[Source: docs/sync-model.md]

### Decisions and alternatives

- **Per-root subdirectory for Claude rules** keeps each root's files separable for drift and
  uninstall.
- **Repository first, then external roots,** in a deterministic order.
- **A missing root is a notice, not a failure.**
[Source: https://github.com/JakeSelby/agent-harness/pull/484]
