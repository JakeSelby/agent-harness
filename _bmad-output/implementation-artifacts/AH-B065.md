## Reproduction

Let a story file on `main` drift from the map, for example with frontmatter naming a different parent
or title than `_bmad-output/issue-map.json` records. Run `python3 scripts/bmad_issue_sync.py apply`. It
finds the artifact on `main`, and writes each issue's Planning block pointing at that file, although its
content disagrees with the map.

The issue records no concrete incident. [ASSUMPTION: the steps above are derived from the issue's
description and the code, not from a recorded run.]

## Root cause

Traced in `scripts/bmad_issue_sync.py` at `origin/main`:

- `apply_manifest` calls `verify_remote_artifacts(manifest)` before it writes anything.
- `verify_remote_artifacts` fetches the recursive tree of `main` through the GitHub API, and returns
  every item whose `artifact_path` is absent. It checks presence only; it never reads a file's content.

## Acceptance criteria

From the issue:

1. **Given** an artifact whose frontmatter on `main` disagrees with the map, **when** `apply` runs,
   **then** it refuses and names the item.
2. **Given** artifacts whose frontmatter agrees, **when** `apply` runs, **then** it proceeds as today.
   [ASSUMPTION: the passing case is implied, not stated.]

## Design

From the issue's scope: verify each artifact's frontmatter against the map before `apply` writes an
issue's Planning block.

Which frontmatter fields must agree is not specified. The sync tool owns the frontmatter's linkage
fields and `updated` (per `docs/bmad.md`, "Story files"), so comparing the fields `refresh` writes is
one reading. [ASSUMPTION: the field set is not recorded.]

Reading each file's content means one API read per artifact, or one read of the tree's blobs, rather
than the single tree listing used today. The cost of that is not discussed in the issue.

Do not implement: the issue records no out-of-scope item.

## Regression test

Not written. A test in `tests/test_bmad_issue_sync.py` would stub the `main` tree and one file's
content with mismatched frontmatter, and assert that `apply_manifest` raises and names the item before
any issue write.
