# AH-B064 — Plugin channel: constrained roles install unconfined, and the manifest version lags VERSION

## Reproduction

Install the Claude Code plugin listing (`/plugin marketplace add JakeSelby/agent-harness`, then
`/plugin install agent-harness@agent-harness`), without running `harness sync`. Then:

- spawn a constrained role, for example `reviewer`, as a native subagent. The plugin installs it as a
  native agent and carries no hooks, so nothing refuses the spawn;
- read `.claude-plugin/plugin.json`. At `origin/main` its `version` is `0.11.1`, while `VERSION` is
  `0.13.0`.

## Root cause

- `.claude-plugin/plugin.json` lists every file in `claude/agents/` under `agents`, and declares no
  hooks. The spawn refusal for constrained roles lives in the `PreToolUse` hook
  (`lib/harness_core/lifecycle.py`), which only `harness sync` installs.
- The manifest's `version` is a literal, not derived from `VERSION`, and no test in
  `tests/test_plugin_manifests.py` compares the two.

**The issue's list of constrained roles is incomplete.** It names `gatherer`, `reviewer` and
`spec-reviewer`. At `origin/main`, `constrained_role` in `lib/harness_core/lifecycle.py` treats every
role whose contract has `read-only` or `artifact-write` authority as constrained. That is also `planner`,
`design-judge` and `log-compressor`, and the plugin lists all six.

## Acceptance criteria

From the issue:

1. **Given** any distribution channel, **when** it installs roles, **then** no constrained role is
   installed without its confinement, or the gap is declared where the channel is described.
2. **Given** the plugin manifest, **when** it is read, **then** its version equals `VERSION`, and a test
   checks it.

## Design

From the issue's scope, one of:

- keep constrained roles out of the plugin; or
- state in the plugin docs that confinement needs `harness sync`.

And in either case, derive the manifest version from `VERSION`.

The PRD's FR-18 already fixes what the docs must say: "The docs say that full enforcement, including
role confinement (FR-40, FR-41), needs `harness sync`." `docs/runtime-installation.md` ("Install from
the plugin marketplace") says a marketplace install gives no hooks, "so command grading, the stop gate
and the usage feed are all off". It does not mention role confinement.

Do not implement: hooks in the plugin. FR-18 and AD-19 both say the plugin carries no hooks, because
plugin hooks would merge with user hooks and fire twice.

## Regression test

Not written. A test in `tests/test_plugin_manifests.py` would assert that the manifest's `version`
equals `VERSION`. If constrained roles are removed, a second test would assert that no `agents` entry
names a role whose authority is `read-only` or `artifact-write`.
