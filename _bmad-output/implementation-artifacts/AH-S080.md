## Story

As a contributor or agent following the harness's roles and skills, I want authoring guidance routed
through the shared primitive and policy sources and every runtime-specific example labelled, so that
active instructions never send me to a Claude-only path or claim a capability that is not universal.

## Context and value

The issue calls itself a delivery slice of #99, under epic #93, and records ownership of the already open
PR #114, stacked after #113. The PR also references #94. Active role and skill instructions still named
Claude-only paths and claimed workflow-status support that was not universal.
[Source: https://github.com/JakeSelby/agent-harness/issues/176]

**Recorded contradiction:** the issue names #99 as its parent, but the issue map and this file's managed
block record #97 (AH-S030) as the primary parent. The issue is left unchanged.

## Acceptance criteria

Taken from the issue's own acceptance section. The outcomes listed under AC 1 restate the
issue's "Proposed design", which AC 1 requires the PR to satisfy.

1. **Given** PR #114, **when** it is reviewed, **then** its implementation and documentation satisfy the
   issue's proposed design and preserve the single shared primitive authority. The design outcomes:
   1. **Given** authoring guidance in roles and skills, **when** it names a source, **then** it points at the
      shared primitive and policy sources.
   2. **Given** a development sync, **when** it runs, **then** it stays isolated from the live configuration.
   3. **Given** active role and skill instructions, **when** they are read, **then** they carry no Claude-only
      path and no unsupported universal workflow-status claim.
   4. **Given** the sandbox example, **when** it is read, **then** its runtime is labelled.
   5. **Given** the changed roles, **when** projections are checked, **then** the generated Claude role views
      are current.
2. **Given** the final integrated commit, **when** the gate runs, **then** applicable regression tests,
   repository lint, generated projections and the existing CI commands pass.
3. **Given** the pull request, **when** it is reviewed, **then** it owns only this delivery issue, and
   broader tracking issues remain contextual references.
4. **Given** native evidence, **when** it is reported, **then** it names its exact tested source and
   versions, and this delivery alone makes no complete client-support or publication claim.

## Design

### Approach

Text changes to the shared roles (`design-judge`, `gatherer`) and six skills, then regeneration of the
Claude role projections. Historical benchmark and attribution records stay unchanged.
[Source: https://github.com/JakeSelby/agent-harness/pull/114]

### Decisions and alternatives

- **Label rather than delete runtime-specific examples.**
- **Leave historical records unchanged.**
- Alternatives considered are not recorded in the issue or pull request.

### Do not implement

- Changes to historical benchmark or attribution records.
