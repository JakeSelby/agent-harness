## Story

As a developer running the design loop, I want a `design-judge` agent carrying the rubrics, so that the scored critique always runs in a context that did not do the building, without the orchestrator pasting a judge prompt each round.

## Context and value

The issue records that the `design-loop` skill's loop is build, screenshot, independent scored critique, fix, and that the critique is only independent when it runs in a context that did not build. The skill asked the orchestrator to spawn a judge and paste the rubric each round.

## Acceptance criteria

1. **Given** render paths, the surface type and the target, **when** `design-judge` runs, **then** it scores every rubric criterion with a reason, reports the four hard gates (accessibility, tokens, runtime, asset licensing) as pass or fail, and returns the three highest-leverage fixes.
2. **Given** the agent definition, **when** it is read, **then** it is read-only with image reading, on the session model, at high effort, and it never edits and never praises.
3. **Given** the design loop's step 6 and its judge reference, **when** they are read, **then** they name the agent instead of pasting a judge prompt, and the reference keeps its handoff guidance.

## Design

### Approach

A new `claude/agents/design-judge.md`. `claude/skills/design-loop/SKILL.md` and `references/judge.md` point at it; the pull request records the reference shrinking from 98 to 41 lines.

### Decisions and alternatives

- **Rubrics stay in the skill.** The issue says the rubrics stay in the skill's references and the agent points at them.
- **Depends on #28.** The pull request relies on the relaxed agents-directory assertion merged there.

### Do not implement

- Edits or praise from the judge (from the issue).
