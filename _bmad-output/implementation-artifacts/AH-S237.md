## Story

As a harness maintainer, I want the six replay defects that leave the harness and bare arms unequal fixed, so that a replay result can test SM-2's hypothesis.

## Context and value

The 2026-09-24 review of the live replay found six defects, listed in FR-56's status, that leave the harness and bare arms unequal or a task unfair. Until they are fixed, no replay result can test SM-2's hypothesis.

Traces to FR-56. Sibling fixes: #428 and #482.

## Acceptance criteria

1. The benchmark docs and the task manifest agree on the task count, and a test fails when they diverge.
2. Each task's `max_turns` reaches the CLI in scored runs, and a test asserts it is in the launched command.
3. The stop gate can fire in a replay snapshot: the snapshot is trusted for its run, and a run that ends with a red gate records stop-hook feedback.
4. Both arms get identical web access, whatever the fence allows.
5. The usage-prices task is passable by an arm that follows its prompt, or it leaves the set with the reason recorded.
6. Runs are captured as `stream-json`, so hook events and per-turn usage are in the saved record.
7. Given a fake launcher, the unit tests cover each fix.
