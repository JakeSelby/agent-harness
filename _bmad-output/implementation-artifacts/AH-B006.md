## Reproduction

Reproduced on Linux with native Codex CLI 0.155.1 against commit `911c938`:
1. In one `apply_patch`, create two intentionally invalid plan files.
2. Codex sends `PostToolUse` with a text `tool_response`.
3. An independent observer captures both paths and the text result, but the agent receives only an
   unrelated user hook's marker and no plan feedback.
4. Replaying the observed event produces `AttributeError: 'str' object has no attribute 'get'`.

For comparison, Claude Code 2.1.273 produced feedback for both equivalent Write operations.
[Source: https://github.com/JakeSelby/agent-harness/issues/181]

## Root cause

The shared lifecycle dispatch passed the runtime's native `tool_response` straight to the plan-card
validator. The validator expects an object and calls `.get` on it; Codex supplies text after
`apply_patch`. The coordinator reported the `AttributeError` and dropped advisory feedback for every plan
file in the patch, and the unrelated user hook still running masked the loss.
[Source: https://github.com/JakeSelby/agent-harness/issues/181]

## Acceptance criteria

1. **Given** a native Codex text-result envelope for a multi-file patch, **when** it is dispatched through
   the real validator, **then** feedback is produced for both plan files.
2. **Given** a Claude object-result Write, **when** it is dispatched, **then** plan feedback is unchanged.
3. **Given** a native Codex retry, **when** the patch runs alongside an unrelated user hook, **then** both
   file-specific messages and the user hook's marker are reported.
4. **Given** the change, **when** the gate runs, **then** lint, tests and generated-source checks pass with no
   new CI.

## Design

Keep one shared policy engine. `lib/harness_core/lifecycle.py` normalizes each path-specific validation
event to the validator's contract instead of passing a runtime-specific result through, while other
policies still receive the native output and every patch path is preserved.

Rejected, per the issue: a Codex-specific plan validator. The fix must not alter permission enforcement.
[Source: https://github.com/JakeSelby/agent-harness/pull/182]

## Regression test

In `tests/test_lifecycle.py`:
- `test_native_patch_text_result_validates_each_plan`: a Codex text result through the real validator
  yields feedback for each plan (fails before the fix with the `AttributeError`).
- `test_native_write_object_result_still_validates_plan`: the Claude object-result path.
- `test_multi_file_patch_enumerates_all_paths`: every patch path is kept.
