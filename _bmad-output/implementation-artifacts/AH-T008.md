## Goal

Give agents a standing rule that "spawn a new chat" is a cloud-run request. The issue records that no
tool opens a sibling top-level session from inside a running one: the Agent tool spawns an in-process
subagent that shares no chat window, and session-scoped wakeups are not new sessions. The nearest real
equivalent is a one-off run through a remote-trigger or routine tool, which creates an independent
session with its own link. Without a standing instruction, each session re-derived this, explained the
boundary, and had to be told to use the remote-trigger mechanism anyway.
[Source: https://github.com/JakeSelby/agent-harness/issues/607]

## Acceptance criteria

1. **Given** `primitives/rules/working-style.md`, **when** it is read, **then** it carries a bullet,
   written generically with no names, paths or product specifics, saying that a request to spawn a new
   chat, conversation or session is a cloud-run request, not a subagent request; that a routine or
   remote-trigger tool, when available, is the mechanism, firing a one-off run and handing back the link;
   and that the agent should neither re-explain the boundary nor substitute a subagent.
2. **Given** the change, **when** `bin/harness lint` runs, **then** it is clean and the always-loaded line
   count stays at or under the cap.
3. **Given** the change, **when** `bin/harness generate --check` runs, **then** it shows no drift.
4. **Given** the change, **when** the unit suite runs, **then** it passes.
