## Story

As a developer who delegates to a constrained role such as the planner or reviewer, I want that role run in
an isolated native CLI worker with the same stances and role definition in either runtime, so that the
parent session's permissions cannot widen what the role may do.

## Context and value

This is a delivery slice of #96 (runtime policy enforcement, roles, gates and observability), under epic
#93; the PR also references #94 and #97. It records ownership of the already open PR #115. The design
reason is recorded in the PR: parent permissions can override native subagent defaults, so a native
subagent alone does not confine a role.
[Source: https://github.com/JakeSelby/agent-harness/issues/177]

## Design

### Approach

`lib/harness_core/workers.py` builds the worker, and each runtime's `adapters/<runtime>/worker.py` launches
its native CLI with the resolved role and stances. The lifecycle routes native launches of constrained
roles to this runner. Role and workflow guidance, the plan command and the BMad templates point at it.
`docs/role-workers.md` documents the boundary and its limitations. No new role catalog or dependency is
added. [Source: https://github.com/JakeSelby/agent-harness/pull/115]

### Decisions and alternatives

- **Isolated CLI worker over a native subagent:** parent permissions can override native subagent
  defaults.
- **Publish only a new caller-selected artifact:** a worker cannot overwrite an existing file.
- **No approval transfer** from worker to caller.

### Do not implement

- Native client qualification.
- A new role catalog or dependency.
