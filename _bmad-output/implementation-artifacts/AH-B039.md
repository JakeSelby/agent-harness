# AH-B039 — Live parent drift is reported in the direction that destroys the newer parent

## Reproduction

1. Map issues #372, #373 and #374 with no parent.
2. Shortly afterwards, make them sub-issues of epic #135 on GitHub.
3. Run `audit --live`: each parent difference is reported as `projection drift; run apply`.
4. Run `plan`: it proposes removing all three from the epic. `refresh` does not help, because it copied
   only title and lifecycle.
[Source: https://github.com/JakeSelby/agent-harness/issues/388]

## Root cause

The live audit treated every parent difference as the manifest being right, and `apply` writes the
manifest's parent onto GitHub. When the newer relationship is the one on GitHub, following the instruction
destroys it, and no command adopted a parent GitHub already recorded.
[Source: https://github.com/JakeSelby/agent-harness/pull/389]

## Acceptance criteria

1. **Given** #372, #373 and #374, **when** `plan` runs, **then** it proposes no parent change for them.
2. **Given** a mapped parent that GitHub records and the manifest lacks, **when** `refresh` runs, **then** it
   adopts it.
3. **Given** a parent that differs on both sides, **when** the live audit runs, **then** it reports a
   conflict naming both numbers, not `run apply`.
4. **Given** a parent the manifest already records, **when** `refresh` runs, **then** it never changes it.

## Design

The live audit now distinguishes three cases: a mapped parent the manifest lacks reports `run refresh`; an
unmapped parent reports `run reserve for it first`; a parent that differs on both sides is a conflict for a
maintainer to settle. `refresh` adopts only the first case, the only one that cannot be a deliberate
reparent. The manifest still owns the primary parent: `apply` is unchanged and keeps projecting a parent the
manifest records onto an issue that has none. The map change is `refresh` output: epic #135 for #372 to
#374, plus five lifecycle entries for issues closed by #376, #379, #381, #382 and #384.
[Source: https://github.com/JakeSelby/agent-harness/pull/389]
