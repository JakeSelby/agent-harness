## Story

As a developer whose commit convention is a stance, I want a `commit-msg` git hook in the repository template that refuses a non-conventional subject, so that Conventional Commits are enforced instead of asked for.

## Context and value

The issue cites `harness usage --rules` over 97 sessions: `commits/non-conventional` fired 278 times across 14 sessions and `commits/missing-trailer` 19 times across 4. `docs/how-it-works.md` already said a rule that trips this often is prose the agent walked past and wants to be a hook. The idea is adapted from `unclebob/swarm-forge`, which enforces its commit byline with a `commit-msg` hook.

## Acceptance criteria

1. **Given** a Conventional Commit subject, including a scope or a breaking marker, **when** the hook runs, **then** the commit passes.
2. **Given** a bare subject or a type not in the list, **when** the hook runs, **then** it exits non-zero and names the offending subject and the accepted types.
3. **Given** `commits: off` or `as-you-go`, or `HARNESS_STANCE_COMMITS=off`, **when** the hook runs, **then** it passes anything; the environment override beats the config.
4. **Given** `conventional-attributed` and no `Co-Authored-By:` trailer, **when** the hook runs, **then** it warns without failing; under `conventional` it does not warn.
5. **Given** a missing or unreadable config, **when** the hook runs, **then** it enforces the default rather than raising.
6. **Given** merge, revert and fixup subjects, comment lines or an empty message, **when** the hook runs, **then** they are exempt, skipped, or left to git.
7. **Given** the detector's Conventional Commits pattern, **when** the parity test runs, **then** the hook's copy matches it.

## Design

### Approach

`templates/repo/hooks/commit-msg`, standard-library Python 3.9, installed per repository with an install line in `templates/repo/README.md`.

### Decisions and alternatives

- **A git hook, not a `PreToolUse` Bash hook.** Both the issue and the pull request record that `_commit_messages()` in `rule-detectors.py` parses only `-m` values, so a commit written with `-F -`, a heredoc or the editor is invisible to it; a Bash-parsing hook would miss the same commits. A `commit-msg` hook sees the final message however it was supplied.
- **Warn, never append, the trailer.** The issue records that the model name is session state the hook cannot read.
- **A standalone copy of the pattern**, guarded by a parity test, because the hook ships on its own.
- The issue said the hook does nothing under `commits: off`; the pull request also makes it a no-op under `as-you-go`.

### Do not implement

- Appending a `Co-Authored-By:` trailer (from the issue).
