## Story

As a harness maintainer, I want the stop-gate decision row to carry the agent's completion claim, behind
its own off-by-default switch, so that a stop claim can be verified against the gate evidence on one row.

## Context and value

The Stop payload carries no assistant text, so the row from #370 held the repository's gate block and the
gate's result, and not what the agent said it had done. The issue records that verifying a stop claim
against gate evidence (#141) needs the claim; without it, #141 could only be evaluated on the hand-labelled
fixtures in #377. This is the one place the decision log holds assistant prose, which #370 deliberately
kept out, hence the separate switch and its default.
[Source: https://github.com/JakeSelby/agent-harness/issues/387]

## Acceptance criteria

1. **Given** the switch off, **when** a stop-gate row is written, **then** it is byte for byte what #370
   writes.
2. **Given** the switch on, **when** the row is written, **then** the claim is capped, the hash covers the
   uncapped text, and a transcript that is missing, unreadable or over a size bound logs the row without the
   claim and records the miss.
3. **Given** a large transcript, **when** the claim is read, **then** the read fits inside the Stop hook's
   budget, and a test pins the bound.
4. **Given** the Codex adapter, **when** it stops, **then** it supplies the same field or its capabilities
   file names the gap.

## Design

### Approach

A `stop-gate` row can carry `completion_claim`, the last 2 KiB of the turn's final assistant message read
from the transcript at Stop, and `completion_claim_sha256` over the uncapped message. The read is a bounded
tail split on newlines only, scanning back to the newest user prompt so the claim belongs to the turn that
stopped; the claim is the last 2,048 bytes, decoded on a character boundary. A miss is written on the row as
`completion_claim_miss` (`no_transcript_path`, `unreadable`, `oversized`, `no_claim`, `error`).

### Decisions and alternatives

- **Switch name:** the issue asked for "its own switch" without naming one; the PR chose
  `telemetry.completion_claim`, a sibling of `telemetry.decisions`, off by default.
- **Miss on the row, not a separate count:** the issue said "counts the miss"; the PR records the miss
  reason on the row itself, so an absence is visible to a reader of the log.
- **Codex:** the reader parses the rollout shape, but no Codex Stop payload had been observed, so the
  capabilities file records it as unverified rather than claiming parity.

### Do not implement

- Any other point's rows; permission points never hold assistant prose or tool output.
- Sending the text anywhere; what a provider may see is #137's question.
- Command sampling (#386) is untouched.
