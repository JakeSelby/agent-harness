# AH-B066 — Replay counts the CLI's synced skill packs as sync leftovers and stops after the first tag

## Reproduction

On macOS with Claude Code 2.1.280 and a signed-in, otherwise empty profile at
`~/.claude-bench-harness`, run `python3 scripts/cost_bench.py replay --tag v0.12.0 --tag a36b4fe
--model claude-sonnet-5 --harness-config ~/.claude-bench-harness`. The first tag's arm launches a
session, the CLI writes its synced skill packs under `skills/synced/<id>/` in that profile, and
after the tag the run stops with `the sync could not be taken back out of …: skills/synced/…;
the sync's records did not cover it`. The harness layer itself is gone (`harness_residue` is
empty, `settings.json` is back to its bytes); the second tag never launches.

## Root cause

`sync_leftovers` in `scripts/cost_bench.py` treats any entry under a `HARNESS_NAMES` top-level
name that was not in the pre-sync listing as the sync's. `skills` is such a name, and the CLI
writes `skills/synced/` there during any session. The `skills` directory itself is created by the
sync, cannot be removed by the undo's `rmdir` while the packs sit inside it, and so is reported
as a leftover too.

## Acceptance criteria

1. **Given** a named profile and a tag's sync, **when** the CLI writes `skills/synced/<id>/…`
   during the run, **then** the undo removes the harness layer and reports no leftovers.
2. **Given** the same run, **when** the undo completes, **then** the packs and `.staging` still
   exist with their bytes, and the profile holds no harness links or rendered files.
3. **Given** two tags into one profile, **when** the first tag's session writes synced packs,
   **then** the second tag launches.

## Design

`skills/synced` joins `RUN_WRITES`, and `_run_write` also accepts a directory that exists only to
hold a run-write root (`skills` above `skills/synced`). Rejected: excluding `skills` from
`HARNESS_NAMES` altogether, which would stop the residue check refusing a profile with stale
harness skill links. The fix must not change what the undo deletes: only what it reports.

## Regression test

`tests/test_cost_bench_tags.py::UndoSyncTests::test_the_clis_synced_skill_packs_are_neither_leftovers_nor_removed`
— fails before the fix with the leftover `skills`, passes after.
