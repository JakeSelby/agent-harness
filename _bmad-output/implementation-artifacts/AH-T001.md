## Goal

Let the replay runner measure one change at a time, with arms that differ only by the harness. The issue
records two defects. `arm_env` gave only the bare arm a `CLAUDE_CONFIG_DIR`; the harness arm inherited
the live config through `HOME`, so it carried personal rules and a rendered personal file the bare arm
never had, and a share of every published gap was the operator's own content. And the history upsert key
`(date, series, version, sha)` meant two measurements taken on one day at one commit overwrote each
other. A profile cannot be shared by copying, because the CLI keys its credential in the keychain under a
hash of the config directory's absolute path, so the bench profile is a second sign-in, not a copy.
[Source: https://github.com/JakeSelby/agent-harness/issues/437]

## Acceptance criteria

1. **Given** `--harness-config`, **when** `arm_env` builds the arms, **then** each arm has its own
   profile and the bare arm's is unchanged; omitted, behaviour is unchanged.
2. **Given** two buckets recorded on one day at one commit, **when** history is written, **then** they
   produce two rows.
3. **Given** a history row written before buckets existed, **when** `history.md` is rendered, **then**
   it still renders.
4. **Given** the arm profile, **when** a run is hashed, **then** it feeds the `series` hash, so a run
   whose harness arm carries a personal layer never reads as comparable to one that does not.
5. **Given** the change, **when** the gate runs, **then** lint is clean and the unit suite is green under
   both `python3` and `/usr/bin/python3`.
