# AH-E005 — Ship a defensible v1.0.0 stable release

<!-- bmad-sync:begin -->
- **GitHub issue:** [#206](https://github.com/JakeSelby/agent-harness/issues/206)
- **Primary parent:** [AH-E001](https://github.com/JakeSelby/agent-harness/issues/93)

The issue carries the summary, discussion and acceptance evidence; this file carries the design.

This work item was authored as part of the repository's committed BMad planning system.
<!-- bmad-sync:end -->

## Goal

Release v1.0.0 with a narrow, explicit stable support promise that a maintainer can defend without
informal knowledge or unverified client claims. Completion is observable when v1.0.0 is published from one
audited, frozen source revision, and every public surface agrees on its support status.

The issue names v0.10.0 (#220) as the required predecessor and as the upgrade and rollback baseline. Its
parent program is #93 and its planning owner #193.

## Scope and requirement coverage

**Stable support floor, as the issue states it:** Claude Code CLI on macOS and Linux, and Codex CLI on macOS
and Linux. VS Code and the Codex desktop app remain preview and do not block v1.

**Out of scope:** stable editor and desktop support. PRD §9.3 also excludes other runtimes as stable
targets, a team surface, a bundled architecture viewer and hosted execution.

**Requirement coverage.** `epics.md` lists this epic against FR-12, FR-66 and NFR-5. Checked against the
2026-09-23 PRD:

- **FR-12 Release integrity** (partial): every release and support statement names the same immutable
  revision, evidence and status. Here that is #207 and #211; the pre-1.0 release floor is AH-E014's.
- **FR-66 Upgrade, rollback and migration** (partial): the PRD's planned remainder is "the proof against
  the 1.0 candidate", which is #209. The policy half, #208, is delivered.
- **NFR-5 Auditability:** a support or release claim traces to exact evidence bytes, and cannot hide a
  contradictory failure. Here that is #210.

PRD §9.1 also places the provider-backed end-to-end tests (#134) in the v1.0.0 contract.

**Recorded contradiction.** The issue's stable floor promises Codex CLI on macOS and Linux unconditionally.
The 2026-09-23 PRD (§9.1, and FR-12's consequences) makes Codex CLI's place in the 1.0 contract
conditional. One scripted round must pass with `--home-confirmed` and agree with a hand-driven round on
every case outcome. The issue has not been amended to match.

## Children

In the order of the v1 release program's steps:

1. AH-S090 #207: Freeze the v1 stable support contract and candidate matrix (open)
2. AH-S091 #208: Publish the v1 SemVer, deprecation, and migration contract (done, PR #221, merged 2026-09-19;
   `docs/compatibility-policy.md`)
3. AH-S092 #209: Prove the v1 install, upgrade, rollback, and uninstall lifecycle (open)
4. AH-S093 #210: Run an independent v1 release audit (open)
5. AH-S094 #211: Cut and publish v1.0.0 from the audited candidate (open)
6. AH-S048 #134: Add bounded provider-backed end-to-end tests with inexpensive models (open)

All six carry the v1.0.0 milestone.

## Architecture slice

- **AD-3 Reversible configuration ownership:** restore only while the current value still matches, and
  compare semantically for rollback, never by byte snapshot. The lifecycle proof (#209) exercises this
  rule.
- **AD-4 Evidence-backed compatibility:** every supported target references passing evidence for the exact
  source revision, and a round runs frozen on a release branch. This is the candidate freeze (#207) and
  the publication (#211).
- **AD-17 Behaviour read from client internals is pinned and checked:** such features stay outside the v1
  stable surface.
- **AD-21 Dependencies:** third-party code enters only as a pinned, licence-reviewed wheel. The audit
  (#210) covers licensing.

## Sequencing

From "Sequencing and ownership" in `_bmad-output/planning-artifacts/v1-release-plan.md`:

- #207 records the candidate before #209 begins.
- #208 may run in parallel until its policy bytes are folded into the candidate. It is now delivered, and
  #207 and #209 rerun any gate its bytes affect.
- #210 starts only when #207, #208 and #209 are complete and the candidate is frozen.
- #211 starts only after #210 records a go verdict. Any change to the candidate returns to the affected
  gate.

The release program does not order #134 among these steps. PRD §9.2 schedules v0.14.0 to v0.16.0 before
1.0.

**Milestones:** the issue's milestone field is v1.0.0, matching `epics.md`. The map parents this epic to
AH-E001 (#93), which closed on 2026-09-19. The parent record is kept in AH-E001.

## Exit criteria

The issue's exit conditions, all open:

- [ ] The frozen release candidate passes the stable compatibility matrix (#207).
- [x] SemVer, deprecation, migration and support policies are public (#208, `docs/compatibility-policy.md`).
- [ ] Clean install, upgrade, repeat sync, rollback and uninstall preserve unrelated user configuration
  (#209).
- [ ] An independent release audit signs off on packaging, licensing, docs, evidence and recovery (#210).
- [ ] The release is cut from the audited immutable source revision, and public surfaces agree on its
  support status (#211).

The release program's own exit test: five stories close against one commit and archive digest, and #211
publishes those exact bytes.
