## Reproduction

The `gatherer` role listed `WebFetch` and `WebSearch`, and the spawn hook refused an in-session
`gatherer` in favour of `harness role run gatherer`. Run a web-research brief through that command:
the isolated worker has only `Glob`, `Grep` and `Read`, so it returns "no web tools", and `/research`
cannot reach the web through the only path left open to it.
[Source: https://github.com/JakeSelby/agent-harness/issues/325]

## Root cause

The role declaration and the worker's launch disagreed. The worker's offline confinement is
deliberate (#115): a worker that can both read a workspace and fetch can carry what it read back out.
The role body and `/research` had not been brought in line with it.
[Source: https://github.com/JakeSelby/agent-harness/pull/328]

## Acceptance criteria

The issue allowed either fix; the PR took the second:
1. **Given** a web dimension in `/research`, **when** it is routed, **then** it goes to an in-session
   band worker, and files and repositories go to the isolated worker.
2. **Given** the role definition, the binding, the refusal message, `/research` and
   `docs/role-workers.md`, **when** compared with the worker's real tool list, **then** they agree
   that the gatherer worker is offline.
3. **Given** an isolated `gatherer`, **when** it is launched on either runtime, **then** a test
   asserts its command line carries read tools and no web tools.

## Design

- **Chosen:** keep the worker offline and make every surface say so; route by where the evidence
  lives.
- **Not taken:** an opt-in `--web` mode granting only `WebFetch` and `WebSearch`. It would keep web
  research confined, but read plus fetch in one process is the combination the boundary excludes, so
  it needs its own decision.
- **Must not change:** the isolated worker's tool set.
[Source: https://github.com/JakeSelby/agent-harness/pull/328]
