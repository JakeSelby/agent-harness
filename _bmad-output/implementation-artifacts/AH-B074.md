# AH-B074 — gate-invalidation reads the stop-gate state at an unresolved path, so a run under a symlinked home is never observed

## Reproduction

Run the case alone on macOS from a clean checkout at `25c4081`:
`python3 scripts/native_acceptance.py --client claude-code-cli-macos --cases gate-invalidation --keep-home`.
It ends `unverified` with "the green gate did not run once and record a pass (runs 1, status
None)", as both Claude Code CLI records of the 0.13.0 round did at `d426d6d`. The kept home holds
one state record, named for the SHA-256 of the `/private/var/folders/...` form of the repository
path, not of the `/var/folders/...` form the case hashed; the record says `unverified`, "working
tree changed during the gate". Inside the Linux target image, where `/tmp` is not a symlink, the
same case at both commits reads that record and reports "(runs 1, status unverified)".

## Root cause

Both defects are on the reader side, in `scripts/native_acceptance.py`; the hook is consistent
with itself.

1. The hook keys its state file on `git rev-parse --show-toplevel`, which git prints resolved,
   and its tree hash resolves the same root, so both agree on one canonical path. `gate_state`
   hashed `str(repo)` unresolved. The disposable home comes from `tempfile.mkdtemp`, and on macOS
   the temporary directory is a symlink into `/private`, so the digests differ and the case
   reads no record.
2. The case's gate appends to `gate-runs.log` in the repository, untracked and not ignored. The
   hook's tree hash covers untracked files, so every green run changed the tree during the gate
   and was correctly released `unverified` rather than recorded `passed`.

## Acceptance criteria

1. **Given** a disposable home reached through a symlink, **when** the hook records a green
   gate, **then** `gate_state` returns that record.
2. **Given** the case's own gate repository, **when** a green Stop is delivered twice, **then**
   the gate runs once and the record says `passed`.
3. **Given** the fixed runner, **when** `gate-invalidation` runs on macOS and in the Linux target
   image, **then** it passes on both.

## Design

`gate_state` hashes `repo.resolve()`, the same canonical path git gives the hook. The case's
repository gains a `.gitignore` naming `gate-runs.log`, so the counter is outside the tree hash.
Rejected: resolving inside the hook's `state_path`, which would change nothing because git already
hands it a resolved root. The hook, its
state layout and the case's assertions do not change.

## Regression test

`tests/test_native_acceptance_gate_state.py` drives the real hook through the Claude Code
lifecycle entrypoint under a symlinked home. Both tests fail before the fix with
`None != 'passed'` and pass after it.
