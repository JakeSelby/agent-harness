## Story

As the maintainer cutting a release before 1.0, I want an explicit waiver in the compatibility catalog
for a release that requires no target, so that shipping with no qualified target is a recorded choice
that preflight can tell apart from a mistake.

## Context and value

The PRD's FR-12 says: "Before 1.0, a release may ship without a qualified target only when its
compatibility status says so." Its status adds that "0.12.0 shipped with no qualified target" and "an
explicit waiver field in the compatibility catalog is planned (unscheduled)".

The issue states the gap: the catalog has no field that records that choice, so a release with no
required target looks the same as a mistake.

At `origin/main`:

- `release_errors` in `lib/harness_core/compatibility.py` fails only for a client that is
  `required_for_release` and not `qualified`. With no required client, it raises nothing for the
  missing floor;
- `scripts/release_preflight.py` calls `release_errors`;
- `compatibility/catalog.json` has no waiver field.

## Acceptance criteria

From the issue:

1. **Given** a catalog with no required target and no waiver, **when** preflight runs, **then** it
   fails.
2. **Given** a catalog with no required target and a waiver, **when** preflight runs, **then** it
   passes.
3. **Given** a waiver, **when** it is read, **then** it carries a reason and the release it applies to.

## Design

### Approach

From the issue's scope: add an explicit waiver, with a reason and the release it applies to, and have
preflight require it whenever no target is required.

### Decisions and alternatives

Not recorded in the issue or pull request.
