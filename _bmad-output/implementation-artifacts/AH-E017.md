## Goal

Bring the code into line with the 2026-09-23 architecture spine wherever the spine records a migration
rather than the current state. Completion is observable through the issue's acceptance: each listed AD's
rule holds in code, and the spine's migration notes for it are removed.

## Scope and requirement coverage

**In scope,** from the issue's Scope section:

- One stance resolver: retire the second precedence ladder in `bin/harness` (AD-2, with #294).
- Ledger rows carry a schema version, and readers tolerate unknown fields (AD-11).
- One shared atomic-write helper that keeps file mode (AD-18).
- Remote Control pinned to its verified client versions, with a doctor warning outside them (AD-17).

**Out of scope:** spine migrations that other epics own. The unguarded spawn paths of AD-8 and the plugin
manifest version of AD-19 are AH-E015's. The per-session stop-gate counter of AD-18 is AH-E015's too
(#611). The viewer's move to a descriptor under AD-10 has no child here.

**Requirement coverage.** `epics.md` lists this epic against FR-2, FR-11, FR-60 and NFR-6. Checked against
the 2026-09-23 PRD:

- **FR-2 One effective selection** (partial): every hook reads the same effective policy that
  `harness stances` prints. #643 removes the second ladder that makes the two disagree.
- **FR-11 Local-first observability:** the ledgers stay the system of record, and a schema version keeps
  old rows readable (#644).
- **FR-60 Remote Control hosts:** pinning the verified client versions, with a doctor warning outside them
  (#646).
- **NFR-6 Reversibility:** configuration, ownership-journal, issue-map and story-file writes each go
  through a temporary file and an atomic replace, keeping the file's mode (#645).

## Children

All open, with no milestone:

1. AH-S210 #643: Resolve stances only through posture.py and retire the CLI ladder (AD-2, AD-6)
2. AH-S211 #644: Ledger rows carry a schema version and readers tolerate unknown fields (AD-11)
3. AH-C054 #645: One kernel helper for atomic whole-file rewrites that keeps file mode (AD-18)
4. AH-S212 #646: Remote Control: pin the verified client versions and warn in doctor outside them (AD-17)

**State at `origin/main`, checked against the code:**

- `bin/harness` still reads `HARNESS_STANCE_*` variables itself, beside `policy/hooks/posture.py`. That is
  the second ladder.
- Whole-file rewrites each call `os.replace` separately in `policy/hooks/stop-gate.py`,
  `policy/hooks/posture.py`, `policy/hooks/usage-feed.py`, `policy/hooks/usage-log.py` and
  `lib/harness_core/reconcile.py`. There is no shared kernel helper.
- The spine records that `lib/harness_core/remote_control.py` names its verified versions only in
  comments.

## Architecture slice

This epic exists to close the migration notes on these ADs:

- **AD-2 One resolver, fixed invariants** (resolver unification in progress): `posture.py` is the only
  resolver, and `bin/harness` stops resolving on its own. The spine names #294 and #554 as carrying the
  migration. `bin/harness stances --json` keeps its output shape across it.
- **AD-6 One effective policy for every consumer** (partial: "the CLI's ladder retires under AD-2"):
  closes with #643.
- **AD-11 Local ledgers are the system of record, and grow compatibly** (partial: schema version planned
  under #636): rows carry a schema version from the next ledger change on, readers tolerate unknown
  fields, and a rename ships with a fold map.
- **AD-17 Behaviour read from client internals is pinned and checked** (partial: pin planned under #636):
  behaviour is pinned to the client versions it was verified on, and `doctor` warns outside them.
- **AD-18 Shared-machine concurrency and writes** (partial: helper and per-session counter planned): one
  kernel helper writes a temporary file, fsyncs, replaces atomically and keeps the mode. The writers in
  `bin/harness`, `reconcile.py`, `cost_bench.py`, `posture.py`, `stop-gate.py`, `usage-feed.py` and
  `usage-log.py` converge on it.

## Sequencing

- The four children touch separate ADs, and the record states no dependency between them.
- #643 must land in step with #294 (AH-E015) and #554 (AH-E011), which the spine names as carrying the
  same resolver migration. AD-2 forbids new code reading the ladder directly in the meantime.
- #644 applies "from the next ledger change on", so it lands before or with the next ledger schema change.

- [ ] Ledger rows carry a schema version, and readers tolerate unknown fields (#644).
- [ ] Every whole-file writer the spine names goes through one kernel helper that keeps file mode

- [ ] Remote Control's verified client versions are pinned in code, and `doctor` warns outside them

  epic covers.
