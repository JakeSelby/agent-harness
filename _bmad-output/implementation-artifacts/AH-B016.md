## Reproduction

1. On the Codex CLI on Linux, select `cost=frugal` and run `harness sync`.
2. Run `harness role run gatherer` in the same home.
3. Compare the worker's model class with what sync rendered for `gatherer`.

Observed during native qualification: the isolated `gatherer` worker ran on the role's own class while
the same sync rendered that role one class lower. The worker's brief carried no budget sentence.
[Source: https://github.com/JakeSelby/agent-harness/issues/277]

## Root cause

`workers.resolve()` in `lib/harness_core/workers.py` built its binding from the role's `tier:` and
`role_bindings` only; the variant reached only the sync path. The brief guard only sees the denied
native spawn, so the budget sentence never reached a worker either. This contradicted
`docs/runtime-controls.md`, which said role workers resolve per run. It mattered because the constrained
roles (gatherer, reviewer, spec-reviewer, planner, design-judge, log-compressor) are denied as native
spawns and always run as isolated workers on both runtimes, and they are the roles with measured
budgets.

## Acceptance criteria

1. **Given** a resolved variant, **when** a role worker starts on either runtime, **then** its model
   and effort equal what `harness sync` would render for that role, with the same precedence.
2. **Given** a worker, **when** it starts, **then** its `status.json` records the variant, the source of
   class, model and effort, and the budget figures, with no prompt text.
3. **Given** a worker's brief, **when** it is built, **then** it ends with the same `Expected spend`
   sentence a native brief gets, from one shared function, unless the brief already states a budget or
   the row has none.
4. **Given** a variant with no rows, or a table that cannot be built, **when** a worker starts, **then**
   it behaves exactly as before.

## Design

A role worker resolves its row through the same function and precedence sync uses: role defaults, then
the cost row (class only under tiered delegation; a fixed role takes neither class nor effort), then
`role_bindings`, then `--model`. A session-scoped cost selection reaches a worker, as the docs already
said. The budget sentence moves into one shared function that both the brief guard and the worker call;
the brief guard's output and tests are unchanged.

## Regression test

`tests/test_role_worker_posture.py` (new): a worker's resolved class and effort match sync's rendering
under the variant.
