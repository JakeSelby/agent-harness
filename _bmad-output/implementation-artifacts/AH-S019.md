## Story

As a maintainer of the rules, I want the detector registry run at the end of every session and a `harness usage --rules` report over the results, so that I can see how often each rule fires and which rules are candidates for promotion or were never observed.

## Context and value

#58 built the registry with no session behaviour. This issue wires it into the existing `usage-log` SessionEnd worker and adds the report, with `--rescan` so the report can backfill from existing transcripts.

## Acceptance criteria

1. **Given** a session ends, **when** the worker runs, **then** the session record carries `rules` (detector id to hit count), `counts` (web searches, subagent spawns, chooser prompts) and `stances` (all eight dimensions, the environment override first).
2. **Given** a registry that will not import, or lacks the function the worker calls, **when** the worker runs, **then** the record carries `rules_error` and keeps the rest of the session.
3. **Given** `harness usage --rules [--days N] [--by rule|repo|stance]`, **when** it runs, **then** it reports hits, sessions with a hit and the share per detector, and lists every registry id so unobserved rules are visible.
4. **Given** a detector above 30 percent of at least 20 sessions, **when** the report runs, **then** it is marked `promote?`; zero hits over at least 20 sessions is marked `unobserved`; a window too narrow is annotated with nothing.
5. **Given** sessions with no rule data, **when** the report runs, **then** they count neither as zero nor in the denominator.
6. **Given** `--rescan`, **when** it runs, **then** `rules` is recomputed from the transcripts.

## Design

### Approach

`claude/hooks/usage-log.py --worker` builds the detector event list in the single pass it already makes over the transcript, keeping result text only for the two tools a detector reads, then calls `rule_detectors.run`. `bin/harness usage --rules` aggregates. `docs/usage.md` gains a rule-telemetry section.

### Decisions and alternatives

- **One pass.** The event list is built on the worker's existing pass (from the issue).
- **Fail soft.** A registry failure costs the record only its rules (from the pull request).
- **Two more detectors.** The pull request adds the grade hook's confirmed re-run (`HARNESS_CONFIRMED=1`) and deny-by-grade detectors, for the hook that landed in #63.
