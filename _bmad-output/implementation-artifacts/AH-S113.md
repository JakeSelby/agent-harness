## Story

As the release maintainer, I want native qualification to require a `cost-posture` case with an exact
procedure, so that a client cannot qualify without the cost posture layer ever running natively.

## Context and value

The ten required cases predated the cost posture layer, so a client could pass every one without
posture-rendered agent definitions, routing of unnamed spawns, the budget in a brief, the usage feed or
per-role telemetry ever running natively. The issue records that a defect in exactly that area passed
every test and review and surfaced only in a live run. Part of #268.
[Source: https://github.com/JakeSelby/agent-harness/issues/269]

## Acceptance criteria

1. **Given** the catalog, **when** it is read, **then** `cost-posture` is in `required_cases`.
2. **Given** the qualification procedure, **when** it is read, **then** it has a `cost-posture` step,
   including the check that an already-running session is never rerouted and still spawns.
3. **Given** evidence recorded for earlier releases, **when** it is validated, **then** it stays valid
   and byte-identical.
4. **Given** the change, **when** it lands, **then** no runtime-source path changes, so a later freeze is
   unaffected, and release preflight still refuses on exactly the four unqualified clients.

## Design

### Approach

`compatibility/catalog.json` adds `cost-posture` to `required_cases`. `docs/compatibility.md` gains a
step naming every observable: only changed roles rewritten at sync; an unnamed spawn running as the
default band worker at the row's model and effort, with the budget sentence in its brief; the feed
reporting spend against that budget; the routed row in `usage --by role`; an already-running session not
rerouted and still spawning; a null variant doing none of it; and what to verify on a runtime that does
not route native spawns.

### Decisions and alternatives

- **No validator change:** evidence is rejected when its `harness_version` differs from the catalog's,
  so each release keeps its own case list and earlier evidence stays valid. Tests pin both directions.

### Do not implement

- Any runtime-source change.
