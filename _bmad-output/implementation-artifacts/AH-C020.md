## Goal

Add two lines to the `builder` role's fixed report, each of which, per the issue, would have saved a
review round in a downstream soak of 0.11.0:
- A builder bumped a format version in one language and hand-edited a test fixture to match. The
  fixture was the output of a generator elsewhere in the same repository that still emitted the old
  version, so a byte-for-byte test on the generator's side broke, outside the gate the brief named.
- A builder reported "exit 0 for the run, result FAILED (failures=3)", which was the status of `tail`.
  The verification rule already wanted the status asserted directly; the role should say how.
[Source: https://github.com/JakeSelby/agent-harness/issues/305]

## Acceptance criteria

1. **Given** a builder that edited a fixture, golden file or pinned value, **when** it reports,
   **then** the report names the generator or the command that printed each one, and "hand-typed,
   copied from run X" is accepted while silence is not.
2. **Given** a builder that runs a test command through a pipe, **when** it reports the result,
   **then** the role tells it to capture the command's own status (`pipestatus`, `PIPESTATUS`, or no
   pipe).
3. **Given** the shared role and its Claude Code projection, **when** they are compared, **then** both
   carry the two additions.
