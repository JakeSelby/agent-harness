# AH-T003 — Let the replay fence admit each arm's own profile directory, and prove the gate passes under it before spending

## Goal

Stop the replay runner's own sandbox fence from contaminating results. The issue records that every
replay result to date was contaminated, asymmetrically between arms: `FENCE` was a single constant that
allowed the CLI's default `~/.claude` but not a `CLAUDE_CONFIG_DIR` override, and denied `/tmp`, while
the repository's suite writes to `<config dir>/plans` and `/tmp/harness-worker-*`. Any arm on a bench
profile therefore failed those tests under the fence and thrashed to make them pass. The bare arm had
been on a bench profile since the first set; the harness arm picked the handicap up when it moved to
one. The issue concludes that no earlier ratio measured the harness, and that a pre-flight running the
gate under the fence would have refused the very first set.
[Source: https://github.com/JakeSelby/agent-harness/issues/487]

## Acceptance criteria

1. **Given** an arm on a bench profile, **when** its fence is built, **then** it allows write and read of
   that directory and `/tmp`; an inherited arm's fence allows `~/.claude`; `denyRead` is unchanged.
2. **Given** recorded gate output, **when** the pre-flight runs, **then** it refuses on a red gate and
   passes on a green one, and every row carries the result (`passed`, or `skipped` under
   `--skip-preflight`).
3. **Given** the change, **when** the gate runs, **then** lint is clean and the unit suite is green under
   both `python3` and `/usr/bin/python3`.

**Not delivered as worded.** The issue also asked for a test that a task whose held-back tests write to
the profile directory passes the pre-flight on a bench profile. The PR records that, with the fence
fixed, the bare arm's gate was still red without any sandbox, because `claude_dir()` read
`CLAUDE_CONFIG_DIR` before a test's `HARNESS_HOME`. It calls the change "necessary and not sufficient"
and says the defect was raised separately; that is #498 (PR #503).

**Later change.** #499 (PR #500) changed the pre-flight bar from the full gate to lint only. At
`origin/main`, `scripts/cost_bench.py`'s pre-flight prompt runs only `python3 bin/harness lint`, and its
verdict requires `lint: 0 finding(s)` and no refused read.

## Dev notes

- **Design, from the PR.**
  - `/tmp` alone did not admit the scratch directory; the resolved `/private/tmp` had to be named too.
    This was verified by direct probe under the sandbox.
  - As of #489, the pre-flight is one `-p` turn per arm in its own profile and fence that runs the full
    gate; PR #500 later reduced it to lint only. Its verdict is read from the Bash tool result (at #489,
    the lint line and unittest's `OK`; any refused read is red), never from what the model relays: block-buffered stdout put a worktree path after `OK`, and the first build refused a
    green gate for that reason.
  - `ERROR:` and `FAIL:` lines are kept so a refusal is readable, and the stream is saved beside the
    scored transcripts. A red arm refuses with exit 2.
- **Bound requirements and decisions:** FR-56 (Live replay against a bare arm): each arm's fence is proved
  before scoring. AD-12 (Measurement invariants): each fence is proved before scoring.
- **Files touched:** `scripts/cost_bench.py`, `tests/test_cost_bench.py`, `docs/benchmarks.md`, the issue
  map and this story file.
- **Testing:** as of #489, the PR's diff adds ten test methods to `tests/test_cost_bench.py`. They
  include `test_the_fence_admits_the_arms_own_profile_and_the_scratch_directory`,
  `test_a_red_gate_refuses_the_replay_before_any_scored_run`,
  `test_unreadable_output_is_a_red_gate_and_never_a_pass`,
  `test_the_verdict_survives_the_suite_flushing_noise_after_ok` and
  `test_skipping_the_pre_flight_stamps_the_rows_and_launches_nothing_extra`.
