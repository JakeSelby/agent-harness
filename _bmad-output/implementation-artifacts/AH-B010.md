## Reproduction

1. Start from `main` after v0.10.0 was released, with `compatibility/catalog.json` `released` and pinned
   to its qualification commit.
2. Change any file under `bin`, `lib`, `adapters`, `primitives`, `policy` or `templates`.
3. Run `python3 -m unittest discover -s tests`.

Observed: `test_current_catalog_is_honest_and_release_ready` fails, because the tree now reports source
drift. Every runtime change made after v0.10.0 fails the suite.
[Source: https://github.com/JakeSelby/agent-harness/issues/231]

## Root cause

The test asserted that the tree had no release errors at all. A released catalog pinned to its
qualification commit reports source drift, by design, as soon as runtime source changes, so the
assertion contradicted the release design rather than checking it.

## Acceptance criteria

1. **Given** a released catalog and changed runtime source, **when** the suite runs, **then** the test
   expects the drift error and no other, and passes.
2. **Given** a released catalog and unchanged runtime source, **when** the suite runs, **then** the test
   expects no release errors.
3. **Given** the change, **when** it lands, **then** the released evidence and the publication block are
   untouched: changed source still blocks publication.
4. **Given** `main` and a branch that changes runtime source, **when** the gate runs, **then** lint is
   clean and the suite passes on both.

## Design

Assert what the design promises: changed source yields the drift error and nothing else; unchanged
source yields none. Only the test changes; the drift check and the preflight block stay as they were.
As of #232 the test is `test_current_catalog_is_honest_and_blocks_release_only_for_changed_source`; #299
(under #298) later renamed it `test_current_catalog_is_honest_and_blocks_release_only_for_its_state` and
made it handle the `candidate` state too.

## Regression test

`tests/test_compatibility.py`, as of #232 (name confirmed in that PR's diff)
`test_current_catalog_is_honest_and_blocks_release_only_for_changed_source`: it computes the expected errors from
`compatibility.source_drift` rather than asserting an empty list, so it fails on the old assertion when
source has drifted and passes after the fix.
