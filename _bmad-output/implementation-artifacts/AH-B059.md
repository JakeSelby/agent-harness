# AH-B059 — reserve hands out a BMad ID another worktree already took, because it trusts a per-checkout counter

## Reproduction

1. In the shared checkout, reserve a bug ID (`AH-B050` for #433) and leave the map uncommitted.
2. In a worktree branched off `main`, where `next_ids.bug` is still 50, run
   `reserve --issue 436 --kind bug`.
3. The second session is handed `AH-B050` as well. Nothing fails.

The issue records this happening on 2026-09-21, caught only because someone read the shared checkout's
uncommitted map, and a second live collision as it was filed: `AH-C033` assigned to #424 on
`origin/main` and to #432 in the shared checkout's uncommitted map.
[Source: https://github.com/JakeSelby/agent-harness/issues/440]

## Root cause

`reserve` allocated the next ID straight from `manifest["next_ids"][kind]` in this checkout's
`_bmad-output/issue-map.json` and never asked whether anyone else had spent it. `audit_manifest` enforces
that `next_ids` is strictly greater than every used ID, but only over the single map it is passed, so a
worktree off `main` audits clean while another checkout's reservation is invisible.

## Acceptance criteria

1. **Given** linked worktrees and branches, **when** `reserve` runs, **then** it surveys every issue map
   the clone can see (each worktree's working copy, so an uncommitted reservation counts, plus every
   local and remote-tracking branch) before trusting the counter.
2. **Given** a counter not strictly greater than every ID of that kind in use elsewhere, **when**
   `reserve` runs, **then** it refuses and names each taken ID and where it was seen.
3. **Given** remote heads the clone holds no object for, **when** the survey runs, **then** they are
   reported, so an incomplete survey is never read as a clean one.
4. **Given** the opt-in `--advance` flag, **when** it is passed, **then** the counter skips the taken IDs
   and says which it left unused.
5. **Given** no git repository, **when** the survey runs, **then** it degrades to a no-op.
6. **Given** two reservations from the same starting counter, **when** the second runs, **then** it is
   refused (regression test).

## Design

**Approach.** `survey_ids_elsewhere` reads the working copy of each linked worktree and every local and
remote-tracking branch's map in one `git cat-file --batch`. `reserve` runs a best-effort
`git fetch origin` first so remote-tracking refs are current. Heads `git ls-remote` advertises but the
clone cannot read are reported.

**Decisions and alternatives.** Read working copies, not worktree HEADs, because the motivating collision
was uncommitted. `--advance` replaces the previous hand-edit of `next_ids` and reports the permanently
unused IDs.

**Do not implement.** The `new` read-after-write failure and its `--kind`-less recovery hint, which
belong to #433.

## Regression test

`tests/test_bmad_issue_sync.py`, classes `SiblingReservationTests` and `SiblingSurveyUnitTests`:
`test_a_second_reservation_from_the_same_counter_is_refused`,
`test_advance_skips_the_taken_ids_and_says_which`,
`test_a_reservation_committed_on_another_branch_is_seen`,
`test_a_counter_a_sibling_has_already_run_past_is_refused`,
`test_an_unrelated_kind_is_untouched_by_the_survey`,
`test_the_survey_degrades_to_nothing_outside_a_git_repository`,
`test_a_remote_head_this_clone_cannot_read_is_reported` and
`test_an_unreadable_remote_head_is_named_in_the_refusal`.
