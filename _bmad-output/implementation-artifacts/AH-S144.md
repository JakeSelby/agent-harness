## Story

As a harness maintainer, I want a reproducible sample of the Bash commands the harness allowed without a
prompt logged to the decision log, so that a check which may only tighten an allow into an ask can measure
its false-alarm rate.

## Context and value

The decision log (#370) records only `ask` and `deny`, because an allowed command carries no gradeable
label. That is right for judging the prompts the harness raised, and it leaves nothing to judge the prompts
it did not raise: a tighten-only check (#372) cannot measure its false-alarm rate without allowed commands
to run against. The sampled rows are ungraded negatives for shadow evaluation.
[Source: https://github.com/JakeSelby/agent-harness/issues/386]

## Acceptance criteria

1. **Given** an input hash and a rate, **when** sampling runs, **then** the choice is deterministic for
   that hash and honours the rate, including a rate of zero.
2. **Given** sampled allows and graded rows, **when** `harness usage --by decision` runs, **then** sampled
   allows are reported separately, so outcome rates are not diluted.
3. **Given** a sampled row, **when** it is written, **then** the 2 KiB input cap, the no-tool-output rule and
   the swallow-every-write-failure rule from #370 hold.

## Design

### Approach

A sampled command is written as a `grade-bash` row with `deterministic_answer: allow`, `sampled: true` and
the `sample_rate` it was drawn at, one in twenty by default. The sample is taken from the command's own
hash, never a random draw or a clock. Sampled rows carry no outcome and no match key, so no later event can
label them. `usage --by decision` counts them on a `grade-bash (sampled)` line of their own. The text is
redacted before it is capped: assignment values and every secret shape the rule detectors match, read out
of the vendored `ruleprobe` wheel rather than copied.

### Decisions and alternatives

- **Rate key:** the issue asked for the rate under `telemetry.decisions`, but that key is a validated
  boolean, so the rate is the sibling `telemetry.allow_sample_rate`, 20 by default and 0 for none.
- **Secret shapes read from the pinned wheel** with `zipfile` and `ast`, not imported (the PR records the
  import cost in a PreToolUse hook) and not copied (`harness lint` refuses a literal copy as a secret
  pattern). If the wheel cannot be read, no sampled row is written.
- **Only an explicit `allow` the runtime was told about is sampled:** a no-answer grade-1 command and every
  Codex command write nothing, and a confirmed command is never sampled.
- **Hash over the redacted text:** the PR's first bullet says the hash stays over the original; its review
  notes change this so a short secret cannot be recovered from hash plus redaction. The code at
  `origin/main` hashes the redacted text.

### Do not implement

- Logging every allowed command; the read-only fast path fires constantly and would swamp the log.
- Any outcome label for these rows.
