## Goal

Let maintainers land a pull request under the `main` ruleset without rediscovering the same failures.
The PR records that each line it adds cost a broken landing on 2026-09-22, and none was written anywhere
a maintainer looks.
[Source: https://github.com/JakeSelby/agent-harness/issues/501]

## Acceptance criteria

1. **Given** `CONTRIBUTING.md`, **when** a maintainer reads it, **then** a short "Landing a pull request"
   section says: merge `origin/main` in to update the branch, never rebase; read gate exit codes directly;
   wait for checks to register before `gh pr checks --watch`; never bypass the pre-commit hook; beware the
   `bmad_issue_sync.py` reservation race; and expect the personal-data lint's npm-spec false positive.
2. **Given** `docs/releasing.md`, **when** the GitHub About section is read, **then** it says to run
   `sync_about.py --apply` only from a checkout at `origin/main`.
3. **Given** the change, **when** the diff is read, **then** no rule, stance or always-loaded file
   changed.
