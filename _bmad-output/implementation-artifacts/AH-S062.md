## Story

As an orchestrating agent's operator, I want a bounded check that a finished worker's return supplies
the result type its brief asked for and separates findings, uncertainty and unresolved items when
required, so that a return that matches the headings but misses the deliverable is caught, measured
first in `shadow`.

## Context and value

A short worker return may not deliver the kind of result its assignment requested. The 2026-09-21
re-scope kept this follow-on because it has a consumer: the `SubagentStop` path that reports a finished
subagent to the orchestrator. It is Claude Code only and stays shadow-only until the decision log (#370)
holds labelled returns. It is not a release dependency of the epic.
[Source: https://github.com/JakeSelby/agent-harness/issues/157]

## Acceptance criteria

1. **Given** the shared provider and versioned pack contracts, **when** a return is judged, **then** each
   criterion returns a typed decision with explicit abstention and unavailable handling.
2. **Given** a pack's declared input limit, **when** an input is oversized or missing, **then** it stays
   unverified rather than being silently truncated, and no transcript or repository is uploaded.
3. **Given** formatting, counts and schema, **when** they are checked, **then** deterministic code
   checks them.
4. **Given** research, implementation and review returns, legitimate no-findings and blocked returns,
   honestly reported partial results, and content that matches headings but misses the deliverable,
   **when** they are judged, **then** each is classified per criterion.
5. **Given** labels fixed before evaluation and a held-out split, **when** the pack is evaluated,
   **then** misses, false alarms, abstentions, errors, latency and available cost are reported; ordinary
   tests stay offline and live tests are opt-in and budgeted.
6. **Given** a provider failure, **when** it occurs, **then** current behaviour is preserved, and
   nothing is enforced by default before workload-specific validation.

## Design

### Approach

One bounded brief and its short worker response, with the applicable return requirements, are judged at
`SubagentStop` in `shadow`, and the result is recorded beside the existing report to the orchestrator.

### Decisions and alternatives

- **Kept at re-scope** because the `SubagentStop` path is a consumer.
- **Claude Code only:** `SubagentStop` has no Codex equivalent, and the gap is named rather than
  emulated (#140).

### Do not implement

Verifying underlying research, code correctness, hidden tool activity or whole-task completion; a
generic quality score; inferred permissions; model training; live configuration changes. Publishing the
provider's performance results stays subject to its terms.
