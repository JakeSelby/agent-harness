## Goal

Leave one open issue per failure, and no open issue without a BMad ID except those on the #529 hold
list ([#696](https://github.com/JakeSelby/agent-harness/issues/696)). The story enrichment recorded three
sets of duplicate or stale open issues:

1. **#392, #433 and #537: one failure.** `bmad_issue_sync.py new` files the issue but does not reserve
   its ID in the same invocation. All three are open. AH-B040 (#392) records the triplet, and that #433's
   body adds a second defect: the printed recovery `reserve --issue N` omits the required `--kind`, so it
   fails as written. PR #441's body assigns "the `new` read-after-write failure and its `--kind`-less
   recovery hint" to #433. AH-B040 says "The three need one delivery issue, with the others closed as
   duplicates. That triage is not recorded"
   [Source: _bmad-output/implementation-artifacts/AH-B040.md#Design]. #537 is AH-B069, on v0.12.1.
2. **#538 duplicates #606.** PR #615 (merged 2026-09-23) fixed the test under #606, which closed. #538
   (AH-B068) is still open, with its second criterion outstanding: an audit of other tests that read a
   real client from `PATH`, which PR #615 did not do
   [Source: _bmad-output/implementation-artifacts/AH-B068.md#Acceptance criteria].
3. **#369 is marked superseded by #560 but is open.** AH-S138 records that on 2026-09-23 the issue was
   "recorded as superseded by #560, the first four-arm live set, to be closed when #560 lands". #560 is
   open on v0.14.0 [Source: _bmad-output/implementation-artifacts/AH-S138.md].

**Hold list.** #433 is not in `_bmad-output/issue-map.json`. Draft PR #529, held for v0.12.1 and
closing #530, holds its reservation: its body lists #433 among the fifteen accepted issues it reserves
IDs for ([PR #529](https://github.com/JakeSelby/agent-harness/pull/529)).

## Dev notes

- **Bound:** FR-9: Traceable work items. Every managed work item has a BMad ID and links both ways
  before implementation, and `reserve` refuses an ID another branch already holds
  [Source: _bmad-output/planning-artifacts/prds/prd-agent-harness-2026-09-23/prd.md#FR-9: Traceable work items].
- **Closing an issue** is a GitHub write by the maintainer. A duplicate closed as "not planned" still
  reads `completed` in the map until #698 lands, because the sync tool maps every closed issue to
  `completed` [Source: scripts/bmad_issue_sync.py#live_lifecycle].
- **Hold list.** The sync tool does not encode the #529 list; `audit --live` reports those issues, and
  the exception in criterion 2 is read by hand. `accepted_for_delivery` returns false for an issue
  whose `state_reason` is `not_planned` or `duplicate`, so closing a duplicate with that reason keeps it
  out of the live audit's findings; it is reported as a notice
  [Source: scripts/bmad_issue_sync.py#live_findings].
- **Files to touch:** the four story files named above, and `_bmad-output/issue-map.json` through
  `reserve` for any new ID.
- **Testing:** `python3 scripts/bmad_issue_sync.py audit` and `audit --live`.
