## Story

As a developer adopting the BMad integration, I want the template README and BMad docs to say what session
startup actually does and how to recover missing review dependencies, so that I do not expect an automatic
install and can repair a broken installation without losing my customization.

## Context and value

This is a delivery slice of #97, under epic #93; the PR is also part of #99. It records ownership of the
already open PR #148, stacked on #132. The template README described session startup and installation
inaccurately: startup only checks the BMad configuration, and installation needs an explicit apply.
[Source: https://github.com/JakeSelby/agent-harness/issues/179]

## Acceptance criteria

1. **Given** the distributed template README, **when** a developer reads it, **then** it says session
   startup checks BMad configuration and installation requires an explicit apply.
2. **Given** missing GDS review dependencies, **when** a developer follows the docs, **then** the pinned
   installer's compatibility-shim recovery restores them.
3. **Given** that recovery, **when** it runs, **then** existing customization and runtime patches are
   preserved.

## Design

### Approach

Documentation only: `templates/bmad/README.md` is corrected, and `docs/bmad.md` documents shim recovery
through the pinned installer. [Source: https://github.com/JakeSelby/agent-harness/pull/148]

### Decisions and alternatives

- **Recover through the pinned installer's shims rather than a harness-side repair.** Why this was
  preferred is not recorded in the issue or pull request.

### Do not implement

- Native workflow qualification, which the PR says remains separate.
