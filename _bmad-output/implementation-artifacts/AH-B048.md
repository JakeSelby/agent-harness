# AH-B048 — usage prints a partial-totals line above a report that already counts those runs

## Reproduction

Run `harness usage` in USD over a ledger that holds runs with an unknown model or partial tokens. Observed,
per the issue, on a real ledger: `Partial totals: unavailable metrics are excluded: ...` printed above a
report whose own footer then said `unpriced: 92 run(s), unknown model or partial tokens`. The same fact was
reported twice, and the two lines read as different problems: the first implies figures were dropped from
the totals, the second that they were counted as unpriced.
[Source: https://github.com/JakeSelby/agent-harness/issues/407]

## Root cause

`bin/harness` printed the partial-totals line and the unpriced footer independently, with no guard between
them, so a report that already accounted for the runs in its footer also carried the warning.

## Acceptance criteria

1. **Given** a USD report carrying an unpriced footer, **when** it prints, **then** it prints the footer only.
2. **Given** a report with no unpriced accounting, **when** metrics are excluded, **then** it still warns.
3. **Given** a regression test, **when** it runs, **then** it covers both.

## Design

### Approach

One guard in `bin/harness`, with a comment saying why: the warning prints only when no run was left
unpriced, which the PR calls the one case where nothing else says a column is short.

### Decisions and alternatives

- **Suppress on any unpriced run:** the guard is whether any run is unpriced, not a per-metric comparison;
  a test pins that one unpriced run silences the warning the rest of the report would carry.
- **No `product.json` change:** this corrects output wording with no new capability.

### Do not implement

Not recorded in the issue or pull request.

## Regression test

`test_a_complete_window_carries_neither_line`.
