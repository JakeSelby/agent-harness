## Story

As a developer who clones a repository that runs BMad, I want the harness's override templates installed at session start and a drifted template refused, so that the framework's spawns never run bare on a fresh clone and an upstream rename never leaves two copies of a review layer running.

## Context and value

The issue records that `harness bmad apply <repo>` (#48) was manual, and that the framework gitignores user overrides, so every fresh clone and every machine started without them until someone remembered. It also records that `apply` wrote a template first and reported drift second, so after an upstream rename the framework's merge appended the override's layer beside the renamed original, and both ran.

## Acceptance criteria

1. **Given** a session starting in a repository with a framework install and a templated skill, **when** the `harness-session` hook runs, **then** it installs the overrides, and adds one line to the session context only when it wrote, kept or skipped a file.
2. **Given** a repository without the framework, or with every override already in place, **when** a session starts, **then** nothing is printed.
3. **Given** an installed skill that no longer declares a template's keys or layer ids, **when** `apply` runs, **then** that template is skipped with a reason and the rest are installed.
4. **Given** `check`, **when** it runs, **then** its behaviour is unchanged.

## Design

### Approach

`claude/hooks/harness-session.py` calls `harness bmad apply` for the session's repository. In `bin/harness`, `apply` computes drift per template before writing anything.

### Decisions and alternatives

- **Silent unless something changed**, so a repository with nothing to do costs no context (from the pull request).
- **Drift first, then write**, so the install is never made worse by an upstream rename (from the issue).

### Do not implement

Not recorded in the issue or pull request.

### Later change

At `origin/main` the session hook no longer installs anything: `policy/hooks/harness-session.py` checks declared integrations "without modifying repository configuration", and "installation requires an explicit CLI operation". `docs/bmad.md` now titles the section "Shared roles and explicit installation". Criterion 1 describes the v0.5.0 design only; the record of when it changed is not in this story's sources.
