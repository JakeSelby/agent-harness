## Reproduction

Run the de-duplication example in `docs/telemetry.md` against the OpenTelemetry ClickHouse exporter's
standard `otel_logs` table, the schema the doc names and the one the reference recipe's backend uses.
Observed, per the issue: the query, which used `argMax(…, ObservedTimestamp)`, fails as written, and
nothing exported says which of two records for one `harness.row_key` is newer.

## Root cause

The `otel_logs` table has no `ObservedTimestamp` column: the observed time is dropped on ingest.
`Timestamp` is the row's own end time, which is identical across replays, so it cannot order two exports
of one row. The exported records carried no other export-time field.
[Source: https://github.com/JakeSelby/agent-harness/issues/365]

## Acceptance criteria

1. **Given** any exported record, **when** it is built, **then** it carries `harness.exported_at`, the
   export time as an RFC 3339 UTC string with sub-second precision, so records for one key order correctly
   as plain strings.
2. **Given** the standard `otel_logs` schema (`Timestamp`, `Body`, `LogAttributes`, `ServiceName`, …),
   **when** the documented de-duplication example runs, **then** it orders by that attribute and runs
   unmodified.
3. **Given** two exports of one row, **when** they are compared, **then** they differ in the stamp and the
   observed time and nothing else.

## Design

### Approach

`policy/hooks/telemetry.py` stamps every exported record with `harness.exported_at` as a fixed-width
RFC 3339 UTC string with six fractional digits, so records order correctly as plain strings in a
`Map(String, String)`. The documented example orders by that attribute and wraps `harness.usd` in
`toFloat64OrNull`, since attributes arrive as strings.

### Decisions and alternatives

- **Fixed width, six fractional digits:** string order then matches time order.
- **A guard test on the documented SQL:** it parses the example and rejects any identifier outside the
  table's real columns, with `ObservedTimestamp` as the negative control, so this class of defect cannot
  return quietly.

### Do not implement

The PR records the "Reference recipe: ClickStack" section as unchanged. Nothing else is recorded in the
issue or pull request.
